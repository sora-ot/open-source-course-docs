# 00.讲义导读与学习路线

> 本讲义面向"想真正读懂 EasySpider 源码"的人。

> 不讲空理论，每一节都对应仓库里的一段真实代码。

示例任务URL：  
https://data.earthquake.cn/datashare/report.shtml?PAGEID=earthquake_csn

---

## 1. EasySpider 是什么

先用一句话说清楚：

> **在浏览器上右键点几下元素，就能生成一个爬虫任务，然后自动跑起来。**

打个比方，它像"录屏"。

你正常地打开网页。

你点按钮。

你翻页。

你选中要采集的文字。

软件在旁边默默把你做的动作**翻译成一份 JSON 任务**。

这份 JSON 可以被随时重放（执行）。

就像录音被重新播放一样。

所以整个软件的核心只有两件事：

```text
① 设计任务：人点元素  →  记录成 JSON          （浏览器扩展 + Electron 流程图）
② 执行任务：读 JSON    →  用浏览器自动重放      （Python 执行器 + Selenium）
```

## 2. 仓库里有哪几个"零件"

打开仓库根目录，你会看到 6 个主要文件夹。

下表逐个说明它们是谁、用什么写的、干什么：

| 文件夹 | 它是谁 | 用什么写的 | 干什么 |
| --- | --- | --- | --- |
| `Extension/` | 浏览器扩展（新，MV3） | TypeScript + Vue3 | 在网页上选中元素、生成任务片段 |
| `ElectronJS/` | 桌面软件壳 | Electron + Vue3 + Node | 任务管理、流程图可视化、串起所有零件 |
| `ExecuteStage/` | 执行引擎 | Python + Selenium | 拿着 JSON 真正去跑任务、抓数据 |
| `Examples/` | 任务样例 | JSON | 官方示例任务，学习格式的最佳材料 |
| `Docs/` | 文档 | Markdown/PDF | 论文、说明 |
| `scripts/` | 杂项脚本 | Python/JS | 环境自检、测试 |

关于这张表，记一个口诀就够：

> 记忆口诀：**扩展负责"点"，Electron 负责"画与管"，Python 负责"跑"。**

## 3. 三个进程是怎么说话的

这是理解整个项目的**第一把钥匙**。

三个进程各在一个世界里。

它们靠 **WebSocket 8084 端口** 聊天。

下面这张图，把三个进程和它们之间的通道画了出来：

```text
┌────────────────┐   WebSocket 8084   ┌─────────────────┐
│  浏览器扩展     │◄──────────────────►│  Electron 主程序 │
│ (content.js)   │   元素/任务/命令    │   (main.js)      │
└────────────────┘                    └────────┬────────┘
                                               │ 本机 HTTP / 子进程
                                               ▼
                                      ┌─────────────────┐
                                      │  Python 执行器   │
                                      │ (Selenium 跑任务) │
                                      └─────────────────┘
```

再补三条细节：

- 扩展连的是 `ws://localhost:8084`（写死在代码里，见 `messageInteraction.js`）；
- Electron 的 `main.js` 里 `WebSocket.Server({port: 8084})` 接住它；
- 设计任务时，Electron 还直接调用 Selenium 做"试运行"（trial），这样不用等任务保存就能看到效果。

## 4. 一个任务 JSON 长什么样

任务定义里有元数据、输入输出摘要和 `graph`。先看一份简化的结构骨架：

~~~json
{
  "name": "房源采集",
  "graph": [
    {"option":0, "title":"root", "sequence":[1,2]},
    {"option":1, "title":"打开网页", "sequence":[]},
    {"option":8, "title":"循环", "sequence":[3,4]},
    {"option":2, "title":"点击元素", "sequence":[]},
    {"option":3, "title":"提取数据", "sequence":[]}
  ]
}
~~~

这是省略参数的教学骨架，不是完整可导入任务。

- **`graph`**：完整节点数组；容器用 `sequence` 保存按顺序排列的孩子**数组下标**。顺序、循环和判断分别解释这些孩子，详细见第 15–16 篇。
- **`inputParameters`**：对外可调整的输入摘要，用 `nodeId` 指回数组位置。
- **`outputParameters`**：输出字段摘要；具体字段定位保存在采集节点的 `parameters.params` 中。

节点 `option` 决定具体执行，以下取值以 `easyspider_executestage.py` 的 `executeNode()` 分发为准。`constants.py` 中的 `GraphOption` 只列出了其中部分操作。

| option | 含义 | option | 含义 |
| --- | --- | --- | --- |
| 0 | root 顺序容器 | 6 | 切换下拉框 |
| 1 | 打开网页 | 7 | 移动到元素 |
| 2 | 点击元素 | 8 | 循环 |
| 3 | 提取数据 | 9 | 判断容器 |
| 4 | 输入文字 | 10 | 条件分支容器 |
| 5 | 自定义操作 | | |

`sequence` 不是所有图形箭头的“下一站”。循环回跳和分支汇合主要由解释器递归与函数返回完成。

## 5. 推荐学习路线

先读第 00～02 篇理解架构与数据流。需要动手实践时，可以提前阅读 [27.项目开发、调试、打包与发布](/easyspider/chapter-27) 的前两部分（第 1～14 节），安装依赖、启动源码、生成执行实例，并在扩展、Electron 主进程、流程图页面和 Python 中练习断点。

环境跑通后按业务依赖往下读：扩展先把网页操作变成消息，流程图接着把消息变成可存储、可执行的任务；正式执行器细节融入第 15–17 篇，再看反向反馈与桌面服务。

~~~text
① 全局：00 导读 → 01 架构 → 02 全链路
② 扩展基础：03 Chrome 扩展 → 04 XPath
③ 选择、参数与遍历：05 选中/待选 → 06 自动匹配 → 07 手动匹配
              → 08 参数生成 → 09 DFS/BFS → 10 选中子元素/预览
④ 界面：11 Vue 背景 → 12 toolkit.vue
⑤ 通信：13 WebSocket 背景 → 14 messageInteraction.js
⑥ 执行阶段：15 Flowchart 怎样存 → 16 递归执行、控制流与生命周期
              → 17 Selenium（基础样例 → 真实 JSON → 动作、提取与历史恢复）
⑦ Flowchart 界面：18 稳定下标与界面编号
              → 19 渲染 → 20 增删改查 → 21 消息加节点 → 22 循环采集子元素与参数栏 → 23 保存/加载
⑧ 桌面与调试：24 Electron 与消息发送 → 25 调试功能与浏览器接收 → 26 Node/Express
⑨ 开发与交付：27 项目开发、调试、打包与发布（环境、源码调试、版本、构建与 Release）
~~~

第 11 篇放在第 12 篇前作为 Vue 背景，第 13 篇放在第 14 篇前作为 WebSocket 背景。第 14 篇发出消息后，先在第 15 篇推导任务结构，第 16 篇理解递归、循环/判断和正式执行器生命周期，再到第 17 篇学习 Selenium。第 17 篇第三部分逐节先读仓库 JSON 参数，再看第 14 篇场景的实现，`handleHistory()` 的浏览器恢复也集中在这里。执行阶段到第 17 篇讲完，再继续第 18～23 篇：沿用第 15 篇从 root 构建的 Flowchart 数据结构，区分稳定下标与界面编号，再讲清渲染和增删改查，再接入消息，最后保存与加载，以及后续桌面服务。

这一组用“海淀、朝阳；两轮页面；只采单间”的房源例子，先从简单顺序列表推到有序层次，再解释调用与返回；界面部分重新从一个 root 起步，先加顺序节点、再在中间加入循环，逐步分清 nodeList 的存储位置与父 sequence 的顺序；接着追踪编号、DOM 和增删改查，再讲消息怎样调用这些入口，最后写入磁盘 JSON。第 24 篇先看 Electron 如何处理调试请求并向浏览器插件发消息，第 25 篇再逐项看插件怎样接收、定位、标记、预览条件和显示试运行结果。最后在第 27 篇完成开发环境搭建与源码调试，再追踪版本号同步、浏览器准备、扩展构建、Python 冻结、Electron 打包、各平台组装、压缩与 Release 发布，以及用户怎样看到新版本。目录中的每篇标题都可点击打开。

## 6. 怎么用这份讲义

先说几条使用建议。

动手实践时，可先完成第 27 篇第 1～6 节的本地“打开网页 → 采集标题 → 保存 → 正式执行”，再配合第 7～14 节的断点步骤阅读各模块源码。第 25 篇讲软件提供的标记与试运行；第 27 篇统一讲开发环境、源码调试以及后续打包发布。

- 每篇文件**只讲一件事**，可以按小节分次阅读，源码详解篇需要更多时间；
- 遇到代码块，**建议打开仓库对照**对应文件看；
- 标了 `💡` 的地方是易错点，标了 `🔬` 的地方是"深入一步"；
- 想看可视化效果，打开同目录下的 `*.html` 交互讲义。
