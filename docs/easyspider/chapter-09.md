# 09.DFS 与 BFS：同一棵树，为什么会走出两种顺序

上一篇已经看过参数对象和各行示例值，知道标题、图片、价格怎样变成不同字段。接着解决“怎样找到这些内容”：选中整个商品块后，软件需要按确定顺序走进块里，检查它的子元素。

在读 EasySpider 的代码之前，我们先解决一个与软件无关的问题：**给你一棵树，怎样按确定的顺序把节点逐个访问一遍？**

这一次先看例子，手工走出 DFS、BFS 的顺序，再写示例代码。下一篇才把这些动作对应到 `handleDescendents()` 的“应选尽选”实现。

## 第一部分：先看一棵树，手工走出两种顺序

### 1. 用 A～H 表示一棵树

下面用 A～H 表示 8 个节点。A 是根节点，孩子从左到右排列：

```text
              A
              │
      ┌───────┴───────┐
      │               │
      B               C
      │               │
  ┌───┴───┐       ┌───┴───┐
  │       │       │       │
  D       E       F       G
                  │
                  H
```

每个字母代表一个节点；A 是根节点，B、C 是 A 的子节点，D、E 是 B 的子节点。字母只是节点名称，不是访问次序；DFS 与 BFS 会按各自的规则决定顺序。

我们约定：每个节点的子节点按图中从左到右的顺序排列；访问一个节点，就是把它的字母记到结果中。

| 概念 | 在这个例子中是什么 |
|---|---|
| 根节点 | A |
| 父节点 | D 的父节点是 B |
| 子节点 | B 的子节点是 D、E |
| 后代节点 | B、C、D、E、F、G、H 都是 A 的后代 |
| 叶子节点 | 没有子节点的节点，例如 D、H |
| 一棵子树 | 以 C 为根，包括 F、H、G 的整个分支 |

遍历这棵树，就是按某个规则逐个访问这些节点。下面两种规则都会覆盖全部 8 个节点，但访问顺序不同。

### 2. DFS：先走完一个分支，再处理旁边的分支

DFS 是 Depth-First Search，中文叫深度优先搜索。这里用它遍历树，并采用“先访问父节点，再从左到右访问子树”的顺序。

先不用代码，按下面的动作走：

1. 记录 A。
2. 进入第一个子节点 B，记录 B。
3. 进入 B 下面的 D，记录 D。它没有孩子，这条路走到头。
4. 回到 B，处理还没访问的 E。
5. B 这一支已经走完，回到 A，再进入 C。
6. 进入 F，再进入它下面的 H。
7. F 这一支走完，最后处理 G。

把访问次序标在原来的树上，方括号中的数字表示“第几次访问”，不是层数：

```text
            [1] A
              │
      ┌───────┴───────┐
      │               │
    [2] B           [5] C
      │               │
  ┌───┴───┐       ┌───┴───┐
  │       │       │       │
[3] D   [4] E   [6] F   [8] G
                  │
                [7] H
```

沿编号读出访问顺序：

```text
A → B → D → E → C → F → H → G
```

**“深度优先”体现在：B 的后代先处理完，才轮到它旁边的 C；F 的后代先处理完，才轮到 G。**

DFS 也可以采用其他访问父节点的时机。本篇始终使用上面这种先访问父节点的前序遍历，方便与下一篇源码对应。

### 3. BFS：先处理同一层，再进入下一层

BFS 是 Breadth-First Search，中文叫广度优先搜索。

仍然不用代码，这次按层记录：

| 层级 | 这一层访问的节点 |
|---|---|
| 第 0 层 | A |
| 第 1 层 | B、C |
| 第 2 层 | D、E、F、G |
| 第 3 层 | H |

在同一棵树上标出 BFS 的访问次序：

```text
            [1] A
              │
      ┌───────┴───────┐
      │               │
    [2] B           [3] C
      │               │
  ┌───┴───┐       ┌───┴───┐
  │       │       │       │
[4] D   [5] E   [6] F   [7] G
                  │
                [8] H
```

同一层从左到右读完，再读下一层，得到：

```text
A → B → C → D → E → F → G → H
```

处理 B 后，先处理同层的 C，再处理 B 的孩子 D、E。这就是它与前面 DFS 的区别。

### 4. 两种顺序都要记住“还有哪些节点没处理”

用手指沿图走时，我们会记住没走过的分支。程序也要保存这些待办节点。

| 方法 | 保存待办节点的容器 | 取出规则 | 对顺序的影响 |
|---|---|---|---|
| DFS | 栈 | 后进先出 | 新发现的下一层节点可以先处理 |
| BFS | 队列 | 先进先出 | 早已排队的同层节点先处理 |

把栈想成叠起来的书：最后放上去的书最先拿走。把队列想成排队领资料：先排队的人先领取。

两者存的都是“待处理节点”，不是已经访问完成的结果。下面开始把这种记忆写成代码。

## 第二部分：把同一个例子写成 JavaScript

### 5. 先表示这棵树

在浏览器控制台或 Node.js 中执行下面的数据和后续函数即可。节点的字母名称保存在普通对象的字符串属性中。

```js
const tree = {
    name: "A",
    children: [
        {
            name: "B",
            children: [
                { name: "D", children: [] },
                { name: "E", children: [] }
            ]
        },
        {
            name: "C",
            children: [
                {
                    name: "F",
                    children: [{ name: "H", children: [] }]
                },
                { name: "G", children: [] }
            ]
        }
    ]
};
```

每个对象用 `name` 表示自己，用 `children` 保存孩子。叶子节点的 `children` 是空数组，程序读到它就知道没有下一层。

读这段数据时，要从树上的关系推回对象里的位置：

1. 最上面的 A 是根，所以整个 `tree` 对象的 `name` 是 `"A"`。
2. 根的下一层有 B、C，所以 `tree.children` 有两个对象，按从左到右的顺序存放。
3. `tree.children[0]` 是 B；继续读它的 `children[0]`，才到 D。这里的下标 `0` 表示第一个孩子，不表示第 0 层。
4. H 在 C 下面的 F 下面，因此它的位置是 `tree.children[1].children[0].children[0]`。
5. H 没有孩子，所以它的 `children` 为 `[]`。遍历到它时仍然要记录“H”，只是不用再添加下一层节点。

**数组只保存当前节点的直接孩子。** 根的 `children` 里没有直接放 D 或 H；程序必须逐层读取，才能走到这些后代。

### 6. DFS 的栈写法：push() 放入，pop() 取出

```js
function dfs(root) {
    const result = [];
    const stack = [root];

    while (stack.length > 0) {
        const node = stack.pop();
        result.push(node.name);

        // ⭐️注意是逆序入栈
        for (let i = node.children.length - 1; i >= 0; i--) {
            stack.push(node.children[i]);
        }
    }

    return result;
}

console.log(dfs(tree).join(" → "));
```

输出正是手工走出的顺序：

```text
A → B → D → E → C → F → H → G
```

#### 6.1 先建立结果数组与待办栈

```js
const result = [];
const stack = [root];
```

`result` 保存已经访问的名字，`stack` 保存还没处理的节点。刚开始只知道根，所以栈里只有 A。

#### 6.2 有待办节点，就取出栈顶并访问

```js
while (stack.length > 0) {
    const node = stack.pop();
    result.push(node.name);
    // 随后把它的孩子加入栈
}
```

`pop()` 从数组末尾取出并删除一个节点。第一次循环要按语句顺序推理：

1. 此时 `stack = [A]`，长度为 `1`，所以 `stack.length > 0` 成立，进入循环。
2. 执行 `const node = stack.pop()`：`node` 得到 A 这个对象，栈同时变成 `[]`。
3. 执行 `result.push(node.name)`：把字符串“A”写入结果，得到 `result = [A]`。
4. 当前节点已经访问，但这一轮还没结束。接着读它的 `children`，把孩子放进栈。
5. 整个循环体完成后，才重新检查 `while` 条件。只要栈还有节点，就继续取下一个。

注意 `result.push()` 和 `stack.push()` 的用途：前者记录已经访问的名字，后者安排以后要访问的节点。

#### 6.3 孩子逆序入栈，实际访问才会从左到右

```js
for (let i = node.children.length - 1; i >= 0; i--) {
    stack.push(node.children[i]);
}
```

A 的孩子数组是 `[B, C]`，长度为 `2`。代入 `for` 循环逐句算：

1. `i = node.children.length - 1 = 2 - 1 = 1`。
2. `i >= 0` 成立；`node.children[1]` 是 C。执行 `push()` 后，栈为 `[C]`。
3. 执行 `i--`，`i` 从 `1` 变成 `0`。
4. `i >= 0` 仍成立；`node.children[0]` 是 B。再次 `push()` 后，栈为 `[C, B]`。
5. 再执行 `i--`，`i` 变成 `-1`；条件不成立，结束 `for` 循环。
6. 下一轮 `while` 调用 `pop()`，取数组末尾的 B。因此虽然 C 先入栈，B 却先访问。

把这几步合起来看：

```text
栈底 → 栈顶：[C, B]
下一次 pop()：取出 B
```

随后处理 B，先压 E，再压 D：

```text
栈底 → 栈顶：[C, E, D]
下一次 pop()：取出 D
```

C 一直留在栈底等待。直到 D、E 处理完，才轮到 C。

**逆序入栈控制的是同级孩子的访问方向。** 正序入栈仍然是 DFS，只是先访问右边的子树。

#### 6.4 把每一轮的栈写出来

下面逐轮推演。所有方括号里的节点名都是为了简化显示；真实的栈保存节点对象。数组右端是栈顶。

1. **第 1 轮：A。** 从 `[A]` 弹出根，栈变空；结果记下 A。根有两个孩子，先压 C，再压 B。本轮结束时栈为 `[C, B]`，所以下一轮取 B。
2. **第 2 轮：B。** 弹出 B 后，栈为 `[C]`；结果追加 B。B 有两个孩子，先压 E，再压 D，得到 `[C, E, D]`。D 位于栈顶，所以它比 C 先处理。
3. **第 3 轮：D。** 弹出后剩 `[C, E]`；结果追加 D。它的孩子数为 `0`，因此 `for` 的初始 `i = -1`，条件直接为假，没有节点入栈。下一轮取 E。
4. **第 4 轮：E。** 弹出后剩 `[C]`；结果追加 E。它也没有孩子，栈不再增加节点。B 这棵子树至此全部访问完，下一轮才轮到 C。
5. **第 5 轮：C。** 弹出后栈为空；结果追加 C。先压 G，再压 F，栈变成 `[G, F]`，下一轮取 F。
6. **第 6 轮：F。** 弹出后剩 `[G]`；结果追加 F。它只有 H 这一个孩子，`i` 从 `0` 开始，只入栈一次，得到 `[G, H]`。H 后入栈，所以下一轮先取 H。
7. **第 7 轮：H。** 弹出后剩 `[G]`；结果追加 H。H 没有孩子，所以 G 成为下一轮要取的节点。
8. **第 8 轮：G。** 弹出后栈为空；结果追加 G。没有孩子可入栈，重新检查 `while` 时 `stack.length = 0`，循环结束，执行 `return result`。

**所谓“回到父节点”，在这份栈代码中没有重新访问父节点。** 例如访问完 D 后，程序直接取出早已存好的 E；访问完 E 后，直接取出 C。栈保存了未完成的分支，所以不需要再把 B 或 A 写进结果。

把逐轮推理压缩成表，方便对照；栈状态均为本轮结束时的状态：

| 轮次 | 本轮弹出 | 本轮结束的栈 | 解释 |
|---:|---|---|---|
| 1 | A | `[C, B]` | B 最后入栈，下一轮先取它 |
| 2 | B | `[C, E, D]` | B 的孩子盖在 C 上面 |
| 3 | D | `[C, E]` | 没有孩子，直接进入下一轮 |
| 4 | E | `[C]` | B 的整支处理完 |
| 5 | C | `[G, F]` | F 先处理 |
| 6 | F | `[G, H]` | H 优先于 G |
| 7 | H | `[G]` | 没有孩子 |
| 8 | G | `[]` | 栈空，循环结束 |

### 7. BFS 的队列写法：按入队顺序取出

```js
function bfs(root) {
    const result = [];
    const queue = [root];
    let head = 0;

    while (head < queue.length) {
        const node = queue[head];
        head++;
        result.push(node.name);

        for (let i = 0; i < node.children.length; i++) {
            queue.push(node.children[i]);
        }
    }

    return result;
}

console.log(bfs(tree).join(" → "));
```

输出：

```text
A → B → C → D → E → F → G → H
```

#### 7.1 head 表示下一个要取的位置

```js
const queue = [root];
let head = 0;
```

`queue` 保存入队顺序，`head` 指向第一个还没访问的位置。数组中 `head` 之前的节点已经处理过，不再参与排队。

初始化后，`queue = [A]`、`head = 0`。因为 `0 < 1`，循环可以开始；`queue[0]` 就是第一轮要访问的 A。

这里不能用 `queue.length > 0` 判断是否继续：这个实现不删除已处理元素，数组会一直非空。正确判断是 `head < queue.length`，也就是“队头后面是否还有待办节点”。

#### 7.2 从队头取节点，向队尾追加孩子

```js
const node = queue[head];
head++;
result.push(node.name);

for (let i = 0; i < node.children.length; i++) {
    queue.push(node.children[i]);
}
```

先看第 1 轮每条语句怎样改变状态：

1. 执行 `const node = queue[head]`。此时 `head = 0`，所以取得 `queue[0]`，即 A；数组本身没有删除任何元素。
2. 执行 `head++`，使 `head` 变成 `1`。这表示下次从位置 `1` 取节点；刚取出的 A 仍由变量 `node` 保存。
3. 执行 `result.push(node.name)`，结果变成 `[A]`。
4. 孩子数为 `2`，`for` 从 `i = 0` 开始。先把 B 追加到队尾，完整数组为 `[A, B]`。
5. `i` 变成 `1`，再把 C 追加到队尾，完整数组为 `[A, B, C]`。
6. `i` 变成 `2`，不再满足 `i < 2`，结束 `for`。此时 `head = 1`，待办部分为 `[B, C]`。
7. 再检查 `while`：`1 < 3` 成立。下一轮取 `queue[1]`，所以访问 B。

第 2 轮取出 B 后，`head` 变成 `2`。它的孩子 D、E 依次追加，完整数组变成：

```text
数组下标： 0  1  2  3  4
完整数组：[A, B, C, D, E]
                 ↑
             head = 2
已经处理：[A, B]
尚未处理：[C, D, E]
```

因此下一轮取的是 `queue[2]`，即 C。D 虽然刚被发现，也必须排在已经入队的 C 后面。这是队列保证先处理同层节点的具体原因。

也可以用 `shift()` 直接删除并取出队头。本例用下标移动队头，避免每轮删除数组首项；已经处理过的元素仍保留在数组中，因此这份实现的数组最终会保存全部节点引用。

#### 7.3 用待办队列检查每一轮

前两轮已经逐句拆开，接着按同样的语句顺序往下推：

1. **第 1 轮：A。** 从下标 `0` 取根，`head` 变成 `1`，记录 A；追加 B、C，待办为 `[B, C]`。
2. **第 2 轮：B。** 从下标 `1` 取 B，`head` 变成 `2`，记录 B；追加 D、E，待办为 `[C, D, E]`。
3. **第 3 轮：C。** 从下标 `2` 取 C，`head` 变成 `3`，记录 C；追加 F、G，待办为 `[D, E, F, G]`。第 1 层全部处理完后，才开始处理第 2 层。
4. **第 4 轮：D。** 从下标 `3` 取 D，`head` 变成 `4`，记录 D。孩子数为 `0`，`for` 的初始条件 `0 < 0` 为假，不追加节点；待办剩 `[E, F, G]`。
5. **第 5 轮：E。** 从下标 `4` 取 E，`head` 变成 `5`，记录 E。没有孩子，待办剩 `[F, G]`。
6. **第 6 轮：F。** 从下标 `5` 取 F，`head` 变成 `6`，记录 F；追加 H，待办为 `[G, H]`。G 早已入队，因此 H 不能排到它前面。
7. **第 7 轮：G。** 从下标 `6` 取 G，`head` 变成 `7`，记录 G。没有孩子，待办只剩 `[H]`。第 2 层全部处理完后，才轮到第 3 层的 H。
8. **第 8 轮：H。** 从下标 `7` 取 H，`head` 变成 `8`，记录 H。没有孩子，此时完整数组长度也是 `8`；`8 < 8` 为假，循环结束，返回结果。

此时完整 `queue` 仍保存全部 8 个节点，但待办队列已经空了。表中只写 `queue.slice(head)`，即尚未处理的部分，左端是队头：

| 轮次 | 本轮取出 | 本轮结束的待办队列 |
|---:|---|---|
| 1 | A | `[B, C]` |
| 2 | B | `[C, D, E]` |
| 3 | C | `[D, E, F, G]` |
| 4 | D | `[E, F, G]` |
| 5 | E | `[F, G]` |
| 6 | F | `[G, H]` |
| 7 | G | `[H]` |
| 8 | H | `[]` |

### 8. DFS 也可以用递归表示

```js
function dfsRecursive(node, result = []) {
    result.push(node.name);
    for (const child of node.children) {
        dfsRecursive(child, result);
    }
    return result;
}

console.log(dfsRecursive(tree).join(" → "));
```

#### 8.1 按层次画出递归调用栈

每次进入 `dfsRecursive()`，运行时都会增加一个调用栈帧；函数返回时，移除最上面的栈帧。**图中上方是栈顶，下方是栈底；栈顶正在执行，下面的调用暂停并等待子调用返回。**

这里把 A 的调用记为第 1 层，子调用每深入一次就增加一层。层数表示当前调用深度，不是访问编号。图中的 `dfsRecursive(A)` 表示传入名称为 A 的节点对象，省略了共用的 `result` 参数；这里只画 DFS 函数的栈帧。

**① 刚进入 A：只有第 1 层。** A 先记录自己，然后准备调用 B。

```text
┌───────────────────────┐
│    dfsRecursive(A)    │  第 1 层：当前执行，栈顶也是栈底
└───────────────────────┘
```

**② A 调用 B，B 再调用 D：逐层入栈。** 此时 D 正在执行，A、B 都没有结束。

```text
┌───────────────────────┐
│    dfsRecursive(D)    │  第 3 层：栈顶，当前执行
├───────────────────────┤
│    dfsRecursive(B)    │  第 2 层：暂停，等待 D 返回
├───────────────────────┤
│    dfsRecursive(A)    │  第 1 层：栈底，暂停，等待 B 返回
└───────────────────────┘
```

A 入栈后记录 A；B 入栈后记录 B；D 入栈后记录 D。因此此时共用的结果数组为 `[A, B, D]`。栈中保存的是尚未返回的三次调用，结果数组保存的是已经访问的名字。

**③ D 没有孩子，执行 return：第 3 层出栈，恢复 B。**

```text
┌───────────────────────┐
│    dfsRecursive(B)    │  第 2 层：栈顶，恢复执行，准备调用 E
├───────────────────────┤
│    dfsRecursive(A)    │  第 1 层：栈底，仍在等待 B 返回
└───────────────────────┘
```

B 从调用 D 的语句之后继续它的 `for` 循环，取下一个孩子 E。它不会从函数开头重来，也不会再记录一次 B。

**④ B 调用 E：重新建立第 3 层。** D 的调用已经结束，E 使用新的栈帧。

```text
┌───────────────────────┐
│    dfsRecursive(E)    │  第 3 层：栈顶，当前执行
├───────────────────────┤
│    dfsRecursive(B)    │  第 2 层：暂停，等待 E 返回
├───────────────────────┤
│    dfsRecursive(A)    │  第 1 层：栈底，暂停，等待 B 返回
└───────────────────────┘
```

E 记录自己后返回，E 出栈；B 的孩子全部处理完，B 也返回并出栈。此时只剩 A，A 恢复后才开始调用 C。

**⑤ 接着 A 调用 C，C 调用 F，F 调用 H：达到第 4 层。**

```text
┌───────────────────────┐
│    dfsRecursive(H)    │  第 4 层：栈顶，当前执行
├───────────────────────┤
│    dfsRecursive(F)    │  第 3 层：暂停，等待 H 返回
├───────────────────────┤
│    dfsRecursive(C)    │  第 2 层：暂停，等待 F 返回
├───────────────────────┤
│    dfsRecursive(A)    │  第 1 层：栈底，暂停，等待 C 返回
└───────────────────────┘
```

H 没有孩子，先出栈；F 恢复后发现自己的循环也结束了，再出栈；C 恢复，继续调用下一个孩子 G。**不会因为 H 返回，就把 C 和 A 一起清掉。** 每次 return 只结束当前调用。

**⑥ C 调用 G：栈又变成 3 层。**

```text
┌───────────────────────┐
│    dfsRecursive(G)    │  第 3 层：栈顶，当前执行
├───────────────────────┤
│    dfsRecursive(C)    │  第 2 层：暂停，等待 G 返回
├───────────────────────┤
│    dfsRecursive(A)    │  第 1 层：栈底，暂停，等待 C 返回
└───────────────────────┘
```

G 返回后出栈，C 随后返回并出栈，最后 A 返回。DFS 的调用栈帧全部移除，但最外层返回的结果数组仍是 `[A, B, D, E, C, F, H, G]`，交给 `console.log()` 使用。

把所有入栈、出栈动作按时间顺序写全。下表为节省空间用字母表示栈帧，数组左端为栈底、右端为栈顶，与上面的竖直栈图对应：

| 步骤 | 动作 | 动作完成后的调用栈 | 正在执行或恢复的层 |
|---:|---|---|---|
| 1 | 进入 A，入栈 | `[A]` | 第 1 层 A |
| 2 | A 调用 B，B 入栈 | `[A, B]` | 第 2 层 B |
| 3 | B 调用 D，D 入栈 | `[A, B, D]` | 第 3 层 D |
| 4 | D 返回，出栈 | `[A, B]` | 第 2 层 B 恢复 |
| 5 | B 调用 E，E 入栈 | `[A, B, E]` | 第 3 层 E |
| 6 | E 返回，出栈 | `[A, B]` | 第 2 层 B 恢复 |
| 7 | B 返回，出栈 | `[A]` | 第 1 层 A 恢复 |
| 8 | A 调用 C，C 入栈 | `[A, C]` | 第 2 层 C |
| 9 | C 调用 F，F 入栈 | `[A, C, F]` | 第 3 层 F |
| 10 | F 调用 H，H 入栈 | `[A, C, F, H]` | 第 4 层 H |
| 11 | H 返回，出栈 | `[A, C, F]` | 第 3 层 F 恢复 |
| 12 | F 返回，出栈 | `[A, C]` | 第 2 层 C 恢复 |
| 13 | C 调用 G，G 入栈 | `[A, C, G]` | 第 3 层 G |
| 14 | G 返回，出栈 | `[A, C]` | 第 2 层 C 恢复 |
| 15 | C 返回，出栈 | `[A]` | 第 1 层 A 恢复 |
| 16 | A 返回，出栈 | `[]` | DFS 返回调用方 |

一个栈帧需要记住本次的 `node`、循环处理到哪个孩子、子调用返回后从哪里继续，以及对 `result` 的引用。每层有自己的执行位置，但这里的所有层共享同一个结果数组。

#### 8.2 沿调用和返回一步步推

这段代码也要按执行顺序推，而不是把“调用自己”当作一句解释：

1. **调用 `dfsRecursive(tree)`。** 第一次没有传 `result`，默认参数创建一个空数组。`node` 是 A，先把 A 写进去，再开始遍历它的孩子。
2. **根的循环先取到 B。** 调用 `dfsRecursive(child, result)`，此时 `child.name` 是 `"B"`，并把同一个结果数组传下去。A 这一层的循环暂时停在这次调用处，必须等 B 的调用返回，才会继续取 C。
3. **B 这一层先记录 B，再调用 D。** D 先把自己的名字写入结果；它没有孩子，`for` 一次也不执行，直接 `return result`，返回到 B 的循环中。
4. **B 的循环继续取 E。** E 记录自己后同样返回。B 的两个孩子都处理完，B 的函数执行 `return result`，回到 A 那一层。
5. **A 的循环现在才取 C。** C 先记录自己，再进入它的第一个孩子 F。此时结果是 `[A, B, D, E, C]`。
6. **F 先记录自己，再调用 H。** H 记录自己后直接返回。F 的孩子已经遍历完，也返回 C 那一层。
7. **C 的循环继续取 G。** G 记录自己后返回，C 的孩子全部处理完，再返回 A 那一层。
8. **根的循环结束。** A 的两个孩子都已完成，最外层函数返回完整结果：`[A, B, D, E, C, F, H, G]`。

这里有两个容易漏掉的细节：

- 每次子调用都显式传入 `result`，所以所有调用向同一个数组追加名字。默认的 `[]` 只在本次最外层调用未传该参数时创建。
- `return result` 不会再次记录节点。它让当前调用结束，上一层从暂停处继续。访问顺序由“先记录自己，再等每棵子树完成”的语句顺序决定。

运行时的函数调用栈保存了尚未完成的上一层，所以这里虽然没有写 `stack` 数组，仍然有栈帮助记住返回位置。这份递归代码与前面的栈版 DFS 得到相同顺序；树很深时，递归可能触及运行环境的调用栈限制。

## 第三部分：从普通树过渡到网页元素树

### 9. DOM 也有父子关系，换的是节点与访问动作

假设一个商品块的 HTML 是：

```html
<article>
  <a href="/book"><span>Java 入门</span></a>
  <img src="book.jpg">
  <p>￥99</p>
</article>
```

只看元素节点，它的树形关系是：

```text
                 article 商品块
                        │
        ┌───────────────┼───────────────┐
        │               │               │
     a 链接         img 图片         p 价格
        │
    span 标题
```

| 遍历方式 | 不加过滤时的元素访问顺序 |
|---|---|
| DFS | `article → a → span → img → p` |
| BFS | `article → a → img → p → span` |

示例对象用 `node.name` 取得名字；DOM 元素可以用 `node.tagName` 取得标签。两者都可以通过 `children` 读取子元素，但 DOM 的 `children` 是集合，不是普通数组。

沿用栈版 DFS，在浏览器中可以这样访问商品块：

```js
function walkElements(root) {
    const result = [];
    const stack = [root];
    while (stack.length > 0) {
        const node = stack.pop();
        result.push(node.tagName);
        for (let i = node.children.length - 1; i >= 0; i--) {
            stack.push(node.children[i]);
        }
    }
    return result;
}

console.log(walkElements(document.querySelector("article")));
```

在含有上面 HTML 的页面中运行，结果为 `["ARTICLE", "A", "SPAN", "IMG", "P"]`。`children` 不包含空白文本节点，所以换行和缩进不会变成待办元素。

把 DOM 代码和前面的普通对象代码逐步对应起来：

1. `document.querySelector("article")` 取得树顶的商品块元素，作为 `root` 传入。示例假定页面中存在这个元素。
2. 第一轮弹出 `article`，用 `node.tagName` 记录 `"ARTICLE"`。它的孩子从左到右是 `a、img、p`，循环从下标 `2` 开始，依次压入 `p、img、a`。
3. 第二轮弹出 `a`，栈剩 `[p, img]`；记录 `"A"`，再把它唯一的孩子 `span` 压入，栈变成 `[p, img, span]`。
4. 第三轮弹出 `span`，记录 `"SPAN"`。里面的“Java 入门”是文本，不在元素 `children` 中，因此没有孩子入栈，栈剩 `[p, img]`。
5. 第四轮弹出 `img`，记录 `"IMG"`。没有子元素，栈剩 `[p]`。
6. 第五轮弹出 `p`，记录 `"P"`。价格文字也是文本，没有子元素入栈；栈空，返回结果。

因此 `span` 会在图片之前被访问：它虽然更深，却在处理 `a` 时被压到了 `img` 上面。代码没有写“优先标题”的特殊规则，这个顺序来自树的结构和栈的取出规则。

### 10. 遍历顺序与采集规则是两个问题

走到一个节点，不表示一定要为它建立字段。软件还要判断：这个节点是否有可采集内容，是否应该跳过，和前面的字段是否对应同一个块内位置。

下一篇的 `handleDescendents()` 使用栈式 DFS，但访问时还会读取路径与内容、建立字段或追加示例值。它也有剪枝：某些节点被跳过后，其下面的整支不再进入待办栈。

DFS 本身不保证字段正确，BFS 本身也不决定字段属于哪一列。**遍历负责按顺序到达节点；字段规则负责解释节点中的内容。**

对于这棵没有环的树，以上代码不需要去重集合。如果换成有环的关系图，就需要另外记录已发现节点，避免反复进入同一个节点。不要把只适用于树的示例直接当作通用图遍历器。

### 11. 用同一棵树练习

1. 把栈版 DFS 的孩子循环改为从 `0` 开始递增，访问顺序怎样变化？它还是 DFS 吗？
2. 给 E 新增一个子节点 I，DFS 与 BFS 分别在哪里访问它？
3. 栈里还有 C 时，为什么 DFS 能先处理 D？
4. 处理 B 后，为什么 BFS 要先处理 C，再处理 D？
5. 如果“跳过 B”的判断发生在它的孩子入栈之前，D 和 E 还会被访问吗？

第 5 题正是下一篇源码里 `continue` 的位置问题。先确认自己能手工推演待办栈，再进入具体采集逻辑。
