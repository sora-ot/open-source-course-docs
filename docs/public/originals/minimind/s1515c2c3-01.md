# 09 · 困惑度与模型评估

<!-- LECTURE-CONTENT-START -->

## 1. 什么是困惑度 PPL？

困惑度（Perplexity，简称 **PPL**）是语言模型中最经典的评价指标之一。

它本质上回答的是：

> **模型看到一段真实文本时，到底有多“意外”、多“困惑”？**

如果模型能够比较准确地预测下一个 token，那么困惑度就低；  
如果模型对下一个 token 非常拿不准，那么困惑度就高。

因此通常：

\[
\boxed{\text{PPL 越低越好}}
\]

---

## 2. 先不看公式：什么叫“困惑”？

假设模型看到：

```text
我今天早上吃了一个____
```

有两个模型。

### 2.1 模型 A

模型 A 认为下一个词的概率是：

```text
苹果     0.70
鸡蛋     0.15
馒头     0.10
电脑     0.01
飞机     0.01
其他     0.03
```

假设真实答案是：

```text
苹果
```

那么模型 A 给真实答案的概率是：

\[
P(\text{苹果})=0.7
\]

说明模型非常有把握。

---

#### 2.1.1 模型 B

模型 B 的预测是：

```text
苹果     0.10
鸡蛋     0.10
馒头     0.10
电脑     0.10
飞机     0.10
……
```

真实答案仍然是：

```text
苹果
```

此时：

\[
P(\text{苹果})=0.1
\]

模型 B 明显更加犹豫。

因此可以直观理解为：

```text
模型 A：困惑程度低
模型 B：困惑程度高
```

PPL 就是把这种“困惑程度”量化成一个数字。

---

## 3. PPL 最核心的直觉

PPL 有一个非常重要的直觉解释：

> **PPL 可以近似理解为：模型在每一步平均感觉自己面对多少个“差不多可能”的候选答案。**

例如：

\[
PPL=2
\]

可以粗略理解为：

> 每预测一个 token，难度大约相当于在 2 个等可能候选中选一个。

如果：

\[
PPL=10
\]

可以粗略理解为：

> 每一步大约像是在 10 个等可能候选中选择。

如果：

\[
PPL=100
\]

说明模型非常迷茫：

> 平均相当于在 100 个差不多可能的答案里选择。

因此：

\[
\boxed{\text{PPL 越低，模型越不困惑}}
\]

---

## 4. 从语言模型概率开始理解 PPL

对于自回归语言模型，例如 GPT，任务就是：

\[
\boxed{\text{根据前面的 token，预测下一个 token}}
\]

设一个 token 序列为：

\[
x_1,x_2,\cdots,x_N
\]

模型预测第 \(t\) 个 token 的概率为：

\[
P(x_t|x_1,\cdots,x_{t-1})
\]

简写为：

\[
P(x_t|x_{<t})
\]

---

### 4.1 一个简单例子

例如：

```text
我 喜欢 吃 苹果
```

模型实际上依次建模：

\[
P(\text{我})
\]

\[
P(\text{喜欢}|\text{我})
\]

\[
P(\text{吃}|\text{我 喜欢})
\]

\[
P(\text{苹果}|\text{我 喜欢 吃})
\]

整句话的联合概率为：

\[
P(x_1,x_2,x_3,x_4)
=
P(x_1)
P(x_2|x_1)
P(x_3|x_1,x_2)
P(x_4|x_1,x_2,x_3)
\]

即：

\[
\boxed{
P(x_1,\cdots,x_N)
=
\prod_{t=1}^{N}P(x_t|x_{<t})
}
\]

---

## 5. 一个完整的数字例子

假设模型预测真实 token 时得到：

```text
我 → 喜欢
```

模型给“喜欢”的概率：

\[
P(\text{喜欢}|\text{我})=0.5
\]

然后：

```text
我 喜欢 → 吃
```

模型给：

\[
P(\text{吃}|\text{我 喜欢})=0.25
\]

最后：

```text
我 喜欢 吃 → 苹果
```

模型给：

\[
P(\text{苹果}|\text{我 喜欢 吃})=0.125
\]

那么真实序列对应的概率为：

\[
0.5\times0.25\times0.125
\]

得到：

\[
0.015625
\]

但是这里有一个问题：

> **句子越长，概率连续相乘后一定越来越小。**

例如 1000 个 token，每个概率都是 0.5：

\[
0.5^{1000}
\]

已经是极其小的数字。

因此我们不能简单用整句话的联合概率来比较不同长度的文本。

---

## 6. 为什么要使用几何平均？

假设真实 token 的预测概率分别是：

\[
p_1,p_2,\cdots,p_N
\]

整个序列的概率是：

\[
p_1p_2\cdots p_N
\]

为了得到“平均每个 token 的概率水平”，应该使用几何平均，几何平均数（Geometric Mean）是一种通过计算多个数值的乘积并开n次方根来反映一组数据集中趋势或典型值的均值：

\[
P_{\text{avg}}
=
(p_1p_2\cdots p_N)^{1/N}
\]

然后，PPL 定义为这个平均概率的倒数：

\[
\boxed{
PPL=
\frac{1}
{(p_1p_2\cdots p_N)^{1/N}}
}
\]

也就是：

\[
\boxed{
PPL=
\left(
\prod_{t=1}^{N}
P(x_t|x_{<t})
\right)^{-1/N}
}
\]

---

## 7. 用刚才的数据计算 PPL

刚才三个真实 token 的概率是：

\[
0.5,\quad0.25,\quad0.125
\]

先求几何平均：

\[
(0.5\times0.25\times0.125)^{1/3}
\]

因为：

\[
0.5\times0.25\times0.125
=
0.015625
\]

所以：

\[
0.015625^{1/3}=0.25
\]

意味着模型平均给真实 token 的概率大约为：

\[
25\%
\]

因此：

\[
PPL=\frac1{0.25}=4
\]

所以：

\[
\boxed{PPL=4}
\]

可以粗略理解为：

> 模型平均每一步的困难程度，相当于从 4 个等可能答案中选择一个。

---

## 8. 一个最直观的特殊情况

假设每一步只有 4 个候选：

```text
苹果
香蕉
西瓜
葡萄
```

而模型认为它们完全等可能：

\[
P=0.25
\]

那么真实答案的概率就是：

\[
0.25
\]

因此：

\[
PPL=\frac1{0.25}=4
\]

即：

\[
\boxed{PPL=4}
\]

这正是为什么人们经常把 PPL 解释为：

> **有效候选数量（effective number of choices）**

注意，这只是直觉理解，并不意味着模型真的只在 4 个 token 中选择。

---

## 9. 如果模型特别厉害会怎样？

假设模型平均给真实 token 的概率为：

\[
0.5
\]

那么：

\[
PPL=\frac1{0.5}=2
\]

如果平均概率为：

\[
0.8
\]

那么：

\[
PPL=\frac1{0.8}=1.25
\]

极端情况下，如果模型每一步都百分之百预测正确：

\[
P=1
\]

那么：

\[
PPL=1
\]

因此 PPL 的理论最小值是：

\[
\boxed{1}
\]

不能小于 1。

---

## 10. PPL 与 Cross Entropy 的关系

实际训练 GPT 时，我们通常并不会直接优化 PPL，而是优化：

\[
\boxed{\text{Cross Entropy Loss}}
\]

定义：

\[
L=
-\frac{1}{N}
\sum_{t=1}^{N}
\ln P(x_t|x_{<t})
\]

而 PPL 定义为：

\[
\boxed{
PPL=
\exp
\left(
-\frac1N
\sum_{t=1}^{N}
\ln P(x_t|x_{<t})
\right)
}
\]

因此：

\[
\boxed{PPL=e^L}
\]

也就是：

\[
\boxed{
PPL=e^{\text{CrossEntropyLoss}}
}
\]

---

## 11. 为什么要使用对数？

原始序列概率是：

\[
p_1p_2p_3\cdots p_N
\]

当 \(N\) 很大时，这个值会非常小。

例如：

\[
0.01^{1000}
\]

计算机处理中容易发生数值下溢。

因此我们利用：

\[
\ln(ab)=\ln a+\ln b
\]

把：

\[
p_1p_2\cdots p_N
\]

转换成：

\[
\ln p_1+\ln p_2+\cdots+\ln p_N
\]

也就是把大量乘法变成加法。

因此实际训练过程可以理解为：

```text
正确 token 的概率
        ↓
      -log(p)
        ↓
Cross Entropy Loss
        ↓
     exp(loss)
        ↓
        PPL
```

---

## 12. 完整数值计算一次 Cross Entropy 和 PPL

还是使用：

```text
我 喜欢 吃 苹果
```

假设真实 token 的预测概率分别是：

\[
0.5,\quad0.25,\quad0.125
\]

Cross Entropy：

\[
L
=
-\frac13
[
\ln(0.5)
+
\ln(0.25)
+
\ln(0.125)
]
\]

其中：

\[
\ln0.5\approx-0.693
\]

\[
\ln0.25\approx-1.386
\]

\[
\ln0.125\approx-2.079
\]

所以：

\[
L
=
-\frac{-0.693-1.386-2.079}{3}
\]

得到：

\[
L\approx1.386
\]

然后：

\[
PPL=e^{1.386}
\]

得到：

\[
\boxed{PPL\approx4}
\]

与前面直接使用几何平均计算得到的结果完全一致。

---

## 13. Cross Entropy 和 PPL 的对应关系

因为：

\[
PPL=e^L
\]

所以可以得到：

| Cross Entropy Loss | PPL |
|---:|---:|
| 0 | 1 |
| 0.69 | ≈ 2 |
| 1.10 | ≈ 3 |
| 1.39 | ≈ 4 |
| 1.61 | ≈ 5 |
| 2.30 | ≈ 10 |
| 3.00 | ≈ 20 |
| 4.61 | ≈ 100 |

因此：

```text
Loss 越低
   ↓
PPL 越低
   ↓
模型对真实文本越不困惑
```

---

## 14. PPL 有什么用？

PPL 最常见的用途主要有以下几个。

---

### 14.1 用途一：评价语言模型训练得怎么样

例如训练过程中：

```text
Epoch 1
Loss = 4.0
PPL  = 54.6

Epoch 2
Loss = 3.0
PPL  = 20.1

Epoch 3
Loss = 2.3
PPL  = 10.0

Epoch 4
Loss = 2.0
PPL  = 7.39
```

可以看到：

```text
54.6
 ↓
20.1
 ↓
10.0
 ↓
7.39
```

说明模型越来越擅长预测下一个 token。

---

### 14.2 用途二：比较两个语言模型

假设在完全相同的测试集、Tokenizer 和评价方式下：

```text
Model A
PPL = 18

Model B
PPL = 10
```

那么通常说明：

> Model B 对这个测试集的语言建模能力更强。

例如：

```text
浙江大学位于____
```

Model A：

```text
杭州  0.30
北京  0.20
上海  0.20
南京  0.10
……
```

Model B：

```text
杭州  0.85
北京  0.03
上海  0.02
……
```

真实答案是“杭州”。

Model B 给真实答案的概率更高，因此其 PPL 往往更低。

---

### 14.3 用途三：发现过拟合

例如：

| Epoch | Train PPL | Validation PPL |
|---:|---:|---:|
| 1 | 50 | 55 |
| 2 | 30 | 34 |
| 3 | 20 | 25 |
| 4 | 14 | 21 |
| 5 | 10 | 23 |
| 6 | 7 | 30 |

Epoch 4 之后：

```text
Train PPL:
14 → 10 → 7
```

仍然不断下降。

但是：

```text
Validation PPL:
21 → 23 → 30
```

反而越来越高。

说明模型越来越适应训练数据，但对没有见过的数据泛化能力正在下降。

这是典型的：

\[
\boxed{\text{Overfitting}}
\]

---

### 14.4 用途四：判断模型对某一领域是否熟悉

假设同一个模型：

```text
普通新闻：PPL = 12
计算机论文：PPL = 18
医学论文：PPL = 45
法律合同：PPL = 55
```

可以粗略理解为：

```text
普通文本      很熟
计算机文本    比较熟
医学文本      不太熟
法律文本      更陌生
```

因此 PPL 也能反映：

> 某一类文本对于模型而言有多“自然”或多“陌生”。

---

## 15. 正常文本和异常文本的 PPL 差异

例如正常文本：

```text
我今天去了学校上课。
```

模型可能认为：

```text
我今天 → 去
P(去)=0.35
```

然后：

```text
我今天去了 → 学校
P(学校)=0.45
```

然后：

```text
我今天去了学校 → 上课
P(上课)=0.60
```

这些 token 都很符合语言规律，所以 PPL 比较低。

但如果文本是：

```text
我今天香蕉量子桌子跑步Windows。
```

模型可能得到：

```text
我今天香蕉 → 量子
P(量子)=0.001
```

然后：

```text
香蕉量子 → 桌子
P(桌子)=0.0005
```

模型不断认为：

> “为什么这里会出现这个 token？”

因此：

\[
-\log P
\]

会很大，最终 PPL 也会很高。

---

## 16. PPL 不是 Accuracy

这是一个非常重要的区别。

假设真实答案是：

```text
苹果
```

Model A：

```text
苹果 0.40
香蕉 0.35
梨   0.25
```

Model B：

```text
苹果 0.90
香蕉 0.05
梨   0.05
```

两个模型的 top-1 都是：

```text
苹果
```

如果只看 Accuracy：

```text
Model A：正确
Model B：正确
```

完全看不出区别。

但是从概率分布来看：

\[
0.9>0.4
\]

Model B 显然更加确定。

PPL 能反映这种差异。

---

## 17. 一个更加极端的例子

真实答案：

```text
苹果
```

Model A：

```text
苹果 0.51
香蕉 0.49
```

Model B：

```text
苹果 0.99
香蕉 0.01
```

两者 top-1 都预测正确。

对于单个 token，可以粗略看作：

\[
PPL_A\approx\frac1{0.51}\approx1.96
\]

而：

\[
PPL_B\approx\frac1{0.99}\approx1.01
\]

Model B 明显更加确定。

所以 PPL 不仅关心：

> “有没有猜对？”

还关心：

> **“对真实答案到底有多确定？”**

---

## 18. PPL 与 Next Token Prediction 的关系

GPT 的预训练目标就是：

\[
\boxed{\text{Next Token Prediction}}
\]

例如：

```text
我 喜欢 吃 苹果
```

从概念上可以拆成：

```text
输入：
我

目标：
喜欢
```

然后：

```text
输入：
我 喜欢

目标：
吃
```

然后：

```text
输入：
我 喜欢 吃

目标：
苹果
```

实际训练中通常会并行计算整个序列：

```text
Input:
[BOS] 我 喜欢 吃

Target:
我 喜欢 吃 苹果
```

每一个位置对应一个 token-level loss：

\[
L_t
=
-\log P(x_t|x_{<t})
\]

然后取平均：

\[
L
=
-\frac1N
\sum_t
\log P(x_t|x_{<t})
\]

最后：

\[
PPL=e^L
\]

因此整个链条是：

```text
Next Token Prediction
        ↓
      Logits
        ↓
      Softmax
        ↓
Vocabulary Probability Distribution
        ↓
正确 token 的 probability
        ↓
Cross Entropy Loss
        ↓
     exp(loss)
        ↓
        PPL
```

---

## 19. 从 Logits 到 PPL 的完整例子

假设词表只有：

```text
苹果
香蕉
汽车
电脑
```

模型最后输出 logits：

\[
z=
[3.0,\;1.0,\;0.5,\;-1.0]
\]

经过 Softmax：

\[
P_i
=
\frac{e^{z_i}}
{\sum_j e^{z_j}}
\]

假设得到大致概率：

```text
苹果  0.82
香蕉  0.11
汽车  0.06
电脑  0.01
```

真实答案是：

```text
苹果
```

那么该 token 的 Cross Entropy Loss 是：

\[
L=-\ln(0.82)
\]

约为：

\[
L\approx0.198
\]

对应的单 token PPL：

\[
PPL=e^{0.198}
\]

约为：

\[
1.22
\]

说明模型对这个 token 非常确定。

---

## 20. 如果模型非常自信地猜错了呢？

真实答案仍然是：

```text
苹果
```

但模型输出：

```text
苹果  0.02
香蕉  0.80
汽车  0.10
电脑  0.08
```

那么：

\[
L=-\ln(0.02)
\]

得到：

\[
L\approx3.91
\]

对应：

\[
PPL=e^{3.91}
\]

约为：

\[
\boxed{50}
\]

模型对真实答案给了极低概率，因此受到很大的惩罚。

---

## 21. 为什么 Cross Entropy 对错误预测很敏感？

因为：

\[
L=-\ln p
\]

例如：

| 正确 token 概率 | Loss |
|---:|---:|
| 0.9 | 0.105 |
| 0.5 | 0.693 |
| 0.1 | 2.303 |
| 0.01 | 4.605 |
| 0.001 | 6.908 |
| 0.0001 | 9.210 |

可以看到：

> 当模型给真实答案极低的概率时，Loss 会迅速增大。

特别是模型非常自信地预测了错误答案时，对真实 token 的概率可能接近 0，因此会受到非常大的惩罚。

---

## 22. PPL 能不能直接判断哪个大模型更好？

不能简单这么做。

例如：

```text
Model A:
PPL = 7

Model B:
PPL = 9
```

不能仅凭这两个数字就宣布：

```text
Model A 一定比 Model B 好
```

因为 PPL 会受到很多因素影响：

- Tokenizer
- Vocabulary Size
- 测试数据集
- 文本预处理方式
- 是否包含 BOS / EOS
- Sequence Length
- Sliding Window 策略
- Padding 和 ignore_index 的处理
- 计算平均 Loss 的方式

其中 Tokenizer 的影响尤其重要。

---

## 23. 为什么 Tokenizer 会影响 PPL？

例如：

```text
中华人民共和国
```

Tokenizer A：

```text
["中华人民共和国"]
```

共 1 个 token。

Tokenizer B：

```text
["中华", "人民", "共和国"]
```

共 3 个 token。

Tokenizer C：

```text
["中","华","人","民","共","和","国"]
```

共 7 个 token。

而：

\[
PPL
=
\exp
\left(
-\frac1N
\sum\log p
\right)
\]

这里的 \(N\) 已经完全不同。

因此不同 Tokenizer 下的 token-level PPL 往往不能直接横向比较。

比较 PPL 时最好满足：

\[
\boxed{
\text{相同 Tokenizer}
+
\text{相同测试集}
+
\text{相同评价方式}
}
\]

---

## 24. PPL 低是否意味着聊天能力一定更强？

不是。

PPL 主要衡量：

\[
\boxed{\text{语言模型预测真实 token 的能力}}
\]

它并不能直接衡量：

- 指令遵循能力
- 数学推理能力
- 逻辑推理能力
- 代码能力
- Agent 能力
- 长上下文推理能力
- 安全性
- 人类偏好
- 多轮对话体验

例如，一个 Base Model 可能在通用语料上 PPL 很低，因为它非常擅长续写文本。

但是你告诉它：

```text
请把下面内容总结成三点。
```

它未必能够稳定遵循指令。

经过 SFT 后的 Instruct Model，即使某些语料上的 PPL 不一定明显更低，但其指令遵循能力可能大幅提升。

因此现代大模型评价不能只看 PPL。

---

## 25. 困惑度数值例子

假设有三个模型。

### 25.1 Model A

真实 token 平均概率：

\[
0.5
\]

因此：

\[
PPL=2
\]

### 25.2 Model B

真实 token 平均概率：

\[
0.25
\]

因此：

\[
PPL=4
\]

### 25.3 Model C

真实 token 平均概率：

\[
0.1
\]

因此：

\[
PPL=10
\]

直观理解：

```text
Model A
正确答案 ██████████ 50%
PPL ≈ 2

Model B
正确答案 █████      25%
PPL ≈ 4

Model C
正确答案 ██         10%
PPL ≈ 10
```

所以最核心的关系是：

\[
\boxed{
\text{真实 token 概率越高}
\Rightarrow
\text{Cross Entropy 越低}
\Rightarrow
\text{PPL 越低}
}
\]

## 26. 把 GPT 训练全过程串起来

完整过程可以表示为：

```text
输入文本
   ↓
Tokenizer
   ↓
Token IDs
   ↓
Transformer
   ↓
Logits
   ↓
Softmax
   ↓
Vocabulary Probability Distribution
   ↓
取出真实 Next Token 的概率 p
   ↓
Loss = -log(p)
   ↓
所有有效 token 求平均
   ↓
Cross Entropy Loss
   ↓
PPL = exp(Loss)
```

因此以下三个概念实际上是一条完整链路：

\[
\boxed{
Probability
\rightarrow
Cross\ Entropy
\rightarrow
Perplexity
}
\]

## 27. MiniMind 里已经有 CrossEntropy Loss，还需要 PPL 吗？

### 27.1 从训练代码角度：不需要

如果 MiniMind 已经计算：

```python
loss = F.cross_entropy(logits, labels)
```

并且：

```python
loss.backward()
optimizer.step()
```

那么模型就已经可以正常训练。

因为：

\[
\boxed{PPL=e^{Loss}}
\]

PPL 并没有额外提供独立的训练信息。

因此：

> **CrossEntropy Loss 是训练必需的，而 PPL 不是。**

---

### 27.2 CrossEntropy Loss 真正负责训练

典型代码：

```python
logits = model(input_ids)

loss = F.cross_entropy(
    logits.view(-1, logits.size(-1)),
    labels.view(-1)
)

optimizer.zero_grad()
loss.backward()
optimizer.step()
```

流程为：

```text
CrossEntropy Loss
        ↓
   loss.backward()
        ↓
      梯度
        ↓
 optimizer.step()
        ↓
   更新模型参数
```

PPL 不参与参数更新。

---

## 28. 为什么不直接优化 PPL？

因为：

\[
PPL=e^L
\]

虽然最小化 PPL 与最小化 Loss 在最优点上方向一致，但梯度尺度不同。

根据链式法则：

\[
\frac{\partial PPL}{\partial\theta}
=
e^L
\frac{\partial L}{\partial\theta}
\]

因此：

\[
\boxed{
\nabla PPL
=
PPL\cdot\nabla L
}
\]

假设：

\[
L=5
\]

那么：

\[
PPL=e^5\approx148
\]

如果直接对 PPL 反向传播，梯度相当于又被乘了约 148 倍。

因此训练中应该：

```python
loss.backward()
```

而不是：

```python
ppl.backward()
```

PPL 更适合用于评价和展示。

假设：

```python
loss = F.cross_entropy(logits, labels)
```

那么：

```python

```

即可。

例如：

```python
print(
    f"loss: {loss.item():.4f}, "
```

如果：

```text

```

那么：

\[
PPL=e^{2.3026}\approx10
\]

日志就是：

```text
loss: 2.3026, ppl: 10.00
```

## 30. Loss 和 PPL 在 MiniMind 中分别扮演什么角色？

最简单的区分是：

```text
Loss：
给模型看的
用于反向传播和参数优化

PPL：
给人看的
用于评价和展示训练效果
```

更正式一点：

\[
\boxed{

=

而：

\[
\boxed{
\text{Perplexity}
=

## 31. Validation 阶段计算 PPL 更有意义

训练过程中只记录 Loss 完全可以。

例如：

```text
step 1000 | loss 3.14
step 2000 | loss 2.85
step 3000 | loss 2.52
```

但是在验证阶段，PPL 会比较直观：

```text
train loss = 2.2
```

## 32. 计算整个验证集 PPL 时的正确方法

假设验证集中有多个 batch。

不要简单计算：

```python
ppl1 = math.exp(loss1)
ppl2 = math.exp(loss2)
ppl3 = math.exp(loss3)

avg_ppl = (ppl1 + ppl2 + ppl3) / 3
```

通常更规范的方法是：

1. 累积所有有效 token 的总 loss；
2. 除以所有有效 token 数；
3. 得到平均 token loss；
4. 最后再取指数。

即：

\[
L_{\text{avg}}
=
\frac{
\text{所有有效 token 的总 NLL}
}{
\text{有效 token 总数}
}
\]

然后：

\[
\boxed{
PPL=e^{L_{\text{avg}}}
}
\]

---

## 33. 为什么不能简单平均 Batch Loss？

假设：

```text
Batch A：
1000 个有效 token
平均 Loss = 2

Batch B：
100 个有效 token
平均 Loss = 4
```

如果直接：

\[
\frac{2+4}{2}=3
\]

这意味着两个 batch 权重完全相同。

但实际上 Batch A 有 1000 个 token，Batch B 只有 100 个 token。

正确平均应该是：

\[
\frac{
2\times1000+
4\times100
}{
1000+100
}
\]

即：

\[
\frac{2400}{1100}
\approx2.18
\]

因此：

\[
PPL=e^{2.18}\approx8.85
\]

如果错误使用平均 loss：

\[
L=3
\]

会得到：

\[
PPL=e^3\approx20.09
\]

两者差别非常大。

## 34. 一个比较规范的验证集 PPL 代码

```python
import math
import torch
import torch.nn.functional as F

total_loss = 0.0
total_tokens = 0

model.eval()

with torch.no_grad():
    for batch in val_loader:

        input_ids = batch["input_ids"]
        labels = batch["labels"]

        logits = model(input_ids)

        loss = F.cross_entropy(
            logits.view(-1, logits.size(-1)),
            labels.view(-1),
            ignore_index=-100,
            reduction="sum"
        )

        valid_tokens = (labels != -100).sum().item()

        total_loss += loss.item()
        total_tokens += valid_tokens

avg_loss = total_loss / total_tokens

ppl = math.exp(avg_loss)

print(f"Val Loss: {avg_loss:.4f}")
print(f"Val PPL : {ppl:.2f}")
```

这里的核心是：

```python
reduction="sum"
```

先把所有有效 token 的 loss 累加，然后：

```python
avg_loss = total_loss / total_tokens
```

最后：

```python
ppl = math.exp(avg_loss)
```

## 35. 为什么 Padding Token 通常不能算进 PPL？

假设：

```text
真实序列：
我 喜欢 吃 苹果

Padding 后：
我 喜欢 吃 苹果 <PAD> <PAD> <PAD>
```

如果把 `<PAD>` 也当成正常目标 token，那么最终 Loss 和 PPL 会受到 Padding 数量影响。

因此通常设置：

```python
ignore_index=-100
```

然后把 padding 对应的 label 设为：

```text
-100
```

这样：

```python
F.cross_entropy(...)
```

会忽略这些位置。

因此真正计算的是：

\[
\boxed{\text{有效文本 token 的平均 Loss}}
\]

而不是：

\[
\text{有效 token + Padding token}
\]

## 36. 训练代码中 PPL 应该放在哪里？

比较推荐：

```python
loss = criterion(logits, labels)

optimizer.zero_grad()
loss.backward()
optimizer.step()

ppl = math.exp(loss.item())
```

即：

```text
                CrossEntropy Loss
                       │
          ┌────────────┴────────────┐
          ↓                         ↓
   loss.backward()              exp(loss)
          ↓                         ↓
      参数更新                     PPL
          ↓                         ↓
      训练模型                 展示 / 评价
```

因此：

\[
\boxed{
\text{Loss 用于训练}
}
\]

而：

\[
\boxed{
\text{PPL 用于理解和评价}
}
\]

## 37. 最值得记住的三个公式

### 37.1 单个 token 的 Loss

\[
\boxed{
L_t
=
-\log P(x_t|x_{<t})
}
\]

---

### 37.2 整个序列的平均 Cross Entropy

\[
\boxed{
L
=
-\frac1N
\sum_{t=1}^{N}
\log P(x_t|x_{<t})
}
\]

---

### 37.3 困惑度

\[
\boxed{
PPL=e^L
}
\]

合并起来：

\[
\boxed{
PPL=
\exp
\left(
-\frac1N
\sum_{t=1}^{N}
\log P(x_t|x_{<t})
\right)
}
\]

## 38. 一句话理解 PPL

如果只记一句话，可以记：

> **困惑度 PPL 衡量语言模型预测真实文本时有多“不确定”；PPL 越低，说明模型平均给真实下一个 token 的概率越高。**

也可以用更加直观的说法：

> **PPL 可以粗略理解为模型每一步预测时面对的“有效候选答案数量”。**

例如：

\[
PPL=5
\]

可以粗略理解为：

> 模型平均每一步的预测难度，相当于从 5 个等可能答案中选择一个。

## 39. MiniMind 中最核心的结论

对于 MiniMind 或 GPT 的训练代码：

\[
\boxed{
\text{CrossEntropy Loss 是训练必需的，PPL 不是。}
}
\]

因为：

\[
\boxed{
PPL=e^{CrossEntropyLoss}
}
\]

因此只要有 CrossEntropy Loss，就可以随时得到 PPL。

代码上：

```python
loss = cross_entropy(logits, labels)

# 真正训练模型
loss.backward()

# 可选：用于展示和评价
ppl = math.exp(loss.item())
```

困惑度的核心含义是：

> **Loss 是模型“学东西”用的；PPL 是人类“看模型学得怎么样”用的。**
