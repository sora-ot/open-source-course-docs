# 04 · Next Token：预测目标与损失计算

<!-- LECTURE-CONTENT-START -->

在 Causal Language Model（如 GPT、MiniMind）中，一个很容易产生的疑问是：

> 为什么是 `BOS I love → AI`，而不是简单地 `love → AI`？
>
> 如果模型只有一次 `forward()`，它是怎么把 `BOS I love` 这些前面的 token 全部作为上下文考虑进去的？

核心答案是：

> **Transformer 在一次 forward 中，会同时为序列中的每一个位置计算一个“包含前文上下文信息”的 hidden state。**

因此：

```text
love 这个位置的 hidden state
```

并不只是表示：

```text
love
```

而是表示：

```text
BOS I love
```

这主要是通过 **Causal Self-Attention** 实现的。

---

## 1. 先看一个具体例子

假设输入序列是：

```text
BOS I love AI
```

对应：

```python
input_ids = [
    BOS,
    I,
    love,
    AI
]
```

一次送进 Transformer：

```python
hidden_states = model(input_ids)
```

模型会一次性产生四个位置的 hidden state：

```text
位置 0：BOS  → h0
位置 1：I    → h1
位置 2：love → h2
位置 3：AI   → h3
```

但是这里需要特别注意：

```text
h0 并不只是普通的 BOS embedding

h1 并不只是普通的 I embedding

h2 并不只是普通的 love embedding

h3 并不只是普通的 AI embedding
```

经过 Transformer 的 Self-Attention 后，它们已经融合了上下文信息。

实际上可以理解成：

```text
h0 = f(BOS)

h1 = f(BOS, I)

h2 = f(BOS, I, love)

h3 = f(BOS, I, love, AI)
```

所以：

```text
h2
```

虽然位于 `love` 这个位置，但是它代表的是：

```text
BOS I love
```

这整个上下文。

---

## 2. 为什么 love 能看到 BOS 和 I？

因为 Transformer 使用了：

```text
Self-Attention
```

同时 Decoder-only 模型又加入了：

```text
Causal Mask
```

也就是因果掩码。

假设输入：

```text
BOS    I    love    AI
```

Causal Mask 规定每个位置：

- 可以看到自己；
- 可以看到前面的 token；
- 不能看到未来 token。

因此：

```text
            可以看到的 token

            BOS    I    love    AI

BOS          ✓     ×      ×      ×

I            ✓     ✓      ×      ×

love         ✓     ✓      ✓      ×

AI           ✓     ✓      ✓      ✓
```

因此：

```text
BOS 位置：
只能看到 BOS

I 位置：
可以看到 BOS + I

love 位置：
可以看到 BOS + I + love

AI 位置：
可以看到 BOS + I + love + AI
```

所以当模型处理 `love` 位置时，它实际上已经可以读取：

```text
BOS
I
love
```

三部分信息。

---

## 3. Self-Attention 是怎么做到的？

假设输入有四个 token：

```text
BOS    I    love    AI
```

首先，每个 token 会生成：

```text
Q：Query
K：Key
V：Value
```

可以表示为：

```text
Q_BOS
Q_I
Q_love
Q_AI
```

```text
K_BOS
K_I
K_love
K_AI
```

```text
V_BOS
V_I
V_love
V_AI
```

然后计算 Attention：

\[
QK^T
\]

得到一个注意力矩阵。

例如：

```text
                 Key

             BOS     I     love     AI

Query

BOS           ?      ?      ?       ?

I             ?      ?      ?       ?

love          ?      ?      ?       ?

AI            ?      ?      ?       ?
```

然后加上 Causal Mask：

```text
                 BOS       I       love       AI

BOS               ✓       -∞        -∞       -∞

I                 ✓        ✓        -∞       -∞

love              ✓        ✓         ✓       -∞

AI                ✓        ✓         ✓        ✓
```

这里的：

```text
-∞
```

表示：

> 这个位置不能看。

经过 Softmax 后：

```text
softmax(-∞) ≈ 0
```

所以未来 token 的注意力权重会变成 0。

---

## 4. love 位置到底算了什么？

对于 `love` 这个位置，它可以看到：

```text
BOS
I
love
```

因此它最终得到的表示可以简化理解为：

\[
h_{\text{love}}
=
a_1 V_{\text{BOS}}
+
a_2 V_{\text{I}}
+
a_3 V_{\text{love}}
\]

其中：

```text
a1
a2
a3
```

是 attention 权重。

例如可能是：

```text
BOS  → 0.1
I    → 0.4
love → 0.5
```

那么：

\[
h_{\text{love}}
=
0.1V_{\text{BOS}}
+
0.4V_{\text{I}}
+
0.5V_{\text{love}}
\]

所以：

```text
h_love
```

已经不是单纯的 `"love"`。

它实际上已经融合了：

```text
BOS
I
love
```

的上下文信息。

---

## 5. 多层 Transformer 会进一步融合上下文

实际模型中一般不是只有一层 Attention。

而是：

```text
输入 Embedding

    ↓

Transformer Block 1

    ↓

Transformer Block 2

    ↓

Transformer Block 3

    ↓

...

    ↓

Transformer Block N
```

假设关注 `love` 位置。

第一层之后：

```text
love
  ↓
融合 BOS、I、love
```

第二层：

```text
继续基于已经融合后的表示进行计算
```

第三层：

```text
进一步抽取更复杂的上下文关系
```

直到最后得到：

```python
hidden_states[:, 2, :]
```

这个向量。

这个向量真正表示的不是：

```text
love
```

而是：

```text
在 "BOS I love" 这个上下文中，
当前 love 位置的语义表示。
```

---

## 6. 为什么只需要一次 forward？

这正是 Transformer 和 RNN 非常不同的地方。

RNN 更接近：

```text
先处理 BOS

    ↓

再处理 I

    ↓

再处理 love

    ↓

再处理 AI
```

是比较明显的串行过程。

而 Transformer 可以直接：

```text
BOS I love AI
```

整个序列一起送进去。

一次矩阵计算就可以同时得到：

```text
h0 = f(BOS)

h1 = f(BOS, I)

h2 = f(BOS, I, love)

h3 = f(BOS, I, love, AI)
```

也就是说，一次 forward 相当于同时计算了多个前缀：

```text
BOS

BOS I

BOS I love

BOS I love AI
```

并不需要真的运行四次模型。

---

## 7. 一次 forward 后发生了什么？

假设输入：

```text
BOS I love AI EOS
```

经过：

```python
hidden_states = self.model(input_ids)
```

得到：

```text
hidden_states[0]
=
BOS 的上下文表示


hidden_states[1]
=
BOS I 的上下文表示


hidden_states[2]
=
BOS I love 的上下文表示


hidden_states[3]
=
BOS I love AI 的上下文表示


hidden_states[4]
=
BOS I love AI EOS 的上下文表示
```

接下来：

```python
logits = self.lm_head(hidden_states)
```

`lm_head` 会把：

```text
hidden_size
```

映射到：

```text
vocab_size
```

也就是：

```text
上下文表示
      ↓
整个词表中每个 token 的预测分数
```

因此：

```text
logits[0]
```

表示：

```text
看到 BOS 后，
下一个 token 是什么？
```

---

```text
logits[1]
```

表示：

```text
看到 BOS I 后，
下一个 token 是什么？
```

---

```text
logits[2]
```

表示：

```text
看到 BOS I love 后，
下一个 token 是什么？
```

---

```text
logits[3]
```

表示：

```text
看到 BOS I love AI 后，
下一个 token 是什么？
```

---

## 8. 为什么 logits[2] 能预测 AI？

现在假设：

```text
input_ids:

BOS    I    love    AI    EOS
```

模型产生：

```text
logits[0]
logits[1]
logits[2]
logits[3]
logits[4]
```

其中：

```text
logits[2]
```

来自：

```text
hidden_states[2]
```

而：

```text
hidden_states[2]
```

已经通过 Causal Self-Attention 融合了：

```text
BOS I love
```

因此：

```text
logits[2]
```

实际表示：

\[
P(\text{next token}\mid BOS,I,love)
\]

所以它预测：

```text
AI
```

是完全合理的。

不是：

\[
P(AI\mid love)
\]

而是：

\[
P(AI\mid BOS,I,love)
\]

---

## 9. labels 为什么要错开一位？

Dataset 中可能返回：

```text
input_ids:

[BOS, I, love, AI, EOS]
```

以及：

```text
labels:

[BOS, I, love, AI, EOS]
```

看起来完全没有错位。

但是在模型的 `forward()` 中：

```python
x = logits[..., :-1, :]
y = labels[..., 1:]
```

会进行错位。

原来的：

```text
logits：

位置0
位置1
位置2
位置3
位置4
```

去掉最后一个：

```text
x：

logits[0]
logits[1]
logits[2]
logits[3]
```

而 labels：

```text
BOS
I
love
AI
EOS
```

去掉第一个：

```text
y：

I
love
AI
EOS
```

于是形成：

```text
logits[0]  ↔ I
logits[1]  ↔ love
logits[2]  ↔ AI
logits[3]  ↔ EOS
```

而 logits 各位置所包含的上下文分别是：

```text
logits[0]
来自 f(BOS)

        ↓

预测 I
```

```text
logits[1]
来自 f(BOS, I)

        ↓

预测 love
```

```text
logits[2]
来自 f(BOS, I, love)

        ↓

预测 AI
```

```text
logits[3]
来自 f(BOS, I, love, AI)

        ↓

预测 EOS
```

因此真正训练的是：

```text
BOS
    → I

BOS I
    → love

BOS I love
    → AI

BOS I love AI
    → EOS
```

## 12. 最关键的理解

很多初学者容易把：

```text
logits[2]
```

理解成：

```text
只根据第 2 个 token，也就是 love，预测 AI
```

这是不对的。

正确理解应该是：

```text
logits[2]
```

虽然位于：

```text
love
```

这个位置，

但是它对应的 hidden state 已经通过 Self-Attention 看到了：

```text
BOS
I
love
```

所以实际上：

\[
\text{logits}_2
=
f(BOS,I,love)
\]

然后模型学习：

\[
P(AI\mid BOS,I,love)
\]

而不是：

\[
P(AI\mid love)
\]

## 13. 为什么训练时一次 forward，生成时却要多次 forward？

这里还可以进一步区分：

### 13.1 训练阶段

训练时整句话已经知道：

```text
BOS I love AI EOS
```

所以可以一次全部输入：

```python
model([
    BOS,
    I,
    love,
    AI,
    EOS
])
```

借助 Causal Mask：

```text
每个位置都只能看前面，
但是所有位置可以并行计算。
```

因此一次 forward 就可以同时训练：

```text
BOS            → I
BOS I          → love
BOS I love     → AI
BOS I love AI  → EOS
```

---

### 13.2 推理生成阶段

生成的时候未来 token 不知道。

例如一开始只有：

```text
BOS I
```

模型先预测：

```text
love
```

然后变成：

```text
BOS I love
```

再预测：

```text
AI
```

再变成：

```text
BOS I love AI
```

再预测：

```text
EOS
```

因此生成是：

```text
一步一步自回归生成
```

而训练可以：

```text
一次 forward 并行计算所有位置。
```

---

## 14. 最后一句话总结

一定要记住：

> **Transformer 中某个位置的 hidden state，不只是这个 token 本身的表示，而是通过 Causal Self-Attention 融合了当前位置以及之前所有 token 的上下文表示。**

因此：

```text
love 位置
```

对应的实际上是：

```text
BOS I love
```

所以：

```text
love 位置的 logits
```

真正表达的是：

\[
P(\text{next token}\mid BOS,I,love)
\]

于是训练：

```text
BOS I love → AI
```

而不是简单的：

```text
love → AI
```

整个过程之所以只需要一次 forward，是因为 Transformer 可以利用矩阵运算，在一次计算中**并行得到所有位置的上下文表示**：

```text
BOS
BOS I
BOS I love
BOS I love AI
...
```

然后同时完成所有位置的 Next Token Prediction。

## 15. 为什么一个序列样本可以完成多条“前缀 → 下一 Token”的训练？

另一个很重要的问题是：

> 按照传统做法，如果一句话是 `I love AI`，似乎应该构造多条训练样本：
>
> - `BOS → I`
> - `BOS I → love`
> - `BOS I love → AI`
> - `BOS I love AI → EOS`
>
> 那为什么在 Transformer 里，只需要一个：
>
> ```text
> [BOS, I, love, AI, EOS]
> ```
>
> 就可以完成上面几条训练任务？

核心答案是：

> **一个 Dataset 样本虽然只有一个序列，但 Transformer 会在这个序列的每一个位置都产生一个预测结果，因此一个长度为 T 的序列，可以同时提供大约 T-1 个 next-token 训练目标。**

---

## 16. 传统做法：显式构造多个样本

假设一句话是：

```text
I love AI
```

加入特殊 token 后：

```text
BOS I love AI EOS
```

如果按照“一个前缀对应一条训练样本”的传统思路，可以构造：

```text
样本 1：

输入：
BOS

标签：
I
```

```text
样本 2：

输入：
BOS I

标签：
love
```

```text
样本 3：

输入：
BOS I love

标签：
AI
```

```text
样本 4：

输入：
BOS I love AI

标签：
EOS
```

也就是：

```text
BOS              → I

BOS I            → love

BOS I love       → AI

BOS I love AI    → EOS
```

如果真的这样训练，就可能需要分别执行：

```python
model([BOS])

model([BOS, I])

model([BOS, I, love])

model([BOS, I, love, AI])
```

也就是多次 forward。

---

## 17. 这样做会产生大量重复计算

观察这些样本：

```text
[BOS]

[BOS, I]

[BOS, I, love]

[BOS, I, love, AI]
```

会发现前面的内容被重复计算了很多次。

例如：

```text
BOS
```

出现在所有样本里。

```text
BOS I
```

也会在后面的多个样本中重复出现。

如果每个前缀都单独做一次 forward，就会产生很多重复计算。

---

## 18. Transformer 的做法：整个序列一次送进去

Transformer 训练时直接输入：

```text
[BOS, I, love, AI, EOS]
```

也就是：

```python
input_ids = [
    BOS,
    I,
    love,
    AI,
    EOS
]
```

然后只做一次：

```python
hidden_states = model(input_ids)
```

一次 forward 就会同时得到：

```text
h0
h1
h2
h3
h4
```

由于 Causal Mask 的存在：

```text
h0 = f(BOS)

h1 = f(BOS, I)

h2 = f(BOS, I, love)

h3 = f(BOS, I, love, AI)

h4 = f(BOS, I, love, AI, EOS)
```

所以一次 forward 实际上已经同时计算了这些前缀：

```text
BOS

BOS I

BOS I love

BOS I love AI

BOS I love AI EOS
```

## 19. 一个序列样本里其实包含多个 token-level 训练目标

Dataset 层面看：

```text
[BOS, I, love, AI, EOS]
```

只是：

```text
1 条 sequence-level sample
```

但是在语言模型的 Loss 层面，它包含多个监督目标：

```text
BOS             → I

BOS I           → love

BOS I love      → AI

BOS I love AI   → EOS
```

所以需要区分两个概念：

### 19.1 Sequence-level sample

Dataset 里的一整条序列：

```text
[BOS, I, love, AI, EOS]
```

这是 1 条样本。

### 19.2 Token-level prediction target

序列中每个位置产生的预测任务：

```text
BOS             → I
BOS I           → love
BOS I love      → AI
BOS I love AI   → EOS
```

这里实际上有 4 个训练目标。

因此：

> **1 条序列样本，不等于只有 1 个预测任务。**

---

## 20. 为什么 Causal Mask 能让一个序列等价于多个前缀样本？

假设输入：

```text
BOS    I    love    AI    EOS
```

Causal Mask 是一个下三角结构：

```text
             BOS     I     love     AI     EOS

BOS           ✓

I             ✓      ✓

love          ✓      ✓       ✓

AI            ✓      ✓       ✓      ✓

EOS           ✓      ✓       ✓      ✓       ✓
```

因此，在同一次 forward 里：

```text
位置 0 只能看到：

BOS
```

```text
位置 1 可以看到：

BOS I
```

```text
位置 2 可以看到：

BOS I love
```

```text
位置 3 可以看到：

BOS I love AI
```

```text
位置 4 可以看到：

BOS I love AI EOS
```

所以这一个序列，天然就在一次矩阵计算中“模拟”出了多个不同长度的前缀。

## 21. lm_head 会给每个位置都产生一次词表预测

经过 Transformer 得到：

```text
h0
h1
h2
h3
h4
```

再经过：

```python
logits = self.lm_head(hidden_states)
```

得到：

```text
logits0
logits1
logits2
logits3
logits4
```

分别可以理解成：

```text
logits0：

根据 BOS
预测下一个 token
```

```text
logits1：

根据 BOS I
预测下一个 token
```

```text
logits2：

根据 BOS I love
预测下一个 token
```

```text
logits3：

根据 BOS I love AI
预测下一个 token
```

因此：

```text
一次 forward
```

不是产生：

```text
1 个 prediction
```

而是产生：

```text
每一个位置各 1 个 prediction
```

---

## 22. labels 错位后，多个预测任务会自动对齐

原始：

```text
input_ids:

[BOS, I, love, AI, EOS]
```

Dataset 中：

```text
labels:

[BOS, I, love, AI, EOS]
```

模型 forward 后：

```text
logits:

[logits0, logits1, logits2, logits3, logits4]
```

MiniMind 中：

```python
x = logits[..., :-1, :]
y = labels[..., 1:]
```

于是：

```text
x：

logits0
logits1
logits2
logits3
```

而：

```text
y：

I
love
AI
EOS
```

形成：

```text
logits0  → I

logits1  → love

logits2  → AI

logits3  → EOS
```

结合每个 logits 的上下文：

```text
f(BOS)             → I

f(BOS, I)          → love

f(BOS, I, love)    → AI

f(BOS, I, love,AI) → EOS
```

所以一条序列一次 forward，就同时完成了四个 next-token prediction。

---

## 23. CrossEntropyLoss 其实会同时计算多个位置的 Loss

假设四个位置的正确答案分别是：

```text
I
love
AI
EOS
```

那么实际上会有多个 token loss：

\[
L_0=-\log P(I\mid BOS)
\]

\[
L_1=-\log P(love\mid BOS,I)
\]

\[
L_2=-\log P(AI\mid BOS,I,love)
\]

\[
L_3=-\log P(EOS\mid BOS,I,love,AI)
\]

最终总 Loss 通常对这些有效位置进行平均或聚合：

\[
L
=
\frac{L_0+L_1+L_2+L_3}{4}
\]

例如：

```text
BOS → I
loss = 0.3

BOS I → love
loss = 0.8

BOS I love → AI
loss = 0.2

BOS I love AI → EOS
loss = 0.5
```

最终：

\[
Loss
=
\frac{0.3+0.8+0.2+0.5}{4}
=
0.45
\]

然后：

```python
loss.backward()
```

这几个位置产生的梯度会一起反向传播。

所以：

> **一次 forward 虽然只返回一个总 loss，但这个 loss 内部实际上综合了序列中多个 token 位置的训练误差。**

---

## 24. 从代码角度看，为什么 CrossEntropyLoss 可以一次处理所有位置？

假设：

```python
x.shape = [B, T-1, V]
```

其中：

```text
B = batch size
T = sequence length
V = vocab size
```

而：

```python
y.shape = [B, T-1]
```

MiniMind 中：

```python
loss = F.cross_entropy(
    x.view(-1, x.size(-1)),
    y.view(-1),
    ignore_index=-100
)
```

会把：

```text
[B, T-1, V]
```

展开成：

```text
[B × (T-1), V]
```

同时把：

```text
[B, T-1]
```

展开成：

```text
[B × (T-1)]
```

也就是说：

> batch 中所有样本、所有 token 位置，都被一次性送进 CrossEntropyLoss。

例如：

```text
batch_size = 2
sequence_length = 5
```

每条序列有：

```text
4 个 next-token target
```

两条序列总共：

```text
2 × 4 = 8
```

个 token-level prediction target。

CrossEntropyLoss 会一次性计算这 8 个位置的损失。

## 25. 一条长度为 T 的序列能提供多少训练目标？

假设序列长度为：

\[
T
\]

例如：

```text
[BOS, I, love, AI, EOS]
```

长度：

```text
T = 5
```

通常可以产生：

\[
T-1
\]

个 next-token prediction target。

所以：

```text
T = 5
```

产生：

```text
4 个训练目标
```

即：

```text
位置 0 → 预测位置 1

位置 1 → 预测位置 2

位置 2 → 预测位置 3

位置 3 → 预测位置 4
```

## 26. 对于长序列，这个效果更加明显

假设一个预训练样本长度是：

```text
2048 tokens
```

它并不是：

```text
1 条样本只训练 1 次预测
```

而是大约可以提供：

```text
2047 个 next-token prediction targets
```

即：

```text
token 0
→ token 1

token 0~1
→ token 2

token 0~2
→ token 3

...

token 0~2046
→ token 2047
```

因此一个长序列本身就包含大量监督信号。

## 27. 为什么说 LLM 训练的数据量通常用 Token 数量衡量？

假设有：

```text
100 万条文本
```

如果每条文本平均：

```text
1000 tokens
```

那么虽然 Dataset 中只有：

```text
100 万条 sequence sample
```

但是实际可以产生接近：

```text
10 亿个 token-level prediction targets
```

所以大语言模型预训练通常更加关注：

```text
训练了多少 token
```

而不仅仅是：

```text
训练了多少条文本
```

因为真正产生监督信号的是序列中的 token 位置。

## 28. 传统做法和 Transformer 做法对比

### 28.1 传统显式展开

```text
样本 1：
[BOS]
→ I

样本 2：
[BOS, I]
→ love

样本 3：
[BOS, I, love]
→ AI

样本 4：
[BOS, I, love, AI]
→ EOS
```

模型可能需要多次 forward：

```text
Forward 1

Forward 2

Forward 3

Forward 4
```

而且有大量重复前缀计算。

---

### 28.2 Transformer 做法

只输入：

```text
[BOS, I, love, AI, EOS]
```

执行：

```text
1 次 forward
```

借助：

```text
Causal Self-Attention
+
Causal Mask
+
每个位置都输出 logits
```

同时得到：

```text
BOS             → I

BOS I           → love

BOS I love      → AI

BOS I love AI   → EOS
```

因此：

> **Transformer 并不是减少了训练目标，而是把原本多个前缀样本的训练目标，打包到了同一个序列和同一次 forward 中并行完成。**

## 30. 最后总结

需要同时理解两个层次。

### 30.1 第一层：为什么 `love` 位置能根据 `BOS I love` 预测 AI？

因为：

> `love` 位置经过 Causal Self-Attention 后，它的 hidden state 已经融合了 `BOS`、`I`、`love` 的上下文信息。

所以：

```text
logits[2]
```

表示的不是：

\[
P(AI\mid love)
\]

而是：

\[
P(AI\mid BOS,I,love)
\]

---

### 30.2 第二层：为什么一条序列可以完成多条训练样本的工作？

因为一次 forward 会同时计算：

```text
f(BOS)

f(BOS, I)

f(BOS, I, love)

f(BOS, I, love, AI)
```

然后每一个位置都产生自己的 logits。

因此：

```text
[BOS, I, love, AI, EOS]
```

这一条 sequence-level sample，可以同时产生：

```text
BOS             → I
BOS I           → love
BOS I love      → AI
BOS I love AI   → EOS
```

四个 token-level prediction target。

所以最核心的一句话是：

> **Transformer 把“多个不同长度前缀分别训练”的传统做法，通过 Causal Mask 和并行 Self-Attention，合并成“一条完整序列一次 forward，同时训练所有位置”。**

这正是 Decoder-only 大语言模型预训练的核心机制之一。
