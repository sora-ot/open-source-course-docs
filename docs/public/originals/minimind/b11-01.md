# 31 · SiLU 与门控 FFN

<!-- LECTURE-CONTENT-START -->

下面仍然使用“浙江大学 软件学院 位于 宁波”作为直观例子。

重点关注：SiLU承担的两个作用（非线性+门控），FFN门控的意义（特征重要性变换），52的例子

---

## 1. 先看 SiLU 和 FFN 在 Transformer 中干什么

可以先把 Transformer Block 粗略理解成两件事：

```text
Attention：
不同 token 之间交换信息

FFN：
每个 token 拿到信息以后，
再独立加工自己的 hidden state
```

例如：

```text
浙江大学
软件学院
位于
宁波
```

经过 Attention 后，“位于”这个 token 的 hidden state 已经可以包含前文的信息。

接下来进入 FFN：

```text
“位于”的 hidden state
        │
        ├───────────────┐
        │               │
        ▼               ▼
     Linear          Linear
        │               │
        ▼               │
      SiLU              │
        │               │
        └────── ⊙ ──────┘
                │
                ▼
              Linear
                │
                ▼
             FFN 输出
```

所以可以先记住：

```text
SiLU：
提供非线性，并参与门控

FFN：
对每一个 token 自己的特征进一步加工
```

---

## 2. 为什么 FFN 里必须有激活函数？

假设完全没有 ReLU、SiLU、GELU 等激活函数。

只有两层 Linear：

$$
y=W_2(W_1x)
$$

展开：

$$
y=W_2W_1x
$$

令：

$$
W=W_2W_1
$$

那么：

$$
y=Wx
$$

也就是说：

> 不管堆多少个 Linear，只要中间没有非线性，数学上都可以合并成一个 Linear。

例如：

```text
Linear
↓
Linear
↓
Linear
↓
Linear
```

最终仍然等价于：

```text
一个 Linear
```

因此需要激活函数把线性变换“打断”。

例如：

$$
y=W_2\,SiLU(W_1x)
$$

这时就不能再简单合并成：

$$
Wx
$$

网络才真正拥有复杂的非线性表达能力。

---


## 3. 非线性的意义到底是什么？

最简单地说：

如果只有 Linear：

```math
y=Wx
```

那么输入和输出之间只能形成：

```text
固定的线性关系
```

例如一维情况下：

```math
y=2x
```

永远：

```text
x = 1  → y = 2
x = 2  → y = 4
x = 3  → y = 6
```

输入扩大几倍，

输出严格扩大几倍。

---

加入非线性以后：

例如：

```math
y=SiLU(x)\cdot x
```

可能：

```text
x = -1 → y ≈ 0.269

x = 0  → y = 0

x = 1  → y ≈ 0.731

x = 2  → y ≈ 3.524
```

此时：

```text
不同输入区域
↓
可以出现完全不同的响应方式
```

所以神经网络才能学习复杂关系。

---

## 4. 再举个例子

假设输入只有一个数：

```math
x
```

如果连续经过两层 Linear：

```math
y=2(3x)
```

那么可以直接合并成：

```math
y=6x
```

所以即使堆很多层 Linear，只要中间没有激活函数，本质上仍然只是一个线性变换：

```math
\boxed{y=ax}
```

例如：

```text
x = 1  → y = 6
x = 2  → y = 12
x = 3  → y = 18
```

**输出永远只是按照固定比例变化。**

---

如果中间加入 ReLU：

```math
y=2\cdot ReLU(3x)
```

那么：

```text
x = 1

3x = 3
↓
ReLU(3) = 3
↓
y = 6
```

但是：

```text
x = -1

3x = -3
↓
ReLU(-3) = 0
↓
y = 0
```

于是：

```text
x = 1   → y = 6
x = -1  → y = 0
```

这时就不能再写成一个简单的：

```math
y=ax
```

因为网络已经可以：

> **根据输入所处的不同区域，产生不同的响应方式。**

---

所以，激活函数提供非线性的意义就是：

> **让网络不再只能做固定比例的线性变换，而能够根据不同输入产生不同的特征变换，从而学习更加复杂的关系。**

放到 Transformer FFN 中也是一样：

```text
Linear
↓
SiLU
↓
后续特征处理
```

其中 SiLU 一方面提供非线性，让 FFN 能学习复杂映射；在 SwiGLU 中，它的输出还进一步参与 Gate，对另一条特征分支进行动态调节。

---


## 5. ReLU 是怎么做的？

ReLU：

$$
\boxed{
ReLU(x)=\max(0,x)
}
$$

也就是：

```text
x < 0  →  直接变成 0

x > 0  →  原样通过
```

例如：

| \(x\) | ReLU(x) |
|---:|---:|
| -2 | 0 |
| -1 | 0 |
| 0 | 0 |
| 1 | 1 |
| 2 | 2 |

图像直觉：

```text
负数区域                  正数区域

全部压成 0                 原样通过

──────────────●────────────── /
              0
```

ReLU 非常简单，而且计算便宜。

它在很多神经网络中都非常成功。

但是它也有一个很明显的特点：

> **负数区域被直接全部砍成 0。**

---

## 6. ReLU 最大的问题之一：负半轴梯度直接为 0

ReLU 的导数：

$$
ReLU'(x)=
\begin{cases}
0,&x<0\\
1,&x>0
\end{cases}
$$

假设某个神经元当前得到：

$$
x=-1
$$

那么：

$$
ReLU(-1)=0
$$

并且：

$$
ReLU'(-1)=0
$$

这意味着反向传播经过这里时：

```text
上游梯度
   │
   ▼
× ReLU'(-1)
   │
   ▼
× 0
   │
   ▼
梯度 = 0
```

这一条路径暂时就没有梯度继续传下去了。

这就是 ReLU 经常被提到的一个现象：

```text
Dead ReLU
```

当然，这不代表用了 ReLU 网络就一定训练不好。

而是说：

> ReLU 对负数采取的是非常“硬”的处理方式：输出直接变 0，梯度也直接变 0。

---

## 7. SiLU 是什么？

SiLU 全称：

```text
Sigmoid Linear Unit
```

公式：

$$
\boxed{
SiLU(x)=x\cdot\sigma(x)
}
$$

其中：

$$
\sigma(x)
=
\frac{1}{1+e^{-x}}
$$

就是 Sigmoid。

可以拆成：

```text
输入 x
 │
 ├───────────────┐
 │               │
 │               ▼
 │           sigmoid(x)
 │               │
 └────── × ──────┘
          │
          ▼
       SiLU(x)
```

---

## 8. SiLU 到底输出什么？

例如：

| \(x\) | \(\sigma(x)\) | SiLU(x) |
|---:|---:|---:|
| -2 | 0.119 | -0.238 |
| -1 | 0.269 | -0.269 |
| 0 | 0.500 | 0 |
| 1 | 0.731 | 0.731 |
| 2 | 0.881 | 1.762 |
| 5 | 0.993 | 4.967 |

可以看到：

### 8.1 当 \(x\) 很大且为正

例如：

$$
x=5
$$

此时：

$$
\sigma(5)\approx1
$$

所以：

$$
SiLU(5)\approx5
$$

大致相当于：

```text
强正特征
↓
基本保留
```

---

### 8.2 当 \(x\) 为负

例如：

$$
x=-1
$$

ReLU 会直接得到：

$$
0
$$

但是 SiLU：

$$
SiLU(-1)\approx-0.269
$$

也就是说：

> SiLU 不会把所有负数信息直接清零，而是会保留一部分。

---

## 9. SiLU 相比 ReLU 到底多了什么？

最重要的不是一句“SiLU 更平滑”，而是下面三件具体的事情。

---

### 9.1 ReLU 是硬切断，SiLU 是连续变化

ReLU：

```text
负数
↓
全部 = 0

正数
↓
直接放行
```

在 0 附近像一个硬开关：

```text
关  →  开
```

SiLU 则是：

```text
强负数
↓
明显抑制

接近 0
↓
部分通过

正数越来越大
↓
越来越接近原值
```

也就是：

```text
不是突然从“关”跳到“开”

而是逐渐变化
```

因此 SiLU 是一个平滑函数。

---

### 9.2 SiLU 在负数区域仍然可以留下梯度

SiLU 的导数：

$$
SiLU'(x)
=
\sigma(x)
+
x\sigma(x)(1-\sigma(x))
$$

例如：

#### 9.2.1 当 \(x=-1\)

$$
SiLU'(-1)\approx0.072
$$

虽然梯度比较小，但：

$$
\boxed{
不是 0
}
$$

而 ReLU：

$$
ReLU'(-1)=0
$$

所以：

```text
ReLU：

x=-1
↓
输出 0
↓
局部梯度 0


SiLU：

x=-1
↓
输出约 -0.269
↓
局部梯度约 0.072
```

这意味着：

> 某个特征当前落在负数区域时，SiLU 仍然可能通过训练把它慢慢调整回来，而不是立刻把这一条路径完全截断。

---


## 10. 为什么 SiLU 在负数区域仍然能继续学习？

前面提到：

> **某个特征当前落在负数区域时，SiLU 仍然可能通过训练把它慢慢调整回来，而不是像 ReLU 那样直接把这一条路径完全截断。**

这个结论可以通过一个非常简单的例子理解。

---

## 11. 假设只有一个神经元

设输入：

```math
x=1
```

只有一个可训练参数：

```math
w
```

线性变换：

```math
z=wx
```

假设当前参数：

```math
w=-1
```

因为：

```math
x=1
```

所以：

```math
z=-1
```

现在假设我们的目标是：

```math
t=1
```

也就是说：

> 当前这个神经元算出了负数，但训练希望它以后输出一个正数。

---

## 12. 如果使用 ReLU

ReLU：

```math
ReLU(z)=\max(0,z)
```

当前：

```math
z=-1
```

所以：

```math
y=ReLU(-1)=0
```

假设使用一个简单的平方误差：

```math
L=
\frac12(y-t)^2
```

代入：

```math
y=0
```

```math
t=1
```

显然模型预测错了。

---

## 13. 但是 ReLU 在负数区域导数为 0

ReLU 的导数：

```math
ReLU'(z)=
\begin{cases}
0,&z<0\\
1,&z>0
\end{cases}
```

当前：

```math
z=-1
```

所以：

```math
ReLU'(-1)=0
```

现在计算参数 \(w\) 的梯度：

```math
\frac{\partial L}{\partial w}
=
\frac{\partial L}{\partial y}
\frac{\partial y}{\partial z}
\frac{\partial z}{\partial w}
```

其中：

```math
\frac{\partial y}{\partial z}
=
ReLU'(-1)
=
0
```

所以：

```math
\boxed{
\frac{\partial L}{\partial w}=0
}
```

这意味着：

```text
w = -1
↓
z = -1
↓
ReLU(-1) = 0
↓
虽然预测是错的
↓
但局部梯度 = 0
↓
w 收不到纠错信号
↓
参数无法通过这条路径继续调整
```

在这个简化例子中，这个神经元就会卡住。

---

## 14. 如果换成 SiLU

SiLU：

```math
SiLU(z)
=
z\sigma(z)
```

其中：

```math
\sigma(z)
=
\frac{1}{1+e^{-z}}
```

当前还是：

```math
z=-1
```

那么：

```math
\sigma(-1)\approx0.269
```

所以：

```math
SiLU(-1)
=
-1\times0.269
```

得到：

```math
y\approx-0.269
```

虽然这个输出同样不正确，

但关键区别是：

> SiLU 在这里的导数不是 0。

---

## 15. SiLU 在 \(z=-1\) 时仍然有梯度

SiLU 的导数：

```math
SiLU'(z)
=
\sigma(z)
+
z\sigma(z)(1-\sigma(z))
```

当：

```math
z=-1
```

时：

```math
SiLU'(-1)\approx0.072
```

所以：

```math
\boxed{
SiLU'(-1)\neq0
}
```

---

## 16. Loss 可以继续传回参数 \(w\)

仍然使用：

```math
L=
\frac12(y-t)^2
```

有：

```math
\frac{\partial L}{\partial y}
=
y-t
```

当前：

```math
y=-0.269
```

```math
t=1
```

所以：

```math
\frac{\partial L}{\partial y}
=
-0.269-1
```

即：

```math
\frac{\partial L}{\partial y}
\approx-1.269
```

又因为：

```math
\frac{\partial y}{\partial z}
=
SiLU'(-1)
\approx0.072
```

以及：

```math
z=wx
```

所以：

```math
\frac{\partial z}{\partial w}
=
x
=
1
```

于是：

```math
\frac{\partial L}{\partial w}
=
(-1.269)\times0.072\times1
```

大约：

```math
\boxed{
\frac{\partial L}{\partial w}
\approx-0.091
}
```

---

## 17. 参数会被慢慢调整

梯度下降公式：

```math
w_{\text{new}}
=
w-
\eta
\frac{\partial L}{\partial w}
```

假设为了方便：

```math
\eta=1
```

那么：

```math
w_{\text{new}}
=
-1-(-0.091)
```

所以：

```math
w_{\text{new}}
\approx
-0.909
```

也就是说：

```text
原来：

w = -1

训练一次之后：

w ≈ -0.91
```

继续训练以后，可能逐渐变成：

```text
-1
↓
-0.91
↓
-0.82
↓
-0.7
↓
-0.5
↓
...
↓
最终可能跨过 0
```

这就是：

> **即使当前激活值是负数，SiLU 仍然可能保留非零梯度，让前面的参数继续被调整。**

---

## 18. ReLU 和 SiLU 对比

### 18.1 ReLU

```text
z = -1
↓
ReLU(z) = 0
↓
ReLU'(z) = 0
↓
梯度断掉
↓
w 很难通过这条路径被继续纠正
```

---

### 18.2 SiLU

```text
z = -1
↓
SiLU(z) ≈ -0.269
↓
SiLU'(z) ≈ 0.072
↓
仍然有梯度
↓
Loss 可以传回去
↓
继续修改 w
↓
w: -1 → -0.91 → ...
```

---



### 18.3 SiLU 自带“输入相关的缩放”

因为：

$$
SiLU(x)=x\sigma(x)
$$

这里的：

$$
\sigma(x)
$$

本身会随着 \(x\) 改变。

例如：

```text
x = -2
sigmoid(x) ≈ 0.119

x = 0
sigmoid(x) = 0.5

x = 2
sigmoid(x) ≈ 0.881
```

所以 SiLU 不是简单地：

```text
正数留下
负数删除
```

而更像：

```text
根据当前输入是多少，
动态决定这个值应该被缩放成多少。
```

**这也是为什么它非常适合放进后面的 Gated FFN。**

---

## 19. 一个具体例子：ReLU 和 SiLU 的差别

假设某个 Linear 输出：

$$
z=[-1,\ 0.2,\ 2]
$$

### 19.1 ReLU

$$
ReLU(z)
=
[0,\ 0.2,\ 2]
$$

第一维：

```text
-1
↓
直接消失
```

---

### 19.2 SiLU

大约：

$$
SiLU(z)
=
[-0.269,\ 0.110,\ 1.762]
$$

于是：

```text
第一维：
-1 → -0.269
没有完全消失

第二维：
0.2 → 0.110
部分保留

第三维：
2 → 1.762
大部分保留
```

所以可以粗略理解：

```text
ReLU：
硬筛选

SiLU：
连续、柔和地调节
```

---

## 20. 但不要理解成“SiLU 永远比 ReLU 好”

更准确的说法是：

> ReLU 更简单、便宜，而且在大量网络里非常有效；SiLU 的优势主要在于平滑、负区间仍保留部分信号和梯度，并且特别适合现代 Transformer 中的门控 FFN。

所以这里不是：

```text
ReLU 错了
SiLU 对了
```

而是：

```text
不同架构选择了不同的非线性形式
```

现代 LLM 里常见的是：

```text
SiLU + Gated FFN
```

---

## 21. FFN 是什么？

FFN：

```text
Feed-Forward Network
```

在 Transformer 中，它最重要的特点是：

> **对每个 token 独立地处理自己的 hidden state。**

假设有：

```text
浙江大学
软件学院
位于
宁波
```

Attention 负责：

```text
“位于”读取“浙江大学”
“位于”读取“软件学院”
“位于”读取“宁波”
……
```

即：

$$
\boxed{
Attention=\text{token 与 token 之间交换信息}
}
$$

而 FFN：

```text
浙江大学 → 自己处理自己

软件学院 → 自己处理自己

位于 → 自己处理自己

宁波 → 自己处理自己
```

即：

$$
\boxed{
FFN=\text{单个 token 内部进一步加工}
}
$$

---

## 22. 最传统的 FFN

经典 Transformer FFN：

$$
FFN(x)
=
W_2\phi(W_1x+b_1)+b_2
$$

结构：

```text
d_model
   │
   ▼
 Linear
   │
   ▼
  d_ff
   │
   ▼
激活函数
   │
   ▼
 Linear
   │
   ▼
d_model
```

也就是：

```text
先升维
↓
在更大的特征空间中进行非线性加工
↓
再降回 d_model
```

---

## 23. 为什么 FFN 中间经常升维？

假设：

$$
x\in\mathbb{R}^{4096}
$$

FFN 可能先映射到更大的中间空间：

$$
4096
\rightarrow
11008
$$

再映射回来：

$$
11008
\rightarrow
4096
$$

可以粗略理解成：

```text
4096 维：
当前压缩后的 token 表示

↓ 展开

11008 维：
更多中间特征通道

↓ 非线性加工

4096 维：
重新压缩成新的 token 表示
```

这里的中间维度不是“更多 token”。

而是：

> **同一个 token 被展开成更多内部特征通道。**

---

## 24. 为什么 MiniMind 里的 FFN 有两条支路？

现代 LLM 常见的 FFN 不再只是：

```text
Linear
↓
Activation
↓
Linear
```

而是：

```text
             ┌→ Linear → SiLU ─┐
输入 x ──────┤                  ├→ ⊙ → Linear
             └→ Linear ────────┘
```

输入 \(x\) 被送到两条不同的 Linear。

一条：

$$
g=SiLU(xW_{gate})
$$

另一条：

$$
u=xW_{up}
$$

然后：

$$
m=g\odot u
$$

最后：

$$
y=mW_{down}
$$

因此：

$$
\boxed{
FFN(x)
=
\left[
SiLU(xW_{gate})
\odot
(xW_{up})
\right]
W_{down}
}
$$

这就是典型的 Gated FFN / SwiGLU-style 思路。

---

## 25. \(\odot\) 是什么？

这里：

$$
\odot
$$

不是矩阵乘法。

而是：

$$
\boxed{
逐元素乘法
}
$$

例如：

$$
g=[0.2,\ 0.8,\ 0.1]
$$

$$
u=[10,\ 5,\ 20]
$$

那么：

$$
g\odot u
=
[2,\ 4,\ 2]
$$

也就是：

```text
第 1 个特征：
0.2 × 10

第 2 个特征：
0.8 × 5

第 3 个特征：
0.1 × 20
```

每一个中间特征通道分别被调节。

## 26. 两条支路可以怎么理解？

为了建立直觉，可以粗略理解为：

```text
up 分支：

“我生成了哪些候选特征？”


gate 分支：

“这些候选特征现在应该被怎样调节？”
```

即：

$$
u=xW_{up}
$$

产生候选内容；

$$
g=SiLU(xW_{gate})
$$

产生输入相关的调节信号；

最后：

$$
g\odot u
$$

得到调节后的特征。

所以可以记成：

$$
\boxed{
u=\text{候选内容}
}
$$

$$
\boxed{
g=\text{门控信号}
}
$$

$$
\boxed{
g\odot u=\text{门控后的内容}
}
$$

## 27. 一个非常重要的纠正：SiLU 门不是简单的 0～1 开关

很容易把：

$$
SiLU(xW_{gate})
$$

误解成：

```text
0 = 完全关闭
1 = 完全打开
```

但这并不准确。

因为：

$$
SiLU(z)=z\sigma(z)
$$

它的输出：

- 可以接近 0；
- 可以是正数；
- 可以大于 1；
- 也可以是小的负数。

例如：

| \(z\) | SiLU(z) |
|---:|---:|
| -2 | -0.238 |
| -1 | -0.269 |
| 0 | 0 |
| 1 | 0.731 |
| 2 | 1.762 |
| 5 | 4.967 |

所以这个“门”不是：

```text
只会 0～1 之间放行百分之多少
```

而更准确地说：

> **它是一个由输入决定的连续调节系数，可以抑制、保留、放大，甚至改变符号。**

## 28. 用一个数字例子看门控到底怎么起作用

假设内容分支得到：

$$
u=[10,\ 5,\ 20]
$$

门控分支得到：

$$
g=[0.1,\ 1.0,\ 0.2]
$$

那么：

$$
m=g\odot u
$$

得到：

$$
[1,\ 5,\ 4]
$$

可以看到：

```text
第 1 维：
10 → 1
明显压低

第 2 维：
5 → 5
基本保留

第 3 维：
20 → 4
明显压低
```

如果门控值是：

$$
g=[2,\ 0.1,\ -0.2]
$$

那么：

$$
m=[20,\ 0.5,\ -4]
$$

此时甚至可以：

```text
第 1 维：
放大

第 2 维：
抑制

第 3 维：
改变符号
```

因此“门”这个词主要是帮助理解。

数学上它其实是：

$$
\boxed{
输入相关的逐维乘法调节
}
$$

## 29. 最关键的问题：这个门是谁规定的？

答案是：

> **没有人提前规定。**

训练开始时：

```text

W_up
W_down
```

通常都只是初始化出来的参数。

模型并不知道：

```text
第 1 维应该关闭
第 2 维应该打开
第 3 维应该放大
```

**这些行为都是训练过程中，通过最终的语言模型 Loss 反向传播逐渐学出来的。**

也就是说：

```text

↓
算 Loss
↓
反向传播
↓
修改 W_down
修改 W_up
修改 W_gate
↓
下一次相似输入时
门控行为发生变化
```

## 30. 门控是怎么被 Loss 训练出来的？

先把一维情况简化到最简单。

假设：

$$
u=4
$$

门控分支：

$$
g=SiLU(z)
$$

其中：

$$
z=xW_{gate}
$$

输出：

$$
y=g\cdot u
$$

也就是：

$$
\boxed{
y=SiLU(z)\times4
}
$$

为了看清楚训练过程，假设：

$$
x=1
$$

于是：

$$
z=W_{gate}
$$

也就是说：

> 现在 \(W_{gate}\) 的变化就会直接改变门控值。

---

## 31. 例子一：这个特征应该被“打开”

假设当前：

$$
z=0
$$

那么：

$$
SiLU(0)=0
$$

所以：

$$
y=0\times4=0
$$

但假设为了让最终预测更正确，这个特征最好输出：

$$
t=4
$$

定义一个最简单的平方误差：

$$
L=\frac12(y-t)^2
$$

当前：

$$
y=0,\quad t=4
$$

所以模型犯了很大错误。

---

### 31.1 Loss 会怎样推动 gate？

我们有：

$$
y=4SiLU(z)
$$

所以：

$$
\frac{\partial L}{\partial z}
=
\frac{\partial L}{\partial y}
\frac{\partial y}{\partial SiLU(z)}
\frac{\partial SiLU(z)}{\partial z}
$$

当前：

$$
\frac{\partial L}{\partial y}
=
y-t
=
-4
$$

而：

$$
\frac{\partial y}{\partial SiLU(z)}
=
4
$$

并且：

$$
SiLU'(0)=0.5
$$

所以：

$$
\frac{\partial L}{\partial z}
=
(-4)\times4\times0.5
=
-8
$$

梯度下降：

$$
z_{\text{new}}
=
z-\eta\frac{\partial L}{\partial z}
$$

因为梯度是负数：

$$
-8
$$

所以：

$$
z_{\text{new}}
>
z
$$

也就是：

```text
原来 z = 0
↓
训练以后 z 变大
↓
SiLU(z) 变大
↓
门控后的输出变大
↓
这个有用的特征被更多地保留下来
```

这就是“门被学着打开”的一个最简单例子。

---

## 32. 例子二：这个特征应该被压制

现在反过来。

仍然：

$$
u=4
$$

但假设当前：

$$
z=1
$$

那么：

$$
SiLU(1)\approx0.731
$$

所以：

$$
y
=
0.731\times4
\approx2.924
$$

但是假设对于当前训练样本，这个特征其实没用，理想目标是：

$$
t=0
$$

那么：

$$
L=\frac12(y-0)^2
$$

当前输出太大。

此时：

$$
\frac{\partial L}{\partial y}
=
y
>
0
$$

又因为在 \(z=1\) 附近：

$$
SiLU'(1)>0
$$

所以最终：

$$
\frac{\partial L}{\partial z}>0
$$

梯度下降会做：

$$
z_{\text{new}}
=
z-\eta
\frac{\partial L}{\partial z}
$$

于是：

$$
z_{\text{new}}<z
$$

也就是：

```text
原来 gate 太大
↓
导致没用的特征通过太多
↓
Loss 变大
↓
反向传播
↓
W_gate 被调整
↓
z 变小
↓
SiLU(z) 变小
↓
这个特征以后被压得更多
```

这就是“门被学着关小”的过程。

## 33. 所以门控真正的训练逻辑是什么？

可以总结成：

```text
某个特征对最终预测有帮助
        ↓
让它通过会降低 Loss
        ↓
反向传播推动 W_gate
        ↓
以后遇到类似 hidden state
        ↓
gate 值更有利于保留这个特征
```

反过来：

```text
某个特征对最终预测有害
        ↓
让它通过会增大 Loss
        ↓
反向传播推动 W_gate
        ↓
以后遇到类似 hidden state
        ↓
gate 更倾向于压制这个特征
```

因此：

$$
\boxed{
\text{门控不是人工规则，而是通过 Loss 学出来的}
}
$$

## 34. 为什么 gate 能针对“不同输入”做不同决定？

因为：

$$
z=xW_{gate}
$$

注意 \(z\) 不是一个固定常数。

它依赖：

$$
x
$$

所以同一个：

$$
W_{gate}
$$

面对不同 token hidden state，会得到不同的 gate。

例如：

```text
输入 A
x_A
↓
x_A W_gate
↓
gate_A


输入 B
x_B
↓
x_B W_gate
↓
gate_B
```

即使参数完全相同：

```text
W_gate 相同
```

只要：

```text
x_A ≠ x_B
```

就可能得到：

```text
gate_A ≠ gate_B
```

所以它是一种：

$$
\boxed{
输入相关的动态门控
}
$$

## 35. 用“浙江大学 软件学院 位于 宁波”理解门控训练

假设 Attention 已经让“位于”的 hidden state 包含：

```text
前面出现了：
浙江大学
软件学院

当前词：
位于

后面很可能需要：
地点相关信息
```

进入 FFN 后：

```text
x_位于
   │
   ├───────────────┐
   │               │
   ▼               ▼
W_gate           W_up
   │               │
   ▼               ▼
SiLU            候选特征
   │               │
   └────── ⊙ ──────┘
```

训练初期，这些维度没有人规定：

```text
“这是地点特征”
“这是学校特征”
“这是语法特征”
```

但如果某些内部特征组合能够帮助模型更正确地预测：

```text
宁波
杭州
北京
……
```

那么最终语言模型 Loss 就会通过反向传播调整：

```text
W_gate
W_up
W_down
```

使得以后遇到类似：

```text
某某大学 ... 位于 ...
```

这样的 hidden state 时，

某些中间特征更容易被：

```text
保留
增强
```

而没用的特征更容易被：

```text
压低
```

注意：

> 这是一种分布式表示，通常不能简单地说某一个具体神经元就是“宁波开关”。

**即：Gated FFN 和 Attention 虽然机制不同，但从更高层看，本质上都在做“根据当前输入，动态调整不同信息/特征的权重，让最终组合更合适”。**

区别是：Attention 调的是“不同 token / 位置信息”的权重；Gated FFN 调的是“同一个 token 内部不同特征维度”的权重。

## 36. 为什么普通 FFN 没有这种显式的乘法门控？

普通 FFN：

$$
FFN(x)
=
W_2\phi(W_1x)
$$

大概是：

```text
生成特征
↓
激活
↓
重新组合
```

而 Gated FFN：

$$
FFN(x)
=
[
SiLU(xW_{gate})
\odot
(xW_{up})
]
W_{down}
$$

多出了一条：

```text
独立 gate 分支
```

于是网络可以形成：

```text
一条分支：
生成候选内容

另一条分支：
根据当前输入决定这些内容怎么被调节

然后：
逐元素相乘
```

因此具有更强的输入相关特征选择能力。

## 37. 为什么 SiLU 特别适合 gate 分支？

因为我们希望 gate 的变化不是：

```text
突然全关
突然全开
```

而是可以：

```text
稍微抑制
↓
部分保留
↓
基本保留
↓
进一步放大
```

SiLU 恰好提供这种连续的变化。

例如 gate pre-activation：

$$
z
$$

从：

```text
-2
-1
0
1
2
```

变化时，SiLU 输出约：

```text
-0.238
-0.269
0
0.731
1.762
```

它不是一个二值开关。

而是：

$$
\boxed{
连续可学习的特征调节器
}
$$

同时 SiLU 又是可微的，

所以 Loss 可以通过它继续把梯度传回：

```text
W_gate
```

## 38. FFN 为什么说是“每个 token 自己加工自己”？

假设：

$$
X
=
\begin{bmatrix}

x_{\text{软件学院}}\\
x_{\text{位于}}\\
x_{\text{宁波}}
\end{bmatrix}
$$

FFN 对每一行使用同一套参数：

$$

$$

$$

$$

$$

参数共享，但 token 之间在 FFN 里不会重新直接做：

$$
x_i\cdot x_j
$$

这样的跨 token 交互。

所以：

$$
\boxed{

\boxed{

}
$$

## 39. FFN 的完整数据流

可以把 Gated FFN 记成下面这张图：

```text
                 输入 hidden state x
                         │
              ┌──────────┴──────────┐
              │                     │
              ▼                     ▼
          W_gate Linear          W_up Linear
              │                     │
              ▼                     ▼
            SiLU                 内容特征 u
              │                     │
              │ 门控特征 g           │
              └──────────⊙──────────┘
                         │
                         ▼
                      g ⊙ u
                         │
                         ▼
                   W_down Linear
                         │
                         ▼
                      FFN 输出
```

公式：

$$

$$

$$
u=xW_{up}
$$

$$
m=g\odot u
$$

$$
y=mW_{down}
$$

最终：

$$
\boxed{
FFN(x)
=
[
SiLU(xW_{gate})
\odot
(xW_{up})
]
W_{down}
}
$$

## 40. Residual 为什么还要加回来？

通常 FFN 输出不会直接完全替换原来的 hidden state。

而是：

$$
x_{\text{new}}
=
x+
FFN(x)
$$

可以粗略理解：

```text
原来的 token 表示
+
FFN 新加工出来的修改量
=
新的 token 表示
```

所以 FFN 更像：

> 在原有表示基础上做一次非线性特征更新。

## 41. 常见误区 1：SiLU 本身有可训练参数吗？

没有。

SiLU：

$$

$$

是一个固定函数。

真正学出来的是：

```text

W_up
W_down
```

也就是说：

> 不是 SiLU 自己学会了“什么时候开门”，而是 \(W_{gate}\) 学会把不同输入映射到合适的 SiLU 输入区域。

这是非常重要的区别。

## 42. 常见误区 2：门控是不是固定对应某个语义？

通常不是这么简单。

不能机械地认为：

所以：

```text

```

通常没有这么直接。

## 50. 更核心的问题：Gate 到底在做什么？

最核心的一句话是：

> **Gate 本质上是在根据当前输入，动态调节不同内部特征的权重，让最终特征组合更适合当前任务。**

例如：

```math id="p01kcd"

```

可以理解成模型生成了三个候选特征。

Gate：

```math id="k70t37"

相当于告诉模型：

→ 压低

第 2 个特征：
比较合适
→ 保留

第 3 个特征：
很有用
→ 增强
```

然后：

```math id="oxqnjx"

```

得到最终组合。


## 51. Attention 和 Gated FFN 的区别

可以直接这样对比：

| 模块        | 在给谁分配权重？            |
| --------- | ------------------- |
| Attention | 不同 token / 不同位置的信息  |
| Gated FFN | 同一个 token 内部的不同特征维度 |

因此：

```text
Attention：

“我现在应该重点看哪个 token？”
```

而：

Attention

“我已经听完大家的话了，

**传统 FFN 里 ReLU 明明直接夹在两个 Linear 中间，所以很好理解它“提供非线性”；但 SwiGLU 里 SiLU 跑到 gate 分支去了，它为什么仍然能给整个 FFN 提供非线性？**

下面这版专门讲这个问题。

## 55. SwiGLU 中 SiLU 到底在哪里提供了非线性？

传统全连接网络很容易理解：

```text
x
↓
Linear
↓
ReLU
↓
Linear
↓
y
```

公式：

```math
y=W_2ReLU(W_1x)
```

ReLU 明确夹在两个 Linear 中间。

所以：

> **ReLU 把原本连续的线性变换打断，使整个网络不能再合并成一个 Linear，从而提供非线性。**

但是现代 Transformer 的 Gated FFN / SwiGLU 通常写成：

```math
FFN(x)
=
W_{down}
\left[
SiLU(W_{gate}x)
\odot
(W_{up}x)
\right]
```

结构：

```text
                  ┌→ Linear(W_gate) → SiLU ─┐
x ────────────────┤                         ├→ ⊙ → Linear(W_down)
                  └→ Linear(W_up) ──────────┘
```

这里 SiLU 不再位于一条单独的：

```text
Linear
↓
激活
↓
Linear
```

路径中。

而是在：

```text
gate 分支
```

上。

那么问题就是：

> **SiLU 放在 gate 分支上，为什么仍然能让整个 FFN 变成非线性？**

---

## 56. 先回顾传统 ReLU 为什么能提供非线性

如果没有 ReLU：

```math
y=W_2W_1x
```

因为：

```math
W_2W_1
```

仍然可以合并成一个新的矩阵：

```math
W=W_2W_1
```

所以：

```math
y=Wx
```

还是 Linear。

即：

```text
Linear
↓
Linear
↓
Linear
```

不管堆多少层，

只要中间没有非线性，

最终都可以压缩成：

```text
一个 Linear
```

---

加入 ReLU：

```math
y=W_2ReLU(W_1x)
```

由于：

```math
ReLU(W_1x)
```

不是线性函数，

所以不能再写成：

```math
Wx
```

因此整个网络变成非线性。

---

## 57. 那 SwiGLU 中 SiLU 在哪里提供非线性？

SwiGLU：

```math
FFN(x)
=
W_{down}
\left[
SiLU(W_{gate}x)
\odot
(W_{up}x)
\right]
```

可以拆成三步。

第一条 gate 分支：

```math
g=SiLU(W_{gate}x)
```

第二条内容分支：

```math
u=W_{up}x
```

然后：

```math
m=g\odot u
```

最后：

```math
y=W_{down}m
```

关键就在：

```math
\boxed{
g=SiLU(W_{gate}x)
}
```

这一项。

因为：

```math
W_{gate}x
```

本来是 Linear，

但是经过：

```math
SiLU
```

以后：

```math
SiLU(W_{gate}x)
```

就已经变成了：

```text
x 的非线性函数
```

然后这个非线性结果再去乘：

```math
W_{up}x
```

所以整个：

```math
SiLU(W_{gate}x)
\odot
(W_{up}x)
```

当然也就不再可能是简单的：

```math
Wx
```

---

## 58. 用最简单的一维情况看

先不要考虑向量。

假设：

```math
x
```

只是一个数。

令：

```math
W_{gate}=a
```

```math
W_{up}=b
```

那么：

```math
W_{gate}x=ax
```

```math
W_{up}x=bx
```

SwiGLU 中间部分就是：

```math
SiLU(ax)\times bx
```

又因为：

```math
SiLU(ax)
=
ax\sigma(ax)
```

所以：

```math
y
=
ax\sigma(ax)\cdot bx
```

也就是：

```math
\boxed{
y=abx^2\sigma(ax)
}
```

注意这里已经出现：

```math
x^2
```

和：

```math
\sigma(ax)
```

所以这显然不可能再写成：

```math
y=cx
```

因此：

```math
\boxed{
SwiGLU 已经是一个非线性函数
}
```

## 59. 一个最小数字例子

为了简单：

```math
W_{gate}=1
```

```math
W_{up}=1
```

先暂时忽略：

```math
W_{down}
```

那么：

```math
y=SiLU(x)\times x
```

也就是：

```math
y=x^2\sigma(x)
```

---

当：

```math
x=1
```

时：

```math
\sigma(1)\approx0.731
```

所以：

```math
y
=
1^2\times0.731
=
0.731
```

---

当：

```math
x=2
```

时：

```math
\sigma(2)\approx0.881
```

所以：

```math
y
=
2^2\times0.881
```

得到：

```math
y\approx3.524
```

---

现在看输入输出：

```text
x = 1  → y ≈ 0.731

x = 2  → y ≈ 3.524
```

如果这是线性函数：

```math
y=ax
```

那么输入从：

```text
1 → 2
```

扩大 2 倍，

输出也必须严格扩大：

```text
2 倍
```

也就是说应该：

```text
0.731 → 1.462
```

但真实输出却变成：

```text
3.524
```

显然不是：

```text
1.462
```

因此：

```math
\boxed{
y=SiLU(x)\times x
}
```

不是线性函数。

## 60. 所以非线性到底在哪里产生？

就在这一条：

```text
x
↓
Linear(W_gate)
↓
SiLU
```

也就是：

```math
SiLU(W_{gate}x)
```

这里已经产生了非线性。

后面的：

```text
⊙ W_up x
```

**则把这个非线性 gate 应用到另一条 feature 分支上。**

所以：

```text
SiLU
↓
首先产生一个非线性的 gate

非线性 gate
↓
再动态调节另一条 Linear 产生的 feature
```

---

## 61. 为什么只在一条分支加 SiLU 就够了？

因为整个函数中：

> **只要有一个地方出现不能被 Linear 合并掉的非线性操作，整个函数就不再是纯 Linear。**

例如：

```math
y
=
SiLU(W_1x)
\odot
(W_2x)
```

虽然：

```math
W_2x
```

这一条路完全是 Linear，

但是：

```math
SiLU(W_1x)
```

已经是非线性的。

两者相乘以后：

```math
y
```

自然也是非线性的。

并不要求：

```text
每一条分支
```

都必须单独加激活函数。

---

## 62. 一个非常直观的类比

假设：

```math
u=W_{up}x
```

生成内容：

```text
[10, 5, 8]
```

如果整个网络只有 Linear，

这些特征基本只是做：

```text
固定的线性组合
```

但是 gate 分支：

```math
g=SiLU(W_{gate}x)
```

可能根据不同输入产生：

```text
输入 A：

g = [0.1, 1.0, 1.8]
```

于是：

```text
[10, 5, 8]

↓

[1, 5, 14.4]
```

而另一个输入 B：

```text
g = [1.5, 0.2, 0.1]
```

那么同样的特征类型可能被调成：

```text
[15, 1, 0.8]
```

所以：

> **网络不再只是用一套固定比例处理所有输入，而是可以根据当前输入，产生不同的 feature 调节方式。**

这就是非线性的实际意义。

## 63. 传统 ReLU 和 SwiGLU SiLU 的相同点

传统 FFN：

```math
y=W_2ReLU(W_1x)
```

SwiGLU：

```math
y
=
W_{down}
[
SiLU(W_{gate}x)
\odot
(W_{up}x)
]
```

它们相同的地方是：

```text
ReLU
和
SiLU
```

都是：

```text
非线性函数
```

它们都会让整个网络无法再简化成：

```math
y=Wx
```

因此：

```math
\boxed{
二者都在给网络提供非线性表达能力
}
```

## 64. 不同点在哪里？

传统 ReLU：

```text
x
↓
Linear
↓
ReLU
↓
Linear
```

ReLU 的输出直接成为：

```text
下一层 Linear 的输入
```

所以它主要体现为：

```text
激活隐藏特征
```

---

SwiGLU：

```text
                ┌→ Linear → SiLU ─┐
x ──────────────┤                  ├→ ⊙ → Linear
                └→ Linear ────────┘
```

SiLU 的输出不是直接送到最后一个 Linear。

而是先：

```text
乘到另一条 feature 分支上
```

所以：

```text
SiLU
```

在这里同时具有：

```text
第一层作用：
提供非线性

第二层作用：
产生 gate 调节信号
```

---

## 65. 最准确的理解

传统 ReLU：

```text
Linear
↓
ReLU
↓
得到非线性 hidden feature
↓
Linear
```

SwiGLU：

```text
Linear(W_gate)
↓
SiLU
↓
得到非线性的 gate
↓
乘另一条 feature 分支
↓
得到非线性的、动态调节后的 feature
↓
Linear
```

所以：

```math
\boxed{
\text{传统 ReLU：直接非线性变换特征}
}
```

而：

```math
\boxed{
\text{SwiGLU 的 SiLU：通过非线性的 gate 去动态调节特征}
}
```

---

## 66. 最核心的一句话

> **传统 FFN 中，ReLU 是直接把 Linear 输出变成非线性特征；SwiGLU 中，SiLU 则是在 gate 分支上先产生一个非线性的、输入相关的调节信号，再用这个信号乘到另一条 feature 分支上。虽然位置不同，但它同样打破了纯 Linear 关系，使整个 FFN 能根据不同输入产生不同的特征组合。**

可以进一步浓缩成：

```text
传统 ReLU：

Linear
↓
非线性处理特征
↓
Linear


SwiGLU SiLU：

Linear
↓
非线性生成 Gate
↓
Gate 动态调节另一条特征
↓
Linear
```

所以：

```math
\boxed{
\text{非线性的来源仍然是 SiLU，
只是它不再直接“激活内容”，而是通过 gate 间接控制内容。}
}
```

## 67. MiniMind 中 `intermediate_size` 为什么这样计算？

源码：

```python
self.intermediate_size = kwargs.get(
    "intermediate_size",
    math.ceil(hidden_size * math.pi / 64) * 64
)
```

这行代码的核心作用是：

> 如果用户没有手动指定 `intermediate_size`，那么默认把 FFN 的中间维度设置为大约 `hidden_size × π`，然后再向上对齐到 64 的整数倍。

---

## 68. `intermediate_size` 是什么？

假设：

```python
hidden_size = 768
```

表示每个 token 在 Transformer Block 中用一个 768 维向量表示。

但是 FFN 通常不会直接做：

```text
768 → 768
```

而是先扩宽，再压回来：

```text
768
 ↓
intermediate_size
 ↓
768
```

在 MiniMind 里，FeedForward 大致是：

```text
                 ┌── gate_proj ──→ I ── SiLU ──┐
H ───────────────┤                              × ──→ down_proj ──→ H
                 └── up_proj   ──→ I ──────────┘
```

其中：

```text
H = hidden_size
I = intermediate_size
```

所以 `intermediate_size` 决定了：

> FFN 中间层到底有多宽。

---

## 69. 为什么中间层要比 `hidden_size` 大？

FFN 的作用不是在不同 token 之间交换信息，而是：

> 对每一个 token 自己的 hidden state 做更丰富的非线性特征变换。

例如：

```text
768 → 2432 → 768
```

可以理解成：

> 先给这个 token 更多“特征槽位”进行组合和门控，再压回原来的 hidden size。

---

## 70. 为什么是 `hidden_size × π`？

源码中：

```python
hidden_size * math.pi
```

也就是：

```math
I \approx \pi H
```

其中：

```math
\pi \approx 3.1415926
```

所以 MiniMind 选择的 FFN 扩展倍数大约是：

```text
3.14 倍
```

例如：

```text
hidden_size = 768
```

则：

```math
768 \times \pi \approx 2412.74
```

也就是说作者希望：

```text
intermediate_size ≈ 2413
```

---

## 71. 这里的 π 有什么特殊理论吗？

没有。

这里的：

```python
math.pi
```

虽然确实是圆周率，但它在这里并不代表：

```text
圆
旋转
三角函数
RoPE
```

之类的数学意义。

它只是被当成一个：

```text
大约 3.14
```

的扩展倍率使用。

所以作者理论上也可以设计成：

```python
hidden_size * 3
```

或者：

```python
hidden_size * 3.5
```

或者其他经验比例。

因此：

> `π` 不是 Transformer 理论强制要求，而是这个实现的架构设计选择。

---

## 72. 为什么不是经典的 `4 × hidden_size`？

传统 Transformer 中常见：

```text
FFN：

H → 4H → H
```

例如：

```text
768 → 3072 → 768
```

但是 MiniMind 使用的是类似 SwiGLU 的结构，有两条输入投影：

```text
gate_proj: H → I
up_proj:   H → I
down_proj: I → H
```

参数量大致为：

```math
HI + HI + IH = 3HI
```

所以使用这种结构以后：

> `intermediate_size` 不一定继续采用传统的 `4H`。

MiniMind 这里选择的是：

```math
I \approx \pi H
```

---

## 73. `/64 → ceil() → ×64` 是什么意思？

完整公式：

```python
math.ceil(hidden_size * math.pi / 64) * 64
```

实际上分成两步：

```text
第一步：
hidden_size × π

第二步：
把结果向上对齐到 64 的整数倍
```

---

## 74. 具体算一次：`hidden_size = 768`

先算：

```math
768 \times \pi \approx 2412.74
```

然后除以 64：

```math
2412.74 / 64 \approx 37.699
```

再：

```python
math.ceil(37.699)
```

得到：

```text
38
```

最后：

```math
38 \times 64 = 2432
```

所以最终：

```python
intermediate_size = 2432
```

完整过程：

```text
768
↓
× π
↓
2412.74
↓
÷ 64
↓
37.699
↓
ceil
↓
38
↓
× 64
↓
2432
```

---

## 75. 为什么要对齐到 64 的整数倍？

这主要是工程实现方面的考虑。

GPU 更喜欢比较规整的矩阵维度。

例如：

```text
2413
```

这种维度比较零碎，而：

```text
2432
```

满足：

```math
2432 = 38 \times 64
```

更加规整。

深度学习模型中经常会看到维度取：

```text
8 的倍数
16 的倍数
32 的倍数
64 的倍数
128 的倍数
256 的倍数
```

这通常对矩阵乘法、GPU Kernel、Tensor Core、内存访问和向量化计算更友好。

因此：

```python
math.ceil(x / 64) * 64
```

可以理解为：

> 把 `x` 向上调整到最近的 64 的整数倍。

---

## 76. 一个最简单的 Python 例子

假设：

```python
x = 1000
```

希望向上取到最近的 64 的倍数：

```python
import math

x = 1000
y = math.ceil(x / 64) * 64

print(y)
```

计算过程：

```text
1000 / 64 = 15.625
ceil(15.625) = 16
16 × 64 = 1024
```

所以：

```text
1000
↓
1024
```

## 77. 把原公式拆成教学版

原代码：

```python
self.intermediate_size = kwargs.get(
    "intermediate_size",
    math.ceil(hidden_size * math.pi / 64) * 64
)
```

可以改写为：

```python
# 第一步：希望 FFN 中间层约为 hidden_size 的 π 倍
target_size = hidden_size * math.pi

# 第二步：向上对齐到 64 的整数倍
default_intermediate_size = math.ceil(target_size / 64) * 64

# 第三步：用户传了 intermediate_size 就用用户的；
# 没传才使用默认值
self.intermediate_size = kwargs.get(
    "intermediate_size",
    default_intermediate_size
)
```

---

## 78. `kwargs.get()` 又是什么意思？

这一行：

```python
kwargs.get(
    "intermediate_size",
    默认值
)
```

表示：

> 如果调用者传了 `intermediate_size`，就使用调用者传入的值；否则使用默认值。

例如：

```python
config = MiniMindConfig(
    hidden_size=768,
    intermediate_size=2048
)
```

那么：

```text
intermediate_size = 2048
```

不会再计算：

```text
768 × π → 2432
```

只有当用户没有指定时，才使用默认公式。

因此：

> `π × H` 只是默认设计，不是强制规则。

## 79. 几个具体例子

| hidden_size `H` | `H × π` | 向上对齐 64 后的 `intermediate_size` |
|---:|---:|---:|
| 128 | 402.12 | 448 |
| 256 | 804.25 | 832 |
| 512 | 1608.50 | 1664 |
| 768 | 2412.74 | 2432 |
| 1024 | 3216.99 | 3264 |

可以看到：

> H 越大，最终 expansion ratio 越接近 `π ≈ 3.14`；小模型会因为 64 对齐而稍微偏大一些。

---

## 80. 最后放回 FFN 中理解

假设：

```text
hidden_size = 768
intermediate_size = 2432
```

那么 MiniMind 的 FFN 就大致是：

```text
768
├──→ 2432 → SiLU ──┐
│                  × → 2432 → 768
└──→ 2432 ─────────┘
```

也就是：

```text
                         ┌── gate_proj ──────────┐
                         │                       ↓
768维 hidden state ──────┤                   2432维
                         │                       │
                         │                     SiLU
                         │                       │
                         │                       ×
                         │                       ↑
                         └── up_proj ────────────┘
                                  ↓
                               2432维

                                  ↓
                              down_proj
                                  ↓
                               768维
```

---

## 81. 一句话总结

源码：

```python
self.intermediate_size = kwargs.get(
    "intermediate_size",
    math.ceil(hidden_size * math.pi / 64) * 64
)
```

可以翻译成人话：

> 如果用户没有自己指定 FFN 中间层宽度，就先把 `hidden_size` 扩大约 `π ≈ 3.14` 倍，再向上调整到最近的 64 的整数倍，作为 `intermediate_size`。

其中：

```text
π
```

负责：

```text
决定 FFN 大约扩宽多少倍
```

而：

```text
64
```

负责：

```text
让实际矩阵维度更加规整，对 GPU 计算更友好
```

需要特别注意：

> `π` 和 `64` 都不是 Transformer 理论强制规定，而是这个 MiniMind 实现采用的架构与工程设计选择。
