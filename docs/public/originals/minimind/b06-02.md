# 16 · Attention：多头结构与 QKV 的分工

## 1. 为什么需要很多 Head？

因为一句话中有很多不同关系。

还是：

```text
浙江大学 软件学院 位于 宁波
```

某个 Head 可能比较关注：

> 哪个实体和哪个机构有关？

另一个 Head 可能更关注：

> “位于”需要寻找哪个主体？

另一个 Head 可能更容易捕获：

> 地理位置相关的信息。

另一个 Head：

> 长距离依赖。

所以可以用一个不完全严格、但容易理解的类比：

> 每个 Head 就像一个观察句子的不同视角。

---

## 2. 但不要认为一个 Head 一定对应一种人类语法规则

例如：

```text
Head 1 = 主谓关系
Head 2 = 地理关系
Head 3 = 指代关系
```

这只是教学类比。

真实训练中：

> 每个 Head 学到的特征通常非常复杂。

它并不会乖乖按照人类语言学分类工作。

准确说法是：

\[
\boxed{
不同 Attention Head 在不同表示子空间中学习不同的信息交互模式
}
\]

---

## 3. Multi-Head 的数学结构

例如：

\[
d_{model}=768
\]

使用：

\[
12
\]

个 Head。

那么每个 Head 常见：

\[
d_{head}=64
\]

因为：

\[
12\times64=768
\]

对于第一个 Head：

\[
Q_1=XW_Q^1
\]

\[
K_1=XW_K^1
\]

\[
V_1=XW_V^1
\]

然后：

\[
head_1
=
softmax
\left(
\frac{Q_1K_1^T}{\sqrt{64}}
+Mask
\right)V_1
\]

第二个：

\[
head_2
=
softmax
\left(
\frac{Q_2K_2^T}{\sqrt{64}}
+Mask
\right)V_2
\]

依次类推。

最后：

\[
Concat(head_1,\ldots,head_{12})
\]

再通过：

\[
W_O
\]

得到最终：

\[
MultiHeadAttention(X)
\]

然后：

\[

\]

## 5. Attention 和 MLP 分别负责什么？

可以用一句特别重要的话总结：

\[
\boxed{
Attention：token 之间交换信息
}
\]

而：

\[
\boxed{
MLP：每个 token 对拿到的信息进一步加工
}
\]

例如对于：

```text
位于
```

Attention 阶段：

> 我先去看“浙江大学”和“软件学院”，收集相关上下文。

MLP：

> 我已经拿到了这些上下文，现在对我自己的 hidden state 做进一步非线性变换。

可以粗略理解成：

```text
Attention：出去搜集资料

MLP：回来以后自己加工资料
```

所以一个 Transformer Block 可以极度简化成：

\[
\boxed{
先交流，再加工
}
\]

---

## 6. 为什么还要 Residual Connection？

你会看到：

\[
x'
=
x+Attention(...)
\]

为什么不是：

\[
x'=Attention(...)
\]

因为我们不希望 Attention 把原来的信息完全覆盖掉。

原始：

\[
x
\]

里面有 token 自身的信息。

Attention：

\[
Attention(...)
\]

里面是从上下文获取的新信息。

把它们加起来：

\[
x+Attention(...)
\]

可以理解成：

```text
原来的我
+
从上下文获得的新知识
```

于是信息更容易保留下来。

同时 Residual Connection 也极大地帮助深层网络训练。

---

## 7. LayerNorm 是干什么的？

神经网络层数越来越深时，不同维度的数值分布可能变得不稳定。

LayerNorm 的主要作用可以理解为：

> 对每个 token 的 hidden representation 做规范化，让后续计算更加稳定。

现代 Transformer 中 LayerNorm / RMSNorm 等归一化结构非常重要。

所以不能简单认为：

> Transformer 就只有 Attention。

真正完整 Block 通常还包含：

```text
Normalization
Attention
Residual
MLP
Residual
```

## 8. 为什么 GPT 要堆几十层 Transformer？

假设只有一层。

那么“位于”可能获得：

```text
软件学院
```

和：

```text
浙江大学
```

的一些信息。

第二层又是在：

> 已经融合过上下文的信息上继续做 Attention。

第三层：

> 再次组合。

于是不断形成越来越高级的表示。

可以粗略想成：

---
### 8.1 第 0 层

```text
浙江大学
软件学院
位于
```

主要还是词本身。

---
#### 8.1.1 第 1 层

开始知道：

```text
浙江大学 ↔ 软件学院
软件学院 ↔ 位于
```

---
#### 8.1.2 更深层

可能逐渐形成：

> “浙江大学软件学院”是一个整体实体。

以及：

> “位于”在这里表达一个地理位置关系。

最终：

\[
h_{\text{位于}}^{(L)}
\]

已经包含非常丰富的上下文信息。

## 9. 最后一层怎么预测“宁波”？

假设最终：

\[
h_{\text{位于}}
\]

是一个：

\[
4096
\]

维向量。

然后 GPT 有一个：

---
### 9.1 LM Head

把 4096 维转换到词表大小。

假设词表：

\[
|\mathcal V|=50000
\]

那么：

\[
logits
=
h_{\text{位于}}W_{vocab}
\]

得到：

\[
50000
\]

个数字。

例如：

| token | logit |
|---|---:|
| 宁波 | 9.2 |
| 杭州 | 7.3 |
| 浙江 | 5.4 |
| 上海 | 3.1 |
| 北京 | 2.7 |
| 苹果 | -2.1 |

再经过 Softmax：

\[
P(token\mid context)
\]

例如：

\[
P(\text{宁波}\mid\text{浙江大学 软件学院 位于})=0.72
\]

于是模型很可能生成：

```text
宁波
```

## 10. 把整个过程一次性串起来

输入：

```text
浙江大学 软件学院 位于
```

---

### 10.1 Step 1：Tokenizer

把文本转换为 token：

```text
浙江大学
软件学院
位于
```

然后转换成 token id：

```text
1523
8271
392
```

数字只是举例。

---

### 10.2 Step 2：Embedding

每一个 token id 查 Embedding Table：

```text
浙江大学  → 一个 d_model 维向量
软件学院  → 一个 d_model 维向量
位于      → 一个 d_model 维向量
```

得到：

\[
X
\]

---

### 10.3 Step 3：加入位置信息

因为：

```text
浙江大学 软件学院 位于
```

和：

```text
位于 软件学院 浙江大学
```

显然完全不是一回事。

所以模型必须知道：

> token 在序列中的位置。

现代模型可能使用：

```text
RoPE
```

早期 GPT 也使用过 learned positional embeddings 等方案。

---

### 10.4 Step 4：生成 QKV

对于当前 Transformer Layer：

\[
Q=XW_Q
\]

\[
K=XW_K
\]

\[
V=XW_V
\]

---

### 10.5 Step 5：计算 QKᵀ

\[
Score=QK^T
\]

得到每个 Query 对每个 Key 的匹配程度。

---

### 10.6 Step 6：加入 Causal Mask

禁止：

```text
前面的位置
```

偷看：

```text
未来的位置
```

---

### 10.7 Step 7：Scaling

\[
\frac{QK^T}{\sqrt{d_k}}
\]

防止点积过大。

---

### 10.8 Step 8：Softmax

得到 Attention Weight：

\[
A
=
softmax
\left(
\frac{QK^T}{\sqrt{d_k}}+Mask
\right)
\]

---

### 10.9 Step 9：乘 V

\[
O=AV
\]

也就是：

> 按照 Attention 权重，从其他 token 那里读取信息。

---

### 10.10 Step 10：Multi-Head

同时从多个不同表示空间进行 Attention。

---

### 10.11 Step 11：Residual + MLP

进一步加工表示。

---

### 10.12 Step 12：重复很多 Transformer Block

```text
Block 1
   ↓
Block 2
   ↓
Block 3
   ↓
...
   ↓
Block L
```

---

### 10.13 Step 13：取“位于”位置的最终 Hidden State

得到：

\[
h_{\text{位于}}
\]

此时它已经包含：

```text
浙江大学
软件学院
位于
```

整个上下文的信息。

---

### 10.14 Step 14：LM Head

\[
h_{\text{位于}}
\rightarrow logits
\]

再：

\[
Softmax
\]

得到下一个 token 的概率。

最终：

```text
宁波
```

概率最高。

于是生成：

```text
浙江大学 软件学院 位于 宁波
```

## 11. 最后再把 QKV 用一句话彻底记住

千万不要死背：

```text
Q = Query 向量
K = Key 向量
V = Value 向量
```

应该记下面的故事。

假设现在：

```text
位于
```

站出来说：

> “我现在要预测后面的东西，我需要知道前面到底在说谁。”

它拿出来的：

\[
Q_{\text{位于}}
\]

就是：

> **我的需求。**

然后：

```text
浙江大学
软件学院
位于
```

都各自拿出：

\[
K
\]

表示：

> **我这里有什么类型的信息，你需不需要我？**

“位于”用自己的：

\[
Q_{\text{位于}}
\]

依次和：

\[
K_{\text{浙江大学}}
\]

\[
K_{\text{软件学院}}
\]

\[
K_{\text{位于}}
\]

匹配。

得到：

```text
浙江大学    24.8%
软件学院    50.3%
位于        24.8%
```

然后再说：

> 好，我决定主要读取软件学院的信息，同时也读取浙江大学和我自己的信息。

真正被读出来的是：

\[
V_{\text{浙江大学}}
\]

\[
V_{\text{软件学院}}
\]

\[
V_{\text{位于}}
\]

最终形成：

\[
h_{\text{位于}}
\]

所以最重要的三句话就是：

\[
\boxed{
Q=\text{我想找什么}
}
\]

\[
\boxed{
K=\text{我是否值得你找}
}
\]

\[
\boxed{
V=\text{你找到我以后真正拿走的信息}
}
\]

## 12. 为什么 QKV 最后会学出各自的功能？

最核心的一句话：

```text
我们从来没有直接告诉模型“Q 应该表示需求、K 应该表示索引、V 应该表示内容”。
模型之所以最后会学出“看起来符合这种分工”的 QKV，
是因为这个结构本身规定了 Q、K、V 分别只能通过不同方式影响最终预测，
而训练目标会逼着它们逐渐承担最有利于降低 Loss 的角色。
```

---

### 12.1 一开始 QKV 都是随机的

Transformer 中：

```math
Q=XW_Q
```

```math
K=XW_K
```

```math
V=XW_V
```

刚开始训练时：

```math
W_Q,\;W_K,\;W_V
```

基本都是随机初始化的。

所以一开始：

```text
Q 是乱的
K 是乱的
V 也是乱的
```

Attention 当然也基本是乱的。

---

### 12.2 模型真正的训练目标只有一个

例如：

```text
浙江大学 软件学院 位于 → 宁波
```

模型最终需要让：

```math
P(\text{宁波}\mid \text{浙江大学 软件学院 位于})
```

尽可能大。

如果模型预测：

```text
苹果
```

而不是：

```text
宁波
```

那么 Loss 就会很高。

---

### 12.3 Loss 会反向传播到 QKV

训练过程：

```text
预测下一个 token
        ↓
计算 Loss
        ↓
反向传播
        ↓
修改 WQ、WK、WV
```

也就是：

```math
Loss
\rightarrow
W_Q,W_K,W_V
```

如果某种 QKV 的计算方式能够让：

```text
宁波
```

的概率提高，

这种参数就会被保留下来。

---

## 13. 为什么 Q 和 K 最终主要通过 Attention 权重发挥作用？

先看标准 Attention：

```math
A=
softmax
\left(
\frac{QK^T}{\sqrt{d_k}}
\right)
```

然后：

```math
O=AV
```

---

### 13.1 Q 和 K 本身可以学到很多信息

例如：

```math
Q_{\text{位于}}
=
[q_1,q_2,\cdots,q_{64}]
```

```math
K_{\text{软件学院}}
=
[k_1,k_2,\cdots,k_{64}]
```

它们都是 64 维向量，所以完全可以编码很多复杂信息。

比如：

```text
是不是机构
是不是地点
当前是不是在寻找位置关系
当前 token 的语法角色
上下文中的各种抽象特征
……
```

所以不能说：

```text
Q 和 K 只能学习权重
```

更准确的是：

> Q 和 K 可以学习很多复杂特征，但这些特征最终主要通过改变 Attention 权重来影响输出。

---

### 13.2 为什么最后会变成权重？

因为 Q 和 K 接下来要做点积：

```math
Q_i\cdot K_j
```

例如：

```math
Q_{\text{位于}}
=
[1,1]
```

```math
K_{\text{软件学院}}
=
[1,2]
```

点积：

```math
Q_{\text{位于}}
\cdot
K_{\text{软件学院}}
=
1\times1+1\times2
=
3
```

原来两个二维向量：

```math
[1,1]
```

和：

```math
[1,2]
```

最后被压成了一个数字：

```math
3
```

这个数字表示：

> “位于”和“软件学院”之间的匹配程度。

---

### 13.3 Softmax 再把分数变成 Attention 权重

假设“位于”和三个 token 的匹配分数是：

```text
浙江大学    1
软件学院    3
位于        1
```

经过 Softmax 后可能得到：

```text
浙江大学    10%
软件学院    80%
位于        10%
```

所以：

```math
QK^T
```

最终形成的是：

```text
谁应该被关注，以及关注多少
```

---

### 13.4 Q 和 K 中的信息不会直接传给下一层

这一点最重要。

例如：

```math
Q_{\text{位于}}
=
[0.2,1.3,-0.8,\cdots]
```

里面即使包含很多复杂信息，

后面的网络也不会直接拿这个 Q 去预测：

```text
宁波
```

Q 必须经过：

```math
QK^T
```

然后：

```math
Softmax
```

最终变成 Attention 权重。

例如：

```text
浙江大学      20%
软件学院      70%
位于          10%
```

所以 Q 和 K 中学到的信息，最终必须转化成：

> “应该更关注谁”。

---

### 13.5 V 的路径不一样

V 会直接进入：

```math
O=AV
```

例如：

```math
V_{\text{软件学院}}
=
[0.8,-1.2,0.3,\cdots]
```

Attention 权重是：

```math
0.7
```

那么：

```math
0.7V_{\text{软件学院}}
```

得到：

```math
[0.56,-0.84,0.21,\cdots]
```

这个完整向量会真正进入 Attention Output。

所以：

```text
Q、K：决定怎么分配权重
V：真正提供被传递的内容
```

---

### 13.6 从维度上看最清楚

假设有 3 个 token：

```text
浙江大学
软件学院
位于
```

每个 Attention Head 的维度是：

```math
d_k=64
```

那么：

```math
Q,K\in\mathbb{R}^{3\times64}
```

计算：

```math
QK^T
```

得到：

```math
3\times3
```

也就是：

```math
QK^T\in\mathbb{R}^{3\times3}
```

这个矩阵表示：

> 3 个 token 两两之间的关系分数。

所以：

```text
3 × 64
↓
QKᵀ
↓
3 × 3
```

原来的高维 token 特征被转换成：

> token 与 token 之间的关系。

**这个维度就决定了QKᵀ只能表示关系，而不能直接传递内容。**

然后：

```math
A\in\mathbb{R}^{3\times3}
```

再乘：

```math
V\in\mathbb{R}^{3\times64}
```

得到：

```math
O=AV
```

所以：

```math
O\in\mathbb{R}^{3\times64}
```

也就是：

```text
关系矩阵 × 内容矩阵
↓
新的 token 表示
```

---

### 13.7 所以最准确的说法

不能说：

```text
Q 和 K 只能学习权重
```

应该说：

```text
Q 和 K 可以学习很多复杂特征，
但由于它们在 Attention 中要经过 QKᵀ 和 Softmax，最终只是一个数字，
所以这些特征最终主要通过“改变 Attention 权重”来影响输出。
```

也就是：

```math
\boxed{
Q,K=\text{学习如何建立 token 之间的关系}
}
```

```math
\boxed{
V=\text{学习真正需要传递的内容}
}
```

## 14. 为什么 Q、K、V 会自然形成各自的角色？

先看一句话：

```text
浙江大学 软件学院 位于
```

我们现在重点看：

```text
位于
```

这个位置。

Attention 的核心公式是：

```math
A=
softmax
\left(
\frac{QK^T}{\sqrt{d_k}}
\right)
```

然后：

```math
O=AV
```

最关键的问题是：

> 为什么训练之后，Q 自然会像“查询”，K 自然会像“键”，V 自然会像“内容”？

答案是：

```text
不是它们自己“悟”出了这些角色，

而是它们在计算公式中的位置，
天然规定了它们只能以不同方式影响最终结果。
```

---

## 15. 先看 Q 为什么自然变成“查询”

对于“位于”这个位置，它会产生：

```math
q_{\text{位于}}
```

然后这个 Q 会和前面每个 token 的 K 分别做点积：

```math
q_{\text{位于}}
\cdot
k_{\text{浙江大学}}
```

```math
q_{\text{位于}}
\cdot
k_{\text{软件学院}}
```

```math
q_{\text{位于}}
\cdot
k_{\text{位于}}
```

也就是说：

```text
“位于”拿着自己的 q，
挨个去和所有 token 的 k 比较。
```

例如最后得到：

```text
浙江大学      1
软件学院      3
位于          1
```

经过 Softmax：

```text
浙江大学      10%
软件学院      80%
位于          10%
```

这意味着：

> “位于”这个位置决定：
> 我主要去看“软件学院”。

所以：

```math
q_{\text{位于}}
```

在整个计算过程中承担的角色天然就是：

```text
“我现在应该找谁？”
```

因此训练时：

```math
W_Q
```

会不断被调整，使生成出来的 Q：

> 更适合表达当前 token “需要寻找什么”。

所以我们把它叫：

```math
\boxed{Query}
```

---

## 16. 为什么 K 自然变成“键”

再看：

```math
k_{\text{软件学院}}
```

它自己并不会主动去找别人。

相反，各个位置的 Query 都会来和它比较：

```math
q_{\text{浙江大学}}
\cdot
k_{\text{软件学院}}
```

```math
q_{\text{软件学院}}
\cdot
k_{\text{软件学院}}
```

```math
q_{\text{位于}}
\cdot
k_{\text{软件学院}}
```

也就是说：

```text
“软件学院”的 K 是站在那里，
让不同的 Query 来判断：

“你是不是我要找的？”
```

所以：

```math
k_{\text{软件学院}}
```

天然承担的是：

> “我有什么特征，使别人能够决定要不要关注我？”

假设训练过程中模型发现：

```text
位于
```

应该经常关注前面的机构实体，

那么为了降低 Loss，训练就会调整：

```math
W_K
```

使得：

```math
q_{\text{位于}}
\cdot
k_{\text{软件学院}}
```

变得更大。

所以 K 会逐渐学成一种：

> 适合被 Query 匹配的表示。

因此叫：

```math
\boxed{Key}
```

## 17. Q 和 K 的关系可以这样理解

对于：

```text
浙江大学 软件学院 位于
```

“位于”问：

```text
我现在应该找谁？
```

这是：

```math
Q_{\text{位于}}
```

而“软件学院”回答：

```text
你看看我的特征，我是不是你需要的那个位置？
```

这是：

```math
K_{\text{软件学院}}
```

然后：

```math
Q_{\text{位于}}
\cdot
K_{\text{软件学院}}
```

得到一个分数。

所以：

```text
Q = 发起匹配的一方

K = 被匹配的一方
```

## 18. 为什么 V 又自然变成“内容”

现在假设经过 Q 和 K 的匹配以后：

```text
浙江大学      10%
软件学院      80%
位于          10%
```

注意：

这些数字只是告诉模型：

```text
看谁、看多少
```

它还没有真正把：

```text
软件学院
```

的信息拿过来。

所以接下来要计算：

```math
O=AV
```

对于“位于”：

```math
o_{\text{位于}}
=
0.1V_{\text{浙江大学}}
+
0.8V_{\text{软件学院}}
+
0.1V_{\text{位于}}
```

这里真正进入新的 hidden representation 的，是：

```math
V_{\text{浙江大学}}
```

```math
V_{\text{软件学院}}
```

```math
V_{\text{位于}}
```

所以 V 承担的角色天然是：

> “如果别人决定关注我，我真正把什么信息交给他？”

因此训练过程中：

```math
W_V
```

会不断被调整，使 V 中包含：

> 对后续预测真正有用的信息。

所以：

```math
\boxed{V=Value}
```

## 19. 为什么 Q、K 和 V 会出现这种分工？

因为它们的信息流不同。

Q 和 K 的路径：

```text
Q
 \
  QKᵀ
 /
K
 ↓
Softmax
 ↓
Attention Weight
```

所以：

```text
Q 和 K 最终主要影响：
“谁被关注、关注多少”
```

而 V 的路径：

```text
V
 ↓
乘 Attention Weight
 ↓
Attention Output
 ↓
进入后续 Transformer
```

所以：

```text
V 最终影响：
“真正传递了什么内容”
```

因此：

```math
\boxed{
Q,K=\text{决定信息从哪里来}
}
```

```math
\boxed{
V=\text{决定真正拿回来什么}
}
```

## 20. 训练一开始其实什么都没有

刚开始：

```math
W_Q,W_K,W_V
```

都是随机初始化的。

所以：

```text
Q 是乱的
K 是乱的
V 也是乱的
```

模型可能输入：

```text
浙江大学 软件学院 位于
```

最后却预测：

```text
苹果
```

于是 Loss 很高。

然后：

```text
Loss
 ↓
反向传播
 ↓
修改 WQ、WK、WV
```

如果训练发现：

```text
让“位于”的 Q
更加容易匹配“软件学院”的 K
```

能够提高：

```math
P(\text{宁波})
```

那么这种 Q/K 的表示方式就会被强化。

同时，如果：

```math
V_{\text{软件学院}}
```

包含更有用的信息，也能够让后续预测更准确，

那么：

```math
W_V
```

也会被对应调整。

经过大量训练以后：

```text
Q 越来越适合表达“我需要什么”

K 越来越适合表达“我是否值得被你找到”

V 越来越适合表达“你找到我后，我应该给你什么”
```

## 21. 最重要的一点：不是名字决定角色

不是因为我们把它叫：

```text

```

它才具有查询能力。

也不是因为我们把它叫：

```text

```

它才会成为键。

名字完全可以换。

真正决定角色的是：

```text
Q 所在的位置：
它拿去和所有 K 比较

它等待不同 Q 来匹配

V 所在的位置：
它真正进入加权求和并向后传递
```

所以真正的顺序是：

```math
\boxed{
\text{计算结构}
\rightarrow
\text{功能角色}
\rightarrow
\text{梯度下降}
\rightarrow
\text{学出对应表示}
}
```

## 26. 最后一句总结整个 Transformer

对于：

```text
浙江大学 软件学院 位于
```

模型并不是简单：

\[
\text{位于}\rightarrow\text{宁波}
\]

而是通过多层 Attention，不断让“位于”从前文读取信息，使最终：

\[
h_{\text{位于}}
=
f(
\text{浙江大学},
\text{软件学院},
\text{位于}
)
\]

然后才：

\[
h_{\text{位于}}
\rightarrow
P(\text{下一个 token})
\]

所以真正发生的是：

\[
\boxed{
\text{浙江大学 软件学院 位于}
\rightarrow
\text{宁波}
}
\]

而 Attention 最核心的工作，就是：

\[
\boxed{
让每一个 token 根据自己的需求，
动态决定应该从哪些历史 token 中读取多少信息。
}
\]

最终那个看起来非常抽象的公式：

\[
\boxed{
Attention(Q,K,V)
=
softmax
\left(
\frac{QK^T}{\sqrt{d_k}}+Mask
\right)V
}
\]

其实就是一句人话：

> **“我先提出我要找什么，用 Q 和大家的 K 比较，算出谁最重要，再按照重要程度读取大家真正携带的 V，最后把这些信息融合进我自己。”**

这就是 GPT 中 Attention 的核心。

## 27. 为什么 Attention Score 矩阵通常不是对称的？

在 Self-Attention 中，Attention Score 通常写成：

```math
S=\frac{QK^T}{\sqrt{d_k}}
```

其中：

```math
Q=XW_Q
```

```math
K=XW_K
```

假设一句话是：

```text
我 喜欢 苹果
```

Attention Score 矩阵可以表示为：

```text
              Key
            我   喜欢   苹果
Query  我     ?    ?      ?
      喜欢    ?    ?      ?
      苹果    ?    ?      ?
```

其中：

```math
S_{ij}=q_i\cdot k_j
```

因此：

```math
S_{\text{喜欢},\text{我}}
=
q_{\text{喜欢}}\cdot k_{\text{我}}
```

而：

```math
S_{\text{我},\text{喜欢}}
=
q_{\text{我}}\cdot k_{\text{喜欢}}
```

这两个值一般并不相等。

---


## 28. 从语义上为什么它们应该不一样？

真正理解 Attention 的关键，是不要把它简单理解成：

> 两个词有多相似。

Attention 更准确的含义是：

> **当前这个 token，需要从另一个 token 那里获取多少信息。**

也就是说：

```math
Attention(i,j)
```

可以粗略理解为：

> token `i` 站在自己的角度看，需要从 token `j` 那里取多少信息。

因此 Attention 天然具有方向性。

---

## 29. 举例：“喜欢 → 我”

还是这句话：

```text
我 喜欢 苹果
```

现在假设当前处理的是：

```text
喜欢
```

“喜欢”是一个动作。

为了理解这个动作，模型可能需要知道：

> 谁喜欢？

也就是需要寻找这个动作的执行者。

因此，“喜欢”的 Query 可以粗略理解成：

```text
我正在寻找：
谁是这个动作的执行者？
谁是主语？
谁做出了“喜欢”这个动作？
```

因此可以把：

```math
q_{\text{喜欢}}
```

理解为某种：

```text
“寻找动作主体”的查询需求
```

---

而“我”的 Key 可能包含这样的特征：

```text
我是一个人称代词
我可以充当主语
我可能是某个动作的执行者
```

因此：

```math
k_{\text{我}}
```

恰好能够很好地匹配：

```math
q_{\text{喜欢}}
```

所以：

```math
q_{\text{喜欢}}\cdot k_{\text{我}}
```

可能比较大。

也就是：

```text
喜欢 → 我
```

Attention 比较强。

可以把它理解成：

```text
“喜欢”问：

谁喜欢？

        ↓

“我”回答：

是我。
```

因此：

```text
喜欢  ───────→  我
      较强 Attention
```

---

## 30. 反过来：“我 → 喜欢”

现在把方向反过来。

当前处理的是：

```text
我
```

那么“我”的 Query 所表达的需求未必是：

> 我做了什么动作？

它可能更关心：

```text
我是谁？
我在句子中的角色是什么？
前面有没有修饰我的信息？
我是不是句子的主体？
```

所以：

```math
q_{\text{我}}
```

所表达的需求可能和：

```math
k_{\text{喜欢}}
```

并没有那么匹配。

于是：

```math
q_{\text{我}}\cdot k_{\text{喜欢}}
```

可能比较小。

也就是：

```text
我 → 喜欢
```

不一定很强。

---

## 31. 两个方向其实是在问两个完全不同的问题

### 31.1 喜欢 → 我

模型更像是在问：

```text
“喜欢”这个动作是谁做的？
```

答案：

```text
我
```

所以 Attention 可能很大。

---

#### 31.1.1 我 → 喜欢

模型更像是在问：

```text
对于“我”这个 token，
“喜欢”对理解当前的“我”到底有多重要？
```

答案可能是：

```text
有一定关系，但并不一定特别重要。
```

所以 Attention 可能较小。

---

因此：

```math
Attention(\text{喜欢},\text{我})
```

和：

```math
Attention(\text{我},\text{喜欢})
```

本来就是两个不同的问题。

没有理由要求：

```math
Attention(\text{喜欢},\text{我})
=
Attention(\text{我},\text{喜欢})
```

## 32. 为什么从数学上看它不一定对称？


在 Self-Attention 中：

```math
S=QK^T
```

其中：

```math
Q=XW_Q,\qquad K=XW_K
```

因此，对于第 \(i\) 个 token 和第 \(j\) 个 token：

```math
q_i=x_iW_Q
```

```math
k_i=x_iW_K
```

同理：

```math
q_j=x_jW_Q
```

```math
k_j=x_jW_K
```

---

## 33. 先看 \(S_{ij}\)

Attention Score 矩阵中的第 \(i\) 行、第 \(j\) 列为：

```math
S_{ij}=q_i k_j^T
```

把 \(q_i\) 和 \(k_j\) 代进去：

```math
S_{ij}
=
(x_iW_Q)(x_jW_K)^T
```

根据：

```math
(AB)^T=B^TA^T
```

有：

```math
(x_jW_K)^T=W_K^Tx_j^T
```

因此：

```math
\boxed{
S_{ij}
=
x_iW_QW_K^Tx_j^T
}
```

它表示：

> 第 \(i\) 个 token 的 Query，与第 \(j\) 个 token 的 Key 进行匹配。

也就是：

```text
i → j
```

---

## 34. 再看 \(S_{ji}\)

矩阵中与其对称的位置是：

```math
S_{ji}=q_jk_i^T
```

代入：

```math
S_{ji}
=
(x_jW_Q)(x_iW_K)^T
```

得到：

```math
S_{ji}
=
x_jW_QW_K^Tx_i^T
```

因为 \(S_{ji}\) 最终是一个标量，所以：

```math
S_{ji}=S_{ji}^T
```

因此：

```math
S_{ji}
=
(x_jW_QW_K^Tx_i^T)^T
```

利用：

```math
(AB)^T=B^TA^T
```

得到：

```math
\boxed{
S_{ji}
=
x_iW_KW_Q^Tx_j^T
}
```

它表示：

> 第 \(j\) 个 token 的 Query，与第 \(i\) 个 token 的 Key 进行匹配。

也就是：

```text
j → i
```

---

## 35. 把两者放在一起看

现在：

```math
\boxed{
S_{ij}
=
x_iW_QW_K^Tx_j^T
}
```

而：

```math
\boxed{
S_{ji}
=
x_iW_KW_Q^Tx_j^T
}
```

两者唯一关键的区别就在中间：

```math
W_QW_K^T
```

和：

```math
W_KW_Q^T
```

而：

```math
W_KW_Q^T
=
(W_QW_K^T)^T
```

所以，如果设：

```math
A=W_QW_K^T
```

那么：

```math
S_{ij}=x_iAx_j^T
```

而：

```math
S_{ji}=x_iA^Tx_j^T
```

---

## 36. 为什么两者一般不相等？

只有当：

```math
A=A^T
```

也就是：

```math
W_QW_K^T
=
W_KW_Q^T
```

时，两者才会相等。

但是一般情况下：

```math
\boxed{
W_QW_K^T
\neq
W_KW_Q^T
}
```

因此：

```math
\boxed{
S_{ij}\neq S_{ji}
}
```

所以 Attention Score：

```math
S=QK^T
```

一般不是对称矩阵。

---

## 37. 为什么 \(W_QW_K^T\) 和 \(W_KW_Q^T\) 不一样？

设：

```math
W_Q=
\begin{bmatrix}
a&b\\
c&d
\end{bmatrix}
```

```math
W_K=
\begin{bmatrix}
e&f\\
g&h
\end{bmatrix}
```

那么：

```math
W_QW_K^T
=
\begin{bmatrix}
ae+bf & ag+bh\\
ce+df & cg+dh
\end{bmatrix}
```

而：

```math
W_KW_Q^T
=
\begin{bmatrix}
ae+bf & ce+df\\
ag+bh & cg+dh
\end{bmatrix}
```

可以看到：

```math
\boxed{
W_KW_Q^T
=
(W_QW_K^T)^T
}
```

也就是说，两者是互为转置的。

但一个矩阵一般不等于自己的转置：

```math
A\neq A^T
```

除非它恰好是一个对称矩阵。

因此一般有：

```math
\boxed{
W_QW_K^T
\neq
W_KW_Q^T
}
```

最终导致：

```math
\boxed{
S_{ij}\neq S_{ji}
}
```

## 38. 最核心的逻辑

整个过程可以压缩成：

```math
S_{ij}
=
q_i k_j^T
=
(x_iW_Q)(x_jW_K)^T
=
x_iW_QW_K^Tx_j^T
```

而：

```math
S_{ji}
=
q_j k_i^T
=
(x_jW_Q)(x_iW_K)^T
=
x_iW_KW_Q^Tx_j^T
```

由于：

```math
\boxed{
W_QW_K^T
\neq
W_KW_Q^T
}
```

所以：

```math
\boxed{
S_{ij}\neq S_{ji}
}
```

因此：

```math
\boxed{
S=QK^T
}
```

一般不是对称矩阵。

只有特殊情况下，例如：

```math
Q=K
```

此时：

```math
S=QQ^T
```

才一定是对称矩阵。
