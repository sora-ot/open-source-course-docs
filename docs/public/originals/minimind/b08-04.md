## 1. GQA、Repeat 与 KV Cache：训练阶段和推理阶段到底分别怎么工作？

这里最容易混淆的是三个概念：

\[
\boxed{GQA}
\]

\[
\boxed{Repeat}
\]

\[
\boxed{KV\ Cache}
\]

它们之间有关系，但不是一回事。

最核心的一句话是：

> **GQA 和 Repeat 属于 Attention 本身的结构，因此训练和推理阶段都会存在；KV Cache 主要是自回归推理阶段为了避免重复计算历史 K/V 而使用的优化机制。**

---

## 2. 先假设一个 GQA

假设：

\[
N_Q=8
\]

也就是有 8 个 Query Head。

但是：

\[
N_{KV}=2
\]

也就是只有 2 个 KV Head。

因此：

\[
n_{rep}
=
\frac{N_Q}{N_{KV}}
=
\frac{8}{2}
=
4
\]

这表示：

> 每一个 KV Head 要被 4 个 Query Head 共享。

对应关系就是：

```text
Q0 Q1 Q2 Q3 → K0 / V0

Q4 Q5 Q6 Q7 → K1 / V1
```

所以：

\[
\boxed{
GQA 的本质：
多个 Query Head 共享一个 KV Head
}
\]

---

## 3. 训练阶段也会使用 GQA

假设训练序列是：

```text
I love AI very much
```

序列长度：

\[
L=5
\]

训练时不会一个 token 一个 token 地送进去，而是：

> **整个序列一次性送进 Transformer。**

因此模型一次性计算所有 token 的 Q、K、V。

Query 的形状：

\[
Q
\in
\mathbb{R}^{B\times L\times8\times d_{head}}
\]

而 K/V：

\[
K'
\in
\mathbb{R}^{B\times L\times2\times d_{head}}
\]

\[
V'
\in
\mathbb{R}^{B\times L\times2\times d_{head}}
\]

注意：

> 即使在训练阶段，模型真正生成的 KV Head 仍然只有 2 个，而不是 8 个。

也就是说：

```text
Q：

Q0
Q1
Q2
Q3
Q4
Q5
Q6
Q7


K/V：

K0 V0
K1 V1
```

---

## 4. 训练阶段仍然需要 Repeat

因为：

\[
Q
\]

有 8 个 Head，

但是：

\[
K,V
\]

只有 2 个 Head。

为了做 Attention，需要建立对应关系：

```text
Q0 → K0 / V0
Q1 → K0 / V0
Q2 → K0 / V0
Q3 → K0 / V0

Q4 → K1 / V1
Q5 → K1 / V1
Q6 → K1 / V1
Q7 → K1 / V1
```

所以训练时仍然存在：

\[
\boxed{Repeat}
\]

或者更准确地说：

\[
\boxed{KV\ Head\ Sharing / Mapping}
\]

有些代码会显式写：

```python
repeat_kv(k, n_rep=4)
repeat_kv(v, n_rep=4)
```

逻辑上变成：

```text
K0 K0 K0 K0 K1 K1 K1 K1

V0 V0 V0 V0 V1 V1 V1 V1
```

这样就可以与：

```text
Q0 Q1 Q2 Q3 Q4 Q5 Q6 Q7
```

一一对应。

---

## 5. 但是训练阶段通常不需要 KV Cache

这才是和推理阶段最大的区别。

推理阶段是逐 token 生成的。

例如第一轮：

```text
I love
```

模型计算：

```text
K_I
V_I

K_love
V_love
```

然后预测：

```text
AI
```

下一轮：

```text
I love AI
```

如果没有 KV Cache，就会重新计算：

```text
K_I
V_I

K_love
V_love
```

这显然是重复计算。

所以推理阶段会把历史 K/V 保存下来：

```text
KV Cache

I     → K_I,    V_I
love  → K_love, V_love
```

下一轮只计算新的：

```text
K_AI
V_AI
```

这就是 KV Cache。

---

## 6. 为什么训练阶段不需要这么做？

训练时，例如整个样本：

```text
I love AI very much
```

会一次性全部输入模型。

也就是说：

```text
I
love
AI
very
much
```

同时进入 Transformer。

模型一次 forward 就会得到：

\[
Q_I,Q_{love},Q_{AI},Q_{very},Q_{much}
\]

同时得到：

\[
K_I,K_{love},K_{AI},K_{very},K_{much}
\]

以及：

\[
V_I,V_{love},V_{AI},V_{very},V_{much}
\]

所以训练时根本不存在：

> 下一轮生成 AI 时，又重新计算 I 和 love 的 K/V。

因为训练不是这样逐 token forward 的。

训练是：

\[
\boxed{
\text{整段序列一次并行计算}
}
\]

因此不需要把上一“生成步”的 K/V 保存给下一步。

## 8. 训练阶段完整的数据流

假设：

\[
N_Q=8
\]

\[
N_{KV}=2
\]

整个流程可以写成：

```text
整个训练序列 X
        ↓
     RMSNorm
        ↓
 ┌──────┼──────┐
 ↓      ↓      ↓
W_Q    W_K    W_V
 ↓      ↓      ↓
8 Q     2 K     2 V
Heads   Heads   Heads
 ↓      ↓
Norm   Norm
 ↓      ↓
RoPE   RoPE
        ↓
Repeat / KV Head Mapping
        ↓
2 个 KV Head
服务 8 个 Query Head
        ↓
QK^T
        ↓
Causal Mask
        ↓
Softmax
        ↓
× V
        ↓
Attention Output
        ↓
后续网络
        ↓
Loss
        ↓
Backward
```

所以训练阶段：

\[
\boxed{
GQA\ 存在
}
\]

\[
\boxed{
Repeat\ 存在
}
\]

但是通常没有：

\[
\boxed{
跨生成步骤持续保存的 KV Cache
}
\]

## 9. 那训练时的 K/V 去哪里了？

训练时 K/V 当然也会暂时保存在显存中。

因为后面反向传播需要它们。

例如：

\[
O
=
Softmax(QK^T)V
\]

最后得到 Loss：

\[
\mathcal L
\]

反向传播时，需要计算：

\[
\frac{\partial\mathcal L}{\partial Q}
\]

\[
\frac{\partial\mathcal L}{\partial K}
\]

\[
\frac{\partial\mathcal L}{\partial V}
\]

然后继续求：

\[
\frac{\partial\mathcal L}{\partial W_Q}
\]

\[
\frac{\partial\mathcal L}{\partial W_K}
\]

\[
\frac{\partial\mathcal L}{\partial W_V}
\]

因此训练阶段的 Q/K/V 会作为：

\[
\boxed{Activation}
\]

暂时保存。

但这和：

\[
\boxed{KV\ Cache}
\]

不是一回事。

---

## 10. Activation 和 KV Cache 有什么区别？

训练阶段：

\[
\boxed{
Q/K/V 是为了反向传播而暂时保存的 Activation
}
\]

流程：

```text
Forward
   ↓
保存部分 Activation
   ↓
Loss
   ↓
Backward
   ↓
Optimizer.step()
   ↓
这批数据的 Activation 可以释放
```

下一批数据会重新计算。

---

推理阶段：

\[
\boxed{
K/V 是为了下一次生成继续使用而保存的 Cache
}
\]

流程：

```text
生成 token 1
   ↓
K/V 保存

生成 token 2
   ↓
历史 K/V 继续保存

生成 token 3
   ↓
历史 K/V 继续保存

...
```

所以：

| 对比 | 训练 | 自回归推理 |
|---|---|---|
| Q/K/V 是否计算 | 是 | 是 |
| GQA 是否存在 | 是 | 是 |
| Repeat 是否存在 | 是 | 是 |
| K/V 是否参与反向传播 | 是 | 否 |
| 是否跨生成步骤保存历史 K/V | 通常否 | 是 |
| 保存 K/V 的主要目的 | Backward | 避免重复计算 |

---

## 11. Repeat 在训练时怎么反向传播？

这是 GQA 一个非常重要的地方。

假设：

```text
Q0 Q1 Q2 Q3
      ↓
共享 K0 / V0
```

正向传播：

\[
O_0
=
Attention(Q_0,K_0,V_0)
\]

\[
O_1
=
Attention(Q_1,K_0,V_0)
\]

\[
O_2
=
Attention(Q_2,K_0,V_0)
\]

\[
O_3
=
Attention(Q_3,K_0,V_0)
\]

虽然它们共享同一个：

\[
K_0,V_0
\]

但是这四个 Query Head 都会对共享的 K/V 产生梯度。

反向传播时：

\[
\frac{\partial\mathcal L}{\partial K_0}
\]

会接收所有共享 Query Head 的梯度贡献。

可以粗略写成：

\[
\boxed{
\frac{\partial\mathcal L}{\partial K_0}
=
\frac{\partial\mathcal L_0}{\partial K_0}
+
\frac{\partial\mathcal L_1}{\partial K_0}
+
\frac{\partial\mathcal L_2}{\partial K_0}
+
\frac{\partial\mathcal L_3}{\partial K_0}
}
\]

同样：

\[
\boxed{
\frac{\partial\mathcal L}{\partial V_0}
=
\frac{\partial\mathcal L_0}{\partial V_0}
+
\frac{\partial\mathcal L_1}{\partial V_0}
+
\frac{\partial\mathcal L_2}{\partial V_0}
+
\frac{\partial\mathcal L_3}{\partial V_0}
}
\]

所以：

> 一个 KV Head 虽然被多个 Query Head 共享，但是训练时它会吸收多个 Query Head 的共同学习信号。

## 12. 如果代码用 expand()，梯度怎么办？

例如：

```python
K_repeat = K.expand(...)
```

逻辑上：

```text
K0
K0
K0
K0
```

这四个位置实际上都来自同一个：

\[
K_0
\]

PyTorch Autograd 会自动处理。

反向传播时：

```text
Q0 → loss0 ─┐
Q1 → loss1 ─┤
Q2 → loss2 ─┼──→ K0
Q3 → loss3 ─┘
```

多个分支的梯度会自动累加回原始：

\[
K_0
\]

所以不需要人工处理。

这就是共享参数、共享张量在自动微分中的正常机制。

## 13. 为什么训练不采用推理那种逐 token + KV Cache？

因为训练最重要的是：

\[
\boxed{
并行
}
\]

假设序列长度：

\[
L=4096
\]

如果像推理一样：

```text
token 1
   ↓
token 2
   ↓
token 3
   ↓
...
   ↓
token 4096
```

逐个 forward，

那么 GPU 的并行能力就无法充分利用。

训练真正做的是：

```text
4096 个 token
      ↓
一次全部送入 GPU
      ↓
一次性生成全部 Q/K/V
      ↓
一次性计算完整的 Causal Attention
```

所以训练时：

\[
\boxed{
\text{序列维度可以并行}
}
\]

而推理时：

\[
x_{t+1}
\]

没有生成出来之前，

模型根本不知道下一步输入是什么。

所以推理必须：

```text
生成一个 token
↓
再生成下一个
↓
再生成下一个
```

因此才需要：

\[
\boxed{KV\ Cache}
\]

## 15. GQA 对训练阶段有什么收益？

虽然训练阶段通常不用 KV Cache，

但 GQA 仍然可以减少 K/V 相关参数和计算。

例如 MHA：

\[
N_Q=32
\]

\[
N_{KV}=32
\]

而 GQA：

\[
N_Q=32
\]

\[
N_{KV}=8
\]

假设：

\[
d_{head}=128
\]

那么 MHA 中：

\[
W_K
\]

输出维度为：

\[
32\times128
=
4096
\]

而 GQA 中：

\[
W_K
\]

只需要输出：

\[
8\times128
=
1024
\]

所以：

\[
W_K
\]

和：

\[
W_V
\]

的参数量都会更小。

因此训练时也能减少一部分：

- 参数量
- K/V Projection 计算
- Activation 大小
- 显存占用

---

## 16. GQA 对推理阶段的收益更明显

推理阶段最重要的收益是：

\[
\boxed{
KV\ Cache\ 更小
}
\]

如果：

\[
N_Q=32
\]

传统 MHA：

\[
N_{KV}=32
\]

而 GQA：

\[
N_{KV}=8
\]

那么 KV Cache 大约变成：

\[
\frac{8}{32}
=
\frac14
\]

也就是：

\[
25\%
\]

所以理论上对应的 KV Cache 可以减少：

\[
75\%
\]

因此：

\[
\boxed{
GQA
\rightarrow
KV\ Head减少
\rightarrow
KV\ Cache减少
\rightarrow
推理显存与访存开销降低
}
\]

## 17. GQA 训练过程中 `repeat` 是如何参与反向传播和求导的？

---

## 18. 先明确我们到底在研究什么

假设一个 GQA 模型有：

```math
n_q = 4
```

个 Query Head，但是只有：

```math
n_{kv}=2
```

个 KV Head。

因此：

```math
n_{\text{rep}}
=
\frac{n_q}{n_{kv}}
=
\frac42
=
2
```

也就是说：

> 每一个 K/V Head 要给两个 Query Head 使用。

结构是：

```text
Q1 ─┐
    ├── K1, V1
Q2 ─┘

Q3 ─┐
    ├── K2, V2
Q4 ─┘
```

---

## 19. 为什么代码里会出现 repeat？

假设经过线性投影以后：

```text
Query：

Q1
Q2
Q3
Q4
```

一共有 4 个 Query Head。

但是 Key 只有：

```text
K1
K2
```

Value 只有：

```text
V1
V2
```

如果代码要使用普通的多头 Attention 形式：

```math
Q^{(h)}K^{(h)T}
```

那么 Query Head 和 KV Head 数量需要对得上。

于是代码把：

```text
K1
K2
```

变成：

```text
K1
K1
K2
K2
```

Value 同样：

```text
V1
V1
V2
V2
```

这就是所谓：

```python
repeat_kv(...)
```

于是前向传播看起来变成：

```text
Q1 → K1, V1

Q2 → K1, V1

Q3 → K2, V2

Q4 → K2, V2
```

---

## 20. 最关键的一点：repeat 不是产生了新的可训练 K

这里特别容易误解。

经过：

```text
K1
↓ repeat
K1a
K1b
```

以后，不要理解成：

```text
K1a 是一套新的参数

K1b 又是一套新的参数
```

实际上：

```math
K_{1a}=K_1
```

```math
K_{1b}=K_1
```

它们都来自**同一个原始 K1**。

只是前向计算时：

```text
同一个 K1

同时被 Head 1 使用
同时被 Head 2 使用
```

所以更准确应该画成：

```text
                  ┌──→ Head 1
K1 ───────────────┤
                  └──→ Head 2
```

而不是：

```text
K1 → 复制一个新的可训练 K1a
K1 → 再复制一个新的可训练 K1b
```

---

## 21. repeat 本身没有任何参数

这一点非常重要。

例如：

```python
k = repeat_kv(k, n_rep=2)
```

`repeat` 本身没有：

```text
weight
bias
```

也没有什么需要学习的参数。

它本质上只是一个张量操作：

```text
输入：

[K1, K2]

↓

repeat

输出：

[K1, K1, K2, K2]
```

所以训练真正需要学习的仍然是：

```math
W_K
```

以及：

```math
W_V
```

而不是：

```text
repeat
```

为了把问题讲透，我们暂时只看：

```text
Q1
Q2
```

共享：

```text
K1
V1
```

也就是：

```text
             ┌── Q1
K1, V1 ──────┤
             └── Q2
```

前向传播：

### 22.1 Head 1

```math
S_1
=
Q_1K_1^T
```

经过 Softmax：

```math
A_1

\operatorname{softmax}(S_1)
```

然后：

```math
O_1
=
A_1V_1
```

### 22.2 Head 2

同一个：

```math

```

和：

```math
V_1
```

又被 Head 2 使用：

```math
S_2
```

```math
\operatorname{softmax}(S_2)
```

```math
O_2
```

## 23. 最终 Loss 同时依赖 O1 和 O2

假设所有 Head 的结果最后经过：

```text
Concat
↓
W_O
↓
后续网络
↓
Cross Entropy
```

得到：

```math
L
```

那么：

```math
L
```

同时依赖：

```math
O_1
```

和：

```math
O_2
```

也就是说：

```text
               O1 ───┐
                     ├──→ 最终 Loss
               O2 ───┘
```

反向传播时：

```text
Loss
 ↓
 ├──→ O1
 │
 └──→ O2
```

于是两个 Head 都会产生自己的梯度。

## 24. 先看 V1 的梯度

我们有：

```math
O_1=A_1V_1
```

以及：

```math
O_2=A_2V_1
```

注意：

> 两个式子里出现的是同一个 \(V_1\)。

因此 Loss 对 \(V_1\) 的梯度，必须考虑两条路径。

也就是：

```math
\frac{\partial L}{\partial V_1}
=
\frac{\partial L}{\partial O_1}
\frac{\partial O_1}{\partial V_1}
+
\frac{\partial L}{\partial O_2}
\frac{\partial O_2}{\partial V_1}
```

因为：

```math
O_1=A_1V_1
```

所以：

```math
\frac{\partial O_1}{\partial V_1}
```

对应：

```math
A_1
```

而：

```math
O_2=A_2V_1
```

对应：

```math
A_2
```

因此可以粗略写成：

```math
\boxed{
\frac{\partial L}{\partial V_1}
=
A_1^T
\frac{\partial L}{\partial O_1}
+
A_2^T
\frac{\partial L}{\partial O_2}
}
```

最重要的是这里的：

```math
+
```

也就是说：

> **两个 Query Head 对同一个 V Head 的梯度，会加起来。**

```text
            O1        O2
```

所以：

```math
\boxed{

\nabla V_{1,\text{from Head2}}
}
```

## 26. repeat 在这个过程中到底干了什么？

假设代码前向传播的时候先：

```text
原始 V：

[V1, V2]
```

然后：

```python
repeat_kv(V)
```

得到：

```text
[V1a, V1b, V2a, V2b]
```

其中：

```math
V_{1a}=V_1
```

```math
V_{1b}=V_1
```

Head 1 使用：

```text
V1a
```

Head 2 使用：

```text
V1b
```

反向传播时，假设得到：

```math
\frac{\partial L}{\partial V_{1a}}
=
G_a
```

以及：

```math
\frac{\partial L}{\partial V_{1b}}
=
G_b
```

那么 `repeat` 的 backward 做的事情就是：

```math
\boxed{
\frac{\partial L}{\partial V_1}
=
G_a+G_b
}
```

也就是说：

```text
前向：

            V1
           /  \
          ↓    ↓
        V1a   V1b


反向：

        Ga     Gb
          \   /
           \ /
            ↓
         Ga + Gb
            ↓
           V1
```

## 27. 这是理解 repeat 求导最核心的一条公式

假设：

```math
y_1=x
```

```math
y_2=x
```

也就是：

```text
x
↓ repeat
[x, x]
```

Loss：

```math
L=L(y_1,y_2)
```

因为：

```math
y_1=x
```

并且：

```math
y_2=x
```

根据链式法则：

```math
\frac{\partial L}{\partial x}
=
\frac{\partial L}{\partial y_1}
\frac{\partial y_1}{\partial x}
+
\frac{\partial L}{\partial y_2}
\frac{\partial y_2}{\partial x}
```

而：

```math
\frac{\partial y_1}{\partial x}=1
```

```math
\frac{\partial y_2}{\partial x}=1
```

所以：

```math
\boxed{
\frac{\partial L}{\partial x}
=
\frac{\partial L}{\partial y_1}
+
\frac{\partial L}{\partial y_2}
}
```

这就是：

## 28. repeat 的反向传播本质

## 31. 暂时忽略 Softmax，可以更容易看出来

```math
S_1=Q_1K_1^T
```

Loss 对：

```math
S_1
```

传回一个梯度：

```math
G_1
=
\frac{\partial L}{\partial S_1}
```

那么：

```math
\frac{\partial L}{\partial K_1}
\bigg|_{\text{Head 1}}
=
G_1^TQ_1
```

同样 Head 2：

```math
G_2
=
\frac{\partial L}{\partial S_2}
```

产生：

```math
\frac{\partial L}{\partial K_1}
\bigg|_{\text{Head 2}}
=
G_2^TQ_2
```

因为两个 Head 使用的是同一个：

```math
K_1
```

所以最终：

```math

+
```

## 32. Softmax 并不会改变这个“梯度相加”的原则

真实 Attention 当然还有：

```math
A_1
=
\operatorname{softmax}
\left(
\frac{Q_1K_1^T}{\sqrt{d}}
\right)
```

以及：

```math
A_2
=
\operatorname{softmax}
\left(
\frac{Q_2K_1^T}{\sqrt{d}}
\right)
```

Softmax 只是让：

```text
Loss
↓
O
↓
A
↓
S
↓
K
```

这条链更复杂。

但是最终仍然存在两条路径：

```text
                        ┌── Head 1 ──→ Loss
K1 ────────────────────┤
                        └── Head 2 ──→ Loss
```

因此链式法则一定得到：

```math
\boxed{
\frac{\partial L}{\partial K_1}
=
\left(
\frac{\partial L}{\partial K_1}
\right)_{\text{Head 1}}
+
\left(
\frac{\partial L}{\partial K_1}
\right)_{\text{Head 2}}
}
```

## 33. Query 的梯度为什么不会这样合并？

因为：

```text
Q1
```

和：

```text
Q2
```

本身就是两个独立 Query Head。

所以：

```text
Q1 → Head 1
```

以及：

```text
Q2 → Head 2
```

它们不是 repeat 出来的。

因此：

```math
\nabla Q_1
```

只沿 Head 1 回去。

而：

```math
\nabla Q_2
```

只沿 Head 2 回去。

结构：

```text
Q1 → Head1 → Loss
Q2 → Head2 → Loss
```

所以：

```text
Q1 有自己的梯度

Q2 有自己的梯度
```

不会先相加成一个 Query Head。

---

## 34. 这正是 GQA 和 MHA 训练上的核心区别之一

### 34.1 MHA

假设：

```text
Q1 → K1,V1

Q2 → K2,V2
```

那么：

```text
K1 只接收来自 Head 1 的梯度

K2 只接收来自 Head 2 的梯度
```

也就是：

```math
\nabla K_1
=
\nabla K_{1,\text{Head1}}
```

```math
\nabla K_2
=
\nabla K_{2,\text{Head2}}
```

---

### 34.2 GQA

变成：

```text
Q1 ─┐
    ├→ K1,V1
Q2 ─┘
```

那么：

```math
\nabla K_1
=
\nabla K_{1,\text{Head1}}
+
\nabla K_{1,\text{Head2}}
```

以及：

```math
\nabla V_1
=
\nabla V_{1,\text{Head1}}
+
\nabla V_{1,\text{Head2}}
```

这就是共享参数最典型的反向传播方式。

## 35. 但是 K1 本身也不是参数，它是 W_K 算出来的

这个地方还要再向前走一步。

真正被 optimizer 更新的并不是：

```math
K_1
```

本身。

而是：

```math
W_K
```

因为：

```math
K=XW_K
```

在 GQA 中，例如：

```math
W_K
```

只生成 2 个 KV Head。

假设：

```math
d_{\text{head}}=128
```

那么：

```math
W_K
\in
\mathbb R^{d_{\text{model}}\times(2\times128)}
```

先得到：

```text
K1
K2
```

然后才：

```text
K1 → repeat → Head 1、Head 2

K2 → repeat → Head 3、Head 4
```

## 36. 梯度如何最终回到 W_K？

完整链路：

```text
Loss
 ↓
Head 1        Head 2
 ↓               ↓
K1a            K1b
  \             /
   \           /
    梯度相加
       ↓
      K1
       ↓
      W_K
```

数学上：

```math
K_1=XW_K^{(1)}
```

所以：

```math
\frac{\partial L}{\partial W_K^{(1)}}
=
X^T
\frac{\partial L}{\partial K_1}
```

但是我们前面已经知道：

```math
\frac{\partial L}{\partial K_1}
=
G_{K1,\text{Head1}}
+
G_{K1,\text{Head2}}
```

所以：

```math
\boxed{
\frac{\partial L}{\partial W_K^{(1)}}
=
X^T
\left(
G_{K1,\text{Head1}}
+
G_{K1,\text{Head2}}
\right)
}
```

这才是真正 optimizer 最终用到的梯度。

## 37. W_V 完全同样

对于：

```math
V_1=XW_V^{(1)}
```

Head 1 和 Head 2 都使用这个 V：

```text
Head 1 → V1

Head 2 → V1
```

所以：

```math
\frac{\partial L}{\partial V_1}
=
G_{V1,\text{Head1}}
+
G_{V1,\text{Head2}}
```

然后：

```math
\boxed{
\frac{\partial L}{\partial W_V^{(1)}}
=
X^T
\left(
G_{V1,\text{Head1}}
+
G_{V1,\text{Head2}}
\right)
}
```

因此：

> 一个 KV Head 会根据它所服务的多个 Query Head 的共同需求进行训练。

## 38. 这其实解释了“共享 K/V 是怎么训练出来的”

很多人会有一个疑惑：

> Q1 和 Q2 需求不一样，共享 K1，K1 到底听谁的？

答案就是：

> **两个都听。**

因为：

```math
\nabla K_1
=
\nabla K_{1,\text{Head1}}
+
\nabla K_{1,\text{Head2}}
```

所以 K1 会朝着：

```text
同时有利于 Head 1
+
同时有利于 Head 2
```

的方向更新。

可以粗略理解成：

```text
Q1 告诉 K1：
“你这样表示对我更有用。”

Q2 也告诉 K1：
“我希望你这样表示。”

        ↓

两个梯度合并

        ↓

K1 的参数寻找一个
同时服务这一组 Query Head 的表示方式
```

这就是：

## 39. Grouped Query Attention 中“Grouped”的训练含义

## 40. 从单头 Attention 到 MQA：KV Cache、显存与表达能力详解

## 41. 先统一模型参数

为了方便理解，假设一个 Transformer 模型的：

```text
hidden_size = 4096
num_query_heads = 32
head_dim = 128
```

因为：

```math
32 \times 128 = 4096
```

也就是说，一个 token 的 hidden state 是：

```math
x\in\mathbb{R}^{4096}
```

后面我们比较：

1. 最早的单头 Attention
2. MHA
3. GQA
4. MQA

最重要的是分清：

```text
hidden size
```

和：

```text
单个 Attention Head 的维度
```

不是一回事。

---

## 42. 最早的单头 Attention 是什么？

最简单的 Self-Attention 中，只有：

```text
1 个 Query Head
1 个 Key Head
1 个 Value Head
```

输入：

```math
x\in\mathbb{R}^{4096}
```

经过：

```math
Q=xW_Q
```

```math
K=xW_K
```

```math
V=xW_V
```

得到：

```math
Q,K,V\in\mathbb{R}^{4096}
```

因此：

```text
Hidden State
4096维
   │
   ├── WQ → Q：4096维
   │
   ├── WK → K：4096维
   │
   └── WV → V：4096维
```

所以传统单头 Attention 中，一个 K 本身就是：

```math
4096\text{维}
```

一个 V 也是：

```math
4096\text{维}
```

---

## 43. 单头 Attention 不等于 MQA

这是非常容易混淆的一点。

因为：

```text
单头 Attention：
只有一个 K Head 和一个 V Head
```

而：

```text
MQA：
也只有一个 K Head 和一个 V Head
```

但它们并不是同一个东西。

真正区别在于 Query。

---

### 43.1 单头 Attention

```text
Q Head：1个
K Head：1个
V Head：1个
```

而且：

```text
Q：4096维
K：4096维
V：4096维
```

因此：

```math
\boxed{\text{Single Head}=1Q+1K+1V}
```

---

### 43.2 MQA

MQA 全称：

```text
Multi-Query Attention
```

关键词就是：

```text
Multi-Query
```

它有很多 Query Head。

例如：

```text
32 个 Query Head
```

但所有 Query Head 共用：

```text
1 个 K Head
1 个 V Head
```

因此：

```math
\boxed{\text{MQA}=32Q+1K+1V}
```

所以判断是不是 MQA 的关键不是：

> 是不是只有一个 K/V。

而是：

> **是不是多个 Query Head 共享同一组 K/V。**

---

## 44. 为什么 MQA 的 K/V 不是 4096 维？

这也是最关键的一个问题。

可能第一反应是：

> hidden size 明明是 4096，MQA 虽然只有一个 K/V，难道这个 K/V 不也是 4096 维吗？

答案是：

> **不是。**

因为 MQA 建立在多头 Attention 的结构之上。

我们有：

```text
32 个 Query Head
```

每个 Head：

```math
d_{head}=128
```

所以：

```math
32\times128=4096
```

Query 总宽度仍然是 4096：

```math
Q\in\mathbb{R}^{32\times128}
```

但是 K/V 只有一个 Head，所以：

```math
K\in\mathbb{R}^{1\times128}
```

```math
V\in\mathbb{R}^{1\times128}
```

也就是：

```text
Hidden State
4096维
   │
   ├──────── WQ ────────→ 4096维
   │                       ↓
   │                   32 × 128
   │
   ├──────── WK ────────→ 128维
   │                       ↓
   │                   1个 K Head
   │
   └──────── WV ────────→ 128维
                           ↓
                       1个 V Head
```

所以：

```math
\boxed{\text{MQA 中单个 K/V Head 只有 }128\text{ 维}}
```

而不是 4096 维。

---

## 45. 为什么 KV Cache 因此变小？

KV Cache 保存的不是：

```text
4096维的原始 hidden state
```

而是 Attention 投影以后得到的：

```text
K
V
```

---

### 45.1 单头 Attention

每个 token：

```math
K\in\mathbb{R}^{4096}
```

```math
V\in\mathbb{R}^{4096}
```

所以一个 token 需要缓存：

```math
4096+4096=8192
```

个数。

---

### 45.2 MQA

每个 token：

```math
K\in\mathbb{R}^{128}
```

```math
V\in\mathbb{R}^{128}
```

所以只需要缓存：

```math
128+128=256
```

个数。

因此：

```math
\frac{8192}{256}=32
```

也就是说：

```math
\boxed{\text{MQA 的 KV Cache 只有传统 4096 维单头的 }1/32}
```

---

## 46. MHA 又是什么情况？

MHA：

```text
Multi-Head Attention
```

拥有：

```text
32 个 Q Head
32 个 K Head
32 个 V Head
```

每个 Head 是：

```math
128\text{维}
```

所以：

```math
Q:
32\times128=4096
```

```math
K:
32\times128=4096
```

```math
V:
32\times128=4096
```

因此虽然每个 K Head 只有 128 维，但总共有 32 个：

```math
32\times128=4096
```

所以 MHA 每个 token 的 KV Cache：

```math
4096+4096=8192
```

个数。

和传统 4096 维单头 Attention 在这个例子里的 KV 总宽度是一样的。

---

## 47. GQA 是什么？

GQA：

```text
Grouped Query Attention
```

是 MHA 和 MQA 之间的折中。

例如：

```text
Query Head = 32
KV Head = 8
```

那么：

```math
Q:
32\times128=4096
```

而：

```math
K:
8\times128=1024
```

```math
V:
8\times128=1024
```

也就是说：

```text
32个 Query Head
分成8组

每4个 Query Head
共享一套 K/V
```

---

## 48. 四种结构放在一起

可以直接记成：

```text
传统单头 Attention
────────────────────
Q：1 × 4096
K：1 × 4096
V：1 × 4096
```

---

```text
MHA
────────────────────
Q：32 × 128
K：32 × 128
V：32 × 128
```

---

```text
GQA
────────────────────
Q：32 × 128
K：8 × 128
V：8 × 128
```

---

```text
MQA
────────────────────
Q：32 × 128
K：1 × 128
V：1 × 128
```

所以可以总结为：

| 方法           | Q Heads | KV Heads | 每个 Head 维度 | K 总宽度 | V 总宽度 |
| ------------ | ------: | -------: | ---------: | ----: | ----: |
| 单头 Attention |       1 |        1 |       4096 |  4096 |  4096 |
| MHA          |      32 |       32 |        128 |  4096 |  4096 |
| GQA          |      32 |        8 |        128 |  1024 |  1024 |
| MQA          |      32 |        1 |        128 |   128 |   128 |

---

## 49. 那 MQA 的 K/V 只有 128 维，信息量不是比传统单头小很多吗？

如果只看：

```text
单个 token 的 K/V 表示容量
```

答案确实是：

```math
\boxed{\text{是的}}
```

传统单头：

```math
K,V\in\mathbb{R}^{4096}
```

MQA：

```math
K,V\in\mathbb{R}^{128}
```

从 4096 压缩到了 128。

也就是说：

> MQA 的共享 K/V 表示确实进行了非常强的压缩。

因此 MQA 是用一部分 K/V 表达能力来换取更低的 KV Cache 显存。

---

## 50. 那为什么 MQA 还可以工作？

因为 MQA 虽然只有一套 K/V：

```text
1个 K
1个 V
```

但它仍然保留：

```text
32个不同的 Query Head
```

也就是：

```math
Q^{(1)},Q^{(2)},\ldots,Q^{(32)}
```

这些 Query 是不同的。

所以：

```math
Q^{(1)}K^T
```

和：

```math
Q^{(2)}K^T
```

得到的 Attention Score 可以完全不同。

得到：

### 51.2 Head 2

可能关注：


得到：

```math

\boxed{\text{MQA 仍然可以产生很多种不同的 Attention Pattern}}
```

## 52. 单头 Attention 的一个重要限制

传统单头虽然：

```math
K,V\in\mathbb{R}^{4096}
```

信息非常宽。

但是它只有：

```text
一个 Query Head
```

所以对于当前 token，只能产生：

```text
一套 Attention 权重
```

例如：

```text
小明：0.10
苹果：0.05
小红：0.75
因为：0.05
其他：0.05
```

然后：

```math

0.10V_{\text{小明}}
+
0.05V_{\text{苹果}}
+
0.75V_{\text{小红}}
+\cdots
```

注意：

> 虽然每个 V 有 4096 维，但是这 4096 个维度共享的是同一套 Attention 权重。

也就是说：

```text
只有一种“怎么看这些历史 token”的方式
```

### 54.1 单头

```text
KV表示能力：
```

### 54.2 MQA

```text
比较窄
```

## 55. 为什么 MQA 最终输出仍然是 4096 维？

这是另一个非常容易误解的问题。

MQA 的：

```math
V\in\mathbb{R}^{128}
```

是不是意味着最终 Attention 只能输出 128 维？

不是。

因为每一个 Query Head 都会产生一个自己的输出。

第一个 Head：

```math
O^{(1)}
=
\sum_j
\alpha_j^{(1)}V_j
```

第二个 Head：

```math
O^{(2)}
=
\sum_j
\alpha_j^{(2)}V_j
```

……

第 32 个 Head：

```math
O^{(32)}
=
\sum_j
\alpha_j^{(32)}V_j
```

每一个：

```math
O^{(i)}\in\mathbb{R}^{128}
```

一共有 32 个。

所以把它们拼起来：

```math
O=
Concat(
O^{(1)},
O^{(2)},
\ldots,
O^{(32)}
)
```

得到：

```math
O\in\mathbb{R}^{32\times128}
```

即：

```math
O\in\mathbb{R}^{4096}
```

因此：

```math
\boxed{\text{MQA 最终 Attention 输出仍然可以是4096维}}
```

## 56. 为什么共享 V，还能产生不同输出？

因为虽然大家读取的是同样的：

```math
V_1,V_2,V_3
```

但是每个 Head 的 Attention 权重不同。

例如：

```math
O_1
=
0.8V_1
+
0.1V_2
+
0.1V_3
```

第二个 Head：

```math
O_2
=
0.1V_1
+
0.8V_2
+
0.1V_3
```

第三个 Head：

```math
O_3
=
0.1V_1
+
0.1V_2
+
0.8V_3
```

虽然它们使用的是同一套：

```math
V_1,V_2,V_3
```

但由于权重不同：

```math
O_1\neq O_2\neq O_3
```

所以仍然可以产生大量不同的信息组合。

## 59. 为什么 Q 还是 4096 维，却不会把显存重新吃回来？

因为：

```text
Q 一般不需要长期缓存
```

自回归生成过程中，真正需要保存历史信息的是：

```text
K Cache
V Cache
```

例如现在生成第 1000 个 token。

当前 token 会生成：

```text
当前 Q
当前 K
当前 V
```

为了计算当前 token 对历史 token 的 Attention，需要历史的：

```text
K1,K2,...,K999
```

以及：

```text
V1,V2,...,V999
```

但是不需要：

```text
Q1,Q2,...,Q999
```

因为过去的 Query 只负责回答过去那个时刻的问题。

例如：

```text
Q500
```

负责的是：

> 第500个 token 当时应该关注前面的哪些 token？

这个问题早就在生成第 500 个 token 时完成了。

第 1000 个 token 到来以后，需要的是：

```text
Q1000
```

去读取：

```text
K1...K1000
```

所以：

```math
\boxed{\text{KV Cache增长，Q不需要跟着长期增长}}
```

这也是为什么 MQA 可以显著降低推理显存。

## 60. MQA 中是不是要把 K/V repeat 31 次？

假设：

```text
Query Head = 32
KV Head = 1
```

那么从**计算逻辑上**来看：

> 是的。

原本有一份：

```text
K
V
```

但有 32 个 Query Head：

```text
Q1
Q2
Q3
...
Q32
```

所以这一份 K/V 要供全部 32 个 Query Head 使用。

可以画成：

```text
                    Q1
                     │
                    K/V

                    Q2
                     │
                    K/V

                    Q3
                     │
                    K/V

                    ...

                    Q32
                     │
                    K/V
```

也就是：

```text
原本1份
+
逻辑上再重复31份
=
32份
```

所以如果只是为了理解：

```math
\boxed{\text{可以理解成 repeat 31 次}}
```

## 61. 从 Tensor Shape 上怎么理解 repeat？

原来的 K：

```text
K shape：

[B, 1, L, 128]
```

其中：

```text
B：
batch size

1：
只有一个 KV Head

L：
序列长度

128：
head_dim
```

而 Query：

```text
Q shape：

[B, 32, L, 128]
```

为了做 Attention，可以逻辑上把 K 变成：

```text
[B, 32, L, 128]
```

也就是：

```text
K1 = K
K2 = K
K3 = K
...
K32 = K
```

V 同理。

## 62. 但实际 KV Cache 不会真的复制 31 份

这一点非常关键。

如果把：

```text
K
```

真正复制 32 份存起来：

```text
K1
K2
...
K32
```

那不就又回到了：

```text
32 × 128 = 4096
```

这样 MQA 就失去节省 KV Cache 的意义了。

因此：

> **KV Cache 本身始终只保存一份 K/V。**

例如：

```text
显存中的 KV Cache：

K：[128维]
V：[128维]
```

然后：

```text
Q1 ─┐
Q2 ─┤
Q3 ─┤
... │──→ 共同读取这一份 K/V
Q32─┘
```

所以更准确的说法是：

```math
\boxed{\text{逻辑上 repeat，物理存储上通常不复制}}
```

## 63. repeat 和真正复制的区别

概念上可以写：

```python
K_repeat = repeat(K, 32)
```

看起来变成：

```text
[K,K,K,...,K]
```

32份。

但是高效实现中不一定真的复制数据。

可以通过：

```text
broadcast
expand
专门的 Attention kernel
```

让 32 个 Query Head 都直接访问同一份 K/V。

因此：

```text
逻辑 Shape：

32 × 128
```

不代表：

```text
物理显存：

真的保存了32份128
```

## 64. 为什么 repeat 后反向传播仍然能训练共享 K/V？

假设只有两个 Query Head，为了简单理解：

```text
Q1
Q2
```

都读取同一个：

```text
K
```

于是计算图类似：

```text
             K
           /   \
          /     \
        Q1       Q2
         │        │
       Loss1    Loss2
```

虽然逻辑上：

```text
K被使用了两次
```

但它们最终连接回的是：

```text
同一个 K
```

所以反向传播时：

```math
\frac{\partial L}{\partial K}
=
\frac{\partial L_1}{\partial K}
+
\frac{\partial L_2}{\partial K}
```

如果 32 个 Query Head：

```math
\frac{\partial L}{\partial K}
=
\sum_{h=1}^{32}
\frac{\partial L_h}{\partial K}
```

V 同理。

也就是说：

> 32 个 Query Head 都会帮助训练这同一套共享的 K/V 表示。

可以理解成：

> 一块共享矩阵，同时接出了 32 条计算路径；反向传播时，32 条路径的梯度最终汇总回来。

## 65. 为什么后来会出现 GQA？

现在整个逻辑就很自然了。

---

### 65.1 单头 Attention

```text
1个 Q
1个 K
1个 V

每个都是4096维
```

优点：

```text
单个 K/V 表达非常宽
```

缺点：

```text
只有一套 Attention Pattern
KV Cache 很大
```

---

### 65.2 MHA

为了让模型从多个角度关注信息：

```text
32个 Q
32个 K
32个 V

每个128维
```

这样：

```text
Head1有自己的Q/K/V
Head2有自己的Q/K/V
...
Head32有自己的Q/K/V
```

表达能力很强。

但是：

```math
32\times128=4096
```

所以总 K/V 宽度还是：

```text
4096维
```

KV Cache 没有减少。

---

### 65.3 MQA

于是进一步想到：

> Query 保留 32 个，但是 K/V 只留一套。

于是：

```text
32个Q
1个K
1个V
```

这样 KV Cache 从：

```text
4096维
```

缩到：

```text
128维
```

非常省显存。

但是问题也出现了：

> 32 个 Query Head 必须共享同一套 K/V，压缩得太激进。

---

### 65.4 GQA

所以再折中一下：

```text
32个 Query Head
8个 KV Head
```

也就是：

```text
Q1~Q4    → KV1
Q5~Q8    → KV2
Q9~Q12   → KV3
...
Q29~Q32  → KV8
```

这样：

```text
比 MHA 更省 KV Cache
```

同时：

```text
比 MQA 保留更多独立的 K/V 表达
```

所以 GQA 可以看作：

```math
\boxed{\text{MHA 与 MQA 之间的折中}}
```

## 69. 最核心的几句话

第一：

```math
\boxed{
\text{只有一个KV Head}
\neq
\text{传统单头 Attention}
}
```

因为 MQA 有：

```text
多个 Query Head
```

---

第二：

传统单头中的 K/V 可以是：

```math
4096\text{维}
```

而 MQA 中：

```math
K,V\in\mathbb{R}^{128}
```

因此 KV Cache 显著减少。

---

第三：

MQA 并不是整个 Attention 只有 128 维。

因为：

```text
32个 Query Head
```

分别得到：

```text
32个128维输出
```

最后：

```math
32\times128=4096
```

仍然得到 4096 维输出。

---

第四：

MQA 中唯一的一份 K/V：

```text
逻辑上
```

相当于供 32 个 Query Head 使用。

可以理解成：

```text
原来1份
+
repeat 31份
=
逻辑上的32份
```

但：

```math
\boxed{\text{KV Cache中仍然只物理保存1份}}
```

否则 MQA 就失去了节省显存的意义。

---

第五：

最终可以用一句话区分：

```text
单头 Attention：

一个人
+
一本非常厚的书


MHA：

32个人
+
32本不同的书


GQA：

32个人
+
8本书
+
每4个人共享一本


MQA：

32个人
+
1本压缩后的书
+
所有人共享
```

因此 MQA 的核心思想就是：

```math
\boxed{
\text{保留多个 Query 的观察角度}
+
\text{大幅压缩共享的 K/V}
}
```

最终换来：

```text
更小的 KV Cache
更低的推理显存
更高效的长上下文推理
```

代价则是：

```text
K/V表示能力受到一定压缩
```

这也正是 GQA 出现的原因。
