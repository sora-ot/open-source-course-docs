## 1. 在看任何一行代码以前：先把 839 行压缩成一张图

这份文件看起来有很多函数和类，但真正的数据主线只有一条：

```text
Token ID
   ↓
Embedding
   ↓
MiniMindBlock × N
   ├─ RMSNorm
   ├─ Attention
   │   ├─ Q/K/V Linear
   │   ├─ Q/K RMSNorm
   │   ├─ RoPE
   │   ├─ KV Cache
   │   ├─ GQA / repeat_kv
   │   ├─ QK^T / sqrt(D)
   │   ├─ Causal Mask
   │   ├─ Softmax
   │   └─ × V
   ├─ Residual
   ├─ RMSNorm
   ├─ FFN / MoE
   └─ Residual
   ↓
Final RMSNorm
   ↓
LM Head
   ↓
Vocabulary Logits
   ├─ 训练：Shift → Cross Entropy → Loss
   └─ 推理：Temperature/Top-k/Top-p → 选一个 token → 下一轮
```

### 1.1 真正的“俄罗斯套娃”关系

```text
MiniMindForCausalLM               完整语言模型
│
├── MiniMindModel                Transformer 主干
│   │
│   ├── Embedding
│   ├── MiniMindBlock × N

│   │   │   ├── RMSNorm(Q/K)
│   │   │   ├── RoPE
│   │   │   └── repeat_kv

│

├── forward()                    一次完整前向
└── generate()                   反复调用 forward() 逐 token 生成
```

## 2. 全程只追踪一个教学样本

为了让整个文件不散掉，我们规定一套很小的模型：

```python
cfg = MiniMindConfig(
    hidden_size=8,
    num_hidden_layers=2,
    num_attention_heads=2,
    num_key_value_heads=1,
    vocab_size=16,
    intermediate_size=12,
    max_position_embeddings=32,
)
```

记号：

```text
B   = batch size               = 1
T   = 本轮输入 token 数         = 3 或 4
S   = 历史缓存长度 + T
H   = hidden size              = 8
V   = vocabulary size          = 16
Nq  = Query Head 数            = 2
Nkv = Key/Value Head 数        = 1
D   = head_dim                 = 4
I   = FFN intermediate size    = 12
```

假设输入：

```python
input_ids = torch.tensor([[1, 5, 7]])
```

其 shape 是：

```text
[1, 3]
```

含义不是“一个三维向量”，而是：

```text
1 条序列
每条序列 3 个 token
token 编号分别为 1、5、7
```

进入 Embedding 后：

```text
[1,3]
   ↓
[1,3,8]
```

经过两个 Block，shape 仍然是：

```text
[1,3,8]
```

经过 `lm_head`：

```text
[1,3,8]
   ↓
[1,3,16]
```

意思是：

```text
3 个位置
每个位置
都对 16 个候选 token 打一个分数
```

这套数字会贯穿整份讲义。

## 3. 阅读源码前必须掌握的三个层次

读这种文件时，每一行至少有三层含义。

### 3.1 Python 层

例如：

```python
self.q_proj = nn.Linear(...)
```

先要知道：

- `self` 是什么；
- `.q_proj` 是实例属性；
- `=` 是把对象的引用赋给属性；
- `nn.Linear(...)` 是创建一个对象；
- `...` 里的参数何时求值。

### 3.2 PyTorch 层

还要知道：

```python
nn.Linear(8, 8, bias=False)
```

会创建可训练参数：

```text
weight.shape = [8,8]
```

调用：

```python
y = layer(x)
```

才真正发生矩阵运算。

### 3.3 Transformer 层

最后才是：

> 为什么这里需要一个 8→8 的 Linear？

因为我们的示例中：

```text
Nq = 2
D  = 4
Nq × D = 8
```

所以这是在给两个 Query Head 一次性产生 `2×4=8` 个 Q 特征。

**后面所有代码都按这三个层次讲。**

## 4. `__init__` 和 `forward`：分清“造机器”和“开机器”

这是理解 PyTorch 源码最重要的前置知识。

看一个最小类：

```python
class TinyModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.linear = nn.Linear(3, 2)

    def forward(self, x):
        return self.linear(x)
```

创建：

```python
model = TinyModel()
```

此时执行的是：

```text
__init__
```

它只是：

```text
创建 Linear
创建权重
把 Linear 挂到 self.linear
```

还没有任何输入经过模型。

直到：

```python
x = torch.randn(1, 3)
y = model(x)
```

PyTorch 的 `nn.Module.__call__` 才进一步调用：

```python
model.forward(x)
```

因此可以牢牢记：

```text
__init__ = 造机器
forward  = 开机器
```

MiniMind 全文件也是如此。

`torch` 是 PyTorch 顶层包，不是 Python 标准库。

最小例子：




最小自动求导例子：

```math

```


### 6.10 Query Head 与 KV Head

```python
self.num_attention_heads = kwargs.get("num_attention_heads", 8)

```

```text

```

意思是：

```text

```

因此这是 GQA。

对比：

```text

```

### 6.11 `head_dim`

```python

```

`//` 是整数除法。

例子：

```python

```

```text

```

所以教学配置：


### 6.13 `intermediate_size`

```python
self.intermediate_size = kwargs.get(
    "intermediate_size",
    math.ceil(hidden_size * math.pi / 64) * 64
)
```

如果调用者明确：

```python
intermediate_size=12
```

教学模型就直接用 12。

如果不传，会执行默认公式。

逐步拆开：

假设：

```text
hidden_size=768
```

先：

```text
768 × π ≈ 2412.74
```

再：

```text
2412.74 / 64 ≈ 37.699
```

`ceil` 向上取整：

```text
38
```

## 8. `RMSNorm`：第一个真正会处理 Tensor 的网络组件

到这里，`MiniMindConfig` 只是在保存“图纸”。现在开始出现第一个真正的 `nn.Module`：

```python
class RMSNorm(torch.nn.Module):
```

先不要急着看公式。先回答四个问题：

```text
它是谁？       一个 PyTorch 网络模块
输入是什么？   Tensor，例如 [B,T,H]
输出是什么？   与输入 shape 完全相同的 Tensor
有没有参数？   有，一个可训练的 weight
改变什么？     改变数值尺度，不改变 token 数、hidden size 或维度数量
```

源码位置：约 L139～L178。

---

### 8.1 `class RMSNorm(torch.nn.Module)`：为什么必须继承 `Module`

原代码：

```python
class RMSNorm(torch.nn.Module):
```

前面我们已经：

```python
import torch
```

因此：

```python
torch.nn.Module
```

就是 PyTorch 所有神经网络层最常见的父类。

也可以写成：

```python
from torch import nn

class RMSNorm(nn.Module):
    ...
```

两种写法本质相同。

为什么不写普通 Python 类？

因为继承 `nn.Module` 后，PyTorch 才能自动管理：

```text
可训练参数 Parameter
子模块 Module
.to("cuda")
.train() / .eval()
.state_dict()
参数递归保存与加载
```

最小例子：

```python
import torch
from torch import nn

class MyLayer(nn.Module):
    def __init__(self):
        super().__init__()
        self.weight = nn.Parameter(torch.tensor([2.0]))

    def forward(self, x):
        return x * self.weight

layer = MyLayer()
print(list(layer.parameters()))
```

PyTorch 会发现：

```text
weight 是需要训练的参数
```

如果只是普通属性：

```python
self.weight = torch.tensor([2.0])
```

它就不是自动注册的 `Parameter`。

---

### 8.2 `__init__(self, dim, eps)`：造一台 RMSNorm 机器

源码：

```python
def __init__(self, dim: int, eps: float = 1e-5):
    super().__init__()
    self.eps = eps
    self.weight = nn.Parameter(torch.ones(dim))
```

逐行拆。

#### 8.2.1 第 1 行：

```python
def __init__(self, dim: int, eps: float = 1e-5):
```

`dim: int` 是类型提示：

```text
dim 期望是整数
```

它不会自动强制检查。

例如：

```python
RMSNorm(dim=8)
```

表示最后一个特征维有 8 个数。

`eps: float = 1e-5`：

```text
默认 eps = 0.00001
```

为什么需要 eps？

RMSNorm 分母含：

```math
\sqrt{\mathrm{mean}(x^2)+\epsilon}
```

如果输入全为 0：

```text
x = [0,0,0,0]
```

那么：

```text
mean(x²) = 0
```

若没有 eps：

```text
1 / sqrt(0)
```

会出问题。

加一个极小正数就是为了数值稳定。

---

#### 8.2.2 第 2 行：

```python
super().__init__()
```

它调用父类 `nn.Module` 的初始化逻辑。

可以概括为：

> 我先把 PyTorch 的“模块管理系统”初始化好，随后才能安全注册参数和子模块。

如果一个 `nn.Module` 子类忘记正确调用父类初始化，后续：

```python
self.weight = nn.Parameter(...)
```

等模块注册逻辑就可能失败。

---

#### 8.2.3 第 3 行：

```python
self.eps = eps
```

这里没有创建 Tensor。

只是把传进来的普通 Python 浮点数保存到对象里。

例如：

```python
norm = RMSNorm(8, eps=1e-6)
```

之后：

```python
norm.eps
```

就是：

```text
0.000001
```

它不是需要训练的参数。

---

#### 8.2.4 第 4 行：

```python
self.weight = nn.Parameter(torch.ones(dim))
```

这一行要拆成三层。

第一层：

```python
torch.ones(dim)
```

例如：

```python
torch.ones(4)
```

得到：

```text
tensor([1., 1., 1., 1.])
```

shape：

```text
[4]
```

第二层：

```python
nn.Parameter(...)
```

告诉 PyTorch：

> 这不是普通 Tensor，这是一个需要优化器训练的模型参数。

第三层：

```python
self.weight = ...
```

把它注册到当前 RMSNorm 模块下。

于是：

```python
norm = RMSNorm(4)
```

初始：

```text
norm.weight = [1,1,1,1]
```

训练后可能变成：

```text
[0.91, 1.08, 0.73, 1.21]
```

这意味着：

> RMSNorm 不仅把整体尺度规范化，还允许每个 hidden dimension 再学习自己的缩放程度。

---

### 8.3 `norm(self, x)`：先只做“纯归一化”

源码：

```python
def norm(self, x):
    return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)
```

这一行包含多个链式调用，可以逐步展开。

不要一口气读。

把：

```python
x.pow(2).mean(-1, keepdim=True)
```

拆成：

```python
x2 = x.pow(2)
mean_x2 = x2.mean(-1, keepdim=True)
```

再把完整代码改写为教学版：

```python
x2 = x.pow(2)
mean_x2 = x2.mean(dim=-1, keepdim=True)
denominator_inv = torch.rsqrt(mean_x2 + self.eps)
out = x * denominator_inv
return out
```

现在逐步看。

#### 8.3.1 `x.pow(2)`

逐元素平方。

若：

```text
x = [3,4]
```

得到：

```text
[9,16]
```

---

#### 8.3.2 `.mean(-1, keepdim=True)`

`-1` 表示最后一维。

如果：

```text
x.shape = [B,T,H]
```

那么：

```python
x.mean(-1)
```

就是沿 `H` 求平均。

这意味着：

> 每一个 token 独立归一化自己的 H 个特征。

例如：

```text
x.shape = [2,3,8]
```

共有：

```text
2 × 3 = 6 个 token 表示
```

每一个 token 都各自用自己的 8 个数求 RMS。

为什么 `keepdim=True`？

如果：

```text
x = [[3,4]]
shape = [1,2]
```

`mean(-1, keepdim=False)`：

```text
shape = [1]
```

`mean(-1, keepdim=True)`：

```text
shape = [1,1]
```

保留最后这个长度为 1 的维度，后面广播乘法会非常自然。

---

#### 8.3.3 `+ self.eps`

若：

```text
mean(x²)=12.5
```

则：

```text
12.5 + 0.00001
```

几乎不影响正常数值，但防止极端情况下分母为 0。

---

#### 8.3.4 `torch.rsqrt(...)`

`rsqrt` = reciprocal square root：

```math
\operatorname{rsqrt}(a)=\frac{1}{\sqrt{a}}
```

所以：

```python
torch.rsqrt(torch.tensor([4.0]))
```

结果：

```text
0.5
```

对于 `[3,4]`：

```text
mean(x²) = 12.5
sqrt(12.5) ≈ 3.5355
1 / 3.5355 ≈ 0.28284
```

于是：

```text
[3,4] × 0.28284
≈
[0.8485,1.1314]
```

---

### 8.4 为什么这个乘法能广播？

假设：

```text
x.shape = [1,3,4]
```

三个 token：

```text
Token 0: [a,b,c,d]
Token 1: [e,f,g,h]
Token 2: [i,j,k,l]
```

算完均方值并 `keepdim=True` 后：

```text
scale.shape = [1,3,1]
```

大概像：

```text
[[[s0],
  [s1],
  [s2]]]
```

与：

```text
[1,3,4]
```

相乘时，最后那个 `1` 自动广播成 `4`：

```text
Token 0 四个维度都乘 s0
Token 1 四个维度都乘 s1
Token 2 四个维度都乘 s2
```

这就是广播。

---

### 8.5 `forward(self, x)`：为什么先 `.float()` 再 `.type_as(x)`

源码：

```python
def forward(self, x):
    return (self.weight * self.norm(x.float())).type_as(x)
```

拆开：

```python
x_fp32 = x.float()
x_norm = self.norm(x_fp32)
x_scaled = self.weight * x_norm
out = x_scaled.type_as(x)
return out
```

#### 8.5.1 `x.float()`

无论输入原来是：

```text
FP16
BF16
```

这里先转成 FP32 做 RMS 相关计算。

原因：

```text
平方
求平均
开平方倒数
```

都属于比较容易受数值精度影响的操作。

因此常见做法是内部提高精度。

---

#### 8.5.2 `self.weight * x_norm`

若：

```text
x_norm.shape = [B,T,H]
weight.shape = [H]
```

PyTorch 会把 `[H]` 广播到所有 batch 和 token。

也就是：

```text
同一个第 0 hidden dimension
在所有 token 上都乘 weight[0]

同一个第 1 hidden dimension
在所有 token 上都乘 weight[1]
...
```

注意：

> 每个 token 的 RMS 尺度是自己计算的，但可学习的 `weight` 是整个模型共享的一组 H 维参数。

---

#### 8.5.3 `.type_as(x)`

意思是：

> 把结果转回与原输入 `x` 相同的数据类型。

例如：

```python
x.dtype == torch.float16
```

那么最终：

```text
out.dtype == torch.float16
```

这样后续 Transformer 的混合精度计算不会因为 RMSNorm 永久变成 FP32。

---

### 8.6 把 RMSNorm 完整跑一遍

```python
import torch
from torch import nn

class RMSNorm(nn.Module):
    def __init__(self, dim, eps=1e-5):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))

    def norm(self, x):
        return x * torch.rsqrt(
            x.pow(2).mean(-1, keepdim=True) + self.eps
        )

    def forward(self, x):
        return (
            self.weight * self.norm(x.float())
        ).type_as(x)

norm = RMSNorm(2)
x = torch.tensor([[3.0, 4.0]])
print(norm(x))
```

初始 `weight=[1,1]`，结果约：

```text
[[0.8485, 1.1314]]
```

如果人为改成：

```python
norm.weight.data = torch.tensor([2.0, 0.5])
```

则输出约：

```text
[[1.6970, 0.5657]]
```

### 8.7 RMSNorm 在整个文件里到底出现在哪里？

它不是只出现一次。

#### 8.7.1 第一类：Block 级归一化

`MiniMindBlock` 中：

```python
self.input_layernorm = RMSNorm(config.hidden_size, ...)
self.post_attention_layernorm = RMSNorm(config.hidden_size, ...)
```

shape：

```text
[B,T,H] → [B,T,H]
```

#### 8.7.2 第二类：Attention 内部 Q/K 归一化

```python
self.q_norm = RMSNorm(self.head_dim, ...)
self.k_norm = RMSNorm(self.head_dim, ...)
```

shape：

```text
Q: [B,T,Nq,D] → [B,T,Nq,D]
K: [B,T,Nkv,D] → [B,T,Nkv,D]
```

此时 RMSNorm 只看最后的：

```text
D
```

也就是每个 Attention Head 内部独立归一化。

#### 8.7.3 第三类：主模型最后一次归一化

```python
self.norm = RMSNorm(config.hidden_size, ...)
```

在全部 Block 结束后再做一次。

### 8.8 如果删掉 RMSNorm 会怎样？

从 Python 语法上，当然可以重新设计一个没有 Norm 的模型。

但在这份模型设计里，它承担的是：

```text
控制中间激活的数值尺度
↓
降低深层堆叠时数值越来越大/越来越小的风险
↓
让 Attention 和 FFN 更容易稳定训练
```

所以不能简单把：

```python
self.input_layernorm(hidden_states)
```

删掉，同时还声称“模型结构没有变化”。

那已经是在改网络架构。

## 9. `precompute_freqs_cis()`：RoPE 还没旋转 Q/K，先把整张 cos/sin 表算出来

接下来出现的是一个普通 Python 函数：

```python
def precompute_freqs_cis(...):
```

它不是 `nn.Module`。

为什么？

因为它没有需要训练的参数，也不是一个网络层。

它主要做一件事：

> 给位置 `0,1,2,...` 提前计算 RoPE 会用到的 cos/sin 数值表。

先看输入输出：

```text
输入：
D = head_dim
end = 最大位置数
rope_base = 频率基数
rope_scaling = 可选长上下文缩放配置

输出：
freqs_cos: [end,D]
freqs_sin: [end,D]
```

例如：

```python
cos, sin = precompute_freqs_cis(
    dim=4,
    end=3,
    rope_base=10000
)
```

会为位置：

```text
0,1,2
```

各准备 4 个 cos 和 4 个 sin 值。

---

### 9.1 函数签名逐项解释

源码：

```python
def precompute_freqs_cis(
    dim: int,
    end: int = int(32 * 1024),
    rope_base: float = 1e6,
    rope_scaling: dict = None
):
```

#### 9.1.1 `dim: int`

就是单个 Attention Head 的维度：

```text
D
```

这份实现要求 D 最好是偶数，因为后面需要成对旋转。

#### 9.1.2 `end = int(32 * 1024)`

先算：

```text
32 × 1024 = 32768
```

所以默认提前算 32768 个位置。

32K是minimind实现选择的默认最大上下文规模，是模型能力、显存占用和实际使用场景之间的工程折中。

`int(...)` 在这里结果本来就是整数，主要是把类型意图写清楚。

#### 9.1.3 `rope_base: float = 1e6`

`1e6`：

```text
1 × 10^6 = 1,000,000
```

它控制不同维度对应的旋转频率分布。

#### 9.1.4 `rope_scaling: dict = None`

默认：

```text
None
```

表示不做额外长上下文频率缩放。

如果给字典，则后面读取：

```text
factor
beta_fast
beta_slow
original_max_position_embeddings
attention_factor
```

---

### 9.2 第一条真正计算频率的代码

源码：

```python
freqs, attn_factor = (
    1.0 / (
        rope_base ** (
            torch.arange(0, dim, 2)[: (dim // 2)].float() / dim
        )
    ),
    1.0
)
```

原文件中的这一行可以拆开分析。

```python
indices = torch.arange(0, dim, 2)
indices = indices[: dim // 2]
indices = indices.float()
exponent = indices / dim
powers = rope_base ** exponent
freqs = 1.0 / powers
attn_factor = 1.0
```

---

#### 9.2.1 `torch.arange(0, dim, 2)`

类似 Python：

```python
range(0, dim, 2)
```

但是返回 Tensor。

例如：

```python
torch.arange(0, 8, 2)
```

得到：

```text
[0,2,4,6]
```

为什么步长是 2？

因为 RoPE 把特征两两配对做二维旋转。

如果：

```text
D=8
```

一共有：

```text
D/2 = 4 组旋转频率
```

---

#### 9.2.2 `[: (dim // 2)]`

`//` 是整数除法。

例如：

```text
8 // 2 = 4
```

所以只保留前 `D/2` 个频率索引。

对于正常偶数 D，`arange(0,D,2)` 本身已经正好产生 D/2 个元素，这个切片更多是把预期边界写明确。

---

#### 9.2.3 `.float()`

把整数索引转换成浮点数。

因为下面要做：

```python
indices / dim
```

并参与指数运算。

---

### 9.3 用 `D=4, base=10000` 手算

```text
indices = [0,2]
```

除以 D=4：

```text
[0/4, 2/4]
=
[0,0.5]
```

于是：

```text
base ** exponent
=
[10000^0, 10000^0.5]
=
[1,100]
```

取倒数：

```text
freqs = [1,0.01]
```

含义：

```text
第 1 对特征旋转得很快
第 2 对特征旋转得很慢
```

因此 RoPE 不是所有 hidden dimension 都用同一个角速度。

---

### 9.4 `if rope_scaling is not None`

源码：

```python
if rope_scaling is not None:
```

Python 里的 `is not None` 是判断对象是不是 `None`。

不要简单写成：

```python
if rope_scaling:
```

两者意义并不完全相同。

例如空字典：

```python
{}
```

是 Falsey，但它并不是 `None`。

这里源码明确判断：

> 调用者到底有没有传缩放配置对象。

---

### 9.5 一次取出五个 YaRN 风格参数

源码：

```python
orig_max, factor, beta_fast, beta_slow, attn_factor = (
    rope_scaling.get("original_max_position_embeddings", 2048),
    rope_scaling.get("factor", 16),
    rope_scaling.get("beta_fast", 32.0),
    rope_scaling.get("beta_slow", 1.0),
    rope_scaling.get("attention_factor", 1.0)
)
```

这是 Python 的：

```text
tuple unpacking
元组解包
```

例如：

```python
a, b = (10, 20)
```

得到：

```text
a=10
b=20
```

这里右侧依次算出五个值，再按顺序给五个变量。

`dict.get()` 前面已经讲过：

```python
d.get("key", 默认值)
```

如果 key 存在就用配置值，不存在就用默认值。

---

### 9.6 `if end / orig_max > 1.0`

源码：

```python
if end / orig_max > 1.0:
```

例如：

```text
end = 32768
orig_max = 2048
```

则：

```text
32768 / 2048 = 16
```

大于 1，说明：

> 当前预计算的位置范围超过了原始上下文窗口，需要进入缩放逻辑。

如果：

```text
end = 1024
orig_max = 2048
```

则：

```text
0.5
```

不进入缩放。

注意源码这里判断的是：

```text
预计算表长 end
```

而不是这一次 forward 实际输入了多少 token。

---

### 9.7 `lambda b: ...` 是什么？

源码：

```python
inv_dim = lambda b: (
    dim * math.log(orig_max / (b * 2 * math.pi))
) / (
    2 * math.log(rope_base)
)
```

`lambda` 是 Python 的匿名函数。

最简单：

```python
square = lambda x: x * x
print(square(3))
```

输出：

```text
9
```

等价于：

```python
def square(x):
    return x * x
```

所以这里也可以改写成：

```python
def inv_dim(b):
    return (
        dim * math.log(orig_max / (b * 2 * math.pi))
    ) / (
        2 * math.log(rope_base)
    )
```

这里的目标是：

> 根据“在原始上下文中大约转 b 圈”的条件，反推出频率索引边界。

这段 YaRN 代码计算的是：哪些频率维度该保留、哪些该缩慢、哪些处于过渡带。

---

### 9.8 `math.log`、`math.pi`、`floor`、`ceil`

源码：

```python
low = max(math.floor(inv_dim(beta_fast)), 0)
high = min(math.ceil(inv_dim(beta_slow)), dim // 2 - 1)
```

#### 9.8.1 `math.log(x)`

自然对数：

```math
\ln x
```

#### 9.8.2 `math.pi`

圆周率：

```text
3.1415926...
```

#### 9.8.3 `math.floor(x)`

向下取整：

```text
floor(2.9) = 2
```

#### 9.8.4 `math.ceil(x)`

向上取整：

```text
ceil(2.1) = 3
```

#### 9.8.5 `max(...,0)`

保证 `low` 不小于 0。

#### 9.8.6 `min(..., dim//2-1)`

保证 `high` 不超出频率索引范围。

### 9.9 构造 `ramp`

源码：

```python
ramp = torch.clamp(
    (
        torch.arange(dim // 2, device=freqs.device).float() - low
    ) / max(high - low, 0.001),
    0,
    1
)
```

拆开：

```python
idx = torch.arange(dim // 2, device=freqs.device).float()
num = idx - low
den = max(high - low, 0.001)
ramp = num / den
ramp = torch.clamp(ramp, 0, 1)
```

#### 9.9.1 `device=freqs.device`

这是很重要的工程细节。

如果 `freqs` 在 GPU：

```text
cuda:0
```

那么新创建的 `idx` 也直接放 GPU。

否则 CPU Tensor 和 GPU Tensor 直接计算会报 device mismatch。

#### 9.9.2 `torch.clamp(x,0,1)`

把小于 0 的变成 0，大于 1 的变成 1。

例如：

```text
[-0.5, 0.2, 0.8, 1.7]
```

变成：

```text
[0,0.2,0.8,1]
```

所以 `ramp` 就形成一个：

```text
0 → 过渡值 → 1
```

的平滑带。

### 9.10 真正修改频率

源码：

```python
freqs = freqs * (1 - ramp + ramp / factor)
```

看三个极端情况。

#### 9.10.1 `ramp=0`

```text
1 - 0 + 0/factor = 1
```

所以：

```text
freq 不变
```

#### 9.10.2 `ramp=1`

```text
1 - 1 + 1/factor
=
1/factor
```

所以：

```text
freq → freq/factor
```

例如 factor=16：

```text
0.01 → 0.000625
```

#### 9.10.3 `ramp=0.5`

```text
1 - 0.5 + 0.5/16
=
0.53125
```

所以处于过渡区，不是突然切换。

### 9.12 `torch.outer(t, freqs)`：一次生成所有“位置 × 频率”的角度

这一行之后：

shape：

### 9.13 为什么 cos/sin 要 `cat` 两遍？

源码：

```python
freqs_cos = torch.cat(
    [torch.cos(freqs), torch.cos(freqs)],
    dim=-1
) * attn_factor

freqs_sin = torch.cat(
    [torch.sin(freqs), torch.sin(freqs)],
    dim=-1
) * attn_factor
```

如果：

```text
freqs.shape = [end,D/2]
```

`cos(freqs)` 还是：

```text
[end,D/2]
```

沿最后一维拼两份：

```text
[end,D]
```

例如 D=4：

```text
原始两个角： [θ0, θ1]

cos 后：      [cosθ0, cosθ1]
复制拼接：    [cosθ0, cosθ1, cosθ0, cosθ1]
```

为什么顺序是这样？

因为本文件后面的 `rotate_half()` 配对方式是：

```text
前半维度
和
后半维度
```

例如：

```text
[x0,x1,x2,x3]
```

配对：

```text
(x0,x2)
(x1,x3)
```

因此：

```text
维 0 和维 2 用 θ0
维 1 和维 3 用 θ1
```

恰好需要：

```text
[θ0,θ1,θ0,θ1]
```

### 9.16 这张表什么时候创建？

不是每次 Attention 都重新计算。

后面 `MiniMindModel.__init__()` 会：

```python
freqs_cos, freqs_sin = precompute_freqs_cis(...)
```

然后：

```python
self.register_buffer("freqs_cos", ...)
self.register_buffer("freqs_sin", ...)
```

于是整台模型共享一张预计算位置表。

每次 forward 只切自己需要的：

```python

```

这就是“precompute”的意义：

> 三角函数提前算一次，运行时按位置查表。

## 10. `apply_rotary_pos_emb()`：真正把 RoPE 旋转施加到 Q 和 K

前一章只是造了两张表：

```text
cos[position, dimension]
sin[position, dimension]
```

还没有真正改变 Q、K。

现在才进入：

```python
def apply_rotary_pos_emb(q, k, cos, sin, unsqueeze_dim=1):
```

输入：

```text
q:   [B,T,Nq,D]
k:   [B,T,Nkv,D]
cos: [T,D]
sin: [T,D]
```

输出：

```text
q_embed: 与 q 同 shape
k_embed: 与 k 同 shape
```

Value 不进入这个函数。

---

### 10.1 为什么只旋转 Q 和 K，不旋转 V？

在 Attention 中：

```math
\text{score}_{ij}=Q_iK_j^T
```

位置关系主要通过 Q/K 点积影响“我应该关注谁”。

而 V 是：

> 被选中以后真正汇总的内容。

所以本实现只给 Q/K 加 RoPE。

---

### 10.2 内部函数 `rotate_half`

源码：

```python
def rotate_half(x):
    return torch.cat(
        (
            -x[..., x.shape[-1] // 2:],
            x[..., : x.shape[-1] // 2]
        ),
        dim=-1
    )
```

原源码压成一行，教学必须拆开。

假设：

```text
x = [1,2,3,4]
```

`x.shape[-1]`：

```text
4
```

`4 // 2`：

```text
2
```

第一片：

```python
x[..., 2:]
```

得到：

```text
[3,4]
```

前面负号：

```text
[-3,-4]
```

第二片：

```python
x[..., :2]
```

得到：

```text
[1,2]
```

`torch.cat(..., dim=-1)`：

```text
[-3,-4,1,2]
```

也就是：

```text
[x0,x1,x2,x3]
      ↓
[-x2,-x3,x0,x1]
```

这恰好构成二维旋转公式中的“与 sin 相乘的那一部分”。

---

### 10.3 `...` 到底是什么？

这个符号表示省略前面的维度。

```python
x[..., 2:]
```

`...` 是 Ellipsis。

意思：

> 前面有多少维我都不管，全部保留，只对最后一维切片。

例如：

```text
x.shape = [2,3,4,8]
```

```python
x[..., 4:]
```

等价于：

```python
x[:, :, :, 4:]
```

这样函数不需要提前知道 x 是二维、三维还是四维。

---

### 10.4 第一条旋转公式

源码：

```python
q_embed = (
    (q * cos.unsqueeze(unsqueeze_dim))
    +
    (rotate_half(q) * sin.unsqueeze(unsqueeze_dim))
).to(q.dtype)
```

数学形式：

```math
q' = q\cos\theta + \operatorname{rotate\_half}(q)\sin\theta
```

如果只看一组二维坐标：

```text
(x,y)
```

标准旋转是：

```text
x' = x cosθ - y sinθ
y' = x sinθ + y cosθ
```

本实现只是把很多二维配对一次并行完成。

---

### 10.5 为什么 `cos.unsqueeze(1)`？

默认：

```python
unsqueeze_dim=1
```

所以：

```python
cos.unsqueeze(1)
```

假设：

```text
cos.shape = [T,D]
```

插入一个维度后：

```text
[T,1,D]
```

而 q：

```text
[B,T,Nq,D]
```

在广播语义下，相当于把 cos 看成：

```text
[1,T,1,D]
```

于是：

```text
同一个位置 t 的 cos/sin
广播给：
- 所有 batch
- 所有 head
```

但是不同 token 位置使用不同的 cos/sin。

---

### 10.6 用一个极端角度手算

假设：

```text
q = [1,2,3,4]
```

为了方便，假设两组角都是：

```text
θ = π/2
```

所以：

```text
cos = [0,0,0,0]
sin = [1,1,1,1]
```

前面算过：

```text
rotate_half(q)
=
[-3,-4,1,2]
```

于是：

```text
q*cos = [0,0,0,0]
```

```text
rotate_half(q)*sin
=
[-3,-4,1,2]
```

相加：

```text
q'=[-3,-4,1,2]
```

这就是一次 90° 旋转。

---

### 10.7 Key 完全相同

源码：

```python
k_embed = (
    (k * cos.unsqueeze(unsqueeze_dim))
    +
    (rotate_half(k) * sin.unsqueeze(unsqueeze_dim))
).to(k.dtype)
```

只是把 q 换成 k。

注意 Q 和 K 的 head 数可以不同：

```text
Q: Nq
K: Nkv
```

因为 cos/sin 在 head 维本来就是 1，能够广播到任意 head 数。

---

### 10.8 `.to(q.dtype)` 与 `.type_as(x)` 的关系

这里：

```python
.to(q.dtype)
```

意思是只指定数据类型转换为 q 的 dtype。

前面 RMSNorm：

```python
.type_as(x)
```

也是恢复成和 x 同类型。

在这段代码里，两者目的类似：

> 防止中间运算因为 cos/sin 的 dtype 让最终 Q/K 类型发生意外变化。

---

### 10.9 `return q_embed, k_embed`

外面调用：

```python
xq, xk = apply_rotary_pos_emb(xq, xk, cos, sin)
```

于是原来的：

```text
xq
xk
```

被替换成：

```text
带位置旋转后的 xq
带位置旋转后的 xk
```

shape 一点不变。

## 11. `repeat_kv()`：GQA 为什么能让多个 Query Head 共用一组 K/V

源码：

```python
def repeat_kv(x: torch.Tensor, n_rep: int) -> torch.Tensor:
    bs, slen, num_key_value_heads, head_dim = x.shape
    if n_rep == 1:
        return x
    return (
        x[:, :, :, None, :]
        .expand(bs, slen, num_key_value_heads, n_rep, head_dim)
        .reshape(bs, slen, num_key_value_heads * n_rep, head_dim)
    )
```

这个函数非常短，但里面包含：

```text
type hint
shape 解包
早返回
None 插轴
expand
reshape
GQA 的实际 head 对齐
```

非常值得逐行讲。

---

### 11.1 函数签名里的类型提示

```python
x: torch.Tensor
```

表示期望 x 是 Tensor。

```python
n_rep: int
```

期望是整数。

```python
-> torch.Tensor
```

表示预期返回 Tensor。

这些是类型注解，不是运行时的强制类型转换。

---

### 11.2 `bs, slen, num_key_value_heads, head_dim = x.shape`

假设：

```text
x.shape = [2,3,4,8]
```

那么 Python 解包：

```text
bs = 2
slen = 3
num_key_value_heads = 4
head_dim = 8
```

这里要求 x 恰好是四维。

在本文件中，repeat 之前 K/V 的布局是：

```text
[B,S,Nkv,D]
```

所以四个变量分别就是：

```text
B
S
Nkv
D
```

---

### 11.3 `if n_rep == 1: return x`

这是典型的“early return”。

如果 Query Head 数和 KV Head 数一样：

```text
Nq = Nkv
```

那么：

```text
n_rep = Nq // Nkv = 1
```

根本不需要复制。

直接返回原 x。

这样既更快，也避免无意义 reshape。

---

### 11.4 `x[:, :, :, None, :]`：第一次看到 None 插轴

假设：

```text
x.shape = [1,3,2,4]
```

其中：

```text
1 个 batch
3 个 token
2 个 KV head
每头 4 维
```

现在：

```python
x[:, :, :, None, :]
```

在第 4 个位置插一个新轴：

```text
[1,3,2,1,4]
```

这里的 `None` 可以理解为：

```python
torch.unsqueeze(x, dim=3)
```

类似效果。

为什么要插这一维？

因为接下来要在这个新维度上“把每个 KV Head 复制 n_rep 份”。

---

### 11.5 `.expand(...)`：广播视图，不是简单 `repeat`

```python
.expand(
    bs,
    slen,
    num_key_value_heads,
    n_rep,
    head_dim
)
```

如果：

```text
原 shape = [1,3,2,1,4]
n_rep = 2
```

expand 后：

```text
[1,3,2,2,4]
```

概念上：

```text
KV head A → A,A
KV head B → B,B
```

`expand` 常常利用 stride/broadcast 创建视图，不一定立即真的复制所有数据。

这一点和：

```python
repeat(...)
```

不同，`repeat` 通常真正重复数据。

不过后面再 `reshape`，根据内存布局可能产生实际拷贝。

---

### 11.6 `.reshape(...)`：把“KV Head × 复制槽位”合并

当前：

```text
[B,S,Nkv,n_rep,D]
```

reshape 为：

```text
[B,S,Nkv*n_rep,D]
```

例如：

```text
[B,S,2,2,D]
```

变：

```text
[B,S,4,D]
```

head 顺序是：

```text
[A,A,B,B]
```

而不是：

```text
[A,B,A,B]
```

这点特别重要，因为 Query Heads 也按组对应它们。

---

### 11.7 用 GQA 的真实数字串起来

假设：

```text
Nq = 8
Nkv = 4
```

那么：

```python
n_rep = Nq // Nkv
```

得到：

```text
2
```

原始 K：

```text
K0 K1 K2 K3
```

repeat 后：

```text
K0 K0 K1 K1 K2 K2 K3 K3
```

对应 Query：

```text
Q0 Q1 Q2 Q3 Q4 Q5 Q6 Q7
```

配对：

```text
Q0,Q1 共用 K0/V0
Q2,Q3 共用 K1/V1
Q4,Q5 共用 K2/V2
Q6,Q7 共用 K3/V3
```

这就是 Grouped Query Attention 的“组”。

---

### 11.8 训练时 repeat 会不会让共享的 K/V 无法反向传播？

不会。

虽然前向看起来：

```text
K0 → K0,K0
```

但它们都来自同一个原始 K0。

反向传播时：

```text
来自 Q0 路径的梯度
+
来自 Q1 路径的梯度
```

都会累积回原来的 K0 计算路径。

所以：

> “共享 K/V”不是停止训练，而是多个 Query Head 对同一份 K/V 参数产生共同梯度贡献。
