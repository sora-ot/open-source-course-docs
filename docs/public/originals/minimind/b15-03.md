## 1. `FeedForward`：Attention 开完会以后，每个 token 自己做一次非线性加工

Attention 负责：

```text
不同 token 之间交换信息
```

FeedForward 负责：

```text
每个 token 独立处理自己的 hidden features
```

所以它不会在时间维 T 上做 token-to-token 混合。

输入输出：

```text
[B,T,H] → [B,T,H]
```

中间暂时扩展为：

```text
[B,T,I]
```

这份实现是门控 FFN，形式可以写成：

```math
\operatorname{FFN}(x)
=
W_{down}
\left(
\operatorname{SiLU}(W_{gate}x)
\odot
(W_{up}x)
\right)
```

其中 `⊙` 是逐元素乘法。

---

### 1.1 构造函数

源码：

```python
class FeedForward(nn.Module):
    def __init__(self, config: MiniMindConfig, intermediate_size: int = None):
        super().__init__()
        intermediate_size = intermediate_size or config.intermediate_size
        self.gate_proj = nn.Linear(config.hidden_size, intermediate_size, bias=False)
        self.down_proj = nn.Linear(intermediate_size, config.hidden_size, bias=False)
        self.up_proj = nn.Linear(config.hidden_size, intermediate_size, bias=False)
        self.act_fn = ACT2FN[config.hidden_act]
```

---

### 1.2 `intermediate_size = intermediate_size or config.intermediate_size`

这里用了 Python 的 `or` 返回值语义。

最简单：

```python
x = None or 12
```

得到：

```text
12
```

```python
x = 16 or 12
```

得到：

```text
16
```

所以这里表示：

```text
如果调用者显式传 intermediate_size
    用传入值
否则
    用 config.intermediate_size
```

注意：

```text
0
```

也是 Falsey，因此传 0 也会回退到配置值。

不过中间维本来也应当是正整数。

---

### 1.3 `gate_proj`

```python
self.gate_proj = nn.Linear(
    config.hidden_size,
    intermediate_size,
    bias=False
)
```

例如：

```text
H=8
I=12
```

则：

```text
8 → 12
```

输入：

```text
[B,T,8]
```

输出：

```text
[B,T,12]
```

这条分支随后会过激活函数。

---

### 1.4 `up_proj`

```python
self.up_proj = nn.Linear(
    config.hidden_size,
    intermediate_size,
    bias=False
)
```

也是：

```text
H → I
```

但它有自己独立的权重矩阵。

所以：

```text
gate_proj(x)
```

和：

```text
up_proj(x)
```

虽然 shape 一样，数值和语义完全不同。

---

### 1.5 `down_proj`

```python
self.down_proj = nn.Linear(
    intermediate_size,
    config.hidden_size,
    bias=False
)
```

把中间宽度：

```text
I
```

重新投影回：

```text
H
```

因为最终还要和残差相加。

---

### 1.6 `ACT2FN[config.hidden_act]`

```python
self.act_fn = ACT2FN[config.hidden_act]
```

假设：

```text
config.hidden_act = "silu"
```

就相当于：

```text
从 ACT2FN 中找到 SiLU 对应函数
```

后面：

```python
self.act_fn(tensor)
```

才真正执行激活。

---

### 1.7 `FeedForward.forward()`：一行里面其实有五步

源码：

```python
def forward(self, x):
    return self.down_proj(
        self.act_fn(self.gate_proj(x)) * self.up_proj(x)
    )
```

教学版：

```python
gate = self.gate_proj(x)
gate = self.act_fn(gate)
up = self.up_proj(x)
merged = gate * up
out = self.down_proj(merged)
return out
```

---

### 1.8 `*` 是逐元素乘，不是矩阵乘

假设中间只有 2 维：

```text
gate = [0,2]
up   = [3,4]
```

SiLU：

```text
SiLU(0)=0
SiLU(2)≈1.7616
```

所以：

```text
activated_gate=[0,1.7616]
```

逐元素乘：

```text
[0×3, 1.7616×4]
=
[0,7.0464]
```

这一步可以理解为：

> gate 分支决定各个中间特征“通过多少”，up 分支提供被调节的内容。

注意 gate 并不是概率：

```text
不需要加起来等于 1
```

---

### 1.9 SiLU 是什么？

```math
\operatorname{SiLU}(x)=x\sigma(x)
```

其中：

```math
\sigma(x)=\frac{1}{1+e^{-x}}
```

例如：

```text
x=2
sigmoid(2)≈0.8808
SiLU(2)≈1.7616
```

与 ReLU：

```text
max(0,x)
```

相比，SiLU 是平滑的非线性函数。

---

### 1.10 FFN 的完整 shape 链

教学配置：

```text
B=1
T=3
H=8
I=12
```

输入：

```text
[1,3,8]
```

两条支路：

```text
gate_proj → [1,3,12]
up_proj   → [1,3,12]
```

SiLU 不改 shape：

```text
[1,3,12]
```

逐元素相乘：

```text
[1,3,12]
```

`down_proj`：

```text
[1,3,8]
```

所以：

```text
FFN 前后 H 不变
```

---

### 1.11 为什么说 FFN 不交换 token 信息？

Linear 只作用最后一维。

如果：

```text
x.shape=[B,T,H]
```

那么它相当于对每一个：

```text
x[b,t,:]
```

使用同一套权重矩阵。

不会把：

```text
t=0
```

的数据直接拿去跟：

```text
t=1
```

矩阵相乘。

因此：

```text
Attention = 跨 token 混合
FFN       = token 内部特征变换
```

## 2. `MOEFeedForward`：不是每个 token 都经过同一个 FFN，而是先选专家

如果：

```text
config.use_moe=False
```

模型使用普通 `FeedForward`。

如果：

```text
config.use_moe=True
```

则每个 Block 使用：

```python
MOEFeedForward
```

先记住最核心结构：

```text
每个 token
   │
   ▼
Router / Gate
   │
   ├─ 给 Expert 0 打分
   ├─ 给 Expert 1 打分
   ├─ 给 Expert 2 打分
   └─ 给 Expert 3 打分
   │
   ▼
选择 Top-K
   │
   ├─ Expert a
   └─ Expert b
   │
   ▼
按路由权重加权求和
```

这里每个 Expert 本质上就是一个独立 `FeedForward`。

---

### 2.1 `self.config = config`

源码：

```python
self.config = config
```

为什么 FeedForward 没保存整个 config，而 MoE 保存了？

因为 `MOEFeedForward.forward()` 运行时还需要读取：

```text
num_experts_per_tok
norm_topk_prob
router_aux_loss_coef
num_experts
```

所以直接把完整配置对象保存下来最方便。

---

### 2.2 Router：`H → E`

源码：

```python
self.gate = nn.Linear(
    config.hidden_size,
    config.num_experts,
    bias=False
)
```

如果：

```text
H=8
E=4
```

那么：

```text
8 → 4
```

每一个 token 的 H 维 hidden state 会产生 4 个专家分数。

例如：

```text
[2.1, 0.4, -0.2, 1.7]
```

这 4 个数分别对应 Expert 0～3。

---

### 2.3 `nn.ModuleList([...])`

源码：

```python
self.experts = nn.ModuleList([
    FeedForward(
        config,
        intermediate_size=config.moe_intermediate_size
    )
    for _ in range(config.num_experts)
])
```

这一行包含两个新知识。

#### 2.3.1 List comprehension

普通写法：

```python
lst = []
for i in range(4):
    lst.append(i * 2)
```

可以写成：

```python
lst = [i * 2 for i in range(4)]
```

这里：

```python
[
    FeedForward(...)
    for _ in range(E)
]
```

就是创建 E 个 FeedForward 对象。

#### 2.3.2 为什么不能只用普通 list？

如果把子模块放普通 Python list：

```python
self.experts = [FeedForward(...), ...]
```

PyTorch 不一定能像 `ModuleList` 那样完整递归注册其中所有子模块。

而：

```python
nn.ModuleList
```

会明确告诉 PyTorch：

> 这里是一组需要统一管理的神经网络子模块。

这样：

```text
.to(device)
state_dict()
parameters()
```

都会递归处理所有专家。

---

### 2.4 专家之间共享参数吗？

不会。

每次：

```python
FeedForward(...)
```

都会新建：

```text
gate_proj
up_proj
down_proj
```

所以：

```text
Expert 0
Expert 1
Expert 2
Expert 3
```

拥有不同参数。

---

### 2.5 `self.act_fn` 在这里其实没有直接使用

源码：

```python
self.act_fn = ACT2FN[config.hidden_act]
```

但当前 `MOEFeedForward.forward()` 没有直接调用它。

真正激活发生在：

```text
每个 Expert 自己的 FeedForward.forward()
```

所以这一属性在当前实现中属于“保存了但没有直接使用”。

读源码时看到一个属性，不要默认它一定会在当前类 forward 中用到；应当搜索引用。

## 3. `MOEFeedForward.forward()`：逐 token 路由

源码开始：

```python
batch_size, seq_len, hidden_dim = x.shape
x_flat = x.view(-1, hidden_dim)
```

假设：

```text
B=2
T=3
H=8
```

原输入：

```text
[2,3,8]
```

`view(-1,8)`：

```text
[6,8]
```

这里：

```text
N = B*T = 6
```

也就是把所有 batch 里的 token 暂时排成一张二维表：

```text
Token 0 → 一行
Token 1 → 一行
...
Token 5 → 一行
```

为什么？

因为 Router 和 Expert 分发都更容易按“token 行”处理。

---

### 3.1 Router 分数与 Softmax

```python
scores = F.softmax(
    self.gate(x_flat),
    dim=-1
)
```

先：

```text
x_flat [N,H]
↓ gate
[N,E]
```

再对 E 维 softmax：

```text
每个 token 对所有 Expert 的概率和为 1
```

例如：

```text
Token 0:
[0.60, 0.30, 0.10]

Token 1:
[0.20, 0.30, 0.50]
```

---

### 3.2 `torch.topk`

源码：

```python
topk_weight, topk_idx = torch.topk(
    scores,
    k=self.config.num_experts_per_tok,
    dim=-1,
    sorted=False
)
```

如果：

```text
scores=[0.6,0.3,0.1]
K=2
```

得到概念上：

```text
topk_weight=[0.6,0.3]
topk_idx=[0,1]
```

其中：

```text
weight = 概率值
idx    = 专家编号
```

为什么 `sorted=False`？

表示：

> 只要求找出 top-k，不保证返回的这 K 个槽位按概率从大到小排列。

后续代码也不依赖槽位顺序。

---

### 3.3 重新归一化 Top-K 概率

源码：

```python
if self.config.norm_topk_prob:
    topk_weight = topk_weight / (
        topk_weight.sum(dim=-1, keepdim=True) + 1e-20
    )
```

例如原始 softmax：

```text
[0.6,0.3,0.1]
```

选前两项：

```text
[0.6,0.3]
```

它们加起来：

```text
0.9
```

重新归一化：

```text
[0.6/0.9, 0.3/0.9]
=
[2/3,1/3]
```

于是被丢掉的专家不再占总概率质量。

`1e-20` 是极小稳定项，避免分母意外成为 0。

---

### 3.4 `torch.zeros_like(x_flat)`

源码：

```python
y = torch.zeros_like(x_flat)
```

如果：

```text
x_flat.shape=[N,H]
```

那么：

```text
y.shape=[N,H]
```

而且：

```text
dtype 相同
device 相同
```

初始全部为 0。

为什么？

因为接下来各专家的贡献会不断：

```text
加到 y 对应 token 行
```

---

### 3.5 `for i, expert in enumerate(self.experts)`

`enumerate` 最小例子：

```python
names = ["A", "B", "C"]
for i, name in enumerate(names):
    print(i, name)
```

输出：

```text
0 A
1 B
2 C
```

所以：

```python
for i, expert in enumerate(self.experts):
```

同时拿到：

```text
i = 专家编号
expert = 专家模块对象
```

---

### 3.6 `mask = (topk_idx == i)`

假设：

```text
topk_idx =
[
 [0,1],
 [2,1]
]
```

当前：

```text
i=1
```

则：

```text
topk_idx == 1
```

得到布尔矩阵：

```text
[
 [False, True],
 [False, True]
]
```

含义：

```text
Token0 的第2个 top-k 槽位选了 Expert1
Token1 的第2个 top-k 槽位也选了 Expert1
```

---

### 3.7 `if mask.any()`

```python
mask.any()
```

只要 mask 中有至少一个 True，就返回 True。

所以：

```text
当前专家至少被一个 token 选中
```

才真正执行专家计算。

如果完全没人选，就避免无意义地跑整个 FFN。

---

### 3.8 `mask.any(dim=-1)`

继续刚才：

```text
mask =
[
 [False,True],
 [False,True]
]
```

沿最后一维 K 合并：

```text
[True,True]
```

意思：

```text
Token0 用了当前专家
Token1 也用了当前专家
```

如果：

```text
[
 [True,False],
 [False,False]
]
```

则：

```text
[True,False]
```

---

### 3.9 `.nonzero().flatten()`

源码：

```python
token_idx = mask.any(dim=-1).nonzero().flatten()
```

假设：

```text
[False, True, False, True]
```

`.nonzero()` 找 True 的位置：

```text
[[1],
 [3]]
```

shape：

```text
[2,1]
```

`.flatten()`：

```text
[1,3]
```

于是：

```text
当前 Expert 只需要处理 token 行 1 和 3
```

---

### 3.10 `topk_weight[mask]`

源码：

```python
weight = topk_weight[mask].view(-1, 1)
```

这是布尔索引。

假设：

```text
topk_weight=
[
 [0.7,0.3],
 [0.625,0.375]
]
```

当前 Expert1 的 mask：

```text
[
 [False,True],
 [False,True]
]
```

取出：

```text
[0.3,0.375]
```

`.view(-1,1)`：

```text
[
 [0.3],
 [0.375]
]
```

为什么变成 `[M,1]`？

因为专家输出：

```text
[M,H]
```

权重：

```text
[M,1]
```

可以广播成：

```text
每个 token 的整个 H 维输出都乘同一个路由权重
```

---

### 3.11 `expert(x_flat[token_idx])`

如果当前专家只被 M 个 token 选中：

```text
x_flat[token_idx]
→ [M,H]
```

然后只把这些 token 送进这个专家 FFN。

不是让所有 N 个 token 都运行每一个专家。

这就是稀疏 MoE 节省计算的关键。

---

### 3.12 `index_add_`：把专家输出加回原 token 行

源码：

```python
y.index_add_(
    0,
    token_idx,
    (
        expert(x_flat[token_idx]) * weight
    ).to(y.dtype)
)
```

这是 MoE 最难读的一行之一。

先举最简单例子。

```python
y = torch.zeros(4,2)
index = torch.tensor([1,3])
source = torch.tensor([
    [10.,20.],
    [30.,40.]
])

y.index_add_(0, index, source)
```

结果：

```text
row0 [0,0]
row1 [10,20]
row2 [0,0]
row3 [30,40]
```

如果后面又往 row1 加一次：

```text
会累加，不是覆盖
```

这正适合 MoE，因为同一个 token 会被 K 个专家贡献。

---

### 3.13 为什么必须“加”而不是赋值？

如果 Token0 选：

```text
Expert0 权重 2/3
Expert1 权重 1/3
```

那么最终：

```math
y_0=\frac23E_0(x_0)+\frac13E_1(x_0)
```

所以：

```text
第一次 expert0 加进去
第二次 expert1 再加进去
```

必须累加。

---

### 3.14 `elif self.training`：没人选这个 Expert，为什么还碰一下参数？

源码：

```python
elif self.training:
    y[0, 0] += 0 * sum(p.sum() for p in expert.parameters())
```

数值上：

```text
加的是 0
```

所以输出不变。

但计算图里仍然把：

```text
当前 expert 的参数
```

通过一个乘 0 的路径连进来。

这常用于减轻某些分布式训练场景对“未使用参数”的处理问题。

---

### 3.15 `sum(p.sum() for p in expert.parameters())`

这又有 generator expression。

```python
for p in expert.parameters()
```

遍历专家全部参数。

```python
p.sum()
```

每个参数 Tensor 求和成标量。

外面 Python `sum(...)` 再把所有标量加起来。

最后：

```python
0 * ...
```

数值恒为 0，但保留计算图连接。

---

### 3.16 MoE 辅助损失：为什么需要负载均衡

如果 Router 总是把所有 token 都送给 Expert0：

```text
Expert0 爆满
Expert1/2/3 几乎不用
```

那么 MoE 的专家容量就浪费了。

所以训练时常加入一个辅助目标，鼓励路由更均衡。

源码：

```python
if self.training and self.config.router_aux_loss_coef > 0:
```

两个条件：

```text
训练模式
并且辅助损失系数 > 0
```

---

### 3.17 `F.one_hot(topk_idx, num_experts)`

假设：

```text
topk_idx=
[
 [0,1],
 [2,1]
]
```

E=3。

one-hot 后 shape：

```text
[N,K,E] = [2,2,3]
```

可以理解为：

```text
Token0 slot0 → [1,0,0]
Token0 slot1 → [0,1,0]
Token1 slot0 → [0,0,1]
Token1 slot1 → [0,1,0]
```

`.float()` 把整数 0/1 转成浮点，方便后续平均。

---

### 3.18 `.mean(0)`

源码：

```python
load = F.one_hot(...).float().mean(0)
```

沿第 0 维 N 个 token 求平均。

结果 shape：

```text
[K,E]
```

表示：

> 每个 top-k 槽位中，各 Expert 被选中的比例。

---

### 3.19 `scores.mean(0)`

`scores`：

```text
[N,E]
```

沿 token 平均：

```text
[E]
```

表示：

```text
Router 平均给每个 Expert 多少概率质量
```

---

### 3.20 aux_loss 公式

源码：

```python
self.aux_loss = (
    load * scores.mean(0)
).sum() * self.config.num_experts * self.config.router_aux_loss_coef
```

按原文件示例：

```text
load=
[[0.5,0,0.5],
 [0,1,0]]

scores.mean(0)=[0.4,0.3,0.3]
```

广播相乘并求和：

```text
0.5×0.4 + 0×0.3 + 0.5×0.3
+
0×0.4 + 1×0.3 + 0×0.3
=
0.65
```

E=3：

```text
0.65×3=1.95
```

系数：

```text
0.0005
```

最终：

```text
0.000975
```

注意本文件最后只是把 `aux_loss` 返回出去，并没有在 `MiniMindForCausalLM.forward()` 中自动：

```text
loss = CE + aux_loss
```

训练脚本如果需要，应当自己决定怎么合并。

---

### 3.21 非训练模式的 aux_loss

源码：

```python
self.aux_loss = scores.new_zeros(1).squeeze()
```

`new_zeros(1)`：

```text
创建一个与 scores 同 dtype、同 device 的 [1] 零 Tensor
```

`.squeeze()`：

```text
[1] → 标量 Tensor shape []
```

所以返回的是 Tensor 0，不是 Python 整数 0。

这对 device/dtype 一致性更友好。

---

### 3.22 最后恢复 [B,T,H]

```python
return y.view(batch_size, seq_len, hidden_dim)
```

前面：

```text
[B,T,H]
→
[N,H]
```

现在恢复：

```text
[N,H]
→
[B,T,H]
```

MoE 对外接口因此与普通 FeedForward 完全一致。

这就是为什么 Block 可以写：

```python
self.mlp = FeedForward(...) if not use_moe else MOEFeedForward(...)
```

而不用为两种情况写两个不同 forward。

---

## 4. `MiniMindBlock`：终于把 Attention 和 FFN 装成一层 Transformer

现在前面所有零件开始真正组装。

Block 构造：

```python
class MiniMindBlock(nn.Module):
    def __init__(self, layer_id: int, config: MiniMindConfig):
        super().__init__()
        self.self_attn = Attention(config)
        self.input_layernorm = RMSNorm(config.hidden_size, eps=config.rms_norm_eps)
        self.post_attention_layernorm = RMSNorm(config.hidden_size, eps=config.rms_norm_eps)
        self.mlp = FeedForward(config) if not config.use_moe else MOEFeedForward(config)
```

核心结构只有：

```text
RMSNorm
Attention
Residual
RMSNorm
FFN/MoE
Residual
```

---

### 4.1 `layer_id` 为什么传进来了却没保存？

函数签名：

```python
def __init__(self, layer_id: int, config: MiniMindConfig):
```

但内部没有：

```python
self.layer_id = layer_id
```

说明当前实现中：

```text
layer_id 只是接口保留/调用时传入
但本类当前逻辑并不使用它
```

读源码时很重要的一条原则：

> 参数写在函数签名里，不代表它一定影响计算；要继续看函数体。

---

### 4.2 `self.self_attn = Attention(config)`

这一步是真正创建当前 Block 自己的 Attention 参数。

如果模型有 8 层：

```text
Block0.Attention
Block1.Attention
...
Block7.Attention
```

是 8 套独立权重。

不会默认共享 Q/K/V/O 参数。

---

### 4.3 两个 RMSNorm 为什么不共享？

```python
self.input_layernorm = RMSNorm(H)
self.post_attention_layernorm = RMSNorm(H)
```

它们分别位于：

```text
Attention 前
FFN 前
```

都有自己独立的 H 维 `weight`。

不能因为都是 RMSNorm 就认为参数相同。

---

### 4.4 条件表达式选择普通 FFN 还是 MoE

```python
self.mlp = (
    FeedForward(config)
    if not config.use_moe
    else MOEFeedForward(config)
)
```

如果：

```text
use_moe=False
```

创建：

```text
FeedForward
```

如果：

```text
use_moe=True
```

创建：

```text
MOEFeedForward
```

但二者接口都保证：

```text
[B,T,H] → [B,T,H]
```

所以 Block.forward 无需知道里面具体是哪一种。

这就是良好的“接口一致性”。

---

## 5. `MiniMindBlock.forward()`：两次 Pre-Norm + 两次 Residual

完整源码骨架：

```python
def forward(...):
    residual = hidden_states

    hidden_states, present_key_value = self.self_attn(
        self.input_layernorm(hidden_states),
        position_embeddings,
        past_key_value,
        use_cache,
        attention_mask
    )

    hidden_states += residual

    hidden_states = hidden_states + self.mlp(
        self.post_attention_layernorm(hidden_states)
    )

    return hidden_states, present_key_value
```

把它压缩成数学故事：

```text
h1 = h0 + Attention(Norm1(h0))

h2 = h1 + FFN(Norm2(h1))
```

这就是一整个 Transformer Block。

---

### 5.1 `residual = hidden_states` 是 clone 吗？

不是。

这只是：

```text
让 residual 和 hidden_states 暂时引用同一个 Tensor 对象
```

没有：

```python
hidden_states.clone()
```

不过下一步：

```python
hidden_states, present_key_value = self.self_attn(...)
```

会让 `hidden_states` 变量重新绑定到 Attention 返回的新 Tensor。

因此 `residual` 仍指向原来的输入 Tensor。

---

### 5.2 为什么先 Norm 再 Attention？

```python
self.self_attn(
    self.input_layernorm(hidden_states),
    ...
)
```

说明结构是：

```text
Norm → Attention → Residual
```

也就是 Pre-Norm。

不是：

```text
Attention → Residual → Norm
```

两种都曾出现在不同 Transformer 架构里，但这份代码明确是 Pre-Norm 风格。

---

### 5.3 位置参数为什么没有写名字？

调用：

```python
self.self_attn(
    self.input_layernorm(hidden_states),
    position_embeddings,
    past_key_value,
    use_cache,
    attention_mask
)
```

这里后四个是位置参数。

它们依次对应函数签名：

```python
def forward(
    self,
    x,
    position_embeddings,
    past_key_value=None,
    use_cache=False,
    attention_mask=None
)
```

所以必须严格按顺序。

后面主模型调用 Block 时，为了更清楚，会使用：

```python
past_key_value=past_key_value
use_cache=use_cache
attention_mask=attention_mask
```

这种关键字参数。

---

### 5.4 第一次残差相加

源码：

```python
hidden_states += residual
```

假设一个 token：

```text
原输入 residual = [1.0,2.0]
Attention 输出 = [0.1,0.2]
```

相加：

```text
[1.1,2.2]
```

直观理解：

```text
原来的信息
+
从上下文读到的新信息
```

---

### 5.5 `+=` 是原地操作意味什么？

`hidden_states += residual` 通常会尝试原地更新左侧 Tensor。

与：

```python
hidden_states = hidden_states + residual
```

在对象/内存语义上并不总是完全相同。

不过这里关注模型数学结构即可：

```text
Attention 输出 + 原输入
```

如果以后排查 autograd 的原地修改错误，才需要特别关注 inplace 语义。

---

### 5.6 第二次：Norm → MLP → Residual

源码：

```python
hidden_states = hidden_states + self.mlp(
    self.post_attention_layernorm(hidden_states)
)
```

教学版：

```python
residual2 = hidden_states
normalized = self.post_attention_layernorm(hidden_states)
ffn_out = self.mlp(normalized)
hidden_states = residual2 + ffn_out
```

假设：

```text
第一次残差后 h1=[1.1,2.2]
FFN 输出=[0.3,-0.2]
```

最终：

```text
h2=[1.4,2.0]
```

---

### 5.7 为什么 FFN 不返回 KV Cache？

因为 KV Cache 只来自 Self-Attention 的：

```text
K
V
```

FFN 只是逐 token 特征变换，没有历史 Key/Value 概念。

所以 Block 返回：

```python
return hidden_states, present_key_value
```

其中：

```text
present_key_value
```

完全由当前层 Attention 产生。

---

### 5.8 一个 Block 的完整 shape 不变量

输入：

```text
[B,T,H]
```

Norm：

```text
[B,T,H]
```

Attention：

```text
[B,T,H]
```

Residual：

```text
[B,T,H]
```

Norm：

```text
[B,T,H]
```

FFN：

```text
[B,T,H]
```

Residual：

```text
[B,T,H]
```

所以整个 Block 的“接口合同”很简单：

```text
[B,T,H] → [B,T,H]
```

真正变化的是：

```text
数值内容 / 语义表示
```

而不是外部 shape。

---

### 5.9 到这里，把一个 Block 压缩成两行

这段源码可以概括为：

```python
x = x + Attention(RMSNorm(x))
x = x + FFN(RMSNorm(x))
```

如果 `use_moe=True`：

```python
x = x + Attention(RMSNorm(x))
x = x + MoE(RMSNorm(x))
```
