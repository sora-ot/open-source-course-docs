```text

model_minimind.py

train_lora.py
    ↓

```

最终我们要回答一个核心问题：

> LoRA 加进去以后，一批训练数据究竟是如何经过 MiniMind，如何得到 CE Loss，又如何通过反向传播修改 LoRA 的 A、B 矩阵的？

## 1. 先用一句话理解整个 LoRA 训练

原来的某个线性层是：

\[
y=Wx
\]

加入 LoRA 后变成：

\[
\boxed{
y=Wx+BAx
}
\]

其中：

- \(W\)：原模型参数，冻结
- \(A\)：LoRA 参数，需要训练
- \(B\)：LoRA 参数，需要训练

因此我们并不是直接修改：

\[
W
\]

而是学习一个增量：

\[
\boxed{
\Delta W=BA
}
\]

最终效果相当于：

\[
\boxed{
W'=W+\Delta W=W+BA
}
\]

整个训练仍然是普通的：

```text
Forward
    ↓
logits
    ↓
Cross Entropy
    ↓
Loss
    ↓
loss.backward()
    ↓
计算 A、B 梯度
    ↓
optimizer.step()
    ↓
更新 A、B
```

LoRA 没有特殊的 Loss，也没有特殊的反向传播算法。

特殊的地方只有：

```text
Wx

变成

Wx + BAx
```

并且：

```text
W 冻结
A、B 训练
```

## 2. LoRA 类本身在做什么？

代码：

```python
class LoRA(nn.Module):
    def __init__(self, in_features, out_features, rank):
        super().__init__()

        self.rank = rank

        self.A = nn.Linear(
            in_features,
            rank,
            bias=False
        )

        self.B = nn.Linear(
            rank,
            out_features,
            bias=False
        )

        self.A.weight.data.normal_(
            mean=0.0,
            std=0.02
        )

        self.B.weight.data.zero_()

    def forward(self, x):
        return self.B(self.A(x))
```

假设：

```text
hidden_size = 768
rank = 16
```

那么：

```text
x
[B,T,768]
    │
    ▼
A
768 → 16
    │
    ▼
[B,T,16]
    │
    ▼
B
16 → 768
    │
    ▼
[B,T,768]
```

所以：

\[
\boxed{
LoRA(x)=BAx
}
\]

## 3. 为什么叫“低秩”？

假设：

\[
W\in\mathbb R^{768\times768}
\]

直接训练一个新的：

\[
\Delta W
\]

需要：

\[
768\times768
=
589824
\]

个参数。

但是 LoRA 使用：

\[
A\in\mathbb R^{16\times768}
\]

和：

\[
B\in\mathbb R^{768\times16}
\]

参数量只有：

\[
16\times768+768\times16
\]

即：

\[
24576
\]

而：

\[
\Delta W=BA
\]

满足：

\[
rank(\Delta W)
\leq16
\]

因此叫：

> Low-Rank Adaptation。

---

## 4. PyTorch 的矩阵方向要注意

数学里我们通常把 \(x\) 看成列向量：

\[
x\in\mathbb R^{768\times1}
\]

因此：

\[
Ax
\]

然后：

\[
B(Ax)
\]

得到：

\[
\boxed{
BAx
}
\]

但是 PyTorch 中 Tensor 通常把特征放在最后一维：

```text
[B,T,768]
```

而：

```python
nn.Linear(768, 16)
```

内部实际计算：

\[
xA^T
\]

因此 PyTorch 真正执行的是：

\[
xA^TB^T
\]

它和列向量写法：

\[
BAx
\]

表达的是同一件事情。

数学推导中使用：

\[
\boxed{BAx}
\]

即可。

## 5. `apply_lora()` 到底干了什么？

核心代码：

```python
def apply_lora(model, rank=16):

    for name, module in model.named_modules():

        if (
            isinstance(module, nn.Linear)
            and module.in_features == module.out_features
        ):

            lora = LoRA(
                module.in_features,
                module.out_features,
                rank=rank
            ).to(model.device)

            setattr(module, "lora", lora)

            original_forward = module.forward

            def forward_with_lora(
                x,
                layer1=original_forward,
                layer2=lora
            ):
                return layer1(x) + layer2(x)

            module.forward = forward_with_lora
```

这里最重要的不是：

```python
LoRA(...)
```

而是最后一句：

```python
module.forward = forward_with_lora
```

---

## 6. `apply_lora()` 没有替换整个 Linear

假设模型原来有：

```python
self.q_proj = nn.Linear(768, 768)
```

原来执行：

```python
self.q_proj(x)
```

实际上大致相当于：

```text
q_proj.__call__(x)
        ↓
q_proj.forward(x)
        ↓
Linear.forward(x)
        ↓
Wx
```

但是执行：

```python
apply_lora(model)
```

之后：

```python
q_proj.forward
```

已经被替换成：

```python
forward_with_lora
```

因此以后 MiniMind 再执行：

```python
self.q_proj(x)
```

实际过程已经变成：

```text
                   x
                   │
          ┌────────┴────────┐
          │                 │
          ▼                 ▼
original_forward          LoRA
          │                 │
          ▼                 ▼
         Wx               BAx
          │                 │
          └────────┬────────┘
                   │
                   ▼
                Wx + BAx
```

所以：

\[
\boxed{
y=Wx+BAx
}
\]

## 7. MiniMind 主模型甚至不知道 LoRA 存在

原来的 Attention 代码仍然写：

```python
xq = self.q_proj(x)
xk = self.k_proj(x)
xv = self.v_proj(x)
```

它完全没有改成：

```python
q = q_proj(x) + lora(x)
```

原因是：

```python
q_proj.forward
```

本身已经被修改了。

所以代码表面上还是：

```python
self.q_proj(x)
```

实际上已经变成：

\[
\boxed{
W_Qx+B_QA_Qx
}
\]

这就是这里 `apply_lora()` 的核心设计：

> 使用 monkey patch 动态修改已有 Linear 的 `forward()`。

## 8. 为什么要 `setattr(module, "lora", lora)`？

这一句：

```python
setattr(module, "lora", lora)
```

非常重要。

执行以后，原来的：

```text
q_proj
```

不再只有：

```text
weight
```

而是大致变成：

```text
q_proj
├── weight
└── lora
    ├── A
    │   └── weight
    └── B
        └── weight
```

因为：

```python
lora
```

本身也是：

```python
nn.Module
```

所以 PyTorch 会自动把它注册成 `q_proj` 的子模块。

之后：

```python
model.named_parameters()
```

就能够看到：

```text
model.layers.0.self_attn.q_proj.weight

model.layers.0.self_attn.q_proj.lora.A.weight
model.layers.0.self_attn.q_proj.lora.B.weight
```

这也是后面能够通过：

```python
'lora' in name
```

找到所有 LoRA 参数的原因。

## 9. `layer1=original_forward` 为什么这样写？

代码：

```python
def forward_with_lora(
    x,
    layer1=original_forward,
    layer2=lora
):
    return layer1(x) + layer2(x)
```

为什么不简单写成：

```python
def forward_with_lora(x):
    return original_forward(x) + lora(x)
```

因为这段代码位于循环内部：

```python
for name, module in model.named_modules():
```

Python 闭包可能最终引用循环后面的变量。

所以：

```python
layer1=original_forward
layer2=lora
```

相当于：

> 在创建这个函数的时候，立即把“当前这一层”的原 Forward 和 LoRA 保存下来。

于是：

```text
Layer 0 q_proj
→ 自己的 LoRA

Layer 0 o_proj
→ 自己的 LoRA

Layer 1 q_proj
→ 自己的 LoRA

Layer 1 o_proj
→ 自己的 LoRA
```

不会全部错误地指向循环中的最后一个 Linear。

## 10. MiniMind 哪些 Linear 会被加 LoRA？

`apply_lora()` 有一个条件：

```python
module.in_features == module.out_features
```

也就是：

> 只给方阵 Linear 添加 LoRA。

MiniMind 默认：

```text
hidden_size = 768
num_attention_heads = 8
num_key_value_heads = 4
```

因此：

\[
head\_dim
=
768/8
=
96
\]

---

### 10.1 `q_proj`

```python
q_proj = nn.Linear(
    hidden_size,
    num_attention_heads * head_dim
)
```

所以：

```text
768 → 8 × 96
768 → 768
```

满足：

```text
in_features == out_features
```

所以：

\[
\boxed{
q\_proj会加入LoRA
}
\]

于是：

\[
Q
=
W_QX+B_QA_QX
\]

```text
768 → 4 × 96
768 → 384
```

不是方阵。

所以：

\[
\boxed{
k\_proj不加入LoRA
}
\]

即：

\[
K=W_KX

同理：

```text
768 → 384
```

所以：

\boxed{
v\_proj不加入LoRA

\[
V=W_VX

## 13. `o_proj`

Attention 输出后：

```python
o_proj = nn.Linear(
```

所以：

```text
768 → 768
```

\[
\boxed{
o\_proj会加入LoRA

\[
O=W_OH

\[
\boxed{

## 14. FeedForward 为什么通常没有加？

MiniMind FFN 包含：

```python
gate_proj:
768 → intermediate_size

up_proj:
768 → intermediate_size

down_proj:
intermediate_size → 768
```

输入输出维度通常不相等。

所以它们不满足：

```python
module.in_features == module.out_features
```

不会被当前这个 `apply_lora()` 加入 LoRA。

---

## 15. `lm_head` 呢？

`lm_head` 是：

```text
768 → vocab_size
```

例如：

```text
768 → 6400
```

也不是方阵。

因此也不会加 LoRA。

## 16. 所以默认每层主要加两个 LoRA

一层 Transformer：

```text
Attention
├── q_proj   768 → 768   ✅ LoRA
├── k_proj   768 → 384   ❌
├── v_proj   768 → 384   ❌
└── o_proj   768 → 768   ✅ LoRA

FFN
├── gate_proj             ❌
├── up_proj               ❌
└── down_proj             ❌
```

如果：

```text
num_hidden_layers = 8
```

那么总共大致：

\[
8\times2=16
\]

组 LoRA：

```text
16个 A
16个 B
```

输入：

```text

[2,128,768]
```

调用：

实际上进入：


也就是：

```python
layer1(x)
```

就是以前的：

```python
Linear.forward(x)
```

即：

\[
Q_{\text{base}}
=
XW_Q^T
\]

shape：

```text
X:
[2,128,768]

Wq:
[768,768]

↓

Q_base:
[2,128,768]
```

执行：

```python
layer2(x)
```

进入：

```python
LoRA.forward(x)
```

即：

```python
B(A(x))
```

首先：

```text
A:

768 → 16
```

所以：

```text
[2,128,768]
      ↓
      A
      ↓
[2,128,16]
```

然后：

```text

```

所以：

```text
[2,128,16]
      ↓
      B
      ↓
[2,128,768]
```

得到：

\[
Q_{\text{LoRA}}
\]

## 20. 两条路径相加

最终：

```python
return layer1(x) + layer2(x)
```

即：

\[
Q
=
Q_{\text{base}}
+
Q_{\text{LoRA}}
\]

所以：

\[
\boxed{
Q
=
W_QX+B_QA_QX
}
\]

PyTorch 行向量写法等价于：

\[
Q
=
XW_Q^T
+
XA_Q^TB_Q^T
\]

## 21. 为什么 B 要初始化成 0？

代码：

```python
self.A.weight.data.normal_(
    mean=0.0,
    std=0.02
)

self.B.weight.data.zero_()
```

开始时：

\[
A\neq0
\]

但是：

\[
B=0
\]

所以：

\[
BA=0
\]

进一步：

\[
BAx=0
\]

因此：

\[
Wx+BAx
=
Wx
\]

即：

\[
\boxed{
LoRA刚加入模型时，不改变原模型输出
}
\]

这是一个非常重要的设计。

## 22. `train_lora.py` 里确实冻结了原模型 W

现在来看训练脚本最重要的一段。

首先：

```python
model, tokenizer = init_model(
    lm_config,
    args.from_weight,
    device=args.device
)
```

先加载原模型。

然后：

```python
apply_lora(model)
```

给符合条件的 Linear 加上 LoRA。

接下来：

```python
lora_params = []

for name, param in model.named_parameters():

    if 'lora' in name:

        param.requires_grad = True
        lora_params.append(param)

    else:

        param.requires_grad = False
```

所以：

```text
原模型参数
requires_grad = False

LoRA A/B
requires_grad = True
```

这就是真正的：

\[
\boxed{
冻结W，只训练A和B
}
\]

## 24. 不仅冻结，而且 Optimizer 也只拿 LoRA 参数

训练脚本后面：

```python
optimizer = optim.AdamW(
    lora_params,
    lr=args.learning_rate
)
```

注意这里不是：

```python
AdamW(model.parameters())
```

而是：

```python

```

因此从两个层面保证：

```text

第二层保证：
Optimizer根本没有拿到原模型W
```

于是原模型：

\[
W
\]

不会被：

```python
optimizer.step()
```

更新。

## 26. 一个非常重要的区别：冻结 W ≠ 梯度不能经过 W

假设：

\[
y=Wx+BAx
\]

现在：

\[
W.requires\_grad=False
\]

很多人容易理解成：

```text
梯度走到 W 就停了
```

这是错误的。

正确理解是：

> W 自己不需要计算并保存参数梯度，但是梯度仍然可以通过这个运算传给前面的 \(x\)。

---

## 27. 从数学上看

有：

\[
y=Wx+BAx
\]

设后面传来的梯度：

\[
g
=
\frac{\partial L}{\partial y}
\]

则：

\[
\frac{\partial L}{\partial x}
=
W^Tg
+
A^TB^Tg
\]

所以即使：

\[
W
\]

被冻结，仍然存在：

\[
W^Tg
\]

这一项。

也就是说：

```text
Loss
 ↑
当前层
 ↑
冻结的 W
 ↑
前面层产生的 x
```

梯度仍然可以继续传播。

冻结只是表示：

\[
\boxed{
不更新W
}
\]

而不是：

\[
\boxed{
切断计算图
}
\]

## 30. Step 2：进入第一个 Transformer Block

每个 Block：

```text
hidden_states
     │
     ▼
RMSNorm
     │
     ▼
Attention
     │
     ▼
Residual
     │
     ▼
RMSNorm
     │
     ▼
FeedForward
     │
     ▼
Residual
```

核心代码逻辑：

```python
residual = hidden_states

hidden_states, present_key_value = self.self_attn(
    self.input_layernorm(hidden_states),
    ...
)

hidden_states += residual

hidden_states = (
    hidden_states
    +
    self.mlp(
        self.post_attention_layernorm(hidden_states)
    )
)
```

```text
o_proj LoRA

↓
Layer 1
q_proj LoRA
o_proj LoRA

↓

...

↓

Layer 7
q_proj LoRA
o_proj LoRA

↓
Final RMSNorm
```

最后得到：

\[
hidden\_states
\]

shape：

```text
[B,T,768]
```

## 38. 一个位置的 logits 是什么？

例如词表为了演示只有：

```text
[我, 爱, 你, AI]
```

模型某个位置输出：

\[

[1,3,0,-1]
\]

这些：

```text

3
0
-1
```

不是概率。

它们叫：

\[
\boxed{logits}
\]

## 39. 为什么 CE Loss 要 shift 一位？

MiniMind 中：

```python
x = logits[..., :-1, :]
y = labels[..., 1:]
```

这是自回归语言模型最核心的一步。

假设训练序列：

```text
我  爱  人工智能  EOS
```

模型任务不是：

```text
“我”预测“我”
“爱”预测“爱”
```

而是：

```text
输入“我”
预测“爱”

输入“我 爱”
预测“人工智能”

输入“我 爱 人工智能”
预测“EOS”
```

---

## 40. 因此 logits 和 label 要错开一位

原序列：

```text
位置        0       1          2       3

token       我      爱       人工智能   EOS
```

取：

```python
logits[..., :-1, :]
```

得到：

```text
位置0的logits
位置1的logits
位置2的logits
```

而：

```python
labels[..., 1:]
```

得到：

```text
爱
人工智能
EOS
```

所以训练对应关系：

| 模型输出 | 正确答案 |
|---|---|
| logits[0] | 爱 |
| logits[1] | 人工智能 |
| logits[2] | EOS |

这就是：

\[
\boxed{
Next Token Prediction
}
\]

## 41. Cross Entropy 到底怎么算？

某个位置 logits：

\[
z=[1,3,0,-1]
\]

正确答案：

```text
爱
```

假设“爱”的 token index：

\[
y=1
\]

首先 Softmax：

\[
p_j
=
\frac{e^{z_j}}
{\sum_k e^{z_k}}
\]

假设得到：

```text
我      0.11
爱      0.81
你      0.04
AI      0.02
```

正确答案“爱”的概率：

\[
p_y=0.81
\]

Cross Entropy：

\[
\boxed{
L=-\log p_y
}
\]

因此：

\[
L=-\log0.81
\]

约为：

\[
0.21
\]

---

## 42. 模型预测越正确，Loss 越小

如果：

\[
p_y=0.99
\]

那么：

\[
-\log0.99
\]

很小。

如果：

\[
p_y=0.01
\]

那么：

\[
-\log0.01
\]

非常大。

因此训练目标就是：

\[
\boxed{
提高正确下一个Token的概率
}
\]

## 43. 一整个序列有很多个 CE Loss

例如：

```text
我 → 爱

爱 → 人工智能

人工智能 → EOS
```

分别有：

\[
L_1
\]

\[
L_2
\]

\[
L_3
\]

最终通常取平均：

\[
\boxed{
L_{CE}
=
\frac{
L_1+L_2+L_3
}{3}
}
\]

更一般地：

\[
\boxed{
L_{CE}
=
-\frac1N
\sum_{t=1}^{N}
\log
p_\theta
(y_t|y_{<t})
}
\]

## 44. `ignore_index=-100` 是什么意思？

代码：

```python
F.cross_entropy(
    x.view(-1, x.size(-1)),
    y.view(-1),
    ignore_index=-100
)
```

如果某个 label：

```text
-100
```

那么这个位置不会计算 CE Loss。

例如：

```text
labels:

[-100, -100, -100, 55, 21]
```

前面三个位置：

```text
不参与Loss
```

后面两个位置：

```text
参与Loss
```

需要注意：

> `model_minimind.py` 只是支持 `-100`；具体哪些位置会被设置为 `-100`，需要看数据集 `SFTDataset` 的实现。

不能只根据模型文件判断 Prompt 是否一定被 mask。

## 45. MiniMind 中真正计算 CE 的代码

核心：

```python
x = logits[..., :-1, :].contiguous()

y = labels[..., 1:].contiguous()

loss = F.cross_entropy(
    x.view(-1, x.size(-1)),
    y.view(-1),
    ignore_index=-100
)
```

因此整体：

```text
hidden_states
↓
lm_head
↓
logits
↓
shift logits
↓
shift labels
↓
CrossEntropy
↓
res.loss
```

## 46. `train_lora.py` 中实际 Loss 是什么？

训练代码：

```python
res = model(
    input_ids,
    labels=labels
)

loss = res.loss + res.aux_loss
```

所以：

\[
\boxed{
L
=
L_{CE}
+
L_{aux}
}
\]

如果使用普通 Dense Model：

```text
aux_loss = 0
```

那么：

\[
\boxed{
L=L_{CE}
}
\]

如果：

```text
use_moe=True
```

还会包含 MoE Router 的 auxiliary loss。

## 47. 梯度累积时还会除以 accumulation_steps

代码：

```python
loss = loss / args.accumulation_steps
```

假设：

```text
accumulation_steps = 8
```

那么每个 mini-batch：

\[
L'
=
\frac{L}{8}
\]

连续 backward 8 次以后：

```text
梯度不断累加
```

第 8 次再：

```python
optimizer.step()
```

相当于用更大的有效 Batch Size 训练。

## 48. 真正开始反向传播

训练脚本：

```python
scaler.scale(loss).backward()
```

如果是 FP16：

```text
GradScaler
```

会先把 Loss 放大再 backward，减少 FP16 梯度下溢。

如果使用 BF16，当前脚本里 GradScaler 不启用，本质仍然相当于：

```python
loss.backward()
```

现在开始沿计算图反向传播。

## 49. CE Loss 对 logits 的梯度

Cross Entropy：

\[
L=-\log p_y
\]

其中：

\[
p_j
=
Softmax(z_j)
\]

非常重要的结果：

\[
\boxed{
\frac{\partial L}
{\partial z_j}
=
p_j-\mathbf 1(j=y)
}
\]

这条公式体现了 LoRA 参数的梯度关系。

## 50. 数值例子

模型预测：

```text
token      probability

A           0.10
B           0.60
C           0.20
D           0.10
```

假设正确答案：

```text
B
```

one-hot：

```text
[0,1,0,0]
```

预测概率：

```text
[0.1,0.6,0.2,0.1]
```

梯度：

\[
p-y
\]

所以：

```text
[0.1,
 -0.4,
 0.2,
 0.1]
```

## 51. 这个梯度是什么意思？

正确答案 B：

\[
-0.4
\]

进行梯度下降：

\[
z_B
\leftarrow
z_B-\eta(-0.4)
\]

所以：

\[
z_B\uparrow
\]

也就是：

> 提高正确 Token 的 Logit。

其他错误 Token：

\[
+0.1,+0.2,+0.1
\]

梯度下降后：

\[
z_{\text{wrong}}\downarrow
\]

所以 CE 在做的事情就是：

\[
\boxed{
正确Token分数提高，
错误Token分数降低
}
\]

## 52. 梯度首先经过 lm_head

有：

\[
Z=HW_{lm}^T
\]

其中：

\[
H
\in
\mathbb R^{B\times T\times768}
\]

而：

\[
Z
\in
\mathbb R^{B\times T\times V}
\]

CE 得到：

\[
\frac{\partial L}{\partial Z}
\]

然后根据链式法则：

\[
\frac{\partial L}{\partial H}
=
\frac{\partial L}{\partial Z}
W_{lm}
\]

注意：

```text
lm_head.weight被冻结
```

因此：

\[
W_{lm}
\]

自己不更新。

但梯度仍然通过它传给：

\[
hidden\_states
\]

一直传播。

## 54. 当梯度走到 LoRA 层时发生什么？

考虑一个最简单的 Linear + LoRA：

\[
\boxed{
y=Wx+BAx
}
\]

定义：

\[
g
=
\frac{\partial L}
{\partial y}
\]

也就是：

> 后面的网络传回这一层输出 \(y\) 的梯度。

现在计算：

```text
A 的梯度
B 的梯度
x 的梯度
```

---

## 55. 先把 LoRA 分成两步

定义：

\[
h=Ax
\]

那么：

\[
y=Wx+Bh
\]

结构：

```text
x
│
├──────────────→ W ───────────┐
│                             │
└──→ A ──→ h ──→ B ──────────┤
                              │
                              ▼
                              y
```

---

## 56. B 的梯度

因为：

\[
Bh
\]

相当于一个普通 Linear。

有：

\[
\boxed{
\frac{\partial L}{\partial B}
=
g h^T
}
\]

而：

\[
h=Ax
\]

所以：

\[
\boxed{
\frac{\partial L}{\partial B}
=
g(Ax)^T
}
\]

这就是 B 的核心梯度公式。

---

## 57. 梯度继续从 B 传到 h

因为：

\[
Bh
\]

所以：

\[
\boxed{
\frac{\partial L}{\partial h}
=
B^Tg
}
\]

这个梯度继续传给 A。

---

## 58. A 的梯度

因为：

\[
h=Ax
\]

所以：

\[
\frac{\partial L}{\partial A}
=
\frac{\partial L}{\partial h}
x^T
\]

代入：

\[
\frac{\partial L}{\partial h}
=
B^Tg
\]

得到：

\[
\boxed{
\frac{\partial L}{\partial A}
=
B^Tgx^T
}
\]

---

## 59. LoRA 最核心的反向传播公式

Forward：

\[
\boxed{
y=Wx+BAx
}
\]

Backward：

\[
\boxed{
\nabla_B L
=
g(Ax)^T
}
\]

以及：

\[
\boxed{
\nabla_A L
=
B^Tgx^T
}
\]

其中：

\[
g=
\frac{\partial L}{\partial y}
\]

---

## 60. W 的梯度呢？

如果 W 没被冻结：

\[
\frac{\partial L}{\partial W}
=
gx^T
\]

但是 `train_lora.py` 已经：

```python
param.requires_grad = False
```

所以原模型 W：

```text
不会保存参数梯度
不会被 optimizer 更新
```

因此真正更新的是：

\[
\boxed{
A,B
}
\]

---

## 61. 一个非常漂亮的现象：第一次训练时 A 的梯度为 0

还记得初始化：

\[
A=random
\]

但是：

\[
B=0
\]

而：

\[
\nabla_A L
=
B^Tgx^T
\]

因为：

\[
B=0
\]

所以第一次 backward：

\[
\boxed{
\nabla_A L=0
}
\]

也就是说：

> 第一次训练时 A 暂时不会更新。

---

## 62. 但是 B 有梯度

B：

\[
\nabla_B L
=
g(Ax)^T
\]

虽然：

\[
B=0
\]

但是：

\[
A\neq0
\]

所以一般：

\[
Ax\neq0
\]

因此：

\[
\boxed{
\nabla_B L\neq0
}
\]

于是第一次：

```text
B开始更新
A基本不变
```

---

## 63. 第二轮以后 A 开始有梯度

第一次：

```text
B = 0
```

Optimizer 更新之后：

```text
B ≠ 0
```

于是下一次：

\[
\nabla_A L
=
B^Tgx^T
\]

就不再为 0。

因此：

```text
第1步：
主要更新 B

后续：
A、B一起学习
```

---

## 64. 为什么这种初始化很好？

一开始：

\[
BA=0
\]

所以：

\[
Wx+BAx=Wx
\]

不会破坏预训练模型。

但是：

\[
A\neq0
\]

保证：

\[
\nabla_BL
\]

能够立即存在。

因此训练过程：

```text
初始：

A = 随机
B = 0

↓

模型功能完全等于原模型

↓

第一次 backward

↓

B先学起来

↓

B ≠ 0

↓

之后 A、B共同学习
```

这是一个非常巧妙的设计。

---

## 65. 反向传播还需要算 x 的梯度

虽然 W 被冻结，但是前面的 LoRA 层还需要训练。

因此必须继续得到：

\[
\frac{\partial L}{\partial x}
\]

由：

\[
y=Wx+BAx
\]

得到：

\[
\boxed{
\frac{\partial L}{\partial x}
=
W^Tg
+
A^TB^Tg
}
\]

于是梯度可以继续传到更前面的 Transformer Layer。

所以再次强调：

\[
\boxed{
冻结参数\neq切断梯度传播
}
\]

---

## 66. `scaler.unscale_(optimizer)` 在做什么？

如果使用 FP16 GradScaler：

Forward 后可能计算的是：

\[
sL
\]

其中：

\[
s
\]

是放大倍数。

Backward 得到：

\[
s\nabla L
\]

在真正更新前，需要执行：

```python
scaler.unscale_(optimizer)
```

将梯度还原：

\[
s\nabla L
\rightarrow
\nabla L
\]

然后才进行梯度裁剪。

---

## 67. LoRA 梯度裁剪

代码：

```python
torch.nn.utils.clip_grad_norm_(
    lora_params,
    args.grad_clip
)
```

注意：

```python
lora_params
```

里面只有 LoRA 参数。

所以实际上裁剪的是：

```text
所有 A 的梯度
+
所有 B 的梯度
```

而不是整个大模型所有参数的梯度。

---

## 68. `optimizer.step()` 真正更新谁？

优化器：

```python
optimizer = optim.AdamW(
    lora_params,
    lr=args.learning_rate
)
```

因此：

```python
scaler.step(optimizer)
```

真正更新的是：

```text
q_proj.lora.A
q_proj.lora.B

o_proj.lora.A
o_proj.lora.B

下一层 q_proj.lora.A
下一层 q_proj.lora.B

...
```

原模型：

```text
q_proj.weight
k_proj.weight
v_proj.weight
o_proj.weight
FFN
Embedding
lm_head
```

都不更新。

---

## 69. 更新后下一轮 Forward 有什么变化？

第一次：

\[
B=0
\]

所以：

\[
BAx=0
\]

经过一次 optimizer.step() 后：

\[
B\neq0
\]

于是下一轮：

\[
BAx\neq0
\]

因此：

\[
Wx+BAx
\]

已经和原模型：

\[
Wx
\]

不同。

这就是 LoRA 学习发生的地方。

2\\
-1
\end{bmatrix}
\]

B 的梯度：

\[
\nabla_BL
=
g(Ax)^T
\]

因为：

\[
Ax=0.5
\]

所以：

\[
\nabla_BL
=
\begin{bmatrix}
2\\
-1
\end{bmatrix}
\times0.5
\]

得到：

\[
\boxed{
\nabla_BL
=
\begin{bmatrix}
1\\
-0.5
\end{bmatrix}
}
\]

所以 B 可以立即更新。

---

## 76. A 第一次的梯度

\[
\nabla_AL
=
B^Tgx^T
\]

但是：

\[
B=0
\]

所以：

\[
\boxed{
\nabla_AL=0
}
\]

这就解释了为什么：

```text
第一次主要训练 B
```

---

## 77. 假设一次 SGD 后 B 发生变化

假设学习率：

\[
\eta=0.1
\]

那么：

\[
B_{new}
=
B-\eta\nabla_BL
\]

所以：

\[
B_{new}
=
\begin{bmatrix}
0\\
0
\end{bmatrix}
-
0.1
\begin{bmatrix}
1\\
-0.5
\end{bmatrix}
\]

得到：

\[
B_{new}
=
\begin{bmatrix}
-0.1\\
0.05
\end{bmatrix}
\]

现在：

\[
B\neq0
\]

下一次 backward：

\[
\nabla_AL
=
B^Tgx^T
\]

就可能：

\[
\neq0
\]

于是 A 也开始训练。

---

## 78. 保存 LoRA 时为什么只保存 A/B？

`save_lora()` 会寻找：

```python
if hasattr(module, 'lora'):
```

然后只保存：

```text
xxx.lora.A.weight
xxx.lora.B.weight
```

因为原模型：

```text
W
```

从头到尾没有变化。

所以没有必要重新保存整个大模型。

只需要保存：

\[
A,B
\]

即可。

---

## 79. LoRA 权重文件本质保存什么？

例如：

```text
model.layers.0.self_attn.q_proj.lora.A.weight
model.layers.0.self_attn.q_proj.lora.B.weight

model.layers.0.self_attn.o_proj.lora.A.weight
model.layers.0.self_attn.o_proj.lora.B.weight

...

model.layers.7.self_attn.o_proj.lora.B.weight
```

这些就是模型学到的：

\[
\boxed{
\Delta W
}
\]

的低秩表示。

---

## 80. `merge_lora()` 最终干了什么？

LoRA 推理时：

\[
y=Wx+BAx
\]

注意：

\[
Wx+BAx
\]

可以提出：

\[
x
\]

得到：

\[
(W+BA)x
\]

所以定义：

\[
\boxed{
W_{new}=W+BA
}
\]

之后直接：

\[
y=W_{new}x
\]

就不需要运行两条支路了。

---

## 81. `merge_lora()` 的核心代码

逻辑相当于：

```python
module.weight += (
    module.lora.B.weight
    @
    module.lora.A.weight
)
```

也就是：

\[
\boxed{
W
\leftarrow
W+BA
}
\]

这就是：

> LoRA Merge。

---

## 82. Merge 前后数学上为什么等价？

Merge 前：

\[
y=Wx+BAx
\]

根据分配律：

\[
y=(W+BA)x
\]

定义：

\[
W'=W+BA
\]

于是：

\[
\boxed{
y=W'x
}
\]

因此推理时可以不再保留单独的：

```text
A branch
B branch
```

而直接使用合并后的 W。

## 84. 一整个 Batch 的完整生命周期

假设 DataLoader 给出：


```python
input_ids = input_ids.to(device)
labels = labels.to(device)
```

```python
res = model(
    input_ids,
    labels=labels
)
```

经过：

```text

↓
LoRA q_proj
↓

↓

```


```python
scaler.scale(loss).backward()
```

得到所有 LoRA：

```text
B.grad
```

```python
scaler.unscale_(optimizer)

```

### 84.9 第九步：更新 GradScaler


主要服务 FP16。

### 84.10 第十步：清除梯度

```python
optimizer.zero_grad(
```

## 87. 最容易混淆的五件事

### 87.1 第一：`apply_lora()` 本身并没有冻结 W

`apply_lora()` 只负责：

\[
Wx
\rightarrow
Wx+BAx
\]

真正冻结 W 的地方是在：

```python
train_lora.py
```

中的：

```python
if 'lora' in name:
    param.requires_grad = True
else:
    param.requires_grad = False
```

---

## 88. 第二：`requires_grad=False` 不等于梯度断掉

它只是表示：

```text
这个参数自己不用训练
```

并不是：

```text
梯度不能从这里经过
```

因此：

\[
W
\]

虽然冻结，依然参与：

```text
Forward
```

也依然参与：

```text
∂L/∂x
```

的计算。

---

## 89. 第三：LoRA 仍然使用普通 CE Loss

LoRA 不需要：

```text
LoRA Loss
```

也不存在：

```text
特殊 LoRA Backward
```

还是普通：

\[
CrossEntropy
\]

然后：

```python
loss.backward()
```

PyTorch 自动根据计算图和链式法则得到 A/B 梯度。

---

## 90. 第四：CE 不直接“知道” A 和 B

CE 只知道：

```text
模型最后预测错了多少
```

即：

\[
\frac{\partial L}{\partial logits}
\]

然后梯度通过：

```text
lm_head
↓
Transformer
↓
Attention
↓
q_proj / o_proj
↓
LoRA
```

一层层传回来。

所以 A/B 能更新的根本原因是：

\[
\boxed{
A/B参与了Forward计算图
}
\]

---

## 91. 第五：LoRA 学的是“如何修改原模型”

原模型：

\[
W
\]

保持固定。

LoRA 学：

\[
\Delta W
\]

其中：

\[
\Delta W=BA
\]

因此整个微调过程可以理解成：

> 不去重新学习一个完整的大模型，而是学习“原模型的权重应该往哪个方向做一个低秩修正”。

---

## 92. LoRA 训练总结

原模型线性层：

\[
\boxed{
y=Wx
}
\]

执行 `apply_lora()` 后：

\[
\boxed{
y=Wx+BAx
}
\]

`train_lora.py` 再将：

\[
W
\]

冻结，只让：

\[
A,B
\]

参与训练。

MiniMind 正常执行：

```text
Input
→ Transformer
→ logits
→ CrossEntropy
→ Loss
```

然后：

```python
loss.backward()
```

利用链式法则得到：

\[
\boxed{
\nabla_BL
=
g(Ax)^T
}
\]

以及：

\[
\boxed{
\nabla_AL
=
B^Tgx^T
}
\]

最后：

```python
optimizer.step()
```

只修改 A、B。

于是训练过程中不断学习：

\[
\boxed{
\Delta W=BA
}
\]

最后如果执行 Merge：

\[
\boxed{
W_{new}=W+BA
}
\]

因此整个 LoRA 可以浓缩成一句话：

\[
\boxed{
\text{冻结原来的 }W，
\text{用两个小矩阵 }A,B
\text{ 学习一个低秩修正 }\Delta W=BA。
}
\]

而 CE Loss 和普通 SFT 完全一样；LoRA 只是改变了：

> **哪些参数参与 Forward，以及最后哪些参数允许被反向传播更新。**
