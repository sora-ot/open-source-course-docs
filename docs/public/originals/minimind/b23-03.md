## 1. MoE 原理与 `MOEFeedForward` 源码完整讲解

下面我们不再把 MoE 只停留在公式层面，而是直接结合下面这段真实代码，从输入到输出完整跑一遍。

核心代码：

```python
class MOEFeedForward(nn.Module):
    def __init__(self, config: MiniMindConfig):
        super().__init__()
        self.config = config

        self.gate = nn.Linear(
            config.hidden_size,
            config.num_experts,
            bias=False
        )

        self.experts = nn.ModuleList([
            FeedForward(
                config,
                intermediate_size=config.moe_intermediate_size
            )
            for _ in range(config.num_experts)
        ])

        self.act_fn = ACT2FN[config.hidden_act]

    def forward(self, x):
        batch_size, seq_len, hidden_dim = x.shape

        x_flat = x.view(-1, hidden_dim)

        scores = F.softmax(
            self.gate(x_flat),
            dim=-1
        )

        topk_weight, topk_idx = torch.topk(
            scores,
            k=self.config.num_experts_per_tok,
            dim=-1,
            sorted=False
        )

        if self.config.norm_topk_prob:
            topk_weight = topk_weight / (
                topk_weight.sum(
                    dim=-1,
                    keepdim=True
                ) + 1e-20
            )

        y = torch.zeros_like(x_flat)

        for i, expert in enumerate(self.experts):

            mask = (topk_idx == i)

            if mask.any():

                token_idx = (
                    mask
                    .any(dim=-1)
                    .nonzero()
                    .flatten()
                )

                weight = (
                    topk_weight[mask]
                    .view(-1, 1)
                )

                y.index_add_(
                    0,
                    token_idx,
                    (
                        expert(x_flat[token_idx])
                        * weight
                    ).to(y.dtype)
                )

            elif self.training:

                y[0, 0] += (
                    0 *
                    sum(
                        p.sum()
                        for p in expert.parameters()
                    )
                )

        if (
            self.training
            and
            self.config.router_aux_loss_coef > 0
        ):

            load = F.one_hot(
                topk_idx,
                self.config.num_experts
            ).float().mean(0)

            self.aux_loss = (
                load
                * scores.mean(0)
            ).sum() \
            * self.config.num_experts \
            * self.config.router_aux_loss_coef

        else:

            self.aux_loss = (
                scores
                .new_zeros(1)
                .squeeze()
            )

        return y.view(
            batch_size,
            seq_len,
            hidden_dim
        )
```

## 2. 先回忆：MoE 本质上在干什么？

普通 Transformer：

```text
Token
  ↓
Attention
  ↓
FFN
```

每一个 Token 都经过：

\[
\boxed{\text{同一个 FFN}}
\]

而 MoE：

```text
Token
  ↓
Router
  ↓
Top-k
  ↓
若干 Expert
```

其中：

\[
\boxed{\text{Expert 本质上就是不同的 FFN}}
\]

所以：

\[
\boxed{
\text{MoE}
=
\text{多个 FFN Expert}
+
\text{一个 Router}
}
\]

例如有 4 个 Expert：

```text
Expert 0
Expert 1
Expert 2
Expert 3
```

对于某个 Token，Router 可能得到：

```text
E0 → 0.10
E1 → 0.60
E2 → 0.25
E3 → 0.05
```

如果：

\[
TopK=2
\]

那么只让这个 Token 经过：

```text
Expert 1
Expert 2
```

最终：

\[
y
=
g_1E_1(x)
+
g_2E_2(x)
\]

---

## 3. 这段代码在 Transformer 中替代的是什么？

普通 Transformer Block 中：

```text
Attention
   ↓
FFN
```

使用 MoE 后：

```text
Attention
   ↓
MOEFeedForward
```

而：

```python
MOEFeedForward
```

内部实际上是：

```text
             ┌→ Expert 0
             ├→ Expert 1
x → Router ──┼→ Expert 2
             └→ Expert 3
```

每个 Expert 本身仍然是：

```python
FeedForward(...)
```

所以 MoE 主要替换的是：

\[
\boxed{\text{FFN 部分}}
\]

## 20. `sorted=False` 是什么意思？

代码：

```python

```


```python
    topk_weight[mask]
    .view(-1, 1)
)
```

变成：

\[
weight=
\begin{bmatrix}
0.571\\
0.1875
\end{bmatrix}
\]

shape：

\[
[2,1]
\]

假设 Expert 输出：

\[
[2,H]
\]

比如：

\[
H=2
\]

那么：

\[
expert\_output
=
\begin{bmatrix}
a&b\\
c&d
\end{bmatrix}
\]

乘：

\[
\begin{bmatrix}
0.571\\
0.1875
\end{bmatrix}
\]

PyTorch 会广播成：

\[
\begin{bmatrix}
0.571a&0.571b\\
0.1875c&0.1875d
\end{bmatrix}
\]

所以每一个 Token：

> 整个 hidden vector 都乘自己的 Gate Weight。

## 43. 为什么 MoE 特别需要它？

因为：

\[
TopK>1
\]

时，一个 Token 会经过多个 Expert。

例如：

```text

 ↓
Expert 1
Expert 2
```

最终需要：

\[
y_0
=
g_1E_1(x_0)
+
g_2E_2(x_0)
\]

也就是说：

> Token 0 的输出位置要被写入不止一次。

所以不能：

```python

```

因为这样后来的 Expert 会把前一个 Expert 的结果覆盖掉。

必须：

```python
y.index_add_(...)
```

不断累加。

## 50. 为什么 `(expert(...) * weight).to(y.dtype)`？

代码：

```python

    expert(x_flat[token_idx])
    * weight
).to(y.dtype)
```

`expert(...)` 得到：

\[
[M,H]
\]

\[
[M,1]

## 52. 为什么会出现“没人使用的 Expert”？

```text
E1：有 Token
E2：没人
E3：没人
...
```

那么：

```python

```

根本没有调用。

这个 Expert 的参数：

```text
不会自然出现在当前前向计算路径中
```

## 53. 为什么这在分布式训练里可能麻烦？

某些分布式训练方式会检查：

```text
哪些参数参与了当前 forward/backward
```

如果某个 Expert 当前完全没被用到：

```text
这些参数可能被认为是 unused parameters
```

所以代码故意写：

\[
0\times
\sum p
\]

## 54. 为什么乘 0 还有意义？

假设某 Expert 参数：

\[
\theta
\]

我们加入：

\[
0\times\theta
\]

数值显然：

\[
0
\]

所以：

> 不会改变 y 的真正结果。

但是从计算图角度：

```text
y
依然和
θ
建立了连接
```

求导：

\[
\frac{\partial (0\theta)}
{\partial\theta}
=
0
\]

虽然梯度是 0：

\[
\boxed{\text{但参数参与了计算图}}
\]

这就是这一行真正的作用。

### 54.1 MoE 中这行代码到底在干什么？

```python
y[0, 0] += 0 * sum(
    p.sum() for p in expert.parameters()
)
```

这行代码看起来很奇怪，因为：

\[
0\times任何东西=0
\]

既然最后一定是 0，为什么还要写？

答案是：

\[
\boxed{
\text{这行代码的目的不是改变数值，而是把“没被选中的 Expert 参数”挂到当前计算图上。}
}
\]

它具有三个特点：

\[
\boxed{
\text{前向贡献}=0
}
\]

\[
\boxed{
\text{梯度}=0
}
\]

但是：

\[
\boxed{
\text{Expert 参数仍然参与当前计算图}
}
\]

这主要是为了处理 MoE 在训练，尤其是某些分布式训练场景中的 **unused parameter** 问题。

## 55. 为什么会出现“没有被使用的 Expert”？

先回忆 MoE。

假设有 4 个 Expert：

```text
Expert 0
Expert 1
Expert 2
Expert 3
```

当前 Batch 中有 3 个 Token，并且：

```text
Token 0 → Expert 0, Expert 1

Token 1 → Expert 0, Expert 2

Token 2 → Expert 1, Expert 2
```

那么当前 Batch：

```text
Expert 0：有人用
Expert 1：有人用
Expert 2：有人用
Expert 3：一个 Token 都没有
```

对于 Expert 0、1、2，会正常执行：

```python
expert(x_flat[token_idx])
```

例如：

```text
Token
  ↓
Expert 参数
  ↓
Expert Output
  ↓
y
  ↓
后续网络
  ↓
Loss
```

所以它们的参数自然参与当前计算图。

但是 Expert 3 一个 Token 都没收到。

于是：

```python
mask.any()
```

等于：

```python
False
```

不会执行：

```python
expert(x_flat[token_idx])
```

那么 Expert 3 的参数就完全没有参与本轮正常前向传播。

## 56. 如果什么都不写，会发生什么？

假设 Expert 3 有参数：

\[
W_1,W_2,W_3
\]

但是当前 Batch 完全没有 Token 使用它。

那么当前计算图可能是：

```text
Expert 0 参数 ─┐
               │
Expert 1 参数 ─┼→ y → 后续网络 → Loss
               │
Expert 2 参数 ─┘


Expert 3 参数

   ×

Loss
```

也就是说：

\[
\boxed{
Expert 3 的参数和当前 Loss 没有任何计算图连接
}
\]

在普通单卡训练里，这不一定马上造成严重问题。

但是在某些分布式训练场景里，框架可能需要判断：

> 哪些参数参加了这一轮 forward/backward？

如果某些 Expert 参数没有参加，可能被认为是：

\[
\boxed{\text{unused parameters}}
\]

因此代码人为给这些 Expert 参数建立一条：

\[
\boxed{\text{数值贡献为 0 的计算图路径}}
\]

那么：

里面可能包含：

```text
W_down
```

也就是这个 Expert 的所有可训练矩阵。

## 58. `p.sum()` 是什么意思？

代码：

```python
p.sum()
```

把一个参数矩阵压缩成一个标量。

例如：

\[
p=
\begin{bmatrix}
1&2\\
3&4
\end{bmatrix}
\]

那么：

\[
p.sum()
=
1+2+3+4
=
10
\]

但是这里：

\[
\boxed{
\text{根本不关心最后等于 10 还是 100}
}
\]

真正目的只是：

> 让参数 \(p\) 出现在计算图里。

计算图：

```text
p
│
▼
sum()
│
▼
标量
```

## 59. 为什么要把所有参数都求和？

代码：

```python
sum(
    p.sum()
    for p in expert.parameters()
)
```

假设 Expert 一共有三个参数：

\[
W_1,W_2,W_3
\]

那么相当于：

\[
S
=
\sum W_1
+
\sum W_2
+
\sum W_3
\]

所以：

\[
S
\]

依赖：

\[
W_1,W_2,W_3
\]

计算图：

```text
W1 → sum ─┐
           │
W2 → sum ─┼→ S
           │
W3 → sum ─┘
```

于是当前 Expert 的所有参数都已经被引用。

## 60. 然后为什么还要乘 `0`？

接下来：

```python

```

也就是：

\[
0\times S
\]

无论：

\[
S
\]

是多少，都有：

\[
0\times S=0
\]

所以从前向数值来看：

\[
\boxed{
0 * sum(...) = 0
}
\]

于是整行：

```python
y[0, 0] += 0 * sum(...)
```

就变成：

```python
y[0, 0] += 0
```

因此：

\[
\boxed{
y 的数值完全不会改变
}
\]

对于前向数值都没有区别。

这里只是选择：

作为一个最简单的“挂钩位置”。

## 65. 这行代码会训练这个没被选中的 Expert 吗？

不会。

这是最重要的一点。

假设某个参数：

\[
w
\]

这一行相当于：

\[
y
=
y_{old}
+
0w
\]

最终 Loss：

\[
L=L(y)
\]

根据链式法则：

\[
\frac{\partial L}{\partial w}
=
\frac{\partial L}{\partial y}
\frac{\partial y}{\partial w}
\]

而：

\[
y
=
y_{old}+0w
\]

所以：

\[
\frac{\partial y}{\partial w}
=
0
\]

因此：

\[
\boxed{
\frac{\partial L}{\partial w}
=
0
}
\]

也就是说：

> 这个 Expert 虽然参加了计算图，但这一轮不会因为这条 dummy 路径获得实际参数更新。

## 66. 最核心的区别：`grad=None` 和 `grad=0`

这是理解这行代码最重要的地方之一。

### 66.1 情况一：参数完全没有参与计算图

假设：

```python
w1 = Parameter(...)
w2 = Parameter(...)
```

Loss：

```python
loss = w1 ** 2
```

那么：

```text
w1 → loss
```

但是：

```text
w2
```

根本没有参与。

所以反向传播后概念上：

```text
w1.grad = 某个梯度

w2.grad = None
```

这里：

```text
None
```

意思是：

> 当前计算根本没有涉及这个参数。

---

## 67. 情况二：参数通过 `0 * w` 参与计算图

如果改成：

```python
loss = w1 ** 2 + 0 * w2
```

那么计算图：

```text
w1 ───────→ loss

w2 → ×0 ──→ loss
```

虽然：

\[
0w_2=0
\]

但是：

\[
w_2
\]

参与了计算图。

所以：

\[
\frac{\partial L}{\partial w_2}
=
0
\]

概念上：

```text
w2.grad = 0
```

而不是：

```text
w2.grad = None
```

因此：

\[
\boxed{
\text{grad=None}
\neq
\text{grad=0}
}
\]

---

## 68. 两者分别是什么意思？

### 68.1 `grad=None`

表示：

\[
\boxed{
\text{这个参数根本没有参与当前 Loss 的计算}
}
\]

---

### 68.2 `grad=0`

表示：

\[
\boxed{
\text{这个参数参与了计算，只不过当前导数恰好为 0}
}
\]

这就是：

```python
0 * parameter
```

技巧最核心的意义。

---

## 69. 为什么这对分布式训练有帮助？

MoE 中 Expert 是稀疏激活的。

比如不同 GPU 上：

```text
GPU 0：
Expert 0
Expert 1

GPU 1：
Expert 2
Expert 3
```

当前 Batch 可能：

```text
E0：有人用
E1：有人用
E2：有人用
E3：没人用
```

那么 E3 的参数如果完全没进入当前图：

```text
E3 参数
   ×
Loss
```

某些分布式训练机制可能把它判断成：

```text
unused parameter
```

这可能给：

```text
梯度同步
参数同步
DDP
```

等机制带来额外处理。

于是人为增加：

```python
0 * sum(...)
```

使它变成：

```text
E3 参数
   │
   ▼
  ×0
   │
   ▼
  Loss
```

于是框架看到的是：

> 这个参数参与了本轮计算，只不过梯度是 0。

而不是：

> 这个参数彻底没出现。

---

## 70. 为什么不直接执行一次 `expert(x)` 再乘 0？

例如为什么不写：

```python
0 * expert(x)
```

理论上也能够把 Expert 参数连进计算图。

但问题是：

> 这样真的会执行一遍完整 Expert FFN。

假设 Expert 包含：

```text
Linear
SiLU
Up Projection
Gate Projection
Down Projection
```

那么明明这个 Expert 一个 Token 都没收到，却还执行一次完整 FFN。

这样会浪费大量计算。

而：

```python
sum(
    p.sum()
    for p in expert.parameters()
)
```

只是简单引用参数并做求和。

不需要执行：

\[
Expert(x)
\]

完整前向。

所以它是一种更轻量的：

\[
\boxed{\text{Dummy Graph Connection}}
\]

即：

> 虚假的、零贡献的计算图连接。

---

## 71. 为什么只在训练时执行？

原代码：

```python
elif self.training:
    y[0, 0] += (
        0 *
        sum(
            p.sum()
            for p in expert.parameters()
        )
    )
```

重点：

```python
self.training
```

因为这个技巧主要解决的是：

```text
backward
梯度
分布式训练
参数同步
```

问题。

如果：

```python
model.eval()
```

进入推理：

```text
不做 backward

不更新参数
```

那么一个 Expert 没被选中：

> 直接跳过就行。

没有必要人为把它挂进计算图。

所以：

```text
训练模式：

Expert 没人用
↓
挂一个 0 贡献计算图


推理模式：

Expert 没人用
↓
直接跳过
```

## 72. 放回原来的 MoE 代码理解

原代码：

```python
for i, expert in enumerate(self.experts):

    mask = (topk_idx == i)

    if mask.any():

        token_idx = (
            mask
            .any(dim=-1)
            .nonzero()
            .flatten()
        )

        weight = (
            topk_weight[mask]
            .view(-1, 1)
        )

        y.index_add_(
            0,
            token_idx,
            (
                expert(x_flat[token_idx])
                * weight
            ).to(y.dtype)
        )

    elif self.training:

        y[0, 0] += (
            0 *
            sum(
                p.sum()
                for p in expert.parameters()
            )
        )
```

可以直接翻译成：

```text
如果当前 Expert 有 Token：

    真正运行 Expert
    ↓
    得到 Expert 输出
    ↓
    乘 Gate Weight
    ↓
    index_add_ 加回 y


如果当前 Expert 没有 Token：

    不运行 Expert
    ↓
    但训练阶段
    ↓
    用 0 × Expert参数
    ↓
    把参数挂到 y 的计算图上
```

## 73. 一个完整的具体例子

假设有：

```text
Expert 0
Expert 1
Expert 2
Expert 3
```

当前 Batch：

```text
Token 0 → Expert 0, Expert 1

Token 1 → Expert 0, Expert 2

Token 2 → Expert 1, Expert 2
```

所以：

```text
Expert 0：
Token 0
Token 1

Expert 1：
Token 0
Token 2

Expert 2：
Token 1
Token 2

Expert 3：
没人
```

---

### 73.1 Expert 0

```python
mask.any() == True
```

所以：

```text
取出 Token 0、1
↓
Expert 0 FFN
↓
乘权重
↓
index_add_
```

Expert 0 参数正常进入计算图。

---

### 73.2 Expert 1

同理：

```text
Token 0、2
↓
Expert 1
↓
y
```

参数正常进入计算图。

---

### 73.3 Expert 2

同理：

```text
Token 1、2
↓
Expert 2
↓
y
```

参数正常进入计算图。

---

### 73.4 Expert 3

因为：

```python
mask.any() == False
```

所以根本没有：

```python
expert3(...)
```

正常情况下：

```text
Expert 3 参数

    ×

    y
```

于是训练模式下执行：

```python
y[0, 0] += (
    0 *
    sum(
        p.sum()
        for p in expert3.parameters()
    )
)
```

构造：

```text
Expert 3 参数
      │
      ▼
  参数全部求和
      │
      ▼
     × 0
      │
      ▼
      0
      │
      ▼
   y[0,0]
      │
      ▼
 后续 Transformer
      │
      ▼
     Loss
```

于是：

\[
\boxed{
Expert 3 进入了计算图
}
\]

但是：

\[
\boxed{
Expert 3 对当前输出贡献为 0
}
\]

并且：

\[
\boxed{
Expert 3 当前梯度为 0
}
\]

## 74. 为什么这种做法不会破坏模型输出？

因为加入：

\[
0\times参数
\]

永远是：

\[
0
\]

所以：

\[
y_{new}
=
y_{old}+0
\]

即：

\[
\boxed{
y_{new}=y_{old}
}
\]

因此：

```text
logits 不变
预测不变
Cross Entropy 不变
前向结果不变
```

唯一改变的是：

\[
\boxed{
\text{计算图结构}
}
\]

## 75. 最终可以把这行代码理解成什么？

原代码：

```python
y[0, 0] += 0 * sum(
    p.sum()
    for p in expert.parameters()
)
```

最容易理解的中文翻译是：

> **“这个 Expert 当前虽然没有任何 Token 使用，但训练时仍然把它的全部参数通过一个数值为 0 的假路径连接到输出 y 上，使它参与当前计算图，从而避免它彻底成为未使用参数；由于前面乘了 0，因此不会改变输出，也不会产生真正的参数更新。”**

---

## 76. 最后记住这三个结论

### 76.1 第一

\[
\boxed{
0\times parameter
\text{ 的前向值为 0}
}
\]

所以：

> 不改变模型输出。

---

### 76.2 第二

\[
\boxed{
\frac{\partial(0\theta)}
{\partial\theta}
=
0
}
\]

所以：

> 不会真正训练这个没有被选中的 Expert。

---

### 76.3 第三

虽然：

\[
0\theta=0
\]

但是：

\[
\theta
\]

依然参与了这个运算，所以：

\[
\boxed{
\theta
\text{ 仍然存在于当前计算图中}
}
\]

---

## 77. 一句话总结

\[
\boxed{
\texttt{y[0,0] += 0 * sum(...)}
}
\]

本质就是：

\[
\boxed{
\text{用一个“数值为 0、梯度也为 0，但计算图不断开”的假连接，
把当前没有被路由到的 Expert 参数挂到最终输出上。}
}
\]

可以把它记成：

```text
没人使用的 Expert
        ↓
不真正执行 FFN
        ↓
所有参数求和
        ↓
      × 0
        ↓
   数值还是 0
        ↓
      加到 y
        ↓
参数仍在计算图中
```

所以这行代码的核心目的不是：

\[
\boxed{\text{计算}}
\]

而是：

\[
\boxed{\text{维持计算图连接}}
\]
