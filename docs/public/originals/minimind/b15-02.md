## 1. `Attention`：把 Q/K/V、RoPE、GQA、Mask、Softmax、KV Cache 全部拼起来

现在终于进入整个文件最核心的模块之一：

```python
class Attention(nn.Module):
```

先不要看细节，先把它的“任务合同”写清楚。

输入：

```text
x: [B,T,H]
```

输出：

```text
output: [B,T,H]
past_kv: 可选的 (K,V)
```

也就是说：

> Attention 可以把每个 token 当前的 H 维表示，变成“已经从可见上下文读取信息之后”的 H 维表示。

内部会经历：

```text
[B,T,H]
   │
   ├─ q_proj → [B,T,Nq*D] → [B,T,Nq,D]
   ├─ k_proj → [B,T,Nkv*D] → [B,T,Nkv,D]
   └─ v_proj → [B,T,Nkv*D] → [B,T,Nkv,D]

Q/K → RMSNorm
Q/K → RoPE
K/V → 与历史 cache 拼接
K/V → repeat_kv
Q/K/V → transpose
QK^T / sqrt(D)
→ causal mask / padding mask
→ softmax
→ @ V
→ 多头合并
→ o_proj
→ [B,T,H]
```

这一章一定要把“创建机器”和“运行机器”分开讲：

```text
Attention.__init__   = 把所有子层装好
Attention.forward    = 真正让 x 流过这些子层
```

---

### 1.1 `class Attention(nn.Module)`

这和前面的 RMSNorm 一样，表示 Attention 是一个 PyTorch 模块。

它里面还会包含很多子模块：

```text
q_proj
k_proj
v_proj
o_proj
q_norm
k_norm
attn_dropout
resid_dropout
```

只要这些东西赋给：

```python
self.xxx
```

而且本身是 `nn.Module`，PyTorch 就会把它们注册成当前 Attention 的子模块。

因此以后：

```python
model.parameters()
```

能够递归找到所有 Q/K/V/O 的权重。

### 1.2 `Attention.__init__(config)`：先读取配置

源码：

```python
def __init__(self, config: MiniMindConfig):
    super().__init__()
```

这里的：

```python
config: MiniMindConfig
```

只是类型提示，告诉读者：

> 这个参数预期是 MiniMindConfig 对象。

比如：

```python
cfg = MiniMindConfig(
    hidden_size=8,
    num_attention_heads=2,
    num_key_value_heads=1,
    head_dim=4
)
attn = Attention(cfg)
```

这一步只是在“造 Attention”，没有输入 token。

---

### 1.3 KV Head 数的兼容逻辑

源码：

```python
self.num_key_value_heads = (
    config.num_attention_heads
    if config.num_key_value_heads is None
    else config.num_key_value_heads
)
```

这是 Python 的条件表达式：

```python
A if condition else B
```

最简单例子：

```python
age = 20
label = "adult" if age >= 18 else "child"
```

这里的逻辑是：

```text
如果 config.num_key_value_heads == None
    那就让 Nkv = Nq
否则
    使用显式配置的 Nkv
```

为什么这样设计？

因为：

```text
Nkv = Nq
```

时，就是普通多头注意力风格，不需要共享 KV。

而：

```text
Nkv < Nq
```

时，才是 GQA/MQA 风格。

---

### 1.4 保存 Query Head、KV Head

源码：

```python
self.n_local_heads = config.num_attention_heads
self.n_local_kv_heads = self.num_key_value_heads
```

例如：

```text
Nq = 8
Nkv = 4
```

那么：

```text
self.n_local_heads = 8
self.n_local_kv_heads = 4
```

这里变量名里虽然有 `local`，但本文件并没有在此处实现 tensor parallel 的“本卡局部 head 划分”。

可以把它单纯理解为本模块当前使用的 head 数。

---

### 1.5 `n_rep`：每个 KV Head 被多少个 Query Head 共用

源码：

```python
self.n_rep = self.n_local_heads // self.n_local_kv_heads
```

例如：

```text
8 // 4 = 2
```

所以：

```text
每个 KV Head 服务 2 个 Query Head
```

如果：

```text
Nq=8
Nkv=1
```

则：

```text
n_rep = 8
```

所有 8 个 Query Head 共用一组 KV，这就更接近 MQA。

这也说明一个隐含要求：

```text
Nq 应该能被 Nkv 整除
```

否则整数除法会产生不完整分组。

---

### 1.6 `head_dim`

源码：

```python
self.head_dim = config.head_dim
```

这是每个注意力头的维度 D。

例如：

```text
H=4096
Nq=32
```

常见：

```text
D=128
```

因为：

```text
32 × 128 = 4096
```

但这份代码允许显式设置 `head_dim`，所以不强制：

```text
Nq*D == H
```

即使不等，最后：

```python
self.o_proj
```

仍会把 `Nq*D` 投影回 H。

---

### 1.7 `self.is_causal = True`

```python
self.is_causal = True
```

非常重要。

它说明这是：

```text
Causal Self-Attention
```

位置 t 只能看：

```text
0 ... t
```

不能看：

```text
t+1 ... future
```

例如四个 token：

```text
BOS   I   love   AI
```

可见关系：

```text
BOS   ✓  ×  ×  ×
I     ✓  ✓  ×  ×
love  ✓  ✓  ✓  ×
AI    ✓  ✓  ✓  ✓
```

这正是后面 causal mask 要实现的规则。

---

### 1.8 `q_proj`：H 维 hidden state 如何变成多头 Query

源码：

```python
self.q_proj = nn.Linear(
    config.hidden_size,
    config.num_attention_heads * self.head_dim,
    bias=False
)
```

假设教学配置：

```text
H=8
Nq=2
D=4
```

输出宽度：

```text
Nq×D = 2×4 = 8
```

因此：

```text
q_proj: 8 → 8
```

输入：

```text
x.shape = [1,3,8]
```

经过 Linear：

```text
xq.shape = [1,3,8]
```

注意这时候还是：

```text
[1,3,Nq*D]
```

并没有真的出现一个独立的 head 轴。

后面才会：

```python
.view(1,3,2,4)
```

变成：

```text
[1,3,2,4]
```

---

### 1.9 `bias=False` 是什么意思？

普通 Linear：

```math
y=xW^T+b
```

但：

```python
bias=False
```

表示不创建 b。

于是只有：

```math
y=xW^T
```

如果：

```python
layer = nn.Linear(8, 8, bias=False)
```

那么参数只有：

```text
weight.shape = [8,8]
```

没有：

```text
bias.shape = [8]
```

---

### 1.10 `k_proj`、`v_proj`：为什么输出比 Q 小？

源码：

```python
self.k_proj = nn.Linear(
    config.hidden_size,
    self.num_key_value_heads * self.head_dim,
    bias=False
)

self.v_proj = nn.Linear(
    config.hidden_size,
    self.num_key_value_heads * self.head_dim,
    bias=False
)
```

教学配置：

```text
H=8
Nq=2
Nkv=1
D=4
```

那么：

```text
q_proj: 8 → 8
k_proj: 8 → 4
v_proj: 8 → 4
```

所以：

```text
Q 有两个 head
K/V 只有一个 head
```

为什么这么做？

核心是节约：

```text
K/V 投影参数
+
推理时 KV Cache 大小
```

尤其 KV Cache 与：

```text
Nkv
```

成正比。

---

### 1.11 `o_proj`：多头结果重新映射回 H

源码：

```python
self.o_proj = nn.Linear(
    config.num_attention_heads * self.head_dim,
    config.hidden_size,
    bias=False
)
```

输入宽度：

```text
Nq×D
```

输出宽度：

```text
H
```

教学配置：

```text
2×4 = 8
```

所以：

```text
8 → 8
```

大型例子：

```text
Nq=32
D=128
H=4096
```

也是：

```text
4096 → 4096
```

但概念上这不是“什么都没做”。

它仍然有一个可学习矩阵：

```text
W_O
```

负责让各个 head 拼接后的信息重新混合。

---

### 1.12 `q_norm` 和 `k_norm`

源码：

```python
self.q_norm = RMSNorm(
    self.head_dim,
    eps=config.rms_norm_eps
)

self.k_norm = RMSNorm(
    self.head_dim,
    eps=config.rms_norm_eps
)
```

这里特别注意：

```text
dim = head_dim = D
```

不是 H。

所以如果 Q：

```text
[B,T,Nq,D]
```

RMSNorm 总是沿最后一维 D。

每个：

```text
batch × token × head
```

组合都自己算一个 RMS。

另外：

```text
q_norm 和 k_norm 不共享 weight
```

因为它们是两个独立 RMSNorm 实例。

### 1.13 两个 Dropout

源码：

```python
self.attn_dropout = nn.Dropout(config.dropout)
self.resid_dropout = nn.Dropout(config.dropout)
self.dropout = config.dropout
```

#### 1.13.1 `attn_dropout`

作用在：

```text
softmax 后的注意力权重
```

#### 1.13.2 `resid_dropout`

作用在：

```text
Attention 输出经过 o_proj 以后
```

#### 1.13.3 `self.dropout`

这里只保存概率值，例如：

```text
0.1
```

因为后面的 SDPA API 需要直接传：

dropout_p=...
```

而不是传一个 `nn.Dropout` 对象。

m = nn.Dropout(p=0.5)

m.eval()

再调用：

model.eval()
```

### 1.15 `self.flash`：这里的名字不要误解成“必然使用 FlashAttention”

源码：

```python
self.flash = (
    hasattr(torch.nn.functional, 'scaled_dot_product_attention')
    and config.flash_attn
)
```

先拆：

```python
hasattr(obj, "name")
```

意思：

> obj 上有没有名为 name 的属性。

例如：

```python
hasattr(torch.nn.functional, "softmax")
```

通常：

```text
True
```

这里检查：

```text
当前 PyTorch 是否提供 scaled_dot_product_attention
```

同时还要求：

```text
config.flash_attn == True
```

只有两个条件都满足：

```text
self.flash = True
```

但这个变量名只是作者的命名。

真正调用的是 PyTorch：

```python
F.scaled_dot_product_attention
```

底层究竟选择哪种 kernel，取决于 PyTorch、硬件、dtype、shape 等运行条件。

因此不能简单理解为：

> `self.flash=True` 就一定在用某个特定 FlashAttention 实现。

## 2. `Attention.forward()`：真正让一批 token 通过 Attention

现在进入最重要的执行函数：

```python
def forward(
    self,
    x,
    position_embeddings,
    past_key_value=None,
    use_cache=False,
    attention_mask=None
):
```

先把每个参数翻译成人话。

```text
x
    当前这次新输入 token 的 hidden states
    shape [B,T,H]

position_embeddings
    这 T 个位置对应的 cos/sin

past_key_value
    本层历史 K/V；第一次推理通常是 None

use_cache
    是否把更新后的 K/V 返回给外层保存

attention_mask
    哪些 Key 位置有效，哪些是 padding
```

非常重要：

> 每一层 Attention 都有自己独立的 KV Cache。

不能把第 0 层的 K/V 给第 1 层用。

---

### 2.1 `bsz, seq_len, _ = x.shape`

源码：

```python
bsz, seq_len, _ = x.shape
```

假设：

```text
x.shape = [2,3,8]
```

那么：

```text
bsz = 2
seq_len = 3
_ = 8
```

Python 里 `_` 并不是特殊关键字，只是约定俗成表示：

> 这个值接到了，但后面我不打算用。

所以相当于：

```python
bsz, seq_len, hidden_size = x.shape
```

只是 hidden_size 后面不需要。

---

### 2.2 一次得到 Q/K/V

源码：

```python
xq, xk, xv = self.q_proj(x), self.k_proj(x), self.v_proj(x)
```

这是 Python 的多变量赋值。

展开如下：

```python
xq = self.q_proj(x)
xk = self.k_proj(x)
xv = self.v_proj(x)
```

教学配置：

```text
x:  [1,3,8]
Q:  [1,3,8]
K:  [1,3,4]
V:  [1,3,4]
```

此时：

```text
Q/K/V 都只是 Linear 输出
```

还没有：

```text
拆头
RoPE
Attention Score
```

---

### 2.3 `.view(...)`：真正出现 head 轴

源码：

```python
xq = xq.view(
    bsz,
    seq_len,
    self.n_local_heads,
    self.head_dim
)
```

教学配置：

```text
[1,3,8]
→
[1,3,2,4]
```

假设某个 token 的 Q 是：

```text
[a,b,c,d,e,f,g,h]
```

重新解释为：

```text
Head 0 = [a,b,c,d]
Head 1 = [e,f,g,h]
```

`.view()` 主要改变 shape 的解释方式，不做一个新的神经网络投影。

所以“每个 head 有独立信息”来源于前面的可训练 Q 投影矩阵学会把不同特征放到不同分块，而不是 `view()` 本身创造语义。

---

### 2.4 K/V 同样拆头

```python
xk = xk.view(
    bsz,
    seq_len,
    self.n_local_kv_heads,
    self.head_dim
)

xv = xv.view(
    bsz,
    seq_len,
    self.n_local_kv_heads,
    self.head_dim
)
```

教学配置：

```text
K: [1,3,4] → [1,3,1,4]
V: [1,3,4] → [1,3,1,4]
```

所以现在终于能清楚看到：

```text
Q 有 2 个 Head
K/V 只有 1 个 Head
```

---

### 2.5 Q/K RMSNorm

源码：

```python
xq, xk = self.q_norm(xq), self.k_norm(xk)
```

展开：

```python
xq = self.q_norm(xq)
xk = self.k_norm(xk)
```

shape 不变：

```text
Q: [B,T,Nq,D]
K: [B,T,Nkv,D]
```

只是每个 head 内部 D 个值的尺度被规范化。

V 不做这一步。

---

### 2.6 `cos, sin = position_embeddings`

外层传进来的是一个 tuple：

```text
(cos_tensor, sin_tensor)
```

于是 Python 解包：

```python
cos, sin = position_embeddings
```

假设本次 T=3：

```text
cos: [3,D]
sin: [3,D]
```

如果这是缓存后的单 token 续写：

```text
T=1
```

可能只切位置 3：

```text
cos: [1,D]
sin: [1,D]
```

---

### 2.7 真正应用 RoPE

源码：

```python
xq, xk = apply_rotary_pos_emb(xq, xk, cos, sin)
```

我们已经讲过这个函数。

关键一句：

> 这里只旋转“本轮新算出来”的 Q/K。

如果有历史 KV Cache，历史 K 在它第一次生成时已经根据当时绝对位置旋转过了。

所以绝对不能每轮把历史 K 再旋转一遍。

---

### 2.8 KV Cache：历史 K/V 与新 K/V 拼接

源码：

```python
if past_key_value is not None:
    xk = torch.cat([past_key_value[0], xk], dim=1)
    xv = torch.cat([past_key_value[1], xv], dim=1)
```

先理解 `past_key_value` 的结构：

```text
past_key_value
=
(
    past_K,
    past_V
)
```

所以：

```python
past_key_value[0]
```

是历史 K。

```python
past_key_value[1]
```

是历史 V。

---

### 2.9 `torch.cat(..., dim=1)` 为什么是 dim=1？

缓存前的布局：

```text
[B,S,Nkv,D]
```

第 1 维是：

```text
sequence length
```

所以历史：

```text
past_K: [1,3,1,4]
```

本轮新 token：

```text
new_K:  [1,1,1,4]
```

沿 dim=1 拼：

```text
[1,4,1,4]
```

直观：

```text
[K1,K5,K7] + [K9]
=
[K1,K5,K7,K9]
```

V 同理。

---

### 2.10 为什么缓存 K/V，不缓存历史 Q？

这一行代码就是最直接的证据。

新 token 需要计算：

```text
Q_new @ [K_old, K_new]^T
```

然后：

```text
weights @ [V_old, V_new]
```

本轮根本没有用到：

```text
Q_old
```

历史 Q 的任务是：

> 当它还是“新 token”的那一轮，决定那个位置应该关注谁。

到了下一轮，新增加的是另一个 Query，所以历史 Q 不再产生新的计算价值。

---

### 2.11 `past_kv = (xk, xv) if use_cache else None`

源码：

```python
past_kv = (xk, xv) if use_cache else None
```

这又是条件表达式。

如果：

```text
use_cache=True
```

就返回：

```text
(K,V)
```

否则：

```text
None
```

特别注意顺序：

> 这里保存 cache 时，K/V 还没有经过 `repeat_kv()`。

这非常合理。

如果 Nkv=4、Nq=32，没必要把 K/V 先重复成 32 个头再存。

否则缓存空间直接膨胀 8 倍。

所以缓存保存：

```text
原始 Nkv 头
```

真正计算 Attention 时临时 repeat。

---

### 2.12 一行里做了三件事：transpose + repeat_kv

源码：

```python
xq, xk, xv = (
    xq.transpose(1, 2),
    repeat_kv(xk, self.n_rep).transpose(1, 2),
    repeat_kv(xv, self.n_rep).transpose(1, 2)
)
```

教学必须拆成：

```python
xq = xq.transpose(1, 2)

xk = repeat_kv(xk, self.n_rep)
xk = xk.transpose(1, 2)

xv = repeat_kv(xv, self.n_rep)
xv = xv.transpose(1, 2)
```

---

### 2.13 `transpose(1,2)` 到底交换什么？

Q 原来：

```text
[B,T,Nq,D]
```

交换维 1 和维 2：

```text
[B,Nq,T,D]
```

为什么？

因为接下来矩阵乘法希望每个 head 独立进行：

```text
Q_head: [T,D]
K_head: [S,D]
```

这样：

```text
Q @ K^T
```

自然得到：

```text
[T,S]
```

所以把 head 放到 sequence 前面，会非常方便。

---

### 2.14 K/V repeat 后的 shape

假设首次输入：

```text
B=1
T=S=3
Nq=2
Nkv=1
D=4
```

原始：

```text
K: [1,3,1,4]
V: [1,3,1,4]
```

repeat 2 份：

```text
[1,3,2,4]
```

transpose：

```text
[1,2,3,4]
```

于是最终：

```text
Q: [1,2,3,4]
K: [1,2,3,4]
V: [1,2,3,4]
```

每个 Query Head 现在都有对应的 K/V 可算。

---

### 2.15 为什么有两条 Attention 路径？

源码：

```python
if self.flash and ...:
    output = F.scaled_dot_product_attention(...)
else:
    ...手动计算...
```

这不是两个不同理论。

两条都在做同一类事情：

```math
\operatorname{softmax}\left(\frac{QK^T}{\sqrt D}+mask\right)V
```

区别只是：

```text
一条交给 PyTorch 的 SDPA 高层接口
另一条把 score、mask、softmax、@V 显式写出来
```

可以对照手动实现与 SDPA 的计算过程。

---

### 2.16 SDPA 分支的条件逐项解释

源码条件：

```python
if (
    self.flash
    and (seq_len > 1)
    and (not self.is_causal or past_key_value is None)
    and (
        attention_mask is None
        or torch.all(attention_mask == 1)
    )
):
```

逐项看。

#### 2.16.1 条件 1：`self.flash`

当前 PyTorch 有 SDPA，并且配置允许。

#### 2.16.2 条件 2：`seq_len > 1`

当前一次至少有两个新 token。

单 token 解码通常走手动路径。

#### 2.16.3 条件 3：

```python
not self.is_causal or past_key_value is None
```

本模型 `is_causal=True`，所以实际要求：

```text
past_key_value is None
```

也就是首次整段输入时可以走这条简单 causal SDPA 路径。

#### 2.16.4 条件 4：

```python
attention_mask is None
or
torch.all(attention_mask == 1)
```

如果有 padding 需要额外屏蔽，则不走这里。

### 2.20 手动 Attention 路径：先算 score

源码：

```python
scores = (
    xq @ xk.transpose(-2, -1)
) / math.sqrt(self.head_dim)
```

先看：

```python
xk.transpose(-2,-1)
```

如果：

```text
K: [B,Nq,S,D]
```

交换最后两维：

```text
[B,Nq,D,S]
```

于是：

```text
Q: [B,Nq,T,D]
K^T:[B,Nq,D,S]
```

矩阵乘：

```text
[B,Nq,T,S]
```

也就是每一个：

```text
batch × head
```

都有一个：

```text
T × S
```

Attention Score 矩阵。

### 2.21 `@` 是矩阵乘法，不是逐元素乘法

Python/PyTorch：

```python
A @ B
```

等价于矩阵乘语义。

而：

```python
A * B
```

是逐元素乘法。

这是后面 FFN 里非常容易混淆的一点。

Attention：

```text
Q @ K^T
```

FFN gate：

```text
act(gate) * up
```

两个完全不同。

---

### 2.22 为什么除以 `sqrt(head_dim)`？

```python
math.sqrt(self.head_dim)
```

例如：

```text
D=4 → sqrt(D)=2
D=128 → sqrt(D)≈11.31
```

Q/K 维度越大，点积累加的项越多，数值通常容易变大。

除以：

```math
\sqrt D
```

控制 score 的尺度，避免 softmax 过早过尖。

### 2.23 因果 Mask：为什么只处理最后 `seq_len` 列？

源码：

```python
if self.is_causal:
    scores[:, :, :, -seq_len:] += torch.full(
        (seq_len, seq_len),
        float("-inf"),
        device=scores.device
    ).triu(1)
```

这是整个缓存逻辑里很漂亮的一行。

先看没有历史 cache：

```text
S=T=3
```

最后 `seq_len=3` 列就是全部列。

创建：

```python
torch.full((3,3), -inf)
```

得到：

```text
[-inf -inf -inf]
[-inf -inf -inf]
[-inf -inf -inf]
```

`.triu(1)`：

只保留主对角线以上：

```text
[0    -inf -inf]
[0     0   -inf]
[0     0    0  ]
```

加到 score 后：

```text
未来位置变成 -inf
```

softmax 后概率就是 0。

---

### 2.24 `.triu(1)` 是什么？

`triu` = upper triangular。

例如：

```python
x = torch.ones(3,3)
print(x.triu(1))
```

得到：

```text
0 1 1
0 0 1
0 0 0
```

参数 `1` 表示：

> 从主对角线的上一条对角线开始保留。

所以自己位置不屏蔽，只屏蔽未来。

---

### 2.25 有 cache 时为什么历史列不需要 causal mask？

假设历史 3 个 token，新输入 2 个 token。

那么：

```text
S=5
T=2
scores.shape=[B,Nq,2,5]
```

列：

```text
历史0 历史1 历史2 新0 新1
```

对于两个新 Query：

```text
新0 可以看全部历史 + 自己，但不能看新1
新1 可以看全部历史 + 新0 + 自己
```

所以历史前三列全部合法，不需要屏蔽。

只需要对最后 T=2 列做：

```text
[0  -inf]
[0   0  ]
```

这正是：

```python
scores[:, :, :, -seq_len:]
```

只取最后的新 token 区域的原因。

### 2.26 Padding Mask

源码：

```python

    scores += (
        1.0
        - attention_mask.unsqueeze(1).unsqueeze(2)
    ) * -1e9
```

假设：

```text
attention_mask = [[1,1,0]]
```

shape：

```text
[B,S] = [1,3]
```

第一次：

```python
unsqueeze(1)
```

变：

```text
[1,1,3]
```

第二次：

```python
unsqueeze(2)
```

变：

```text
[1,1,1,3]
```

然后广播到：

```text

```

### 2.27 为什么是 `(1-mask)*-1e9`？

mask：

```text
[1,1,0]
```

`1-mask`：

```text
[0,0,1]
```

乘：

```text
-1e9
```

得到：

```text
[0,0,-1000000000]
```

加到 score：

```text
有效位置：不变
padding：极大负数
```

softmax 后 padding 概率接近 0。

注意：

> 这主要是在屏蔽 Key 列，不是把“padding Query 行”自动清零。

这是理解 attention_mask 很重要的细节。

### 2.29 `dim=-1`：沿谁做 Softmax？

score：

```text
[B,Nq,T,S]
```

最后一维 S 表示：

```text
当前 Query 能看的所有 Key 位置
```

所以对每一个 Query：

```text
S 个分数 → S 个概率
```

并满足：

```text
这些概率之和 = 1
```

例如：

```text
scores = [2,1,0]
```

softmax 约：

```text
[0.665,0.245,0.090]
```

意思：

```text
当前 Query
从三个 Value 中分别读 66.5%、24.5%、9.0%
```

---

### 2.30 为什么 Softmax 先 `.float()`？

同 RMSNorm 类似。

softmax 包含：

```text
指数
求和
归一化
```

对数值精度比较敏感。

所以先 FP32：

```python
scores.float()
```

算完后再：

```python
.type_as(xq)
```

恢复 Q 的 dtype。

### 2.31 `weights @ xv` 到底算什么？

shape：

```text
weights: [B,Nq,T,S]
V:       [B,Nq,S,D]
```

矩阵乘：

```text
[B,Nq,T,D]
```

对某一个 Query：

```math
O_i=\sum_j\alpha_{ij}V_j
```

例如：

```text
alpha = [0.7,0.2,0.1]
```

三个 Value：

```text
V1=[1,0]
V2=[0,2]
V3=[3,1]
```

输出：

```text
0.7*[1,0]
+
0.2*[0,2]
+
0.1*[3,1]
```

得到：

```text
[1.0,0.5]
```

这才是 Attention 真正“从上下文读取内容”的动作。

### 2.36 缓存后单 token 续写的完整 shape

已有历史 3 个 token：

```text
past_K/V = [1,3,1,4]
```

本轮只输入新 token：

```text
x=[1,1,8]
T=1
```

新 Q/K/V：

```text
Q [1,1,2,4]
K [1,1,1,4]
V [1,1,1,4]
```

K/V 与历史拼：

```text
[1,4,1,4]
```

保存新 cache：

```text
长度 4
```

repeat + transpose：

```text
Q [1,2,1,4]
K [1,2,4,4]
V [1,2,4,4]
```

score：

```text
[1,2,1,4]
```

解释：

> 两个 Query Head，各自只有 1 个新 Query；这个 Query 可以对 4 个历史/当前 Key 打分。

最后输出：

```text
[1,1,8]
```

这就是 KV Cache 为什么让生成从“每轮重算整个序列”变成“每轮只处理新增 token”。

### 2.37 Attention 这一章最终应该记住的代码骨架

把工程细节全部拿掉，只剩：

```python
def attention(x, past_kv=None):
    Q = q_proj(x)
    K = k_proj(x)
    V = v_proj(x)

    Q = split_heads(Q)
    K = split_heads(K)
    V = split_heads(V)

    Q = q_norm(Q)
    K = k_norm(K)

    Q, K = rope(Q, K)

    if past_kv is not None:
        K = cat(past_K, K)
        V = cat(past_V, V)

    cache = (K, V)

    K = repeat_kv(K)
    V = repeat_kv(V)

    score = Q @ K.T / sqrt(D)
    score = causal_mask(score)
    weight = softmax(score)
    out = weight @ V

    out = concat_heads(out)
    out = o_proj(out)

    return out, cache
```
