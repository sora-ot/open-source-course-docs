## 1. 接下来进入 Aux Loss

代码：

```python
if (
    self.training
    and
    self.config.router_aux_loss_coef > 0

```

也就是：

> 只有训练时，并且辅助损失系数大于 0，才计算 Router 负载均衡损失。

因为推理时：

```text
不需要训练 Router
```

---

## 2. 为什么 MoE 需要 Aux Loss？

因为 Router 可能产生：

\[
\boxed{\text{Expert Collapse}}
\]

比如：

```text
E0 → 几乎没人
E1 → 几乎没人
E2 → 80% Token
E3 → 几乎没人
```

这会导致：

```text
大量 Expert 参数浪费

负载不均衡

某些 GPU 特别忙

其他 GPU 空闲
```

因此要额外惩罚严重偏向某些 Expert 的 Router。


真正主要任务还是：

\[
L_{\text{LM}}
\]

也就是语言模型的 Cross Entropy。

所以最后：

\[
L
=
L_{\text{LM}}
+
L_{\text{aux}}
\]

而配置：

```python

```

> 负载均衡到底有多重要。

如果它太大：

```text

牺牲真正的模型能力。
```

如果太小：

```text

```

## 17. 为什么需要同时有“实际负载”和“Router 概率”？

如果只看实际选择：

```text

```

我们确实知道它过载。

但是实际选择来源于：

```text
Top-k
```

这是一个离散过程。

它不方便直接给 Router 一个平滑梯度。

而：

\[
P_i
\]

来自：

\[
softmax(W_rx)
\]

它是：

\[
\boxed{\text{可微}}
\]

的。

所以：

```text
load
告诉模型：
实际谁太忙。

P_i
提供梯度：
Router 应该怎么调。
```

## 19. General Aux Loss 和代码实现里的区别

先看最通用的公式：

\[
\boxed{
L_{\text{aux}}
=
\lambda E
\sum_{i=1}^{E}
f_iP_i
}
\]

其中：

\[
P_i
=
\frac1T
\sum_{t=1}^{T}
p_{t,i}
\]

表示：

> Router 对 Expert \(i\) 的平均概率。

而：

\[
f_i
=
\frac{
\text{Expert }i\text{ 被 Top-k 选中的总次数}
}{
T\times K
}
\]

表示：

> 把所有 Top-k 位置合在一起以后，Expert \(i\) 实际承担了多少比例的路由。

---

## 20. General 公式：不区分“第几个 Top-k”

假设：

\[
TopK=2
\]

有 3 个 Token：

```text
Token 0 → E1, E2

Token 1 → E0, E3

Token 2 → E2, E0
```

一共有：

\[
3\times2=6
\]

次 Expert 选择。

统计每个 Expert 总共被选中了多少次：

```text
E0：2 次
E1：1 次
E2：2 次
E3：1 次
```

因此：

\[
f_0=\frac26=\frac13
\]

\[
f_1=\frac16
\]

\[
f_2=\frac26=\frac13
\]

\[
f_3=\frac16
\]

所以：

\[
\boxed{
f=
\left[
\frac13,
\frac16,
\frac13,
\frac16
\right]
}
\]

这里完全不关心：

```text
E0 是第一个被选中，
还是第二个被选中。
```

只要被选中一次，就记一次。

所以 General 公式的思想是：

\[
\boxed{
\text{把全部 }T\times K\text{ 次路由放在一起统计}
}
\]

---

```text

Token 1 → E0, E3

Token 2 → E2, E0
```

但是代码不会立刻把 6 次选择全部混在一起。

而是分别看两个位置。

General 公式：

\[
\boxed{

\left[

\frac16,

\frac16
\right]
}
\]

\[

=

## 26. 但是有一个非常重要的系数区别

General 形式：

\[
L_{\text{aux}}
=
\lambda E
\sum_i
f_iP_i
\]

因为：

\[
f_i
=
\frac{
f_i^{(1)}+f_i^{(2)}
}{2}
\]

所以代入：

\[

\[
\boxed{

\right]
}
\]

代码式的思路更接近：

\[
\boxed{

=

\left[

+
\sum_i f_i^{(2)}P_i
\right]
}
\]

所以对于：

\[

\]

\[

\[

## 28. 为什么会有这个差别？

原因不是负载均衡思想不同。

而是：

> **归一化方式不同。**

General 定义：

\[
f_i
=
\frac{
\text{Expert i 被选择次数}
}{
T\times K
}
\]

所以：

\[
\sum_i f_i=1
\]

---

而按槽位分别统计时：

\[
\sum_i f_i^{(1)}=1
\]

同时：

\[
\sum_i f_i^{(2)}=1
\]

所以把两个槽位直接加起来以后：

\[
\sum_i
\left(
f_i^{(1)}+f_i^{(2)}
\right)
=
2
\]

因此相比 General 的统计方法，多出了一个：

\[
K=2
\]

的尺度。

---

## 29. 更一般的 Top-k 情况

如果：

\[
TopK=K
\]

General 定义：

\[
\boxed{
f_i
=
\frac{
\text{Expert i 在所有 Top-k 中被选择的次数}
}{
TK
}
}
\]

那么：

\[
\sum_i f_i=1
\]

而如果按照每个槽位分别统计：

\[
f_i^{(1)},f_i^{(2)},\dots,f_i^{(K)}
\]

则：

\[
\boxed{
f_i
=
\frac1K
\sum_{k=1}^{K}
f_i^{(k)}
}
\]

因此：

\[
\boxed{
L_{\text{aux}}^{general}
=
\frac{\lambda E}{K}
\sum_{k=1}^{K}
\sum_{i=1}^{E}
f_i^{(k)}P_i
}
\]

如果某个实现直接对所有槽位求和，而没有再除以 \(K\)，那么：

\[
\boxed{
L_{\text{aux}}^{code}
=
\lambda E
\sum_{k=1}^{K}
\sum_{i=1}^{E}
f_i^{(k)}P_i
}
\]

两者只是在：

\[
\boxed{\text{尺度}}
\]

上相差一个：

\[
K
\]

---

## 30. 所以到底应该记哪个？

通用形式如下：

\[
\boxed{
L_{\text{aux}}
=
\lambda E
\sum_i
f_iP_i
}
\]

其中：

\[
\boxed{
f_i
=
\frac{
\text{Expert i 在全部 }TK\text{ 次路由中被选中的次数}
}{
TK
}
}
\]

这样最容易理解。

然后看到具体代码时再补一句：

> 有些实现不会先把 Top-k 的 \(K\) 个槽位合并，而是分别统计每个槽位的 Expert 使用率后直接求和，因此会和这个 General 公式相差一个与 \(K\) 有关的常数尺度；这个常数通常可以被辅助损失系数 \(\lambda\) 吸收。

---

## 31. 一句话总结两者区别

General 公式：

\[
\boxed{
\text{把所有 Top-k 选择合起来，统一统计一个 }f_i
}
\]

代码中的方式：

\[
\boxed{
\text{保留每个 Top-k 槽位，分别统计 }f_i^{(1)},f_i^{(2)},\dots
}
\]

对于 Top-2：

\[
\boxed{
f_i
=
\frac{
f_i^{(1)}+f_i^{(2)}
}{2}
}
\]

所以两种方法：

> **负载均衡思想完全一样，主要区别只是统计方式和归一化尺度不同。**

## 32. 为什么 Aux Loss 能改变 Router？

假设：

\[
f_2
\]

很大。

那么：

\[
f_2P_2
\]

对：

\[
P_2
\]

会非常敏感。

为了降低 Loss，训练会倾向于：

\[
P_2\downarrow
\]

而：

\[
P_2
=
softmax(W_rx)
\]

所以：

\[
\frac{\partial L}
{\partial W_r}
\neq0
\]

最终：

\[
W_r
\]

会被更新。

于是 Router 下一次就会：

> 少把 Token 往已经拥挤的 Expert 2 上送。

## 33. `scores.new_zeros(1).squeeze()` 是什么？

如果：

```text
当前不是训练模式
```

或者：

```text
router_aux_loss_coef <= 0
```

就不计算真正 Aux Loss。

代码：

```python
self.aux_loss = (
    scores
    .new_zeros(1)
    .squeeze()
)
```

先：

```python
scores.new_zeros(1)
```

创建：

```text
长度为 1 的零 Tensor
```

并且：

```text
device
dtype
```

和 `scores` 一致。

例如：


## 69. 这段代码最核心的 6 个 Tensor

关键结论如下。

| Tensor | Shape | 含义 |
|---|---|---|
| `x_flat` | \([N,H]\) | 展平后的所有 Token |
| `scores` | \([N,E]\) | 每个 Token 对所有 Expert 的概率 |
| `topk_idx` | \([N,K]\) | 每个 Token 选择的 K 个 Expert |
| `topk_weight` | \([N,K]\) | 被选 Expert 的 Gate Weight |
| `y` | \([N,H]\) | 最终 MoE 输出 |
| `load` | \([K,E]\) | 各 Top-k 槽位的 Expert 实际选择比例 |

其中：

\[
N=B\times T
\]

## 70. 最核心的三个公式对应哪段代码？

### 70.1 Router

数学：

\[
\boxed{
P
=
softmax(XW_r)
}
\]

代码：

```python
scores = F.softmax(
    self.gate(x_flat),
    dim=-1
)
```

---

### 70.2 Top-k MoE 输出

数学：

\[
\boxed{
y_t
=
\sum_{i\in TopK(t)}
g_{t,i}E_i(x_t)
}
\]

代码核心：

```python
y.index_add_(
    0,
    token_idx,
    expert(x_flat[token_idx])
    * weight
)
```

---

### 70.3 负载均衡

概念公式：

\[
\boxed{
L_{\text{aux}}
=
N_E
\sum_i
f_iP_i
}
\]

代码：

```python
load = F.one_hot(
    topk_idx,
    self.config.num_experts
).float().mean(0)

self.aux_loss = (
    load
    * scores.mean(0)
).sum() \
* self.config.num_experts \
* self.config.router_aux_loss_coef
```

## 71. 为什么 MoE 可以“参数很多，但每 Token 计算较少”？

假设：

```text
8 个 Expert
```

每个 Expert：

\[
100M
\]

参数。

那么总 Expert 参数：

\[
800M
\]

但是：

\[
TopK=2
\]

意味着每个 Token 只真正执行：

```text
2 个 Expert
```

所以每个 Token 只激活大约：

\[
200M
\]

Expert 参数。

于是：

\[
\boxed{
\text{Total Parameters}
\gg
\text{Activated Parameters per Token}
}
\]

这就是 MoE 最大价值。

## 72. 为什么不同 Expert 会慢慢学出不同能力？

因为不同 Expert 收到：

\[
\boxed{\text{不同 Token}}
\]

例如：

```text
Expert 0
长期收到某类 Token

Expert 1
长期收到另一类 Token
```

于是它们的：

```text
训练数据不同

梯度不同

参数更新方向不同
```

所以最后形成：

\[
\boxed{\text{Expert Specialization}}
\]

## 73. Router 看的是词本身吗？

不是。

Router 输入：

\[

\]

是：

\boxed{\text{当前 Transformer 层的 hidden state}}
\]

hidden state 已经包含上下文信息。

所以：

```text

```

里的 `Apple`

和：

```text

```

里的 `apple`

虽然词面相同或接近：

```text
hidden state 完全可能不同
```

所以它们可能：

\[
\boxed{\text{被路由到不同 Expert}}
\]

所以：


都是正常的。

## 75. 这段实现为什么没有把所有 Expert 都计算一遍？

因为那样就失去了 MoE 的意义。

如果：

\[
8
\]

个 Expert 全部执行：

\[
y
=
\sum_{i=1}^{8}
g_iE_i(x)
\]

虽然数学没问题，但计算量会近似变成：

```text
8 个 FFN 全算
```

就失去了：

\[
\boxed{\text{Sparse Activation}}
\]

这段代码通过：

```python
mask
```

只找到真正被使用的 Expert。

再通过：

```python
if mask.any():
```

确保：

\[
\boxed{\text{没人选择的 Expert 根本不执行}}
\]

## 76. `index_add_` 为什么可以看成 MoE 汇流器？

可以把整个 MoE 想象成：

```text
                    → Expert 0 ─┐
                    → Expert 1 ─┤
Token → Router →    → Expert 2 ─┼→ 汇总
                    → Expert 3 ─┘
```

而：

```python
index_add_
```

就是最后这个：

\[
\boxed{\text{汇总}}
\]

它干的事情是：

```text
Expert 输出先乘自己的 Gate Weight

然后按照原 Token 编号

加回对应位置
```

因此：

\[
\boxed{
index\_add_
=
MoE 中把“分流”后的结果重新“汇流”
}
\]

这个理解非常重要。

## 79. 最后把整段代码压缩成人话

这段 `MOEFeedForward` 实际上只做了 7 件事：

```text
1. 把所有 Token 展平。

2. Router 给每个 Token 对所有 Expert 打分。

3. 每个 Token 只选择 Top-k 个 Expert。

4. 按 Expert 对 Token 重新分组。

5. 每个 Expert 只处理属于自己的 Token。

6. Expert 输出乘 Gate Weight，
   再用 index_add_ 加回原 Token。

7. 训练时额外计算负载均衡 Aux Loss。
```

## 80. 一句话总结这段源码

\[
\boxed{
\texttt{MOEFeedForward}
\text{ 做的就是：
先用 Router 把 Token 分流到少数 Expert，
每个 Expert 独立做 FFN，
再按照 Gate Weight 用 index\_add\_ 把结果汇流回来。}
}
\]

而训练阶段再通过：

\[
\boxed{
\text{实际 Expert 负载}
\times
\text{Router 平均偏好}
}
\]

构造辅助损失，避免：

\[
\boxed{\text{所有 Token 都挤到少数 Expert}}
\]

因此整个 MoE 可以最终概括成：

```text
Router
  ↓
Top-k
  ↓
Token 分流
  ↓
Expert FFN
  ↓
Gate Weight
  ↓
index_add_ 汇流
  ↓
MoE Output

同时：

Routing Load
+
Router Probability
↓
Aux Loss
↓
Load Balance
```

这就是这段代码从头到尾真正做的事情。
