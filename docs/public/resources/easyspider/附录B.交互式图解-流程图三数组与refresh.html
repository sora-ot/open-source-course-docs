1流程图的三兄弟：nodeList / actionSequence / queue

一张流程图，其实只有三个数组在配合。点「加一个节点」，看 nodeList 怎么增长。

nodeList 仓库

所有节点，按创建顺序存放

actionSequence 字典

id → nodeList 下标（渲染时重排）

queue 队列

只在 refresh 时用的 BFS 队列
注意：加节点只动 nodeList 和 root.sequence，actionSequence 要等 refresh 才会更新。
三句话记住： nodeList 是仓库（东西都在这）； actionSequence 是字典（编号→货架号）； queue 是队伍（渲染时按顺序点名）。

最容易搞混的一点： nodeList 里 sequence 装的是下标（所以是单层 nodeList[...]）； 而 parentId 装的是 id（要先用 actionSequence[parentId] 翻译回下标）。

3加循环、加判断时，sequence 怎么变

插入新节点，本质就是往"父节点的 sequence"里 splice 一项。

加一个普通节点

原：root.sequence = [1, 2]
在锚点(position=0)后插入新节点 idx=3
→ splice(1, 0, 3)
新：root.sequence = [1, 3, 2]

加一个循环（option=8）

新节点：type=1, sequence=[]
锚点自动跳进循环内部：
nowArrow = { position:-1, pId:新节点id }
所以你接着加的节点，都会落进循环体

加一个判断（option=9）：自动生两个分支

t["type"] = 2;                              // 判断节点
nt  = { type:3, option:10, title:"无条件" };  // 分支1
nt2 = { type:3, option:10, title:"无条件" };  // 分支2
t["sequence"].push(nt.index);   // 判断 → 分支1
t["sequence"].push(nt2.index);  // 判断 → 分支2
nodeList.push(nt); nodeList.push(nt2);
判断节点自己不干活，它靠 sequence 里的"分支"来分岔 —— 判断与分支是连体婴。

4要点速查

名词含义怎么用
nodeList所有节点的扁平仓库按创建顺序；删除先断开父 sequence 引用，再标记子树 id=-1
index在 nodeList 里的下标基本不变
idBFS 逻辑编号每次 refresh 重发
parentId父节点的 id先 actionSequence[parentId]
position在父 sequence 里排第几splice 插入用 position+1
sequence有序孩子清单（装 index）单层 nodeList[seq[i]]
actionSequenceid → 下标 的字典nodeList[actionSequence[id]]
一句话：加节点 = 造对象 + splice 进父的 sequence + refresh； refresh = 清画布 + BFS 重排 id/parentId/position + 重画 DOM。
