## 1. 预训练数据流

MiniMind 预训练包含下面这条完整链路：

```text
原始文本
  ↓
Tokenizer
  ↓
Token IDs
  ↓
添加 BOS / EOS
  ↓
Padding
  ↓
构造 input_ids / labels
  ↓
Embedding
  ↓
8 层 Decoder-only Transformer
  ↓
LM Head
  ↓
每个位置得到一个 6400 维 logits
  ↓
Shift 一位
  ↓
Cross Entropy
  ↓
反向传播
  ↓
AdamW 更新参数
  ↓
模型逐渐学会“根据前文预测下一个 token”
```

MiniMind 的预训练本质可以浓缩成一句话：

> **给模型看大量文本，然后让它不断做“下一个 token 是什么？”这道题。**

但真正重要的是理解：

1. 为什么“预测下一个 token”可以学到语言、知识和一定程度的推理能力？
2. 一个句子究竟会产生多少个训练样本？
3. `input_ids` 和 `labels` 为什么几乎一模一样？
4. causal mask 为什么必不可少？
5. logits、softmax、cross entropy 在数学上是什么关系？
6. loss 是如何从一句话一路反传到几十万个甚至几千万个参数的？
7. MiniMind 代码中的每一部分分别对应哪一个数学概念？

<a id="origin-68"></a>
## 2. 什么是 Pretraining？

<a id="origin-70"></a>
### 2.1 从“训练一个分类器”说起

传统监督学习通常是：

$$
x \rightarrow y
$$

例如：

```text
输入：这部电影太好看了
标签：正面
```

模型的目标是：

$$
P(y \mid x)
$$

但语言模型面对的问题不同。

我们没有必要人工给互联网中的每一句话标标签。

文本本身就包含监督信号。

例如：

```text
北京是中国的首都
```

可以自动构造出：

```text
输入：北京
目标：是

输入：北京是
目标：中国

输入：北京是中国
目标：的

输入：北京是中国的
目标：首都
```

因此，大规模文本可以自动变成训练数据。

这叫：

> **Self-Supervised Learning，自监督学习。**

这里不需要人手工标注“正确答案”。

正确答案就是文本中的下一个 token。

## 3. 为什么叫“预训练”？

现代 LLM 常见训练链路是：

```text
随机初始化模型
      ↓
Pretraining
      ↓
Base Model
      ↓
SFT
      ↓
Instruct / Chat Model
      ↓
DPO / PPO / GRPO 等 Alignment
```

预训练阶段解决的是：

> **让模型学会语言世界本身。**

包括但不限于：

- 词语之间的搭配关系
- 语法
- 上下文依赖
- 常识
- 世界知识
- 代码模式
- 数学表达模式
- 文档结构
- 一定程度的推理模式

SFT 才主要解决：

> “用户问我问题时，我应该以什么形式回答？”

所以：

<a id="origin-171"></a>
### 3.1 Pretrain 更像“读书”

模型大量阅读：

```text
新闻
百科
书籍
代码
论文
网页
对话
……
```

<a id="origin-186"></a>
#### 3.1.1 SFT 更像“教它怎么回答问题”

例如：

```text
user: 什么是 Transformer？
assistant: Transformer 是一种……
```

这是两个不同阶段。

<a id="origin-199"></a>
## 4. Decoder-only LLM 的核心概率模型

MiniMind 是 Decoder-only Causal Language Model。

假设一句话经过 tokenizer 后得到：

$$
x_1,x_2,\ldots,x_T
$$

语言模型试图学习整个序列的概率：

$$
P(x_1,x_2,\ldots,x_T)
$$

根据概率链式法则：

$$
P(x_1,x_2,\ldots,x_T)
=
P(x_1)
P(x_2\mid x_1)
P(x_3\mid x_1,x_2)
\cdots
P(x_T\mid x_1,\ldots,x_{T-1})
$$

可以写成：

$$
\boxed{
P(x_{1:T})
=
\prod_{t=1}^{T}
P(x_t\mid x_{<t})
}
$$

其中：

$$x_{<t}=(x_1,\ldots,x_{t-1})
$$

这就是自回归语言模型（Autoregressive Language Model）。

---

<a id="origin-247"></a>
## 5. Pretrain 的训练目标

如果模型希望正确文本的概率尽可能大，那么目标是：

$$
\max_\theta
\prod_{t=1}^{T}
P_\theta(x_t\mid x_{<t})
$$

因为连乘不好优化，对数之后：

$$
\max_\theta
\sum_{t=1}^{T}
\log P_\theta(x_t\mid x_{<t})
$$

机器学习通常写成最小化 loss：

$$
\boxed{
\mathcal{L}
=
-\sum_{t=1}^{T}
\log P_\theta(x_t\mid x_{<t})
}
$$

如果取平均：

$$
\boxed{
\mathcal{L}
=
-\frac{1}{N}
\sum_{t=1}^{N}
\log P_\theta(y_t\mid x_{\leq t})
}
$$

这就是 Negative Log-Likelihood。

对于词表分类问题，它正好等价于 Cross Entropy。

<a id="origin-294"></a>
## 6. 一句话是如何变成很多道训练题的？

为了直观起见，假设 tokenizer 把：

```text
我爱人工智能
```

切成：

```text
我 | 爱 | 人工智能
```

再加特殊 token：

```text
<BOS> | 我 | 爱 | 人工智能 | <EOS>
```

那么模型实际上同时做四道题：

| 模型看到的前文 | 应预测 |
|---|---|
| `<BOS>` | `我` |
| `<BOS> 我` | `爱` |
| `<BOS> 我 爱` | `人工智能` |
| `<BOS> 我 爱 人工智能` | `<EOS>` |

注意：

> Transformer 并不是把这四道题真的循环跑四遍。

由于 causal mask 的存在，一次 forward 就可以并行计算所有位置。

这正是 Transformer 训练非常高效的原因之一。

<a id="origin-333"></a>
## 7. MiniMind 中最关键的“Shift 一位”

MiniMind `PretrainDataset` 返回：

```python
input_ids = [...]
labels = input_ids.clone()
```

很多初学者看到这里会产生一个问题：

> input 和 label 完全一样，那模型不是直接抄答案了吗？

答案是：

> **没有。真正的错位是在模型 forward 中完成的。**

MiniMind：

```python
x, y = logits[..., :-1, :].contiguous(), labels[..., 1:].contiguous()
loss = F.cross_entropy(
    x.view(-1, x.size(-1)),
    y.view(-1),
    ignore_index=-100
)
```

假设：

```text
input_ids:
[BOS, 我, 爱, AI, EOS]

labels:
[BOS, 我, 爱, AI, EOS]
```

模型产生：

```text
logits:
位置0预测 ...
位置1预测 ...
位置2预测 ...
位置3预测 ...
位置4预测 ...
```

代码取：

```python
logits[..., :-1, :]
```

即：

```text
位置0
位置1
位置2
位置3
```

而 label 取：

```python
labels[..., 1:]
```

即：

```text
我
爱
AI
EOS
```

因此真正的监督关系是：

```text
位置0 → 我
位置1 → 爱
位置2 → AI
位置3 → EOS
```

这就是标准的：

$$
\boxed{x_t \rightarrow x_{t+1}}
$$

<a id="origin-429"></a>
## 8. 为什么不能预测当前位置自己？

如果不 shift：

```text
输入 token：我
目标 token：我
```

模型最容易学成 Identity Mapping：

> “看见‘我’，就输出‘我’。”

这毫无意义。

语言模型真正需要学习的是：

```text
根据当前位置及之前的信息
→ 预测下一个 token
```

也就是：

$$
P(x_{t+1}\mid x_{\le t})
$$

<a id="origin-459"></a>
## 9. Tokenizer：文字如何进入神经网络？

神经网络不能直接处理：

```text
Transformer 是一种神经网络
```

必须先转成整数。

MiniMind 的 tokenizer 是 BPE tokenizer，词表大小：

$$
V=6400
$$

源码配置中：

```python
self.vocab_size = 6400
```

MiniMind 当前 tokenizer 的几个重要特殊 token：

```text
ID 0 = <|endoftext|>   （同时作为 PAD / UNK）
ID 1 = <|im_start|>    （BOS）
ID 2 = <|im_end|>      （EOS）
```

也就是说：

```text
bos_token_id = 1
eos_token_id = 2
pad_token_id = 0
```

## 10. MiniMind PretrainDataset 逐行分析

源码：

```python
class PretrainDataset(Dataset):
    def __init__(self, data_path, tokenizer, max_length=512):
        super().__init__()
        self.tokenizer = tokenizer
        self.max_length = max_length
        self.samples = load_dataset(
            'json',
            data_files=data_path,
            split='train'
        )
```

数据格式来自 README：

```json
{"text": "如何才能摆脱拖延症？治愈拖延症并不容易，但以下建议可能有所帮助。"}
{"text": "清晨的阳光透过窗帘洒进房间，桌上的书页被风轻轻翻动。"}
{"text": "Transformer 通过自注意力机制建模上下文关系，是现代大语言模型的重要基础结构。"}
```

因此每一行就是一个：

```python
sample['text']
```

<a id="origin-532"></a>
## 11. 文本 Tokenization

关键代码：

```python
tokens = self.tokenizer(
    str(sample['text']),
    add_special_tokens=False,
    max_length=self.max_length - 2,
    truncation=True
).input_ids
```

这里有三个值得讲的地方。

<a id="origin-547"></a>
### 11.1 `add_special_tokens=False`

告诉 tokenizer：

> 不要自动加 BOS / EOS。

因为后面 MiniMind 自己手动加。

<a id="origin-555"></a>
### 11.2 `max_length=self.max_length - 2`

为什么减 2？

因为还要留两个位置：

```text
BOS
EOS
```

如果最终长度最大为：

$$
L=340
$$

则正文最多：

$$
340-2=338
$$

个 token。

<a id="origin-580"></a>
### 11.3 `truncation=True`

正文太长时截断。

所以 MiniMind 当前 pretrain 并不是：

> 把超长文档连续切成很多 block 全部利用。

而是：

> 每条 JSONL 文本最多取前 `max_length-2` 个 token。

这是一个非常简洁、适合教学和低成本训练的数据方案。

<a id="origin-596"></a>
## 12. 手动加入 BOS / EOS

源码：

```python
tokens = (
    [self.tokenizer.bos_token_id]
    + tokens
    + [self.tokenizer.eos_token_id]
)
```

例如：

```text
原文：
北京是中国的首都

token：
[100, 215, 378, 421]

加入特殊 token：

[1, 100, 215, 378, 421, 2]
```

其中：

```text
1 = BOS
2 = EOS
```

BOS 告诉模型：

> 一个序列开始了。

EOS 告诉模型：

> 这个序列应该结束了。

模型因此不仅学会：

> “接下来应该说什么”

也学会：

> “什么时候应该停止”。

<a id="origin-647"></a>
## 13. Padding

MiniMind 需要组成 batch。

一个 batch 中每个 Tensor 的长度必须一样。

假设：

$$
L_{\max}=10
$$

原 token：

```text
[1, 100, 215, 378, 421, 2]
```

只有 6 个 token。

因此补 4 个 PAD：

```text
[1, 100, 215, 378, 421, 2, 0, 0, 0, 0]
```

源码：

```python
input_ids = tokens + [self.tokenizer.pad_token_id] * (
    self.max_length - len(tokens)
)
```

---

<a id="origin-683"></a>
## 14. 为什么 PAD 不能计算 loss？

如果 PAD 也参与 loss，模型会学：

```text
EOS 后面应该疯狂预测 PAD
```

短文本越多，PAD 越多，这会严重污染训练目标。

因此：

```python
labels = input_ids.clone()
labels[input_ids == self.tokenizer.pad_token_id] = -100
```

例如：

```text
input_ids:
[1, 100, 215, 378, 421, 2, 0, 0, 0, 0]

labels:
[1, 100, 215, 378, 421, 2, -100, -100, -100, -100]
```

PyTorch 后面使用：

```python
F.cross_entropy(..., ignore_index=-100)
```

因此 target 为 `-100` 的位置不计算 loss。

## 16. Batch 后 Tensor 的形状

MiniMind 默认：

```python
batch_size = 32
max_seq_len = 340
vocab_size = 6400
hidden_size = 768
```

因此进入模型：

$$
\text{input\_ids.shape}
=
[B,L]
=
[32,340]
$$

Embedding 后：

$$
[32,340]
\rightarrow
[32,340,768]
$$

最终 logits：

$$
[32,340,768]
\rightarrow
[32,340,6400]
$$

shift 后：

$$
x.shape=[32,339,6400]
$$

$$
y.shape=[32,339]
$$

flatten：

$$
x:
[32\times339,6400]
=
[10848,6400]
$$

y:
[10848]
$$

所以 PyTorch 的 CrossEntropy 实际上看到的是：

> **10848 道 6400 分类题。**

当然其中 PAD 对应的位置因为 label = -100 被忽略。

<a id="origin-865"></a>
## 17. 模型输出的 logits 是什么？

对每个位置，模型输出一个 6400 维向量：

$$
z=(z_1,z_2,\ldots,z_{6400})
$$

例如：

```text
[2.1, -0.3, 4.7, ..., 1.2]
```

它们不是概率。

叫：

> logits。

通过 softmax：

$$
p_i=
\frac{e^{z_i}}
{\sum_{j=1}^{V}e^{z_j}}
$$

得到：

$$
\sum_i p_i=1
$$

例如模型认为下一个 token：

```text
“是”       0.60
“的”       0.10
“中国”     0.08
……
```

如果正确答案是“是”，那么该位置 loss：

$$
L=-\log(0.60)
$$

概率越高：

$$
-\log p
$$

越小。

<a id="origin-924"></a>
## 18. Cross Entropy 到底是什么？

假设词表只有四个词：

```text
[我, 爱, AI, 猫]
```

正确答案：

```text
AI
```

one-hot：

$$
y=[0,0,1,0]
$$

模型预测：

$$
p=[0.1,0.1,0.7,0.1]
$$

交叉熵：

$$
H(y,p)
=
-\sum_i y_i\log p_i
$$

因为只有正确类别的 \(y_i=1\)，所以：

$$
L=-\log 0.7
$$

也就是说：

$$
\boxed{
L=-\log P(\text{正确 token})
}
$$

这是理解语言模型 loss 最简单的方式。

<a id="origin-976"></a>
## 19. 一个完整的数值例子

序列：

```text
<BOS> 我 爱 AI <EOS>
```

假设模型四个位置对正确答案给出的概率分别为：

```text
P(我 | BOS)          = 0.60
P(爱 | BOS,我)       = 0.70
P(AI | BOS,我,爱)    = 0.80
P(EOS | BOS,我,爱,AI)= 0.50
```

平均 loss：

$$
L
=
-\frac14
(
\log0.6+
\log0.7+
\log0.8+
\log0.5
)
$$

得到约：

$$
\boxed{L\approx0.446}
$$

Perplexity：

$$
PPL=e^L
$$

所以：

$$
PPL\approx1.562
$$

直观理解：

> 模型在每一步平均像是在约 1.56 个同等可能的候选中做选择。

注意真实 LLM 词表有 6400 个 token，情况当然复杂得多。

<a id="origin-1033"></a>
## 20. 为什么 CrossEntropy 代码里没有 Softmax？

MiniMind：

```python
loss = F.cross_entropy(...)
```

常见问题：

> 前面没写 softmax，怎么就是概率？

因为：

```python
F.cross_entropy(logits, target)
```

数学上等价于：

```text
log_softmax
+
negative log likelihood
```

即：

$$
\text{CrossEntropy}(z,y)
=
-\log
\frac{e^{z_y}}
{\sum_j e^{z_j}}
$$

PyTorch 直接从 logits 计算，数值更稳定。

所以：

> **训练时不要先自己 softmax 再传给 `F.cross_entropy`。**

<a id="origin-1077"></a>
## 21. 为什么一个位置不能偷看未来？

假设训练：

```text
我 爱 人工智能
```

当模型在“我”这个位置预测“爱”时，如果 Attention 可以看到右侧：

```text
爱
```

那答案已经泄露了。

模型会作弊。

因此 Decoder-only Transformer 必须使用 causal mask。

---

<a id="origin-1099"></a>
## 22. Causal Mask

长度为 4 时，注意力可见关系：

```text
        K0  K1  K2  K3

Q0      ✓   ×   ×   ×
Q1      ✓   ✓   ×   ×
Q2      ✓   ✓   ✓   ×
Q3      ✓   ✓   ✓   ✓
```

数学上 mask：

$$
M=
\begin{bmatrix}
0&-\infty&-\infty&-\infty\\
0&0&-\infty&-\infty\\
0&0&0&-\infty\\
0&0&0&0
\end{bmatrix}
$$

Attention：

$$
\boxed{
\mathrm{Attention}(Q,K,V)
=
\mathrm{softmax}
\left(
\frac{QK^\top}{\sqrt{d_k}}
+
M
\right)V
}
$$

因为：

$$
e^{-\infty}=0
$$

右上角未来位置 softmax 后概率变成 0。

<a id="origin-1149"></a>
## 23. MiniMind 如何实现 causal attention？

MiniMind：

```python
self.is_causal = True
```

如果支持 PyTorch Flash / SDPA：

```python
F.scaled_dot_product_attention(
    xq,
    xk,
    xv,
    ...,
    is_causal=self.is_causal
)
```

这里：

```python
is_causal=True
```

由 PyTorch 完成 causal mask。

如果不用 Flash Attention，则自己构造：

```python
scores = (xq @ xk.transpose(-2, -1)) / math.sqrt(self.head_dim)

scores[:, :, :, -seq_len:] += torch.full(
    (seq_len, seq_len),
    float("-inf"),
    device=scores.device
).triu(1)
```

核心就是：

```python
triu(1)
```

得到严格上三角矩阵。

也就是把未来位置变成：

```text
-inf
```

## 24. MiniMind 的整体模型结构

默认配置：

```python
hidden_size = 768
num_hidden_layers = 8
vocab_size = 6400

num_attention_heads = 8
num_key_value_heads = 4

head_dim = 768 / 8 = 96
```

中间层：

```python
intermediate_size =
ceil(hidden_size * pi / 64) * 64
```

代入：

$$

<a id="origin-1435"></a>
## 28. 为什么需要位置编码？

Self-Attention 本身并不知道：

```text
我 爱 你
```

和：

```text
你 爱 我
```

谁在前谁在后。

所以必须加入位置信息。

MiniMind 使用：

> **RoPE：Rotary Position Embedding**

不是传统 Transformer 那种：

$$
x + PE
$$

而是对 Query / Key 做旋转。

---

<a id="origin-1467"></a>
## 29. RoPE 的直观理解

对二维向量：

$$
\begin{bmatrix}
x_1\\x_2
\end{bmatrix}
$$

旋转角度 \(\theta\)：

$$
R(\theta)=
\begin{bmatrix}
\cos\theta&-\sin\theta\\
\sin\theta&\cos\theta
\end{bmatrix}
$$

RoPE 给不同位置不同旋转角度。

位置 \(m\)：

$$
q_m'=R(m\theta)q_m
$$

位置 \(n\)：

$$
k_n'=R(n\theta)k_n
$$

二者点积天然包含：

$$
m-n
$$

即相对位置信息。

---

<a id="origin-1511"></a>
## 30. MiniMind 的 RoPE 代码

初始化时预计算：

```python
freqs_cos, freqs_sin = precompute_freqs_cis(
    dim=config.head_dim,
    end=config.max_position_embeddings,
    rope_base=config.rope_theta,
    rope_scaling=config.rope_scaling
)
```

默认：

```text
head_dim = 96
max_position_embeddings = 32768
rope_theta = 1e6
```

forward：

```python
xq, xk = apply_rotary_pos_emb(
    xq,
    xk,
    cos,
    sin
)
```

值得强调：

> RoPE 只作用于 Q 和 K，不直接作用于 V。

因为位置信息需要改变：

> “谁应该关注谁”

而 Attention 权重来自 Q 和 K。

## 33. MiniMind 不是普通 MHA，而是 GQA

MiniMind 默认：

```text
Q heads  = 8
KV heads = 4
```

这叫：

> **Grouped Query Attention，GQA**

即多个 Q head 共用较少的 K/V head。

MiniMind：

```python
self.n_rep = (
    self.n_local_heads //
    self.n_local_kv_heads
```

$$

$$

每个 KV head 被两个 Query head 使用。

<a id="origin-1662"></a>
## 34. GQA 为什么有用？

普通 Multi-Head Attention：

```text
8 Q
8 K
8 V
```

GQA：

```text
8 Q
4 K
4 V
```

优势：

- K/V 参数更少
- 推理时 KV Cache 更小
- 生成速度更友好
- 通常效果损失较小

所以现代 LLM 很常见。

MiniMind 中：

```python
repeat_kv(xk, self.n_rep)
repeat_kv(xv, self.n_rep)
```

把 4 个 KV 逻辑复制为供 8 个 Q head 使用。

注意：

> 这不是增加新的参数，仅仅是计算上的展开。

<a id="origin-1724"></a>
## 36. RMSNorm

传统 LayerNorm：

$$
\frac{x-\mu}{\sqrt{\sigma^2+\epsilon}}
$$

RMSNorm 不减均值，只按照均方根归一化：

$$
\mathrm{RMS}(x)
=
\sqrt{
\frac1d
\sum_{i=1}^d x_i^2
+
\epsilon
}
$$

$$
\boxed{
\mathrm{RMSNorm}(x)
=
g\odot
\frac{x}{\mathrm{RMS}(x)}
}
$$

MiniMind：

```python
return x * torch.rsqrt(
    x.pow(2).mean(-1, keepdim=True)
    + self.eps
)
```

然后：

```python
self.weight * normalized_x
```

<a id="origin-1771"></a>
## 37. Attention 公式

每个 head：

$$
S=
\frac{QK^\top}
{\sqrt{d_k}}
$$

加 causal mask：

$$
S'=S+M
$$

softmax：

$$
A=\mathrm{softmax}(S')
$$

输出：

$$
O=AV
$$

最终多头拼接后：

$$
\mathrm{Concat}(O_1,\ldots,O_h)W_O
$$

MiniMind 对应：

```python
scores = (
    xq @ xk.transpose(-2, -1)
) / math.sqrt(self.head_dim)
```

```python
output =
self.attn_dropout(
    F.softmax(scores.float(), dim=-1).type_as(xq)
) @ xv
```

<a id="origin-1822"></a>
## 38. 为什么除以 \(\sqrt{d_k}\)？

如果 Q 和 K 每个维度方差大致为 1：

$$
q\cdot k
=
\sum_{i=1}^{d_k}q_i k_i
$$

其方差会随：

$$
d_k
$$

增大。

\(d_k\) 大时 logits 绝对值会很大。

softmax 容易变得过尖：

```text
[0.999999, 0.000001, ...]
```

梯度变差。

因此缩放：

$$
\frac{QK^\top}{\sqrt{d_k}}
$$

使数值尺度更稳定。

MiniMind：

```text
d_k = 96
```

所以除以：

$$
\sqrt{96}
$$

## 39. Transformer Block 的结构

MiniMind 每层：

```python
residual = hidden_states

hidden_states, ... = self.self_attn(
    self.input_layernorm(hidden_states),
    ...
)

hidden_states += residual

hidden_states = hidden_states + self.mlp(
    self.post_attention_layernorm(hidden_states)
)
```

可以写为：

$$
H'_l
=
H_l
+
\mathrm{Attention}
(
\mathrm{RMSNorm}(H_l)
)
$$

然后：

$$
\boxed{
H_{l+1}
=
H'_l
+
\mathrm{FFN}
(
\mathrm{RMSNorm}(H'_l)
)
}
$$

这属于：

> **Pre-Norm Transformer**

Normalization 在子层之前。

<a id="origin-1927"></a>
## 40. 为什么需要 Residual Connection？

Attention 层不是直接替换旧表示，而是：

$$
x+\mathrm{Attention}(x)
$$

FFN：

$$
x+\mathrm{FFN}(x)
$$

Residual 的意义包括：

- 保留原始信息
- 改善深层网络梯度传播
- 让每层更像是在原表示上学习“增量修正”

可以直观地理解为：

> 每层 Transformer 不是把上一层推倒重建，而是在上一层知识表示上“补充一点新的理解”。

<a id="origin-1953"></a>
## 41. MiniMind 的 FFN 不是普通两层 MLP

源码：

```python
return self.down_proj(
    self.act_fn(self.gate_proj(x))
    * self.up_proj(x)
)
```

默认：

```python
hidden_act = 'silu'
```

所以：

$$
g=\mathrm{SiLU}(XW_g)
$$

$$
u=XW_u
$$

逐元素乘：

$$
z=g\odot u
$$

最后：

$$
\boxed{
FFN(X)=
(
\mathrm{SiLU}(XW_g)
\odot
XW_u
)
W_d
}
$$

这是 SwiGLU 类结构。

## 42. SiLU

$$

=

$$

其中：

$$
\sigma(x)
=
\frac1{1+e^{-x}}
$$

和 ReLU 相比，SiLU 更平滑。

现代 LLM 中经常与 GLU 类门控结合。

## 48. 为什么训练可以同时预测所有 token，而推理不能？


<a id="origin-2272"></a>
### 48.1 训练

我们已经知道完整文本：

```text
我 爱 人工智能
```

借助 causal mask，可以一次输入整个序列：

```text
我
我 爱
我 爱 人工智能
```

对应的所有位置可以矩阵并行。

<a id="origin-2290"></a>
### 48.2 推理

假设只有：

```text
我
```

后面的“爱”还不存在。

必须先生成：

```text
爱
```

然后才能生成下一个：

```text
人工智能
```

所以生成天然是：

$$
x_1
\rightarrow x_2
\rightarrow x_3
\rightarrow\cdots
$$

自回归过程。

<a id="origin-2325"></a>
## 49. Pretrain 为什么能学到“知识”？

例如训练语料里反复出现：

```text
法国的首都是巴黎
巴黎是法国最大的城市之一
埃菲尔铁塔位于巴黎
……
```

模型在大量 next-token prediction 中不断降低：

$$
-\log P(
\text{巴黎}
\mid
\text{法国的首都是}
)
$$

为了预测准确，它必须从参数中捕捉：

```text
法国 ↔ 巴黎
巴黎 ↔ 埃菲尔铁塔
```

等统计关联。

因此语言模型知识不是传统数据库：

```text
key → value
```

而是分布式编码在大量神经网络权重中的。

<a id="origin-2365"></a>
## 50. 为什么 next-token prediction 可以产生“涌现能力”？

因为要准确预测下一个 token，很多时候模型不能只记局部词频。

例如：

```text

```

如果训练数据丰富，模型为了预测：

```text
5
```

可能需要内部表示：

- 数字
- 加法
- 语义关系
- 文本结构

再例如代码：

```python
for i in range(10):
    print(
```

要预测后面的代码，需要学习：

- Python 语法
- 括号
- API 模式
- 缩进
- 上下文变量

所以一个非常简单的统一训练目标：

$$
\boxed{
\text{Predict Next Token}
}
$$

可以迫使网络学习非常复杂的内部表示。

## 56. 梯度累积为什么先除以 accumulation_steps？

源码：

```python
loss = loss / args.accumulation_steps
```

然后：

```python
loss.backward()
```

假设 8 个 micro-batch：

$$
g_i=\nabla L_i
$$

如果不除 8：

$$
g=
\sum_{i=1}^8 g_i
$$

梯度规模会放大约 8 倍。

除以 8：

$$
g=
\frac18
\sum_{i=1}^8 g_i
$$

相当于大 batch 平均梯度。

## 58. 学习率调度

MiniMind：

```python

```

`get_lr`：

```python
return lr * (
    0.1
    + 0.45 * (
        1 + cos(pi * current_step / total_steps)
    )
)
```

数学形式：

$$
\boxed{
\eta_t
=
\eta_0
\left[
0.1+
0.45
\left(
1+\cos\frac{\pi t}{T}
\right)
\right]
}
$$

---

<a id="origin-2654"></a>
## 59. 这个 cosine schedule 从多少降到多少？

当：

$$
t=0
$$

时：

$$
\cos0=1
$$

所以：

$$
0.1+0.45(2)=1
$$

$$
\eta_0=5\times10^{-4}
$$

训练末尾：

$$
t=T
$$

$$
\cos\pi=-1
$$

所以：

$$
0.1+0=0.1
$$

最终学习率：

$$
0.1\eta_0
=
5\times10^{-5}
$$

所以 MiniMind 当前实现是：

> **无 warmup 的 cosine decay，从初始 LR 平滑衰减到初始值的 10%。**

这是源码事实。

需要注意：

> 大型正式预训练通常经常还会加入 warmup；MiniMind 为了保持训练代码极简，这里没有实现 warmup。

## 62. 反向传播

MiniMind：

```python
scaler.scale(loss).backward()
```

从 CrossEntropy 开始，梯度一路反传：

```text
CrossEntropy
      ↓
LM Head
      ↓
第8层 Transformer
      ↓
……
      ↓
第1层 Transformer
      ↓
Embedding
```

用链式法则：

$$
\frac{\partial L}{\partial W}
=
\frac{\partial L}{\partial z}
\frac{\partial z}{\partial h}
\frac{\partial h}{\partial W}
$$

最终每个可训练参数都获得梯度。

<a id="origin-2824"></a>
## 63. Softmax + Cross Entropy 的梯度为什么漂亮？

设 logits：

$$
z_i
$$

softmax：

$$
p_i
$$

真实标签 one-hot：

$$
y_i
$$

Cross Entropy 对 logits 的梯度：

$$
\boxed{
\frac{\partial L}{\partial z_i}
=
p_i-y_i
}
$$

如果正确 token 是第 3 类：

```text
y = [0,0,1,0]
```

模型：

```text
p = [0.1,0.1,0.7,0.1]
```

梯度：

```text
[+0.1, +0.1, -0.3, +0.1]
```

含义：

- 错误 token 的 logits 往下压
- 正确 token 的 logits 往上推

模型就这样一步一步变得更准确。

<a id="origin-2881"></a>
## 64. AdamW

MiniMind：

```python
optimizer = optim.AdamW(
    model.parameters(),
    lr=args.learning_rate
)
```

Adam 的核心是维护：

一阶动量：

$$
m_t
=
\beta_1m_{t-1}
+
(1-\beta_1)g_t
$$

二阶动量：

$$
v_t
=
\beta_2v_{t-1}
+
(1-\beta_2)g_t^2
$$

参数更新大致：

$$
\theta_{t+1}
=
\theta_t
-
\eta
\frac{\hat m_t}
{\sqrt{\hat v_t}+\epsilon}
$$

AdamW 将 weight decay 与梯度更新解耦。

MiniMind 没有显式填写 betas / weight_decay，所以使用 PyTorch `AdamW` 默认值。

<a id="origin-2932"></a>
## 65. 梯度裁剪

MiniMind：

```python
torch.nn.utils.clip_grad_norm_(
    model.parameters(),
    args.grad_clip
)
```

默认：

```text
grad_clip = 1.0
```

如果整体梯度范数：

$$
\|g\|_2>1
$$

就按比例缩小。

例如：

$$
\|g\|=5
$$

大约乘：

$$
\frac15
$$

使 norm 变为 1。

目的：

> 防止偶发的大梯度让参数更新爆炸。

<a id="origin-2977"></a>
## 66. 为什么先 `scaler.unscale_` 再梯度裁剪？

float16 混合精度训练时，GradScaler 会把 loss 放大。

如果直接 clip：

> clip 的其实是被放大的梯度。

所以 MiniMind：

```python
scaler.unscale_(optimizer)
torch.nn.utils.clip_grad_norm_(...)
```

先恢复真实梯度尺度，再 clip。

这是正确顺序。

## 68. FP16 与 BF16

FP16：

```text
1 sign
5 exponent
10 mantissa
```

BF16：

```text
1 sign
8 exponent
7 mantissa
```

BF16 和 FP32 都有 8 位 exponent，因此数值范围很大，更不容易 overflow。

所以现代大模型训练如果硬件支持，通常更偏向 BF16。

MiniMind 默认：

```text
bfloat16
```

## 69. 为什么 BF16 时不启用 GradScaler？

MiniMind：


也就是说：

BF16 范围更接近 FP32，一般不需要 loss scaling。

## 71. `zero_grad(set_to_none=True)` 为什么不是清零？

普通：

```python
grad.zero_()
```

会保留 gradient tensor，只把值改为 0。

`set_to_none=True`：

```python
param.grad = None
```

通常更省内存 / 更高效。

下一次 backward 再创建 gradient。

## 83. MoE Auxiliary Loss

MoE 如果不加约束，router 可能：


+

## 84. Pretrain 和 SFT 的核心区别：Loss Mask


<a id="origin-3570"></a>
### 84.1 Pretrain

MiniMind：

```python
labels = input_ids.clone()
labels[PAD] = -100
```

除了 padding：

> **几乎每个 token 都需要预测。**

例如：

```text
Transformer 是一种神经网络
```

所有正文 token 都训练。

---

<a id="origin-3593"></a>
### 84.2 SFT

SFTDataset 的 `generate_labels()` 会先：

```python
labels = [-100] * len(input_ids)
```

只把：

```text
assistant 回答部分
```

改回真实 token id。

也就是说 SFT 通常不要求模型学习：

```text
user 问题本身应该如何生成
```

主要要求模型学习：

```text
给定 system + user
→ assistant 应该回答什么
```

<a id="origin-3624"></a>
## 85. 一个最直观的 Pretrain vs SFT 对比

<a id="origin-3626"></a>
### 85.1 Pretrain

文本：

```text
北京是中国的首都
```

loss：

```text
BOS → 北京
北京 → 是
是 → 中国
中国 → 的
的 → 首都
首都 → EOS
```

几乎全算。

<a id="origin-3647"></a>
### 85.2 SFT

```text
user: 中国的首都是哪里？
assistant: 北京。
```

loss 常见做法：

```text
system/user 部分 → mask
assistant 的“北京。” → 计算 loss
```

所以：

> Pretrain 学“语言和知识分布”。

> SFT 学“按照指令回答”。

## 86. 为什么 Pretrain 后模型还不一定会聊天？

因为预训练目标只是：

> 预测互联网文本接下来是什么。

它可能看到：

```text
问：1+1等于多少？
答：2
```

也可能看到：

```text
有人问“1+1等于多少？”

```

也可能看到文章、小说、网页、代码。

所以 Base Model 学的是：

$$
P(\text{text})
$$

而不是明确学：

$$
P(\text{helpful answer}\mid \text{user instruction})
$$

SFT 才把行为分布拉向：


## 89. 从概率角度再看一次源码

源码：

```python
logits = self.lm_head(hidden_states)
```

代表模型参数化：

$$
P_\theta(x_{t+1}\mid x_{\le t})
$$

源码：

```python
x = logits[..., :-1, :]
y = labels[..., 1:]
```

代表：

$$
(x_{\le t}, x_{t+1})
$$

监督对。

源码：

```python
F.cross_entropy(x, y)
```

代表：

$$
-\log
P_\theta(x_{t+1}\mid x_{\le t})
$$

全数据训练就是：

$$
\boxed{
\min_\theta
-\sum_{\text{documents}}
\sum_t
\log
P_\theta(
x_{t+1}
\mid
x_{\le t}
)
}
$$

整个 Pretraining 最终就是这一个式子。

## 90. 从“信息压缩”的角度理解语言模型

一个好语言模型能给真实文本更高概率。

例如：

```text
中国的首都是北京
```

好模型可能：

```text
P(北京 | 中国的首都是) = 0.8
```

差模型：

```text
P(北京 | 中国的首都是) = 0.0001
```

Negative log probability：

好模型：

$$
-\log0.8
$$

很小。

差模型：

$$
-\log0.0001
$$

很大。

因此最小化 cross entropy，也可以理解成：

> 让模型越来越能够“压缩”真实语言。

越可预测，编码真实文本所需的信息量越低。

## 91. Perplexity（PPL）

如果平均 token loss：

$$
L
$$

定义：

$$
\boxed{
PPL=e^L
}
$$

例如：

$$
L=2
$$

则：

$$
PPL=e^2\approx7.39
$$

直观上可粗略理解成：

> 模型平均每一步像在约 7.39 个等可能候选中犹豫。

PPL 越低通常表示语言建模能力越好。

但注意：

> 不同 tokenizer 下 PPL 不宜简单横向比较。

MiniMind README 也专门指出 tokenizer 会影响按 token 统计的 PPL，跨 tokenizer 时 BPB 往往更公平。

如果词表从：

MiniMind 选择 6400 是一种小模型体积优先设计。

<a id="origin-4022"></a>
## 93. 小词表的代价

词表小意味着：

> 一个中文词、英文单词可能被拆成更多 token。

例如某个长英文词：

```text
transformation
```

大 tokenizer 可能：

```text
transformation
```

一个 token。

小 tokenizer 可能：

```text
trans
form
ation
```

三个 token。

因此：

- 序列变长
- Attention 计算变多
- PPL 的 token 单位发生变化

这也是为什么 tokenizer 是 LLM 系统设计的重要一部分。

<a id="origin-4062"></a>
## 94. 最大序列长度 340 是什么意思？

训练参数：

```python
--max_seq_len 340
```

表示当前 PretrainDataset 每条样本最终固定为：

$$
340
$$

个 token。

如果原文短：

> PAD 到 340。

如果原文长：

> 截断到正文最多 338，再加 BOS/EOS。

注意这和模型配置：

```python
max_position_embeddings = 32768
```

不是一回事。

<a id="origin-4096"></a>
## 95. `max_seq_len` 和 `max_position_embeddings`

<a id="origin-4098"></a>
### 95.1 `max_seq_len=340`

训练数据当前实际喂入的长度。

<a id="origin-4102"></a>
### 95.2 `max_position_embeddings=32768`

模型 RoPE 预计算支持的位置范围。

所以模型结构理论位置范围很长，但当前默认快速预训练只用 340 长度。

不能简单认为：

> “训练长度 340，因此模型已经充分学会处理 32768 token。”

长上下文能力仍然受到训练长度分布影响。

<a id="origin-4116"></a>
## 96. Flash Attention 在这里真正是什么？

MiniMind 判断：

```python
self.flash = (
    hasattr(
        torch.nn.functional,
        'scaled_dot_product_attention'
    )
    and config.flash_attn
)
```

满足条件时：

```python
F.scaled_dot_product_attention(...)
```

更准确的表述是：

> 使用 PyTorch 的 SDPA 接口；后端在合适硬件和条件下可能选择 Flash Attention 等高效 kernel。

不要简单讲成：

> 这行一定就是某一个固定 FlashAttention 库。

MiniMind 没有依赖独立 `flash-attn` 包来实现核心 Attention。

<a id="origin-4148"></a>
## 97. 为什么 Attention 的复杂度是 \(O(L^2)\)？

Attention score：

$$
QK^\top
$$

shape：

$$
[L,d]\times[d,L]
\rightarrow
[L,L]
$$

所以每个 token 都和其他可见 token 计算关系。

复杂度：

$$
O(L^2d)
$$

memory 也容易受到：

$$
L^2
$$

影响。

例如长度从：

$$
340\rightarrow680
$$

score matrix 面积变为：

$$
4\times
$$

这就是长上下文成本高的重要原因。

## 100. 随机初始化意味着什么？

训练开始前模型并不知道：

```text
“北京”
```

和：

```text
“中国”
```

有什么关系。

Embedding 也是随机的。

例如初始：

```text
北京 → [0.01, -0.03, ...]
中国 → [-0.02, 0.01, ...]
```

这些数一开始没有语义。

经过大量梯度更新后，相似上下文中的 token 会形成有结构的表示空间。

所以 embedding 的语义：

> 不是人预先写进去的，而是通过 next-token prediction 学出来的。

## 101. 为什么 Pretrain 要大量数据？

假设只训练一句：

```text
北京是中国的首都
```

模型完全可以死记硬背。

但泛化不了。

当语料达到大量不同文本时：

> 单纯记住每个完整句子越来越困难。

模型必须学习可复用的统计结构：

- 语法
- 实体关系
- 模式
- 语义
- 推理结构

这就是规模化数据的重要性。

<a id="origin-4328"></a>
## 102. 数据质量为什么重要？

训练目标不会判断：

> 这句话是真的还是假的。

它只会学：

> 数据里什么 token 经常跟在什么上下文之后。

如果训练数据大量包含：

- 错误事实
- 垃圾重复
- 乱码
- 广告模板
- 极度低质量合成数据

模型就会学习这些分布。

所以：

$$
\boxed{
\text{Model Quality}
\neq
\text{Only Model Architecture}
}
$$

还高度取决于：

$$
\text{Data Quality}
$$

MiniMind README 也强调主线数据经过清洗、去重、长度控制和格式统一。

<a id="origin-4496"></a>
## 104. 初始 loss 大约会是多少？


如果模型完全随机，6400 个 token 大致均匀：

$$
P(correct)\approx\frac1{6400}
$$

loss：

$$
-\log\frac1{6400}
=
\log6400
$$

约：

$$
\boxed{8.76}
$$

所以一个完全随机、近似均匀的 6400 词表语言模型，CrossEntropy 常可粗略从 8~9 左右理解。

训练后如果 loss：

```text
8.7 → 6 → 4 → 3 → ...
```

说明模型对正确 token 的概率在不断提高。

注意真实初始化、数据分布、weight tying 等因素会使实际初始值不一定恰好等于 8.76。

---

<a id="origin-4534"></a>
## 105. Loss 降低到底意味着什么？

Cross entropy：

$$
L=-\log p
$$

粗略地：

$$
p\approx e^{-L}
$$

如果一个单独位置：

```text
loss = 8
```

对应正确 token 概率约：

$$
e^{-8}\approx0.000335
$$

如果：

```text
loss = 2
```

约：

$$
e^{-2}\approx0.135
$$

真实平均 loss 不能直接等同于每个位置都具有相同概率，但这个例子说明：

> loss 每下降一点，正确 token 的整体概率分布已经发生了明显改善。

<a id="origin-4578"></a>
## 106. 为什么训练时不关心 argmax 对不对？

假设正确 token：

```text
北京
```

两个模型：

A：

```text
北京 0.30
上海 0.29
```

B：

```text
北京 0.90
上海 0.02
```

两者 argmax 都正确。

但 B 显然更有信心。

Cross Entropy 会区分：

$$
-\log0.3
$$

和：

$$
-\log0.9
$$

因此训练语言模型不是仅仅优化：

```text
accuracy
```

而是在拟合完整概率分布。

<a id="origin-4628"></a>
## 107. 为什么生成时还要 temperature / top-p，而训练时不用？

训练目标：

> 对真实 token 最大化概率。

因此直接对完整 softmax 分布做 CrossEntropy。

生成时则要从：

$$
P(x_{t+1}|x_{\le t})
$$

中选择一个 token。

可以：

```text
argmax
sampling
temperature
top-k
top-p
```

所以：

> 训练解决“学概率分布”。

> decoding 解决“怎么从概率分布选择 token”。

两者不要混为一谈。

```python
    enabled=(dtype == 'float16')
```

<a id="origin-4678"></a>
### 108.2 细节 2：无 warmup

`get_lr()` 是纯 cosine decay 到 10%。

<a id="origin-4684"></a>
### 108.3 细节 3：PAD label = -100

利用 PyTorch：

```python
ignore_index=-100
```

---

<a id="origin-4694"></a>
### 108.4 细节 4：Dataset 不创建 attention_mask

对于右侧 padding，Pretrain forward 没传显式 attention mask。

但因为：

- loss 对 padding target 做了 ignore
- causal mask 限制当前位置只能看左侧
- PAD 位于序列右侧

所以真实正文 token 不会看到未来的右侧 PAD。

PAD 自己产生的 hidden state 虽然会被计算，但其 target loss 被忽略。

这是一种简化实现。

---

<a id="origin-4712"></a>
## 109. 关于“没有 attention_mask”的更严谨解释

例如：

```text
BOS 我 爱 EOS PAD PAD
```

当位置：

```text
“我”
```

做 causal attention 时，它只能看：

```text
BOS
我
```

看不到右侧 PAD。

因此右 padding 不会污染正文 token 的表示。

PAD 位置本身可以看前文，但：

```text
它们的 labels = -100
```

所以不贡献语言模型 loss。

因此在这种：

> **全部 padding 都在右侧 + causal decoder**

的简单 pretrain 场景中，可以不显式传 padding attention mask。

---

<a id="origin-4753"></a>
## 110. 但什么时候 attention_mask 很重要？

例如：

- 左 padding
- packed sequences
- 多段样本拼接但不希望跨样本 attention
- 更复杂 batch packing
- 推理场景
- 不规则 padding

这时不能简单依赖 causal mask。

所以不要把 MiniMind 这里的简化结论推广成：

> Decoder LLM 永远不需要 attention mask。

<a id="origin-4772"></a>
## 111. 最后一个不满 accumulation_steps 的 batch

MiniMind 训练 epoch 结束时：

```python
if last_step % accumulation_steps != 0:
    ...
    scaler.step(optimizer)
```

所以不会丢掉最后残余的梯度。

但这里有一个很细的实现特点：

每个 micro-batch 都提前：

```python
loss /= accumulation_steps
```

即便最后只剩：

```text
3 个 micro-batch
```

仍然每个除以 8。

所以最后那个不完整 accumulation group 的梯度幅度会比“按实际 3 个 batch 平均”更小。

这是为了代码简洁可以接受的实现细节，但如果做严格大规模训练，可以对最后剩余 micro-batch 数重新归一化。

<a id="origin-4806"></a>
## 112. DDP + Gradient Accumulation 的通信细节

MiniMind 在梯度累积期间没有显式使用：

```python
model.no_sync()
```

因此 DDP 通常会在每个 backward 都进行梯度同步。

数学结果仍然可以正确累积，但通信效率不是最极致。

更典型的优化做法：

```text
前 7 个 accumulation micro-batch：
no_sync()

第 8 个：
正常 backward + all-reduce
```

这样能减少多卡通信。

MiniMind 的取舍很明显：

> 更重视代码清晰、易学，而不是把训练系统优化写得极其复杂。

## 122. 练习五：为什么 EOS 也要训练？

如果不训练 EOS：

> 模型只会学“接下来写什么”，却没有明确学习“什么时候结束”。

加入 EOS 后：

```text
文章最后一个正文 token
→ EOS
```

模型学习：

$$
P(EOS\mid\text{完整上下文})
$$

生成时才能合理停止。

## 123. MiniMind Pretrain 的一句话源码总结

如果把所有工程细节去掉，它做的事情就是：

$$
\boxed{
\text{Text}
\rightarrow
\text{Tokenizer}
\rightarrow
x_1,\ldots,x_T
\rightarrow
\text{Transformer}
\rightarrow
P(x_{t+1}|x_{\le t})
\rightarrow
CE
\rightarrow
\text{Backprop}
}
$$

其中训练目标：

$$
\boxed{
\min_\theta
-\sum_t
\log
P_\theta(
x_{t+1}
\mid
x_{\le t}
)
}
$$

这就是 MiniMind Pretraining 的数学本质。

## 126. 预训练的三个核心公式


<a id="origin-5397"></a>
### 126.1 公式一：自回归分解

$$
\boxed{
P(x_{1:T})
=
\prod_{t=1}^{T}
P(x_t|x_{<t})
}
$$

<a id="origin-5408"></a>
### 126.2 公式二：预训练 Loss

$$
\boxed{
\mathcal L
=
-\frac1N
\sum_t
\log
P_\theta(
x_{t+1}
\mid
x_{\le t}
)
}
$$

<a id="origin-5425"></a>
### 126.3 公式三：Causal Self-Attention

$$
\boxed{
\mathrm{Attention}(Q,K,V)
=
\mathrm{softmax}
\left(
\frac{QK^\top}{\sqrt{d_k}}
+
M_{\text{causal}}
\right)V
}
$$

这三个公式分别回答：

```text
语言概率如何分解？
模型到底在优化什么？
为什么训练时不能看到未来？
```

## 127. 一句话收尾

**MiniMind 的 Pretrain 并没有神秘的“知识注入”模块。**

它只是把海量文本变成海量：

```text
前缀 → 下一个 token
```

的预测任务，然后通过：

```text
Causal Transformer
+
Cross Entropy
+
Backpropagation
+
AdamW
```

不断调整约 6400 万个参数。

当这件简单的事被重复足够多次、使用足够多高质量文本之后，模型参数中逐渐形成了对语言、知识和各种模式的压缩表示。

这就是大语言模型预训练最核心的机制。
