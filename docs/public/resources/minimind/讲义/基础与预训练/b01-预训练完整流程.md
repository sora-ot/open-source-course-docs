# 预训练完整流程


> **预训练本质上只有一件事：给模型看海量文本，不断遮住“未来”，让它根据前面的 token 猜下一个 token；猜错了就通过反向传播修改参数。重复几万亿次以后，模型逐渐学会语言、知识、模式和一定程度的推理能力。**


---

<a id="origin-9"></a>
## 1. 大语言模型预训练到底在干什么？

以 Decoder-only LLM，也就是 GPT、Llama、Qwen 这类模型为例。

假设训练语料里有一句话：

> 浙江大学位于杭州。

经过 tokenizer 之后，假设被切成：

\[
[\text{浙江大学},\text{位于},\text{杭州},\text{。}]
\]

训练的时候，实际上相当于同时做下面几个预测：

| 已经看到的内容 | 模型应该预测 |
|---|---|
| `<BOS>` | 浙江大学 |
| `<BOS> 浙江大学` | 位于 |
| `<BOS> 浙江大学 位于` | 杭州 |
| `<BOS> 浙江大学 位于 杭州` | 。 |

也就是说：

\[
P(\text{浙江大学})
\]

\[
P(\text{位于}\mid \text{浙江大学})
\]

\[
P(\text{杭州}\mid \text{浙江大学, 位于})
\]

\[
P(\text{。}\mid \text{浙江大学, 位于, 杭州})
\]

这就是所谓：

\[
\boxed{\text{Next Token Prediction}}
\]

也就是**下一个 Token 预测**。

---

<a id="origin-60"></a>
## 2. 整个预训练过程先看一张“脑内流程图”

预训练的整体流程如下：

```text id="n42xia"
原始文本
   ↓
数据清洗
   ↓
Tokenizer
   ↓
Token IDs
   ↓
切成固定长度序列
   ↓
Embedding
   ↓
Transformer × N 层
   ↓
每个位置输出一个隐藏向量
   ↓
Linear / LM Head
   ↓
Vocabulary Logits
   ↓
Softmax
   ↓
预测“下一个 Token”的概率
   ↓
和真实 Token 比较
   ↓
Cross Entropy Loss
   ↓
反向传播
   ↓
AdamW 更新模型参数
   ↓
继续下一个 Batch
   ↓
重复几百万/几千万 Step
   ↓
Base Model
```

真正的大模型训练虽然工程上极其复杂，但是**算法主线基本就是这条链**。

<a id="origin-108"></a>
## 3. Step 1：准备海量预训练语料

所谓“无标注数据”，并不是完全没有监督信号。

比如互联网中天然存在：

> The capital of France is Paris.

不需要人工再告诉模型：

> Question: What is the capital of France?  
> Answer: Paris.

模型只需要看到原始文本就可以训练。

因为：

> The capital of France is

后面的真实 token：

> Paris

本身就是标签。

所以预训练有一个特别重要的特点：

\[
\boxed{\text{数据自己产生标签}}
\]

这也是为什么叫：

\[
\text{Self-Supervised Learning}
\]

即**自监督学习**。

---

<a id="origin-149"></a>
### 3.1 一个非常直观的例子

原始文本：

> 猫喜欢吃鱼。

Tokenizer 后：

```text id="mh59dp"
[BOS, 猫, 喜欢, 吃, 鱼, 。]
```

可以自动构造：

| 输入 | Label |
|---|---|
| BOS | 猫 |
| BOS 猫 | 喜欢 |
| BOS 猫 喜欢 | 吃 |
| BOS 猫 喜欢 吃 | 鱼 |
| BOS 猫 喜欢 吃 鱼 | 。 |

不需要人来标。

因此互联网本身就变成了一个巨大的训练集。

<a id="origin-177"></a>
## 4. 真实预训练语料都是什么？

现代 LLM 的预训练数据往往混合很多来源，例如：

| 类型 | 模型可能学到什么 |
|---|---|
| 网页 | 常识、事实、语言表达 |
| Wikipedia | 结构化知识 |
| 新闻 | 事件、正式语言 |
| 书籍 | 长文本、叙事、逻辑 |
| 论文 | 科学知识、专业表达 |
| GitHub | 代码生成 |
| Stack Overflow | 编程问答 |
| 数学文本 | 数学推理 |
| 论坛 | 日常表达 |
| 多语言语料 | 翻译和跨语言能力 |

例如模型可能看到：

```text id="iw6e7r"
Python 中可以使用 list.append() 向列表末尾添加元素。
```

也可能看到：

```python id="8nkv8b"
for i in range(10):
    print(i)
```

也可能看到：

\[
a^2+b^2=c^2
\]

于是同一个 next-token prediction 任务，可以让模型逐渐学会非常不同的能力。

<a id="origin-217"></a>
## 5. Step 2：数据清洗

真正进入模型之前，一般不能把互联网文本直接扔进去。

例如网页可能包含：

```text id="jtbhtr"
Buy now!!!
Cookie settings
Sign in
广告
导航栏
重复文本
乱码
HTML
```

所以通常要经历：

```text id="52470e"
原始互联网数据
        ↓
HTML 解析
        ↓
语言识别
        ↓
垃圾文本过滤
        ↓
质量过滤
        ↓
色情 / 恶意内容过滤
        ↓
去重
        ↓
PII 等敏感信息处理
        ↓
形成训练 Corpus
```

这里有一个容易忽视的点：

> **模型能力不仅取决于参数量，也极其依赖训练数据的质量。**

假设两个模型参数完全一样：

\[
7B\text{ parameters}
\]

一个训练集里：

```text id="9wrz34"
40% 重复网页
20% 垃圾广告
10% 乱码
```

另一个训练集经过高质量清洗。

最后效果可以差很多。

<a id="origin-280"></a>
## 6. 为什么必须去重？

例如互联网上同一句话出现了一百万遍：

> Paris is the capital of France.

如果不去重，这条知识在 loss 中的权重实际上被人为放大了：

\[
1,000,000\times
\]

模型就会过度记忆某些高频文本。

所以常见做法包括：

\[
\text{Exact Deduplication}
\]

完全重复去重，以及：

\[
\text{Near Deduplication}
\]

近似重复去重。

例如：

```text id="t2qloj"
浙江大学是一所著名高校。
浙江大学是一所非常著名的高校。
```

虽然不完全相同，也可能被认为高度重复。

<a id="origin-319"></a>
## 7. Step 3：Tokenizer——文字怎样进入神经网络？

神经网络不能直接理解：

> 浙江大学

它只能接收数字。

所以需要 Tokenizer。

例如：

```text id="m2rn5b"
浙江大学位于杭州。
```

可能变成：

```text id="xgz9iy"
浙江大学
位于
杭州
。
```

再映射成 Token ID：

```text id="y23iqk"
[8123, 19382, 7261, 1773]
```

于是：

\[
x_1=8123,\quad
x_2=19382,\quad
x_3=7261,\quad
x_4=1773
\]

模型真正看到的是数字。

<a id="origin-363"></a>
## 8. Token 不等于“一个字”也不等于“一个单词”

比如：

```text id="qaaup6"
unbelievable
```

可能拆成：

```text id="ui8lvb"
un
believ
able
```

或者：

```text id="k983ip"
un
believable
```

中文也可能：

```text id="aajk1w"
人工智能
```

被拆成：

```text id="z5sq8q"
人工
智能
```

甚至：

```text id="gakss3"
人
工
智能
```

取决于 tokenizer。

现在常见方法包括 BPE、SentencePiece 等。

<a id="origin-413"></a>
## 9. 为什么不直接把每个单词作为 Token？

因为世界上词太多了。

例如：

```text id="h4b2vc"
run
running
runner
runs
rerun
```

如果每一个词都单独占 vocabulary，非常浪费。

采用 subword：

```text id="hddh3f"
run
ning
er
s
re
```

可以组合出大量单词。

因此词表大小通常是：

\[
V\approx 30,000\sim 200,000
\]

例如：

\[
V=100,000
\]

意味着模型每次预测下一个 token，其实是在：

> **10 万个候选 token 中进行一次分类。**

这个理解非常重要。

<a id="origin-461"></a>
## 10. Step 4：构造训练样本

假设有：

```text id="haya9k"
[BOS, 我, 喜欢, 人工智能, 。]
```

训练数据实际上通常不会生成四条独立样本。

而是一次喂进去：

```text id="g3ii8s"
Input:
[BOS, 我, 喜欢, 人工智能]

Label:
[我, 喜欢, 人工智能, 。]
```

也就是：

\[
\mathbf{x}
=
[x_0,x_1,x_2,x_3]
\]

标签：

\[
\mathbf{y}
=
[x_1,x_2,x_3,x_4]
\]

可以把它理解成：

\[
\boxed{\text{Label = Input 向左移动一个 Token}}
\]

这是讲 LLM 预训练时非常值得强调的一句话。

---

<a id="origin-507"></a>
## 11. 为什么一次 Forward 就能训练所有位置？

假设：

```text id="y1jrki"
输入：
[BOS, 浙江大学, 位于, 杭州]
```

Transformer 一次 forward 会产生：

```text id="refnbe"
位置 0 → 猜 浙江大学
位置 1 → 猜 位于
位置 2 → 猜 杭州
位置 3 → 猜 。
```

也就是一次 forward 同时完成：

\[
T
\]

个 next-token prediction。

例如 sequence length：

\[
T=4096
\]

一个 sequence 一次就可以产生大约：

\[
4096
\]

个监督信号。

这也是 LLM 能高效利用海量文本的一个重要原因。

---

<a id="origin-551"></a>
## 12. Step 5：Token ID 变成 Embedding

假设：

\[
x_t=8123
\]

8123 只是一个编号，本身没有数学意义。

所以要查 embedding table：

\[
E\in \mathbb R^{V\times d}
\]

其中：

\[
V=\text{词表大小}
\]

\[
d=\text{模型隐藏维度}
\]

例如：

\[
V=100000
\]

\[
d=4096
\]

那么：

\[
E\in\mathbb R^{100000\times4096}
\]

Token 8123 对应：

\[
\mathbf e_{8123}
=
E[8123]
\]

得到一个：

\[
4096
\]

维向量。

---

<a id="origin-611"></a>
## 13. Embedding 的直观解释

可以把它理解为：

> Token 在一个高维“语义空间”里的坐标。

例如理论上可能出现：

\[
\mathbf e_{\text{猫}}
\]

和：

\[
\mathbf e_{\text{狗}}
\]

比较接近。

而：

\[
\mathbf e_{\text{猫}}
\]

和：

\[
\mathbf e_{\text{数据库}}
\]

距离比较远。

当然，真正大模型内部的表示要比这个直觉复杂得多。

---

<a id="origin-649"></a>
## 14. Step 6：Embedding 进入 Transformer

输入：

\[
H^{(0)}
=
[\mathbf h_1,\mathbf h_2,\dots,\mathbf h_T]
\]

不断经过：

\[
N
\]

层 Transformer：

\[
H^{(1)}
=
\operatorname{TransformerBlock}_1(H^{(0)})
\]

\[
H^{(2)}
=
\operatorname{TransformerBlock}_2(H^{(1)})
\]

一直到：

\[
H^{(N)}
\]

可以把每一层粗略理解成两件事：

\[
\boxed{\text{Attention：从上下文获取信息}}
\]

以及：

\[
\boxed{\text{MLP：对信息进一步变换和处理}}
\]

---

<a id="origin-699"></a>
## 15. Self-Attention 在这里到底干什么？

假设一句话：

> 小明把苹果放在桌子上，因为它太重了。

模型处理“它”的时候，需要判断：

> “它”可能指什么？

Attention 就允许当前 token 根据上下文寻找相关 token。

核心公式：

\[
Q=HW_Q
\]

\[
K=HW_K
\]

\[
V=HW_V
\]

然后：

\[
\boxed{
\operatorname{Attention}(Q,K,V)
=
\operatorname{softmax}
\left(
\frac{QK^T}{\sqrt{d_k}}
+M
\right)V
}
\]

其中：

\[
Q=\text{Query}
\]

\[
K=\text{Key}
\]

\[
V=\text{Value}
\]

---

<a id="origin-755"></a>
## 16. Q、K、V 怎么给本科生解释？

可以用“搜索”类比。

当前 token：

> “它”

生成一个 Query：

> **我现在想找和谁有关？**

前面的每个 Token 都有一个 Key：

> **我是什么类型的信息？**

Query 和 Key 做点积：

\[
q_i^Tk_j
\]

得到相关性。

相关性越高：

\[
\Rightarrow
\]

分配越大的 attention weight。

然后从对应 Value 中读取信息。

所以 Attention 可以粗略理解为：

> **每一个 token 都在上下文中进行一次软搜索。**

---

<a id="origin-795"></a>
## 17. 为什么有 \(\sqrt{d_k}\)？

Attention 中：

\[
QK^T
\]

维度很大时，点积数值可能变大。

如果直接送入 Softmax，很容易出现：

```text id="p3342k"
[20, -10, -15]
```

Softmax 以后几乎变成：

```text id="9cu86r"
[1,0,0]
```

梯度容易非常小。

所以除以：

\[
\sqrt{d_k}
\]

控制数值尺度。

因此称为：

\[
\boxed{\text{Scaled Dot-Product Attention}}
\]

---

<a id="origin-835"></a>
## 18. 预训练里最关键的一个东西：Causal Mask

GPT 不允许“偷看答案”。

比如：

```text id="ti602z"
我 喜欢 人工智能 。
```

预测：

> 人工智能

的时候，模型只能看到：

```text id="ntnl7m"
我 喜欢
```

不能提前看到：

```text id="b3p5ia"
人工智能
```

更不能看到：

```text id="qt3b15"
。
```

因此 Attention Matrix 会加一个 causal mask：

\[
M_{ij}
=
\begin{cases}
0,&j\leq i\\
-\infty,&j>i
\end{cases}
\]

矩阵形式：

\[
M=
\begin{bmatrix}
0&-\infty&-\infty&-\infty\\
0&0&-\infty&-\infty\\
0&0&0&-\infty\\
0&0&0&0
\end{bmatrix}
\]

这意味着：

```text id="t7r50v"
Token 1 → 只能看自己和前面
Token 2 → 只能看自己和前面
Token 3 → 只能看自己和前面
...
```

所以叫：

\[
\boxed{\text{Causal Language Model}}
\]

## 20. Step 7：Transformer 最终输出什么？

假设输入长度：

\[
T=4
\]

隐藏维度：

\[
d=4096
\]

最终得到：

\[
H\in\mathbb R^{4\times4096}
\]

即：

\[
\mathbf h_1,
\mathbf h_2,
\mathbf h_3,
\mathbf h_4
\]

每一个位置都有一个 contextual representation。

注意，这时候还不是：

> “下一个 token 的概率”。

还需要一个 LM Head。

<a id="origin-969"></a>
## 21. Step 8：LM Head——把 4096 维变成 10 万维

假设词表：

\[
V=100000
\]

用一个线性层：

\[
\mathbf z_t
=
W_{\text{LM}}\mathbf h_t+b
\]

其中：

\[
W_{\text{LM}}
\in
\mathbb R^{V\times d}
\]

所以：

\[
\mathbf h_t\in\mathbb R^{4096}
\]

经过映射后：

\[
\mathbf z_t\in\mathbb R^{100000}
\]

这 10 万个数叫：

\[
\boxed{\text{Logits}}
\]

例如：

```text id="k88zww"
浙江大学     7.2
清华大学     1.8
杭州         0.5
位于         9.1
苹果        -2.3
......
```

---

<a id="origin-1024"></a>
## 22. Logit 不是概率

比如：

\[
z=
[2,1,0]
\]

三个 token：

```text id="89i070"
A
B
C
```

通过 Softmax：

\[
P_i
=
\frac{e^{z_i}}
{\sum_j e^{z_j}}
\]

于是：

\[
P(A)
=
\frac{e^2}{e^2+e^1+e^0}
\approx0.665
\]

\[
P(B)\approx0.245
\]

\[
P(C)\approx0.090
\]

于是：

```text id="31l3ua"
A: 66.5%
B: 24.5%
C: 9.0%
```

这才是概率。

<a id="origin-1079"></a>
## 23. 来做一个完整的小例子

上下文：

> 中国的首都是

正确答案：

> 北京

假设词表里只有四个词：

```text id="80y57u"
北京
上海
南京
东京
```

模型产生 logits：

\[
z=
[3.5,2.0,1.0,0.5]
\]

经过 Softmax：

\[
P(\text{北京})\approx0.738
\]

假设大概得到：

```text id="w073vl"
北京  73.8%
上海  16.5%
南京   6.1%
东京   3.7%
```

正确 token 是：

\[
y=\text{北京}
\]

如果模型已经给北京很高概率，那么 loss 就比较小。

<a id="origin-1130"></a>
## 24. 最关键的公式：Cross Entropy Loss

对于正确 token：

\[
y_t
\]

loss 为：

\[
\boxed{
L_t
=
-\log P_\theta(y_t\mid x_{<t})
}
\]

如果：

\[
P(\text{北京})=0.9
\]

那么：

\[
L=-\ln0.9\approx0.105
\]

很小。

如果模型认为：

\[
P(\text{北京})=0.01
\]

那么：

\[
L=-\ln0.01\approx4.605
\]

非常大。

因此：

> **正确答案概率越高，Loss 越低。**

---

<a id="origin-1182"></a>
## 25. Loss 的完整数值例子

假设三个候选 token：

```text id="h3v673"
猫
狗
鱼
```

模型 logits：

\[
[2,1,0]
\]

Softmax：

\[
[0.665,\;0.245,\;0.090]
\]

假设正确答案是：

> 狗

那么：

\[
P(\text{狗})=0.245
\]

所以：

\[
L
=
-\ln0.245
\]

\[
\boxed{L\approx1.408}
\]

如果下一轮训练以后模型变成：

```text id="a0mhqd"
猫  10%
狗  80%
鱼  10%
```

那么：

\[
L=-\ln0.8
\approx0.223
\]

Loss 明显降低。

也就是说优化器做的事情就是：

\[
1.408
\rightarrow
1.0
\rightarrow
0.6
\rightarrow
0.3
\rightarrow
0.2
\]

<a id="origin-1259"></a>
## 26. 一整句话的 Loss 怎么算？

假设：

```text id="vj1x45"
[BOS, 我, 喜欢, 猫, 。]
```

需要预测：

```text id="unpq2h"
我
喜欢
猫
。
```

对应概率为：

\[
P(\text{我}|\text{BOS})
\]

\[
P(\text{喜欢}|\text{BOS,我})
\]

\[
P(\text{猫}|\text{BOS,我,喜欢})
\]

\[
P(\text{。}|\text{BOS,我,喜欢,猫})
\]

总 loss：

\[
\boxed{
L
=
-\frac1T
\sum_{t=1}^{T}
\log
P_\theta(x_t|x_{<t})
}
\]

这基本就是 GPT 预训练最核心的目标函数。

---

<a id="origin-1311"></a>
## 27. 从概率论角度，预训练是在最大化什么？

一段文本：

\[
x_1,x_2,\dots,x_T
\]

联合概率根据链式法则：

\[
P(x_1,x_2,\dots,x_T)
=
P(x_1)
P(x_2|x_1)
P(x_3|x_1,x_2)
\dots
\]

统一写成：

\[
\boxed{
P_\theta(x_{1:T})
=
\prod_{t=1}^{T}
P_\theta(x_t|x_{<t})
}
\]

预训练想让真实文本概率越大越好：

\[
\max_\theta
P_\theta(x_{1:T})
\]

因为连乘不方便，所以取 log：

\[
\max_\theta
\sum_t
\log P_\theta(x_t|x_{<t})
\]

再把最大化变成最小化：

\[
\boxed{
\min_\theta
-\sum_t
\log P_\theta(x_t|x_{<t})
}
\]

这就是 Cross Entropy / Negative Log-Likelihood。

所以实际上：

\[
\boxed{
\text{Next Token Prediction}
=
\text{Maximum Likelihood Estimation}
}
\]

这个关系给研究生讲非常合适。

---

<a id="origin-1382"></a>
## 28. Step 9：反向传播

得到：

\[
L(\theta)
\]

之后，需要计算：

\[
\nabla_\theta L
=
\frac{\partial L}{\partial\theta}
\]

这里：

\[
\theta
\]

表示整个模型的所有参数。

比如一个 70B 模型：

\[
|\theta|
\approx70,000,000,000
\]

也就是大约：

> 700 亿个参数。

反向传播计算：

\[
\frac{\partial L}{\partial W_{\text{attention}}}
\]

\[
\frac{\partial L}{\partial W_{\text{MLP}}}
\]

\[
\frac{\partial L}{\partial E}
\]

等等。

<a id="origin-1435"></a>
## 29. 反向传播的直观解释

假设模型预测：

```text id="eekat7"
中国的首都是：
北京 20%
上海 60%
南京 20%
```

正确答案是北京。

Loss 很大。

反向传播会产生一个梯度，大致告诉每个参数：

> 你刚才导致“上海”的分数过高、“北京”的分数过低，下一次应该往什么方向改一点。

于是：

```text id="gz62r3"
训练前：
北京 20%
上海 60%
```

经过很多类似样本训练：

```text id="bxo66z"
训练后：
北京 95%
上海 3%
```

当然真正模型不是直接存：

```text id="j8i8jr"
China → Beijing
```

而是通过上百亿参数形成分布式表示。

<a id="origin-1480"></a>
## 30. Softmax + Cross Entropy 的梯度其实特别漂亮

假设：

\[
p_i=\operatorname{softmax}(z_i)
\]

真实标签 one-hot 为：

\[
y_i
\]

Cross Entropy：

\[
L=-\sum_i y_i\log p_i
\]

则对 logits 的梯度：

\[
\boxed{
\frac{\partial L}{\partial z_i}
=
p_i-y_i
}
\]

这个公式体现了梯度下降的参数更新方向。

比如正确答案是：

```text id="st36xp"
北京
```

模型预测：

```text id="52xylc"
北京 0.2
上海 0.6
南京 0.2
```

真实标签：

```text id="yckj5l"
北京 1
上海 0
南京 0
```

所以梯度：

\[
p-y
=
\begin{bmatrix}
0.2-1\\
0.6-0\\
0.2-0
\end{bmatrix}
=
\begin{bmatrix}
-0.8\\
0.6\\
0.2
\end{bmatrix}
\]

所以梯度下降以后：

> 北京的 logit 被推高，上海和南京的 logit 被压低。

非常直观。

<a id="origin-1560"></a>
## 31. Step 10：Optimizer 更新参数

最简单的梯度下降：

\[
\boxed{
\theta_{t+1}
=
\theta_t-\eta\nabla_\theta L
}
\]

其中：

\[
\eta
\]

就是 learning rate。

例如：

\[
\eta=10^{-4}
\]

但是现代大模型通常不会使用最简单的 SGD，而会用 AdamW 一类优化器。

Adam 的核心思想是：

> 不仅看当前梯度，还维护梯度的一阶矩和二阶矩。

---

<a id="origin-1594"></a>
## 32. AdamW 公式

梯度：

\[
g_t=\nabla_\theta L_t
\]

一阶动量：

\[
m_t
=
\beta_1m_{t-1}
+
(1-\beta_1)g_t
\]

二阶动量：

\[
v_t
=
\beta_2v_{t-1}
+
(1-\beta_2)g_t^2
\]

偏差修正：

\[
\hat m_t
=
\frac{m_t}{1-\beta_1^t}
\]

\[
\hat v_t
=
\frac{v_t}{1-\beta_2^t}
\]

更新：

\[
\theta_{t+1}
=
\theta_t
-
\eta
\frac{\hat m_t}
{\sqrt{\hat v_t}+\epsilon}
\]

AdamW 还额外把 weight decay 从梯度更新中解耦。

链式法则的核心关系是：

\[
\boxed{
Loss
\rightarrow Gradient
\rightarrow Optimizer
\rightarrow Parameter Update
}
\]

## 35. 完整训练例子

训练样本：

> 人工智能正在改变世界。

Tokenizer：


构造：

```text id="ttw6nq"

[人工智能, 正在, 改变, 世界, 。]
```

Embedding：

\[
x_t
\rightarrow
e_t\in\mathbb R^d
\]

Transformer：

\[
e_{1:T}
\rightarrow
h_{1:T}
\]

LM Head：

\[
h_t
\rightarrow
z_t\in\mathbb R^V
\]

Softmax：

\[
z_t
\rightarrow
p_t
\]

比如第三个位置：


模型：


正确：


\rightarrow

\]

\[
\theta
\rightarrow\theta'
\]

## 39. 为什么还会出现“推理能力”？

例如训练语料中：

可能逐步学到某些计算与推理模式。

\[
\text{数据规模}\uparrow

\text{训练计算量}\uparrow
\]

模型会形成越来越复杂的内部表示。

需要注意：

> **预训练目标本身仍然只是 next-token prediction；所谓知识、语法、代码、一定程度的推理，是模型为了把 next token 猜得更准而涌现出来的能力。**

<a id="origin-2032"></a>
## 40. 预训练和“背书”到底有什么区别？

这里容易产生误解。

不是简单：

```text id="xa6a5i"
看到 A
记住 B
```

例如一句：

> 浙江大学位于杭州。

它对参数只造成很小的一次更新。

参数改变的是：

\[
\theta_1,\theta_2,\dots,\theta_{100B}
\]

形成高度分布式的表示。

所以一个知识点通常不是：

```text id="pghii8"
某个神经元 = 杭州
```

而是在大量参数和激活模式中共同表示。

但是模型确实也可能：

\[
\text{memorize}
\]

某些训练数据，尤其是高度重复、罕见或唯一文本。

所以更准确地说：

> **LLM 同时具有泛化和记忆。**

<a id="origin-2079"></a>
## 41. 怎么判断模型是不是训练得越来越好？

最常见指标之一就是验证集 Loss。

例如：

```text id="mkd4of"
Step 0          Loss = 10.2
Step 10k        Loss = 5.8
Step 100k       Loss = 3.2
Step 500k       Loss = 2.4
Step 2M         Loss = 1.9
```

另外一个常见指标：

\[
\boxed{
\operatorname{Perplexity}=e^L
}
\]

简称：

\[
PPL
\]

例如：

\[
L=2
\]

那么：

\[
PPL=e^2\approx7.39
\]

直觉上可以粗略理解为：

> 模型平均感觉“下一个 token 大概有几个比较像样的候选”。

PPL 越低通常越好。

## 42. 交叉熵与困惑度的关系

Cross Entropy：

\[
L=1
\]

则：

\[
PPL=e^1=2.72
\]

如果：

\[
L=2
\]

则：

\[
PPL=e^2=7.39
\]

如果：

\[
L=3
\]

则：

\[
PPL=e^3=20.09
\]

因此 Loss 只差 1：

\[
2\rightarrow3
\]

Perplexity 却：

\[
7.4\rightarrow20.1
\]

## 43. Learning Rate 为什么很重要？

如果：

\[
\eta
\]

太大：

```text id="j7wehk"

2.1
1.9
3.7
8.4
NaN
```

可能训练崩溃。

如果太小：


学习非常慢。

所以通常会有：

\[

\rightarrow

\rightarrow

\]

一个典型策略是 cosine decay。

## 44. 为什么一开始需要 Warmup？

随机初始化或者训练早期，梯度可能非常不稳定。

如果一开始直接：

\[
\eta=10^{-4}
\]

可能参数更新过猛。

所以先：

\[
10^{-7}
\]

逐渐增加：

\[
10^{-6}
\]

\[
10^{-5}
\]

\[
10^{-4}
\]

相当于让模型先“热身”。

## 45. Gradient Accumulation 又是什么？

假设 GPU 一次只能放：

\[
8
\]

个 sequence。

但是希望 effective batch：

\[
128
\]

那么可以：

```text id="q84tkz"
Batch 1 → 算梯度，不更新
Batch 2 → 累加梯度
...
Batch 16 → 累加梯度
然后 Update 一次
```

于是：

\[
8\times16=128
\]

这就是：

\[
\boxed{\text{Gradient Accumulation}}
\]

## 49. Pretraining 和 SFT 最核心的区别

各阶段的区别如下：

| | Pretraining | SFT |
|---|---|---|
| 数据 | 海量自然文本 | 高质量 instruction-response |
| 数据量 | Trillion tokens | Million 级样本 |
| 目标 | 学语言与世界模式 | 学会按指令回答 |
| 学习方式 | Next-token prediction | 本质仍然是 next-token prediction |
| Loss | Cross Entropy | 通常仍是 Cross Entropy |
| 最终产物 | Base Model | Instruct Model |

需要注意：

> **SFT 在数学上并没有突然换一个神奇算法。很多时候仍然是在做 next-token prediction，只是数据变了，而且通常只对 response 部分计算 loss。**

<a id="origin-2445"></a>
## 50. 把整个预训练压缩成一个公式

核心公式如下：

\[
\boxed{
\mathcal L_{\text{pretrain}}(\theta)
=
-\frac{1}{N}
\sum_{n=1}^{N}
\sum_{t=1}^{T_n}
\log
P_\theta
\left(
x_t^{(n)}
\mid
x_{<t}^{(n)}
\right)
}
\]

里面每个符号都可以解释：

\[
N
=
\text{训练样本数量}
\]

\[
T_n
=
\text{第 n 个 sequence 的长度}
\]

\[
x_t^{(n)}
=
\text{真实的第 t 个 token}
\]

\[
x_{<t}^{(n)}
=
\text{它前面的所有 token}
\]

\[
P_\theta
=
\text{由 Transformer 参数 }\theta\text{ 给出的概率}
\]

训练的目标：

\[
\boxed{
\theta^*
=
\arg\min_\theta
\mathcal L_{\text{pretrain}}(\theta)
}
\]

一句中文：

> **找到一组模型参数，使真实世界文本中的下一个 token 尽可能容易被模型预测出来。**

## 51. 预训练流程总结

预训练可以概括为：

> **读文本 → 猜下词 → 算误差 → 改参数**

更完整一点就是：

\[
\boxed{
\text{Text}
\rightarrow
\text{Token}
\rightarrow
\text{Transformer}
\rightarrow
\text{Logits}
\rightarrow
\text{Softmax}
\rightarrow
\text{Cross Entropy}
\rightarrow
\text{Backprop}
\rightarrow
\text{AdamW}
}
\]

然后不断重复：

\[
\boxed{
\text{Trillions of Tokens}
+
\text{Billions of Parameters}
+
\text{Massive Compute}
\Longrightarrow
\text{Base LLM}
}
\]

这基本就是大语言模型 **Pretraining 的完整主线**。
