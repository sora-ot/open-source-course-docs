# 28 · 位置编码：绝对位置与正弦编码

<a id="origin-16659"></a>
## 1. 传统位置编码完整讲义：从绝对位置到相对位置

<a id="origin-16661"></a>
## 2. 为什么 Transformer 必须加入位置编码？

先看一句话：

```text
我 喜欢 小明
```

和：

```text
小明 喜欢 我
```

这两句话包含的 token 是一样的：

```text
我
喜欢
小明
```

但是顺序完全不同，语义也完全不同。

问题在于：

> Self-Attention 本身并不知道 token 的先后顺序。

如果只看 token embedding：

```math
X_{\text{我}}
```

```math
X_{\text{喜欢}}
```

```math
X_{\text{小明}}
```

模型知道：

```text
这个词是谁
```

但是不知道：

```text
它在第几个位置
```

所以 Transformer 必须额外加入：

```text
Position Encoding
位置编码
```

---

<a id="origin-16724"></a>
## 3. Token Embedding 和 Position Encoding 分别解决什么问题？

可以简单理解为：

```text
Token Embedding
↓
告诉模型：
“我是谁？”
```

例如：

```text
我
喜欢
小明
```

都有自己的语义表示。

而：

```text
Position Encoding
↓
告诉模型：
“我在哪里？”
```

例如：

```text
我      → 第1个位置
喜欢    → 第2个位置
小明    → 第3个位置
```

最后把两者加起来：

```math
H_i=X_i+P_i
```

其中：

```text
Xi = token embedding
Pi = position encoding
```

于是模型得到的是：

```text
“我是谁”
+
“我在哪里”
```

<a id="origin-16785"></a>
## 4. 先用一个极度简化的例子理解位置编码

假设 token embedding 只有 3 维：

```math
X=[1,2,3]
```

现在为了教学方便，我们人为规定：

```text
第1个位置 → 0.1
第2个位置 → 0.2
第3个位置 → 0.3
```

那么最简单的想法可能是：

```text
位置1 → 0.1
位置2 → 0.2
位置3 → 0.3
```

但问题来了：

> 这个 0.1 到底放到向量的哪一维？

比如可以写成：

```math
P_1=[0.1,0,0]
```

也可以：

```math
P_1=[0,0.1,0]
```

还可以：

```math
P_1=[0,0,0.1]
```

到底哪个对？

答案是：

<a id="origin-16835"></a>
## 5. 都可以。

---

<a id="origin-16839"></a>
## 6. 为什么放第一维、第二维、第三维都可以？

假设我们规定：

```text
位置1 → 0.1
位置2 → 0.2
位置3 → 0.3
```

我们完全可以采用方案 A：

```text
位置1 → [0.1,0,0]
位置2 → [0.2,0,0]
位置3 → [0.3,0,0]
```

也可以采用方案 B：

```text
位置1 → [0,0.1,0]
位置2 → [0,0.2,0]
位置3 → [0,0.3,0]
```

甚至可以采用方案 C：

```text
位置1 → [0,0,0.1]
位置2 → [0,0,0.2]
位置3 → [0,0,0.3]
```

三种方式都能够区分位置。

因为只要：

```math
P_1\neq P_2\neq P_3
```

模型就能知道：

```text
它们不是同一个位置。
```

---

<a id="origin-16889"></a>
## 7. 那为什么之前会写成 `[0,0.1,0]`？

只是为了方便举例。

例如：

```math
X=[1,2,3]
```

位置编码：

```math
P_1=[0,0.1,0]
```

那么：

```math
H=X+P_1
```

得到：

```math
H=[1,2.1,3]
```

目的只是为了展示：

```text
Token Embedding
+
Position Encoding
```

这个过程。

并不是说：

```text
位置一定要加在第2维
```

也不是说：

```text
第2维专门负责位置
```

所以：

> `[0,0.1,0]` 只是一个教学例子，不是 Transformer 真实的位置编码方式。

---

<a id="origin-16945"></a>
## 8. 为什么模型能知道 `[0.1,0,0]` 和 `[0,0.1,0]` 不一样？

因为它们是两个不同的向量。

例如：

```math
A=[0.1,0,0]
```

```math
B=[0,0.1,0]
```

后面假设接一个矩阵：

```math
W=
\begin{bmatrix}
10\\
20\\
30
\end{bmatrix}
```

那么：

```math
AW
=
0.1\times10
=
1
```

而：

```math
BW
=
0.1\times20
=
2
```

所以：

```text
虽然数值都是 0.1，
但是所在维度不同，
经过矩阵运算以后结果就不同。
```

因此模型当然能够区分。

---

<a id="origin-17002"></a>
## 9. 但这里有一个更重要的问题

如果我们真的这样设计：

```text
位置1 → [0.1,0,0]
位置2 → [0.2,0,0]
位置3 → [0.3,0,0]
```

其实非常粗糙。

因为我们只是把：

```text
位置编号
```

简单塞进一个维度里。

真实 Transformer 并不是这么做的。

真实的位置编码使用：

> 整个高维向量共同表示一个位置。

例如：

```text
位置1：

[0.84,0.54,0.10,0.99,0.01,0.999,...]
```

```text
位置2：

[0.91,-0.42,0.20,0.98,0.02,0.999,...]
```

```text
位置3：

[0.14,-0.99,0.30,0.95,0.03,0.999,...]
```

所以：

```text
位置1
```

不是：

```text
0.1
```

而是：

```text
一整个高维向量 P1
```

---

<a id="origin-17068"></a>
## 10. 为什么要用整个向量表示位置？

因为模型的 hidden state 本身就是高维的。

例如：

```text
hidden size = 4096
```

那么：

```math
X_i\in R^{4096}
```

为了相加：

```math
H_i=X_i+P_i
```

位置编码也必须是：

```math
P_i\in R^{4096}
```

所以每一个位置实际上都有：

```text
4096 个位置相关数值
```

共同描述当前位置。

---

<a id="origin-17106"></a>
## 11. 那这 4096 个维度分别是什么意思？

这里非常重要：

> 一般不能简单地给每个维度赋予一个人类可解释的含义。

不能说：

```text
第1维 = 位置
第2维 = 距离
第3维 = 前后关系
```

真实神经网络通常不是这么组织信息的。

更加准确的理解是：

```text
很多维度共同组成一种模式
```

就像：

```text
条形码
```

一样。

一个条形码里：

```text
第17根线
```

本身没有必要单独解释。

重要的是：

```text
整个条形码组合起来
```

代表一个唯一的信息。

位置编码也是这样。

## 12. 原始 Transformer 到底是怎么生成位置编码的？

原始 Transformer 使用的是：

<a id="origin-17160"></a>
## 13. Sinusoidal Position Encoding

公式为：

```math
PE(pos,2i)
=
\sin
\left(
\frac{pos}
{10000^{2i/d}}
\right)
```

```math
PE(pos,2i+1)
=
\cos
\left(
\frac{pos}
{10000^{2i/d}}
\right)
```

其中：

```text
pos
```

表示：

```text
token 的绝对位置
```

例如：

```text
0
1
2
3
4
...
```

而：

```text
i
```

表示：

```text
不同的维度组。
```

---

<a id="origin-17221"></a>
## 14. 最直观的理解：不同维度就是不同速度的钟

这是理解 Sinusoidal Position Encoding 最容易的方法。

假设只用 6 维。

可以理解成有三只钟：

```text
第1、2维
→ 快钟

第3、4维
→ 中速钟

第5、6维
→ 慢钟
```

每只钟都随着：

```text
位置增加
```

不断旋转。

---

<a id="origin-17250"></a>
## 15. 为什么一对维度要用 sin 和 cos？

因为：

```text
sin
cos
```

共同可以表示一个二维圆上的位置。

例如一个角度：

```math
\theta
```

可以表示成：

```math
[\sin\theta,\cos\theta]
```

例如：

```text
位置1
↓
角度 θ1
↓
[sin θ1, cos θ1]
```

位置2：

```text
位置2
↓
角度 θ2
↓
[sin θ2, cos θ2]
```

于是：

```text
每个位置
```

都会对应圆上的一个不同方向。

---

<a id="origin-17303"></a>
## 16. 为什么还要有很多不同频率？

如果只有一只钟，会发生一个严重问题：

> 钟会转一圈。

例如：

```text
位置1
```

可能是：

```text
30°
```

过了一整圈之后：

```text
位置13
```

也可能重新来到：

```text
30°
```

那么仅靠这一只钟：

```text
位置1
```

和：

```text
位置13
```

就分不出来了。

怎么办？

再加入很多不同速度的钟。

例如：

```text
快钟：
已经转了一圈

慢钟：
只转了一小点
```

所以虽然快钟一样：

```text
位置1 ≈ 位置13
```

但慢钟不一样。

多个频率一起看，就可以区分。

---

<a id="origin-17373"></a>
## 17. 所以真实位置编码更像“多只不同速度的钟”

例如：

```text
位置 1
```

可能得到：

```text
快钟：某个角度
中钟：某个角度
慢钟：某个角度
```

位置 2：

```text
快钟：转了一些
中钟：转了一点
慢钟：几乎没动
```

位置 100：

```text
快钟：已经转了很多圈
中钟：转了一部分
慢钟：只转了一点
```

最终把这些：

```text
sin
cos
sin
cos
sin
cos
...
```

全部拼起来：

```math
P_{100}
=
[
\sin\theta_1,
\cos\theta_1,
\sin\theta_2,
\cos\theta_2,
...
]
```

形成：

```text
位置100的高维位置指纹。
```

<a id="origin-17439"></a>
## 18. 所以现在重新理解 `[0,0.1,0]`

现在可以更加准确地说：

```math
[0,0.1,0]
```

这个例子只是为了说明：

```text
“往 token embedding 中加入位置信息”
```

而不是说明：

```text
Transformer 真的是把 0.1 塞进第二维。
```

如果真的只用：

```text
0.1
0.2
0.3
```

表示位置，

那么它们放：

```text
第一维
第二维
第三维
```

都没有本质区别。

真正的 Transformer 采用的是：

```text
一个完整的高维位置向量
```

而不是：

```text
一个标量 + 某一个特殊维度。
```

<a id="origin-17493"></a>
## 19. 为什么这种位置编码叫“绝对位置编码”？

因为它直接输入的是：

```text
当前位置是多少。
```

例如：

```text
token A → 位置3
token B → 位置5
```

模型得到的是：

```math
P_3
```

以及：

```math
P_5
```

也就是：

```text
A 在第3个位置
B 在第5个位置
```

所以这是：

<a id="origin-17529"></a>
## 20. Absolute Position

绝对位置。

<a id="origin-17535"></a>
## 21. 但一个关键问题来了

既然传统位置编码给的是：

```text
绝对位置
```

那么模型是不是不知道：

```text
两个 token 相隔多少？
```

不是。

实际上：

**模型完全可以根据两个绝对位置，进一步学习出相对位置。**

<a id="origin-17557"></a>
## 22. 最简单的生活例子

假设告诉你：

```text
小明住 8 楼
小红住 11 楼
```

这里给你的都是：

```text
绝对位置
```

分别是：

```text
8
11
```

但是你马上可以算出：

```math
11-8=3
```

于是得到：

```text
小红比小明高3层。
```

这个：

```text
3
```

就是：

```text
相对位置。
```

所以：

```text
有绝对位置
```

并不代表：

```text
不知道相对位置。
```

而是：

```text
绝对位置
↓
比较
↓
得到相对位置
```

<a id="origin-17627"></a>
## 23. Transformer 里面怎么实现这种“比较”？

假设两个 token 在：

```text
位置 i
位置 j
```

加入位置编码以后：

```math
H_i=X_i+P_i
```

```math
H_j=X_j+P_j
```

然后生成：

```math
Q_i=H_iW_Q
```

```math
K_j=H_jW_K
```

Attention Score：

```math
S_{ij}=Q_iK_j^T
```

代进去：

```math
S_{ij}
=
(X_i+P_i)W_Q
\left(
(X_j+P_j)W_K
\right)^T
```

展开以后会包含：

```math
P_iW_QW_K^TP_j^T
```

也就是说：

> 两个位置编码之间确实会发生交互。

所以模型可以逐渐学习：

```text
位置 i
和
位置 j
```

之间是什么关系。

例如：

```text
j=i+1
```

可能意味着：

```text
下一个 token
```

```text
j=i-1
```

可能意味着：

```text
前一个 token
```

```text
|i-j| 很小
```

可能意味着：

```text
两个 token 距离很近。
```

<a id="origin-17727"></a>
## 24. Sin/Cos 为什么特别适合学习相对位置？

因为三角函数有一个非常重要的性质：

```math
\cos(a-b)
=
\cos a\cos b
+
\sin a\sin b
```

假设：

```text
位置 i
```

对应角度：

```math
\theta_i
```

位置 j：

```math
\theta_j
```

那么两个位置的 sin/cos 进行组合时：

```math
\sin\theta_i
```

```math
\cos\theta_i
```

和：

```math
\sin\theta_j
```

```math
\cos\theta_j
```

可以产生：

```math
\cos(\theta_i-\theta_j)
```

注意这里出现的是：

```math
\theta_i-\theta_j
```

也就是：

> 两个位置之间的差。

---

<a id="origin-17795"></a>
## 25. 这意味着什么？

虽然传统 Sinusoidal Position Encoding 输入的是：

```text
绝对位置 i
```

和：

```text
绝对位置 j
```

但它们之间发生数学运算以后，很容易得到：

```text
i-j
```

相关的信息。

所以：

```text
绝对位置
```

可以进一步产生：

```text
相对位置关系。
```

---

<a id="origin-17831"></a>
## 26. 一个具体例子

假设有：

```text
位置100
位置101
```

从绝对位置看：

```text
100
101
```

数值都很大。

但是对于语言而言，真正重要的往往是：

```math
101-100=1
```

也就是说：

```text
它们是相邻 token。
```

Sin/Cos 的结构，使模型比较容易从：

```text
P100
P101
```

中学习：

```text
距离 = 1
```

这样的关系。

## 27. 所以“绝对位置编码”到底是什么意思？

这里一定要区分：

<a id="origin-17882"></a>
### 27.1 编码进去的东西

传统位置编码直接提供：

```text
“我在第几个位置”
```

例如：

```text
位置3
位置5
```

这是：

```text
绝对位置。
```

---

<a id="origin-17905"></a>
### 27.2 模型最后学到的东西

模型可以进一步学习：

```text
位置5
相对于
位置3
```

是：

```text
后面2个位置。
```

这就是：

```text
相对位置。
```

所以：

> “绝对位置编码”描述的是输入方式，而不是模型最终只能理解绝对位置。

## 28. 可以把整个过程理解成

```text
A 在位置3
B 在位置5
        ↓
输入两个绝对位置
        ↓
Attention 中发生交互
        ↓
模型学习：
5 - 3 = 2
        ↓
B 在 A 后面两个位置
```

<a id="origin-17951"></a>
## 29. 那 RoPE 为什么还要出现？

既然传统位置编码已经可以学习相对位置，

为什么后来还要 RoPE？

因为传统方法更像：

```text
先告诉模型：

A 在位置3
B 在位置5

        ↓

然后让模型自己学习：

位置5和位置3之间是什么关系
```

也就是：

```text
绝对位置
↓
模型再学习相对关系
```

---

<a id="origin-17982"></a>
## 30. RoPE 的思路更加直接

RoPE 不再简单使用：

```math
X+P
```

而是：

```text
根据 token 的位置
直接旋转 Q 和 K
```

然后：

```math
Q_iK_j^T
```

中会自然出现：

```text
位置差 i-j
```

相关的信息。

所以可以粗略理解为：

```text
传统位置编码：

先告诉模型
“你在哪里”

然后让模型学习
“你们相距多远”
```

而：

```text
RoPE：

直接让 Attention Score
对“你们相距多远”敏感
```

<a id="origin-18034"></a>
## 31. 用一句话总结传统位置编码和 RoPE

传统位置编码：

```text
绝对位置
↓
加入 Hidden State
↓
Attention
↓
模型学习相对位置
```

RoPE：

```text
绝对位置
↓
旋转 Q、K
↓
QK^T
↓
天然体现相对位置
```

<a id="origin-18198"></a>
## 33. 最核心的几个结论

<a id="origin-18200"></a>
### 33.1 结论一

```math
[0,0.1,0]
```

只是教学示例。

它不是 Transformer 真实的位置编码。

---

<a id="origin-18212"></a>
### 33.2 结论二

如果真的规定：

```text
位置1 → 0.1
位置2 → 0.2
```

那么：

```text
把 0.1 放第一维
第二维
第三维
```

理论上都可以。

并不存在：

```text
“为什么一定放第二维”
```

的问题。

---

<a id="origin-18241"></a>
### 33.3 结论三

真实 Transformer 不会把位置简单塞进某一个维度。

而是：

```text
整个高维向量
```

共同表示一个位置。

---

<a id="origin-18255"></a>
### 33.4 结论四

Sinusoidal Position Encoding 可以理解成：

```text
很多不同速度的钟
```

一起记录当前位置。

---

<a id="origin-18267"></a>
### 33.5 结论五

传统位置编码显式提供的是：

```text
绝对位置
```

但是模型可以通过 Attention 中的位置交互学习：

```text
相对位置。
```

---

<a id="origin-18283"></a>
### 33.6 结论六

最准确的一句话是：

> **传统位置编码告诉模型“我在哪里”；模型再根据不同 token 的位置表示，学习“我们之间相距多远”。**

而 RoPE 则进一步把：

> **“我们之间相距多远”直接融入 Q、K 的 Attention 计算中。**
