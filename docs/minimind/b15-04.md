# 38 · 模型源码：Transformer 主干、LM Head 与 Loss

<a id="origin-8127"></a>
## 1. `MiniMindModel`：把 Embedding、N 个 Block、最终 Norm 组装成 Transformer 主干

前面我们一直在研究“一层内部”。

现在进入：

```python
class MiniMindModel(nn.Module):
```

它的职责可以压缩成一句话：

> 把整数 token ID 变成最终上下文化 hidden states。

注意：

```text
MiniMindModel 还不是完整语言模型
```

它没有负责：

```text
H → Vocabulary logits
CrossEntropy Loss
generate 采样
```

它只做 Transformer backbone。

整体：

```text
input_ids [B,T]
    │
    ▼
Embedding
    │
    ▼
[B,T,H]
    │
    ▼
Block 0
    │
    ▼
Block 1
    │
   ...
    │
    ▼
Block N-1
    │
    ▼
Final RMSNorm
    │
    ▼
hidden_states [B,T,H]
```

---

<a id="origin-8188"></a>
### 1.1 保存配置

源码：

```python
self.config = config
```

为什么要保存？

后面 `forward()` 中若需要重建 RoPE 表，会用到：

```text
config.head_dim
config.max_position_embeddings
config.rope_theta
config.rope_scaling
```

所以不能只在构造时临时读取完就丢掉。

---

<a id="origin-8211"></a>
### 1.2 一行保存两个属性

源码：

```python
self.vocab_size, self.num_hidden_layers = (
    config.vocab_size,
    config.num_hidden_layers
)
```

Python 元组解包。

等价于：

```python
self.vocab_size = config.vocab_size
self.num_hidden_layers = config.num_hidden_layers
```

---

<a id="origin-8233"></a>
### 1.3 `nn.Embedding(V,H)`：token ID 真正变成向量

源码：

```python
self.embed_tokens = nn.Embedding(
    config.vocab_size,
    config.hidden_size
)
```

例如：

```text
V=16
H=8
```

Embedding 内部有一个可训练参数表：

```text
weight.shape = [16,8]
```

可以想成：

```text
Token 0 → 第 0 行 8 个数
Token 1 → 第 1 行 8 个数
...
Token 15 → 第 15 行 8 个数
```

输入：

```python
input_ids = torch.tensor([[1,5,7]])
```

shape：

```text
[1,3]
```

输出：

```python
x = self.embed_tokens(input_ids)
```

shape：

```text
[1,3,8]
```

---

<a id="origin-8292"></a>
### 1.4 Embedding 不是 one-hot 后再显式矩阵乘吗？

数学上可以理解为类似：

```text
one-hot(token_id) @ W_embedding
```

但工程实现不会真的创建一个 V 维 one-hot 向量再乘矩阵。

`nn.Embedding` 本质更像：

> 按整数索引直接查参数矩阵对应行。

所以 token 5：

```text
取 weight[5]
```

效率更高。

---

<a id="origin-8316"></a>
### 1.5 输入 Dropout

源码：

```python
self.dropout = nn.Dropout(config.dropout)
```

它将在：

```text
Embedding 输出之后
```

使用。

若：

```text
dropout=0
```

训练时也不会丢任何元素。

---

<a id="origin-8342"></a>
### 1.6 `ModuleList` 创建 N 个独立 Block

源码：

```python
self.layers = nn.ModuleList([
    MiniMindBlock(l, config)
    for l in range(self.num_hidden_layers)
])
```

如果：

```text
num_hidden_layers=3
```

就相当于：

```python
self.layers = nn.ModuleList([
    MiniMindBlock(0, config),
    MiniMindBlock(1, config),
    MiniMindBlock(2, config),
])
```

每调用一次：

```python
MiniMindBlock(...)
```

都会创建一套新的：

```text
Attention 参数
Norm 参数
FFN/MoE 参数
```

所以各层默认不共享权重。

---

<a id="origin-8387"></a>
### 1.7 `range(self.num_hidden_layers)`

最简单：

```python
list(range(3))
```

得到：

```text
[0,1,2]
```

因此 `l` 依次是：

```text
0,1,...,N-1
```

虽然当前 `MiniMindBlock.__init__` 没实际使用 layer_id，但调用接口还是传了进去。

---

<a id="origin-8411"></a>
### 1.8 主干末尾的 RMSNorm

源码：

```python
self.norm = RMSNorm(
    config.hidden_size,
    eps=config.rms_norm_eps
)
```

全部 Block 结束后：

```text
[B,T,H]
```

再进行最后一次 H 维归一化。

---

<a id="origin-8432"></a>
### 1.9 在模型创建时预计算整张 RoPE 表

源码：

```python
freqs_cos, freqs_sin = precompute_freqs_cis(
    dim=config.head_dim,
    end=config.max_position_embeddings,
    rope_base=config.rope_theta,
    rope_scaling=config.rope_scaling
)
```

例如：

```text
D=4
max_position_embeddings=32
```

得到：

```text
freqs_cos [32,4]
freqs_sin [32,4]
```

注意：

> 不是每一层各算一张。

位置编码规则相同，所以整台主干共享这两张表。

---

<a id="origin-8467"></a>
### 1.10 `register_buffer`：不是 Parameter，但要跟模型一起移动设备

源码：

```python
self.register_buffer(
    "freqs_cos",
    freqs_cos,
    persistent=False
)

self.register_buffer(
    "freqs_sin",
    freqs_sin,
    persistent=False
)
```

这是非常值得讲的 PyTorch 概念。

模型中的 Tensor 大致可以分：

```text
Parameter
    需要梯度训练

Buffer
    不训练，但属于模型状态/计算需要

普通临时 Tensor
    只是某次 forward 的中间变量
```

RoPE 的 cos/sin 表：

```text
不需要梯度
```

所以不应该是 Parameter。

但我们又希望：

```python
model.to("cuda")
```

时它们也自动移动到 GPU。

于是很适合注册成 buffer。

---

<a id="origin-8520"></a>
### 1.11 `persistent=False` 是什么意思？

默认 buffer 可能会进入：

```python
state_dict()
```

但这里：

```python
persistent=False
```

表示：

> 这个 buffer 可以跟设备移动，但不需要保存进模型 state_dict。

原因也很自然：

```text
cos/sin 可以根据 config 随时重新计算
```

没有必要让 checkpoint 再存一大份可重建表。

---

<a id="origin-8548"></a>
## 2. `MiniMindModel.forward()`：token ID 开始真正走过所有层

函数签名：

```python
def forward(
    self,
    input_ids,
    attention_mask=None,
    past_key_values=None,
    use_cache=False,
    **kwargs
):
```

这里要注意名字：

```text
past_key_value   单数
```

前面 Attention/Block 指的是“一层”的 K/V。

这里：

```text
past_key_values  复数
```

指的是：

```text
所有层的 cache 列表
```

概念结构：

```text
past_key_values = [
    (K_layer0, V_layer0),
    (K_layer1, V_layer1),
    ...
]
```

---

<a id="origin-8595"></a>
### 2.1 `batch_size, seq_length = input_ids.shape`

输入 token ID 是二维：

```text
[B,T]
```

例如：

```python
input_ids = [[1,5,7]]
```

shape：

```text
[1,3]
```

得到：

```text
batch_size=1
seq_length=3
```

当前函数后面实际上没有直接使用 `batch_size`，但保留下来也有利于表达输入语义。

---

<a id="origin-8626"></a>
### 2.2 `hasattr(past_key_values, 'layers')`

源码：

```python
if hasattr(past_key_values, 'layers'):
    past_key_values = None
```

这是一段兼容处理。

如果调用方传入某种具有：

```text
.layers
```

属性的缓存对象，本实现当前并没有把它转换成自己的列表格式，而是直接清空：

```text
None
```

所以这份讲义中我们始终使用本文件自己返回的：

```text
list[(K,V),...]
```

来理解缓存。

---

<a id="origin-8659"></a>
### 2.3 `past_key_values = past_key_values or [None] * len(self.layers)`

这一行非常 Python。

如果：

```text
past_key_values is None
```

或是空列表等 Falsey 值，则右侧生效：

```python
[None] * len(self.layers)
```

例如两层：

```text
[None, None]
```

表示：

```text
Layer0 没历史 cache
Layer1 没历史 cache
```

如果已经传入非空缓存列表，则保留原值。

---

<a id="origin-8692"></a>
### 2.4 `[None] * N`

最简单：

```python
[None] * 3
```

得到：

```text
[None,None,None]
```

因为 None 是不可变单例，这里不存在像“多个可变 list 引用同一对象”那类陷阱。

---

<a id="origin-8710"></a>
### 2.5 `start_pos`：本轮新 token 的绝对起始位置

源码：

```python
start_pos = (
    past_key_values[0][0].shape[1]
    if past_key_values[0] is not None
    else 0
)
```

为什么只看第 0 层？

正常情况下：

```text
所有层的 cache 序列长度应该一致
```

所以第 0 层就足够得到历史 token 数。

---

<a id="origin-8734"></a>
### 2.6 第一次输入

```text
past_key_values[0] = None
```

于是：

```text
start_pos=0
```

如果本轮 T=3：

```text
位置 = 0,1,2
```

---

<a id="origin-8754"></a>
### 2.7 缓存后续写

假设第 0 层历史 K：

```text
shape = [1,3,Nkv,D]
```

`shape[1]`：

```text
3
```

所以：

```text
start_pos=3
```

本轮一个新 token 的位置就是：

```text
3
```

这正是 RoPE 必须知道的信息。

---

<a id="origin-8784"></a>
### 2.8 Embedding 真正执行

源码：

```python
hidden_states = self.dropout(
    self.embed_tokens(input_ids)
)
```

拆开：

```python
hidden_states = self.embed_tokens(input_ids)
hidden_states = self.dropout(hidden_states)
```

shape：

```text
[B,T]
↓ Embedding
[B,T,H]
↓ Dropout
[B,T,H]
```

从这一刻开始：

```text
整数 token ID
```

已经变成：

```text
浮点 hidden states
```

后续所有 Transformer 计算都处理 hidden states，而不是直接处理 token 编号。

---

<a id="origin-8827"></a>
### 2.9 为什么检查 `self.freqs_cos[0,0] == 0`

源码：

```python
if self.freqs_cos[0, 0] == 0:
```

正常普通 RoPE：

```text
位置0角度=0
cos(0)=1
```

所以：

```text
freqs_cos[0,0]
```

理论上应为 1（考虑当前 attention_factor 默认也是 1）。

如果它变成 0，作者把它当成某种“位置表异常/需要重建”的触发标志。

注意：

> 这并不是一个完整的通用校验机制，只检查一个元素。

读源码时应当按“当前代码实际做什么”理解，而不要额外想象它验证了整张表。

---

<a id="origin-8860"></a>
### 2.10 重新计算位置表

如果触发：

```python
freqs_cos, freqs_sin = precompute_freqs_cis(...)
```

然后：

```python
self.freqs_cos, self.freqs_sin = (
    freqs_cos.to(hidden_states.device),
    freqs_sin.to(hidden_states.device)
)
```

<a id="origin-8877"></a>
#### 2.10.1 `.to(hidden_states.device)`

如果 hidden states 在：

```text
cuda:0
```

则新算出来默认 CPU 的位置表要移到同一设备。

否则：

```text
CPU Tensor × CUDA Tensor
```

会报错。

---

<a id="origin-8897"></a>
### 2.11 切出“本轮真正需要的位置”

源码：

```python
position_embeddings = (
    self.freqs_cos[
        start_pos:start_pos + seq_length
    ],
    self.freqs_sin[
        start_pos:start_pos + seq_length
    ]
)
```

第一次：

```text
start_pos=0
T=3
```

切：

```text
[0:3]
```

也就是位置：

```text
0,1,2
```

缓存后：

```text
start_pos=3
T=1
```

切：

```text
[3:4]
```

只取位置 3。

这就把 KV Cache 和 RoPE 的绝对位置完整对上了。

---

<a id="origin-8950"></a>
### 2.12 `presents = []`

创建一个普通空 Python list。

后面每一层处理完，都会：

```python
presents.append(present)
```

最后得到：

```text
[
 cache_layer0,
 cache_layer1,
 ...
]
```

这就是下一轮传回来的：

```text
past_key_values
```

---

<a id="origin-8978"></a>
### 2.13 `zip(self.layers, past_key_values)`

源码：

```python
for layer, past_key_value in zip(
    self.layers,
    past_key_values
):
```

`zip` 最简单例子：

```python
A = ["a","b","c"]
B = [1,2,3]

for x,y in zip(A,B):
    print(x,y)
```

输出：

```text
a 1
b 2
c 3
```

这里就是：

```text
Layer0 ↔ Cache0
Layer1 ↔ Cache1
...
```

注意 Python `zip` 会以较短的序列为准停止。

所以如果调用方错误地只传了部分层缓存：

```text
可能导致后面的层根本不循环
```

这份代码没有在这里额外做长度断言，因此调用者应保证缓存列表长度正确。

---

<a id="origin-9027"></a>
### 2.14 调用当前 Block

源码：

```python
hidden_states, present = layer(
    hidden_states,
    position_embeddings,
    past_key_value=past_key_value,
    use_cache=use_cache,
    attention_mask=attention_mask
)
```

第一次循环：

```text
hidden_states = Embedding 输出
```

第二层开始：

```text
hidden_states = 上一层 Block 输出
```

所以数据流：

```text
Embedding
→ Layer0
→ Layer1
→ Layer2
→ ...
```

不是多层并行。

---

<a id="origin-9067"></a>
### 2.15 为什么所有层共享同一段 `position_embeddings`？

因为 token 的绝对位置不因 Transformer 层数而改变。

例如新 token 位于位置 3：

```text
Layer0 中它还是位置3
Layer1 中它还是位置3
...
```

所以所有层可以使用同一段：

```text
cos[3], sin[3]
```

但各层 Q/K 内容不同，所以旋转后的结果仍不同。

---

<a id="origin-9089"></a>
### 2.16 为什么每层的 `past_key_value` 又不同？

因为每层 hidden state 不同。

第 0 层的 K：

```text
由第0层输入投影得到
```

第 1 层的 K：

```text
由第0层输出经过第1层 K 投影得到
```

所以各层 cache 必须分开保存。

结构：

```text
Layer0: K0_history, V0_history
Layer1: K1_history, V1_history
...
```

绝对不能只保存“一份全模型 K/V”。

---

<a id="origin-9119"></a>
### 2.17 `presents.append(present)`

如果：

```text
use_cache=True
```

每个 `present` 是：

```text
(K,V)
```

如果：

```text
use_cache=False
```

Attention 返回：

```text
None
```

但这里仍然 append。

所以最终：

```text
presents
```

长度仍然等于层数，只是元素可能全部为 None。

---

<a id="origin-9157"></a>
### 2.18 全部层后 Final Norm

```python
hidden_states = self.norm(hidden_states)
```

shape：

```text
[B,T,H]
```

不变。

到这里主干处理完成。

---

<a id="origin-9175"></a>
### 2.19 汇总各层 MoE 辅助损失

源码：

```python
aux_loss = sum(
    [
        l.mlp.aux_loss
        for l in self.layers
        if isinstance(l.mlp, MOEFeedForward)
    ],
    hidden_states.new_zeros(1).squeeze()
)
```

这一行包含三个知识点：

```text
isinstance
带条件的 list comprehension
sum 的 start 参数
```

---

<a id="origin-9200"></a>
### 2.20 `isinstance(obj, Class)`

最简单：

```python
isinstance(3, int)
```

得到：

```text
True
```

这里：

```python
isinstance(l.mlp, MOEFeedForward)
```

只挑出：

```text
mlp 真的是 MoE 的层
```

普通 FeedForward 层没有 `aux_loss` 属性，不应该去访问。

---

<a id="origin-9230"></a>
### 2.21 带 if 的列表推导式

```python
[
    l.mlp.aux_loss
    for l in self.layers
    if isinstance(l.mlp, MOEFeedForward)
]
```

相当于：

```python
losses = []
for l in self.layers:
    if isinstance(l.mlp, MOEFeedForward):
        losses.append(l.mlp.aux_loss)
```

---

<a id="origin-9251"></a>
### 2.22 `sum(iterable, start)`

Python：

```python
sum([1,2,3], 10)
```

得到：

```text
16
```

这里 start 是：

```python
hidden_states.new_zeros(1).squeeze()
```

也就是与 hidden_states 同 device/dtype 的 0 标量 Tensor。

为什么不直接用默认 Python 整数 0？

因为这样即使没有 MoE 层，也能保证：

```text
aux_loss 是 Tensor
并且 device/dtype 合适
```

---

<a id="origin-9284"></a>
### 2.23 `return hidden_states, presents, aux_loss`

到这里 `MiniMindModel` 返回：

```text
hidden_states
    [B,T,H]

presents
    每一层的 KV cache / None

aux_loss
    MoE 辅助损失标量
```

特别注意：

```text
这里没有 logits
没有 CrossEntropy
```

所以 `MiniMindModel` 只是 backbone。

---

<a id="origin-9310"></a>
### 2.24 首次输入完整追踪

假设：

```text
input_ids=[[1,5,7]]
B=1,T=3,H=8
layers=2
Nkv=1,D=4
use_cache=True
```

步骤：

```text
input_ids
[1,3]

↓ Embedding

hidden_states
[1,3,8]

↓ Layer0

hidden_states
[1,3,8]
cache0 K/V
[1,3,1,4]

↓ Layer1

hidden_states
[1,3,8]
cache1 K/V
[1,3,1,4]

↓ Final RMSNorm

hidden_states
[1,3,8]
```

返回：

```text
presents = [
    (K0,V0),
    (K1,V1)
]
```

<a id="origin-9364"></a>
### 2.25 缓存后单 token 续写

下一轮只输入：

```text
[[9]]
```

shape：

```text
[1,1]
```

历史长度：

```text
start_pos=3
```

Embedding：

```text
[1,1,8]
```

RoPE 切：

```text
position 3
```

Layer0：

```text
输入新 token [1,1,8]
+
Layer0 历史 KV 长3
→ cache 长4
```

Layer1 同理。

最终只返回：

```text
新 token 的 hidden state [1,1,8]
```

不会重复返回前三个 token 的 hidden states。

## 3. `MiniMindForCausalLM`：在 Transformer 主干上再加“词表预测头”

现在进入最外层：

```python
class MiniMindForCausalLM(
    PreTrainedModel,
    GenerationMixin
):
```

这是用户真正更常直接实例化和调用的完整语言模型。

它在：

```text
MiniMindModel
```

上再增加：

```text
lm_head
loss
自定义 generate
```

整体：

```text
input_ids
   ↓
MiniMindModel
   ↓
hidden_states [B,T,H]
   ↓
lm_head
   ↓
logits [B,T,V]
   ↓
训练：CrossEntropy
或
生成：选下一个 token
```

Embedding 参数：



shape 完全一致。

输入时：

```text

```

输出时：

```text
hidden state 与每一行做点积得到词表分数
```

所以同一张矩阵可以承担两种角色。

<a id="origin-9745"></a>
## 4. `MiniMindForCausalLM.forward()`：完整的一次训练/推理前向

函数签名：

```python
def forward(
    self,
    input_ids,
    attention_mask=None,
    past_key_values=None,
    use_cache=False,
    logits_to_keep=0,
    labels=None,
    **kwargs
):
```

这个函数是整个文件最重要的“总入口”之一。

它做三件事：

```text
1. 调 MiniMindModel 得 hidden states
2. 调 lm_head 得 logits
3. 如果有 labels，计算 next-token CrossEntropy
```

---

<a id="origin-9774"></a>
### 4.1 先调用主干

源码：

```python
hidden_states, past_key_values, aux_loss = self.model(
    input_ids,
    attention_mask,
    past_key_values,
    use_cache,
    **kwargs
)
```

这里 `self.model(...)` 之所以可以像函数一样调用，是因为它继承 `nn.Module`。

PyTorch 会走：

```text
Module.__call__
→ forward(...)
```

所以：

```python
self.model(...)
```

最终执行的是：

```python
MiniMindModel.forward(...)
```

---

<a id="origin-9811"></a>
### 4.2 为什么一般不手动写 `self.model.forward(...)`？

PyTorch 推荐：

```python
self.model(...)
```

因为 `nn.Module.__call__` 周围还会处理 hooks、autocast 等模块机制。

直接调用 `.forward()` 可能绕开这些框架行为。

---

<a id="origin-9825"></a>
### 4.3 `logits_to_keep`：为什么生成时可以只投影最后几个位置

源码：

```python
slice_indices = (
    slice(-logits_to_keep, None)
    if isinstance(logits_to_keep, int)
    else logits_to_keep
)
```

这里先认识：

```python
slice(start, stop)
```

例如：

```python
x[-1:]
```

可以表示为：

```python
x[slice(-1, None)]
```

---

<a id="origin-9857"></a>
### 4.4 `logits_to_keep=1`

```python
slice(-1, None)
```

表示：

```text
只取最后一个位置
```

于是：

```text
hidden_states [B,T,H]
↓ 只取最后位置
[B,1,H]
↓ lm_head
[B,1,V]
```

生成时通常只需要最后位置预测“下一个 token”，所以能省输出投影计算。

---

<a id="origin-9883"></a>
### 4.5 为什么 `logits_to_keep=0` 反而是保留全部？

Python 中：

```text
-0 == 0
```

所以：

```python
slice(-0, None)
```

等价于：

```python
slice(0, None)
```

也就是：

```text
从第0位置取到末尾
```

因此这里巧妙地让默认 0 表示“全部保留”。

---

<a id="origin-9913"></a>
### 4.6 非整数时按原样作为索引

```python
else logits_to_keep
```

说明作者也允许调用方传某种可用于：

```python
hidden_states[:, slice_indices, :]
```

的索引对象。

但常规教学场景只关注整数 0 或 1 即可。

---

<a id="origin-9931"></a>
### 4.7 `lm_head` 真正得到 logits

源码：

```python
logits = self.lm_head(
    hidden_states[:, slice_indices, :]
)
```

例如：

```text
hidden_states [1,4,8]
V=16
logits_to_keep=0
```

则：

```text
logits [1,4,16]
```

每个位置都有 16 个词表候选分数。

---

<a id="origin-9959"></a>
### 4.8 `loss = None`

```python
loss = None
```

先默认：

```text
这次没有监督损失
```

为什么不是 0？

因为：

```text
None = 没有计算 loss
0    = 计算过，而且结果恰好是 0
```

语义不同。

推理通常不传 labels，所以返回 `loss=None`。

---

<a id="origin-9986"></a>
### 4.9 `if labels is not None`

特别注意：

这份实现不是：

```python
if self.training:
```

才算 loss。

而是：

```text
只要 labels 被提供
就计算 loss
```

所以即使：

```python
model.eval()
```

但传了 labels，仍会计算交叉熵。

反过来即使：

```python
model.train()
```

但没传 labels，loss 仍是 None。

---

<a id="origin-10023"></a>
### 4.10 自回归训练最关键的 shift

源码：

```python
x, y = (
    logits[..., :-1, :].contiguous(),
    labels[..., 1:].contiguous()
)
```

这就是 next-token training 的核心。

假设：

```text
input_ids = labels = [1,5,7,2]
```

logits 有 4 个位置：

```text
logit0
logit1
logit2
logit3
```

`logits[..., :-1, :]`：

```text
只取 logit0,1,2
```

`labels[..., 1:]`：

```text
只取 5,7,2
```

配对：

```text
logit0 → label5
logit1 → label7
logit2 → label2
```

也就是：

```text
看 [1]       预测 5
看 [1,5]     预测 7
看 [1,5,7]   预测 2
```

最后位置 logit3 没有“输入内部的下一个 token”作为标签，所以不参与这次 loss。

---

<a id="origin-10083"></a>
### 4.11 `...` 在这里再次出现

```python
logits[..., :-1, :]
```

logits 常见：

```text
[B,T,V]
```

所以等价于：

```python
logits[:, :-1, :]
```

保留：

```text
所有 batch
除了最后一个 token 位置
所有 vocab 维
```

labels：

```python
labels[..., 1:]
```

常见等价：

```python
labels[:, 1:]
```

---

<a id="origin-10123"></a>
### 4.12 `.contiguous()` 为什么出现？

切片、transpose 等操作可能产生非连续内存布局的 Tensor view。

后面马上要：

```python
.view(...)
```

而 `.view()` 对内存连续性要求比较严格。

所以：

```python
.contiguous()
```

确保得到连续布局，方便后续 flatten。

核心关系如下：

> 切片后为了安全 `view()`，作者先把 Tensor 整理成连续内存。

---

<a id="origin-10149"></a>
### 4.13 `x.view(-1, x.size(-1))`

这里：

```text
x.shape=[B,T-1,V]
```

`x.size(-1)`：

```text
V
```

所以：

```python
x.view(-1, V)
```

变成：

```text
[B*(T-1), V]
```

也就是把所有 batch、所有训练位置合并成一张：

```text
N 个样本 × V 个类别分数
```

的二维表。

---

<a id="origin-10185"></a>
### 4.14 `y.view(-1)`

labels：

```text
[B,T-1]
```

flatten 成：

```text
[B*(T-1)]
```

每一项就是对应样本的正确 token ID。

---

<a id="origin-10203"></a>
### 4.15 `F.cross_entropy(...)`

源码：

```python
loss = F.cross_entropy(
    x.view(-1, x.size(-1)),
    y.view(-1),
    ignore_index=-100
)
```

输入要求：

```text
logits: [N,V]
target: [N]
```

其中 target 每个元素是：

```text
0～V-1 的正确类别编号
```

例如某位置词表概率正确 token 是 7。

CrossEntropy 会鼓励：

```text
logit[7] 相对其他候选更大
```

---

<a id="origin-10238"></a>
### 4.16 `ignore_index=-100`

如果某个 label 是：

```text
-100
```

该位置不计入 loss。

例如：

```text
labels=[-100,-100,7,2]
```

shift 后目标：

```text
[-100,7,2]
```

第一个位置忽略，只监督后两个。

注意：

> label=-100 只是“不算这个位置的 loss”，并不代表输入 token 从模型上下文中消失。

只要它仍在 `input_ids` 且 attention mask 允许，模型仍然能读取它。

---

<a id="origin-10270"></a>
### 4.17 一个最简单的 CrossEntropy 数值例子

假设某位置正确 token 概率：

```text
0.5
```

负对数似然：

```math
-\log(0.5)\approx0.6931
```

如果三个有效位置正确概率都恰好 0.5，默认 mean reduction 的平均 loss 仍约：

```text
0.6931
```

<a id="origin-10331"></a>
### 4.19 一个完整训练 forward 的故事

假设：

```python
input_ids = torch.tensor([[1,5,7,2]])
labels = input_ids.clone()
```

教学配置：

```text
B=1,T=4,H=8,V=16,layers=2
```

第一步：主干

```text
[1,4]
→ Embedding
[1,4,8]
→ 2个Block
[1,4,8]
→ Final Norm
[1,4,8]
```

第二步：lm_head

```text
[1,4,8]
→
[1,4,16]
```

第三步：shift

```text
logits[:, :-1, :]
→ [1,3,16]

labels[:,1:]
→ [1,3]
```

第四步：flatten

```text
[3,16]
[3]
```

第五步：CrossEntropy

```text
3 个 next-token 目标求平均损失
```

这就是“一次 forward 为什么可以同时训练多个位置”。

<a id="origin-10393"></a>
### 4.20 到这里训练故事已经闭环

如果只做训练，这份文件的核心故事已经完整：

```text
Token IDs
→ Embedding
→ N×Transformer Block
→ Final Norm
→ LM Head
→ Logits
→ Shift
→ CrossEntropy
→ Loss
```

下一章 `generate()` 并没有发明一个新的 Transformer。

它做的事情是：

> 反复调用我们刚刚讲完的 `forward()`，每一轮只选出一个新的 token，再把它接回序列继续。
