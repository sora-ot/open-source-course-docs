## 1. 预训练数据流

MiniMind 预训练包含下面这条完整链路：

```text
原始文本
  ↓
Tokenizer
  ↓
Token IDs
  ↓
添加 BOS / EOS
  ↓
Padding
  ↓
构造 input_ids / labels
  ↓
Embedding
  ↓
8 层 Decoder-only Transformer
  ↓
LM Head
  ↓
每个位置得到一个 6400 维 logits
  ↓
Shift 一位
  ↓
Cross Entropy
  ↓
反向传播
  ↓
AdamW 更新参数
  ↓
模型逐渐学会“根据前文预测下一个 token”
```

MiniMind 的预训练本质可以浓缩成一句话：

> **给模型看大量文本，然后让它不断做“下一个 token 是什么？”这道题。**

但真正重要的是理解：

1. 为什么“预测下一个 token”可以学到语言、知识和一定程度的推理能力？
2. 一个句子究竟会产生多少个训练样本？
3. `input_ids` 和 `labels` 为什么几乎一模一样？
4. causal mask 为什么必不可少？
5. logits、softmax、cross entropy 在数学上是什么关系？
6. loss 是如何从一句话一路反传到几十万个甚至几千万个参数的？
7. MiniMind 代码中的每一部分分别对应哪一个数学概念？

<a id="origin-68"></a>
## 2. 什么是 Pretraining？

<a id="origin-70"></a>
### 2.1 从“训练一个分类器”说起

传统监督学习通常是：

$$
x \rightarrow y
$$

例如：

```text
输入：这部电影太好看了
标签：正面
```

模型的目标是：

$$
P(y \mid x)
$$

但语言模型面对的问题不同。

我们没有必要人工给互联网中的每一句话标标签。

文本本身就包含监督信号。

例如：

```text
北京是中国的首都
```

可以自动构造出：

```text
输入：北京
目标：是

输入：北京是
目标：中国

输入：北京是中国
目标：的

输入：北京是中国的
目标：首都
```

因此，大规模文本可以自动变成训练数据。

这叫：

> **Self-Supervised Learning，自监督学习。**

这里不需要人手工标注“正确答案”。

正确答案就是文本中的下一个 token。

<a id="origin-131"></a>
## 3. 为什么叫“预训练”？

现代 LLM 常见训练链路是：

```text
随机初始化模型
      ↓
Pretraining
      ↓
Base Model
      ↓
SFT
      ↓
Instruct / Chat Model
      ↓
DPO / PPO / GRPO 等 Alignment
```

预训练阶段解决的是：

> **让模型学会语言世界本身。**

包括但不限于：

- 词语之间的搭配关系
- 语法
- 上下文依赖
- 常识
- 世界知识
- 代码模式
- 数学表达模式
- 文档结构
- 一定程度的推理模式

SFT 才主要解决：

> “用户问我问题时，我应该以什么形式回答？”

所以：

<a id="origin-171"></a>
### 3.1 Pretrain 更像“读书”

模型大量阅读：

```text
新闻
百科
书籍
代码
论文
网页
对话
……
```

<a id="origin-186"></a>
#### 3.1.1 SFT 更像“教它怎么回答问题”

例如：

```text
user: 什么是 Transformer？
assistant: Transformer 是一种……
```

这是两个不同阶段。

<a id="origin-199"></a>
## 4. Decoder-only LLM 的核心概率模型

MiniMind 是 Decoder-only Causal Language Model。

假设一句话经过 tokenizer 后得到：

$$
x_1,x_2,\ldots,x_T
$$

语言模型试图学习整个序列的概率：

$$
P(x_1,x_2,\ldots,x_T)
$$

根据概率链式法则：

$$
P(x_1,x_2,\ldots,x_T)
=
P(x_1)
P(x_2\mid x_1)
P(x_3\mid x_1,x_2)
\cdots
P(x_T\mid x_1,\ldots,x_{T-1})
$$

可以写成：

$$
\boxed{
P(x_{1:T})
=
\prod_{t=1}^{T}
P(x_t\mid x_{<t})
}
$$

其中：

$$x_{<t}=(x_1,\ldots,x_{t-1})
$$

这就是自回归语言模型（Autoregressive Language Model）。

---

<a id="origin-247"></a>
## 5. Pretrain 的训练目标

如果模型希望正确文本的概率尽可能大，那么目标是：

$$
\max_\theta
\prod_{t=1}^{T}
P_\theta(x_t\mid x_{<t})
$$

因为连乘不好优化，对数之后：

$$
\max_\theta
\sum_{t=1}^{T}
\log P_\theta(x_t\mid x_{<t})
$$

机器学习通常写成最小化 loss：

$$
\boxed{
\mathcal{L}
=
-\sum_{t=1}^{T}
\log P_\theta(x_t\mid x_{<t})
}
$$

如果取平均：

$$
\boxed{
\mathcal{L}
=
-\frac{1}{N}
\sum_{t=1}^{N}
\log P_\theta(y_t\mid x_{\leq t})
}
$$

这就是 Negative Log-Likelihood。

对于词表分类问题，它正好等价于 Cross Entropy。

<a id="origin-294"></a>
## 6. 一句话是如何变成很多道训练题的？

为了直观起见，假设 tokenizer 把：

```text
我爱人工智能
```

切成：

```text
我 | 爱 | 人工智能
```

再加特殊 token：

```text
<BOS> | 我 | 爱 | 人工智能 | <EOS>
```

那么模型实际上同时做四道题：

| 模型看到的前文 | 应预测 |
|---|---|
| `<BOS>` | `我` |
| `<BOS> 我` | `爱` |
| `<BOS> 我 爱` | `人工智能` |
| `<BOS> 我 爱 人工智能` | `<EOS>` |

注意：

> Transformer 并不是把这四道题真的循环跑四遍。

由于 causal mask 的存在，一次 forward 就可以并行计算所有位置。

这正是 Transformer 训练非常高效的原因之一。

<a id="origin-333"></a>
## 7. MiniMind 中最关键的“Shift 一位”

MiniMind `PretrainDataset` 返回：

```python
input_ids = [...]
labels = input_ids.clone()
```

很多初学者看到这里会产生一个问题：

> input 和 label 完全一样，那模型不是直接抄答案了吗？

答案是：

> **没有。真正的错位是在模型 forward 中完成的。**

MiniMind：

```python
x, y = logits[..., :-1, :].contiguous(), labels[..., 1:].contiguous()
loss = F.cross_entropy(
    x.view(-1, x.size(-1)),
    y.view(-1),
    ignore_index=-100
)
```

假设：

```text
input_ids:
[BOS, 我, 爱, AI, EOS]

labels:
[BOS, 我, 爱, AI, EOS]
```

模型产生：

```text
logits:
位置0预测 ...
位置1预测 ...
位置2预测 ...
位置3预测 ...
位置4预测 ...
```

代码取：

```python
logits[..., :-1, :]
```

即：

```text
位置0
位置1
位置2
位置3
```

而 label 取：

```python
labels[..., 1:]
```

即：

```text
我
爱
AI
EOS
```

因此真正的监督关系是：

```text
位置0 → 我
位置1 → 爱
位置2 → AI
位置3 → EOS
```

这就是标准的：

$$
\boxed{x_t \rightarrow x_{t+1}}
$$

<a id="origin-429"></a>
## 8. 为什么不能预测当前位置自己？

如果不 shift：

```text
输入 token：我
目标 token：我
```

模型最容易学成 Identity Mapping：

> “看见‘我’，就输出‘我’。”

这毫无意义。

语言模型真正需要学习的是：

```text
根据当前位置及之前的信息
→ 预测下一个 token
```

也就是：

$$
P(x_{t+1}\mid x_{\le t})
$$

<a id="origin-459"></a>
## 9. Tokenizer：文字如何进入神经网络？

神经网络不能直接处理：

```text
Transformer 是一种神经网络
```

必须先转成整数。

MiniMind 的 tokenizer 是 BPE tokenizer，词表大小：

$$
V=6400
$$

源码配置中：

```python
self.vocab_size = 6400
```

MiniMind 当前 tokenizer 的几个重要特殊 token：

```text
ID 0 = <|endoftext|>   （同时作为 PAD / UNK）
ID 1 = <|im_start|>    （BOS）
ID 2 = <|im_end|>      （EOS）
```

也就是说：

```text
bos_token_id = 1
eos_token_id = 2
pad_token_id = 0
```

## 10. MiniMind PretrainDataset 逐行分析

源码：

```python
class PretrainDataset(Dataset):
    def __init__(self, data_path, tokenizer, max_length=512):
        super().__init__()
        self.tokenizer = tokenizer
        self.max_length = max_length
        self.samples = load_dataset(
            'json',
            data_files=data_path,
            split='train'
        )
```

数据格式来自 README：

```json
{"text": "如何才能摆脱拖延症？治愈拖延症并不容易，但以下建议可能有所帮助。"}
{"text": "清晨的阳光透过窗帘洒进房间，桌上的书页被风轻轻翻动。"}
{"text": "Transformer 通过自注意力机制建模上下文关系，是现代大语言模型的重要基础结构。"}
```

因此每一行就是一个：

```python
sample['text']
```

<a id="origin-532"></a>
## 11. 文本 Tokenization

关键代码：

```python
tokens = self.tokenizer(
    str(sample['text']),
    add_special_tokens=False,
    max_length=self.max_length - 2,
    truncation=True
).input_ids
```

这里有三个值得讲的地方。

<a id="origin-547"></a>
### 11.1 `add_special_tokens=False`

告诉 tokenizer：

> 不要自动加 BOS / EOS。

因为后面 MiniMind 自己手动加。

<a id="origin-555"></a>
### 11.2 `max_length=self.max_length - 2`

为什么减 2？

因为还要留两个位置：

```text
BOS
EOS
```

如果最终长度最大为：

$$
L=340
$$

则正文最多：

$$
340-2=338
$$

个 token。

<a id="origin-580"></a>
### 11.3 `truncation=True`

正文太长时截断。

所以 MiniMind 当前 pretrain 并不是：

> 把超长文档连续切成很多 block 全部利用。

而是：

> 每条 JSONL 文本最多取前 `max_length-2` 个 token。

这是一个非常简洁、适合教学和低成本训练的数据方案。

<a id="origin-596"></a>
## 12. 手动加入 BOS / EOS

源码：

```python
tokens = (
    [self.tokenizer.bos_token_id]
    + tokens
    + [self.tokenizer.eos_token_id]
)
```

例如：

```text
原文：
北京是中国的首都

token：
[100, 215, 378, 421]

加入特殊 token：

[1, 100, 215, 378, 421, 2]
```

其中：

```text
1 = BOS
2 = EOS
```

BOS 告诉模型：

> 一个序列开始了。

EOS 告诉模型：

> 这个序列应该结束了。

模型因此不仅学会：

> “接下来应该说什么”

也学会：

> “什么时候应该停止”。

<a id="origin-647"></a>
## 13. Padding

MiniMind 需要组成 batch。

一个 batch 中每个 Tensor 的长度必须一样。

假设：

$$
L_{\max}=10
$$

原 token：

```text
[1, 100, 215, 378, 421, 2]
```

只有 6 个 token。

因此补 4 个 PAD：

```text
[1, 100, 215, 378, 421, 2, 0, 0, 0, 0]
```

源码：

```python
input_ids = tokens + [self.tokenizer.pad_token_id] * (
    self.max_length - len(tokens)
)
```

---

<a id="origin-683"></a>
## 14. 为什么 PAD 不能计算 loss？

如果 PAD 也参与 loss，模型会学：

```text
EOS 后面应该疯狂预测 PAD
```

短文本越多，PAD 越多，这会严重污染训练目标。

因此：

```python
labels = input_ids.clone()
labels[input_ids == self.tokenizer.pad_token_id] = -100
```

例如：

```text
input_ids:
[1, 100, 215, 378, 421, 2, 0, 0, 0, 0]

labels:
[1, 100, 215, 378, 421, 2, -100, -100, -100, -100]
```

PyTorch 后面使用：

```python
F.cross_entropy(..., ignore_index=-100)
```

因此 target 为 `-100` 的位置不计算 loss。

## 15. 完整的数据样例

假设：

```text
文本：
我爱AI
```

为了教学，假设 tokenizer 得到：

```text
我  → 101
爱  → 205
AI → 399
```

最大长度：

$$
L=8
$$

那么 `PretrainDataset` 返回：

```text
input_ids =
[1, 101, 205, 399, 2, 0, 0, 0]

labels =
[1, 101, 205, 399, 2, -100, -100, -100]
```

到了模型内部：

```python
x = logits[..., :-1, :]
y = labels[..., 1:]
```

对应：

```text
x 有 7 个位置：

x0
x1
x2
x3
x4
x5
x6

y =
[101, 205, 399, 2, -100, -100, -100]
```

实际计算 loss 的只有：

```text

x1 → 205（爱）
x2 → 399（AI）
x3 → 2（EOS）
```

```text
-100
```

全部忽略。

## 16. Batch 后 Tensor 的形状

MiniMind 默认：

```python
batch_size = 32
max_seq_len = 340
vocab_size = 6400
hidden_size = 768
```

因此进入模型：

$$
\text{input\_ids.shape}
=
[B,L]
=
[32,340]
$$

Embedding 后：

$$
[32,340]
\rightarrow
[32,340,768]
$$

最终 logits：

$$
[32,340,768]
\rightarrow
[32,340,6400]
$$

shift 后：

$$
x.shape=[32,339,6400]
$$

$$
y.shape=[32,339]
$$

flatten：

$$
x:
[32\times339,6400]
=
[10848,6400]
$$

$$
y:
[10848]
$$

所以 PyTorch 的 CrossEntropy 实际上看到的是：

> **10848 道 6400 分类题。**

当然其中 PAD 对应的位置因为 label = -100 被忽略。

<a id="origin-865"></a>
## 17. 模型输出的 logits 是什么？

对每个位置，模型输出一个 6400 维向量：

$$
z=(z_1,z_2,\ldots,z_{6400})
$$

例如：

```text
[2.1, -0.3, 4.7, ..., 1.2]
```

它们不是概率。

叫：

> logits。

通过 softmax：

$$
p_i=
\frac{e^{z_i}}
{\sum_{j=1}^{V}e^{z_j}}
$$

得到：

$$
\sum_i p_i=1
$$

例如模型认为下一个 token：

```text
“是”       0.60
“的”       0.10
“中国”     0.08
……
```

如果正确答案是“是”，那么该位置 loss：

$$
L=-\log(0.60)
$$

概率越高：

$$
-\log p
$$

越小。

<a id="origin-924"></a>
## 18. Cross Entropy 到底是什么？

假设词表只有四个词：

```text
[我, 爱, AI, 猫]
```

正确答案：

```text
AI
```

one-hot：

$$
y=[0,0,1,0]
$$

模型预测：

$$
p=[0.1,0.1,0.7,0.1]
$$

交叉熵：

$$
H(y,p)
=
-\sum_i y_i\log p_i
$$

因为只有正确类别的 $y_i=1$，所以：

$$
L=-\log 0.7
$$

也就是说：

$$
\boxed{
L=-\log P(\text{正确 token})
}
$$

这是理解语言模型 loss 最简单的方式。

<a id="origin-976"></a>
## 19. 一个完整的数值例子

序列：

```text
<BOS> 我 爱 AI <EOS>
```

假设模型四个位置对正确答案给出的概率分别为：

```text
P(我 | BOS)          = 0.60
P(爱 | BOS,我)       = 0.70
P(AI | BOS,我,爱)    = 0.80
P(EOS | BOS,我,爱,AI)= 0.50
```

平均 loss：

$$
L
=
-\frac14
(
\log0.6+
\log0.7+
\log0.8+
\log0.5
)
$$

得到约：

$$
\boxed{L\approx0.446}
$$

Perplexity：

$$
PPL=e^L
$$

所以：

$$
PPL\approx1.562
$$

直观理解：

> 模型在每一步平均像是在约 1.56 个同等可能的候选中做选择。

注意真实 LLM 词表有 6400 个 token，情况当然复杂得多。

<a id="origin-1033"></a>
## 20. 为什么 CrossEntropy 代码里没有 Softmax？

MiniMind：

```python
loss = F.cross_entropy(...)
```

常见问题：

> 前面没写 softmax，怎么就是概率？

因为：

```python
F.cross_entropy(logits, target)
```

数学上等价于：

```text
log_softmax
+
negative log likelihood
```

即：

$$
\text{CrossEntropy}(z,y)
=
-\log
\frac{e^{z_y}}
{\sum_j e^{z_j}}
$$

PyTorch 直接从 logits 计算，数值更稳定。

所以：

> **训练时不要先自己 softmax 再传给 `F.cross_entropy`。**

<a id="origin-1077"></a>
## 21. 为什么一个位置不能偷看未来？

假设训练：

```text
我 爱 人工智能
```

当模型在“我”这个位置预测“爱”时，如果 Attention 可以看到右侧：

```text
爱
```

那答案已经泄露了。

模型会作弊。

因此 Decoder-only Transformer 必须使用 causal mask。

---

<a id="origin-1099"></a>
## 22. Causal Mask

长度为 4 时，注意力可见关系：

```text
        K0  K1  K2  K3

Q0      ✓   ×   ×   ×
Q1      ✓   ✓   ×   ×
Q2      ✓   ✓   ✓   ×
Q3      ✓   ✓   ✓   ✓
```

数学上 mask：

$$
M=
\begin{bmatrix}
0&-\infty&-\infty&-\infty\\
0&0&-\infty&-\infty\\
0&0&0&-\infty\\
0&0&0&0
\end{bmatrix}
$$

Attention：

$$
\boxed{
\mathrm{Attention}(Q,K,V)
=
\mathrm{softmax}
\left(
\frac{QK^\top}{\sqrt{d_k}}
+
M
\right)V
}
$$

因为：

$$
e^{-\infty}=0
$$

右上角未来位置 softmax 后概率变成 0。

<a id="origin-1149"></a>
## 23. MiniMind 如何实现 causal attention？

MiniMind：

```python
self.is_causal = True
```

如果支持 PyTorch Flash / SDPA：

```python
F.scaled_dot_product_attention(
    xq,
    xk,
    xv,
    ...,
    is_causal=self.is_causal
)
```

这里：

```python
is_causal=True
```

由 PyTorch 完成 causal mask。

如果不用 Flash Attention，则自己构造：

```python
scores = (xq @ xk.transpose(-2, -1)) / math.sqrt(self.head_dim)

scores[:, :, :, -seq_len:] += torch.full(
    (seq_len, seq_len),
    float("-inf"),
    device=scores.device
).triu(1)
```

核心就是：

```python
triu(1)
```

得到严格上三角矩阵。

也就是把未来位置变成：

```text
-inf
```

<a id="origin-1435"></a>
## 28. 为什么需要位置编码？

Self-Attention 本身并不知道：

```text
我 爱 你
```

和：

```text
你 爱 我
```

谁在前谁在后。

所以必须加入位置信息。

MiniMind 使用：

> **RoPE：Rotary Position Embedding**

不是传统 Transformer 那种：

$$
x + PE
$$

而是对 Query / Key 做旋转。

---

<a id="origin-1467"></a>
## 29. RoPE 的直观理解

对二维向量：

$$
\begin{bmatrix}
x_1\\x_2
\end{bmatrix}
$$

旋转角度 $\theta$：

$$
R(\theta)=
\begin{bmatrix}
\cos\theta&-\sin\theta\\
\sin\theta&\cos\theta
\end{bmatrix}
$$

RoPE 给不同位置不同旋转角度。

位置 $m$：

$$
q_m'=R(m\theta)q_m
$$

位置 $n$：

$$
k_n'=R(n\theta)k_n
$$

二者点积天然包含：

$$
m-n
$$

即相对位置信息。

---

<a id="origin-1511"></a>
## 30. MiniMind 的 RoPE 代码

初始化时预计算：

```python
freqs_cos, freqs_sin = precompute_freqs_cis(
    dim=config.head_dim,
    end=config.max_position_embeddings,
    rope_base=config.rope_theta,
    rope_scaling=config.rope_scaling
)
```

默认：

```text
head_dim = 96
max_position_embeddings = 32768
rope_theta = 1e6
```

forward：

```python
xq, xk = apply_rotary_pos_emb(
    xq,
    xk,
    cos,
    sin
)
```

值得强调：

> RoPE 只作用于 Q 和 K，不直接作用于 V。

因为位置信息需要改变：

> “谁应该关注谁”

而 Attention 权重来自 Q 和 K。

## 33. MiniMind 不是普通 MHA，而是 GQA

MiniMind 默认：

```text
Q heads  = 8
KV heads = 4
```

这叫：

> **Grouped Query Attention，GQA**

即多个 Q head 共用较少的 K/V head。

MiniMind：

```python
self.n_rep = (
    self.n_local_heads //
    self.n_local_kv_heads
)
```

因此：

$$
n_{rep}=8/4=2
$$

每个 KV head 被两个 Query head 使用。

<a id="origin-1662"></a>
## 34. GQA 为什么有用？

普通 Multi-Head Attention：

```text
8 Q
8 K
8 V
```

GQA：

```text
8 Q
4 K
4 V
```

优势：

- K/V 参数更少
- 推理时 KV Cache 更小
- 生成速度更友好
- 通常效果损失较小

所以现代 LLM 很常见。

MiniMind 中：

```python
repeat_kv(xk, self.n_rep)
repeat_kv(xv, self.n_rep)
```

把 4 个 KV 逻辑复制为供 8 个 Q head 使用。

注意：

> 这不是增加新的参数，仅仅是计算上的展开。

<a id="origin-1724"></a>
## 36. RMSNorm

传统 LayerNorm：

$$
\frac{x-\mu}{\sqrt{\sigma^2+\epsilon}}
$$

RMSNorm 不减均值，只按照均方根归一化：

$$
\mathrm{RMS}(x)
=
\sqrt{
\frac1d
\sum_{i=1}^d x_i^2
+
\epsilon
}
$$

$$
\boxed{
\mathrm{RMSNorm}(x)
=
g\odot
\frac{x}{\mathrm{RMS}(x)}
}
$$

MiniMind：

```python
return x * torch.rsqrt(
    x.pow(2).mean(-1, keepdim=True)
    + self.eps
)
```

然后：

```python
self.weight * normalized_x
```

<a id="origin-1771"></a>
## 37. Attention 公式

每个 head：

$$
S=
\frac{QK^\top}
{\sqrt{d_k}}
$$

加 causal mask：

$$
S'=S+M
$$

softmax：

$$
A=\mathrm{softmax}(S')
$$

输出：

$$
O=AV
$$

最终多头拼接后：

$$
\mathrm{Concat}(O_1,\ldots,O_h)W_O
$$

MiniMind 对应：

```python
scores = (
    xq @ xk.transpose(-2, -1)
) / math.sqrt(self.head_dim)
```

```python
output =
self.attn_dropout(
    F.softmax(scores.float(), dim=-1).type_as(xq)
) @ xv
```

---

<a id="origin-1822"></a>
## 38. 为什么除以 $\sqrt{d_k}$？

如果 Q 和 K 每个维度方差大致为 1：

$$
q\cdot k
=
\sum_{i=1}^{d_k}q_i k_i
$$

其方差会随：

$$
d_k
$$

增大。

$d_k$ 大时 logits 绝对值会很大。

softmax 容易变得过尖：

```text
[0.999999, 0.000001, ...]
```

梯度变差。

因此缩放：

$$
\frac{QK^\top}{\sqrt{d_k}}
$$

使数值尺度更稳定。

MiniMind：

```text
d_k = 96
```

所以除以：

$$
\sqrt{96}
$$

<a id="origin-1872"></a>
## 39. Transformer Block 的结构

MiniMind 每层：

```python
residual = hidden_states

hidden_states, ... = self.self_attn(
    self.input_layernorm(hidden_states),
    ...
)

hidden_states += residual

hidden_states = hidden_states + self.mlp(
    self.post_attention_layernorm(hidden_states)
)
```

可以写为：

$$
H'_l
=
H_l
+
\mathrm{Attention}
(
\mathrm{RMSNorm}(H_l)
)
$$

然后：

$$
\boxed{
H_{l+1}
=
H'_l
+
\mathrm{FFN}
(
\mathrm{RMSNorm}(H'_l)
)
}
$$

这属于：

> **Pre-Norm Transformer**

Normalization 在子层之前。

---

<a id="origin-1927"></a>
## 40. 为什么需要 Residual Connection？

Attention 层不是直接替换旧表示，而是：

$$
x+\mathrm{Attention}(x)
$$

FFN：

$$
x+\mathrm{FFN}(x)
$$

Residual 的意义包括：

- 保留原始信息
- 改善深层网络梯度传播
- 让每层更像是在原表示上学习“增量修正”

可以直观地理解为：

> 每层 Transformer 不是把上一层推倒重建，而是在上一层知识表示上“补充一点新的理解”。

<a id="origin-1953"></a>
## 41. MiniMind 的 FFN 不是普通两层 MLP

源码：

```python
return self.down_proj(
    self.act_fn(self.gate_proj(x))
    * self.up_proj(x)
)
```

默认：

```python
hidden_act = 'silu'
```

所以：

$$
g=\mathrm{SiLU}(XW_g)
$$

$$
u=XW_u
$$

逐元素乘：

$$
z=g\odot u
$$

最后：

$$
\boxed{
FFN(X)=
(
\mathrm{SiLU}(XW_g)
\odot
XW_u
)
W_d
}
$$

这是 SwiGLU 类结构。

---

<a id="origin-2004"></a>
## 42. SiLU

$$
\mathrm{SiLU}(x)
=
x\sigma(x)
$$

其中：

$$
\sigma(x)
=
\frac1{1+e^{-x}}
$$

和 ReLU 相比，SiLU 更平滑。

现代 LLM 中经常与 GLU 类门控结合。

## 48. 为什么训练可以同时预测所有 token，而推理不能？


<a id="origin-2272"></a>
### 48.1 训练

我们已经知道完整文本：

```text
我 爱 人工智能
```

借助 causal mask，可以一次输入整个序列：

```text
我
我 爱
我 爱 人工智能
```

对应的所有位置可以矩阵并行。

<a id="origin-2290"></a>
### 48.2 推理

假设只有：

```text
我
```

后面的“爱”还不存在。

必须先生成：

```text
爱
```

然后才能生成下一个：

```text
人工智能
```

所以生成天然是：

$$
x_1
\rightarrow x_2
\rightarrow x_3
\rightarrow\cdots
$$

自回归过程。

<a id="origin-2325"></a>
## 49. Pretrain 为什么能学到“知识”？

例如训练语料里反复出现：

```text
法国的首都是巴黎
巴黎是法国最大的城市之一
埃菲尔铁塔位于巴黎
……
```

模型在大量 next-token prediction 中不断降低：

$$
-\log P(
\text{巴黎}
\mid
\text{法国的首都是}
)
$$

为了预测准确，它必须从参数中捕捉：

```text
法国 ↔ 巴黎
巴黎 ↔ 埃菲尔铁塔
```

等统计关联。

因此语言模型知识不是传统数据库：

```text
key → value
```

而是分布式编码在大量神经网络权重中的。

<a id="origin-2365"></a>
## 50. 为什么 next-token prediction 可以产生“涌现能力”？

因为要准确预测下一个 token，很多时候模型不能只记局部词频。

例如：

```text
小明有3个苹果，又买了2个，现在有____
```

如果训练数据丰富，模型为了预测：

```text
5
```

可能需要内部表示：

- 数字
- 加法
- 语义关系
- 文本结构

再例如代码：

```python
for i in range(10):
    print(
```

要预测后面的代码，需要学习：

- Python 语法
- 括号
- API 模式
- 缩进
- 上下文变量

所以一个非常简单的统一训练目标：

$$
\boxed{
\text{Predict Next Token}
}
$$

可以迫使网络学习非常复杂的内部表示。
