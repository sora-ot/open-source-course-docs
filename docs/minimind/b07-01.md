# 18 · MHA：多头投影、维度与参数量


---

<a id="origin-5"></a>
## 1. 从最普通的单头 Attention 开始

先暂时不要考虑 Multi-Head Attention。

假设当前有一句话：

```text
I love artificial intelligence
```

对于某一层 Transformer 来说，每个 token 都有一个 hidden state。

例如：

```math
x_I,\quad
x_{\text{love}},\quad
x_{\text{artificial}},\quad
x_{\text{intelligence}}
```

然后通过三组参数矩阵：

```math
W_Q,\quad W_K,\quad W_V
```

得到：

```math
Q=XW_Q
```

```math
K=XW_K
```

```math
V=XW_V
```

对于 `love` 这个 token：

```math
Q_{\text{love}}
=
x_{\text{love}}W_Q
```

对于 `I`：

```math
K_I
=
x_IW_K
```

```math
V_I
=
x_IW_V
```

对于 `love` 自己：

```math
K_{\text{love}}
=
x_{\text{love}}W_K
```

```math
V_{\text{love}}
=
x_{\text{love}}W_V
```

于是 `love` 可以通过：

```math
Q_{\text{love}}K_I^T
```

以及：

```math
Q_{\text{love}}K_{\text{love}}^T
```

判断：

> 当前这个 `love` 应该关注前面的哪些 token？

经过 Softmax：

```math
\alpha
=
\operatorname{softmax}
\left(
\frac{QK^T}{\sqrt{d_k}}
\right)
```

最后得到输出：

```math
O_{\text{love}}
=
\alpha_I V_I
+
\alpha_{\text{love}}V_{\text{love}}
```

这就是最基本的 Self-Attention。

**注意这里的输出$O_\text{love}$是一个加权求和的向量或矩阵，它代表了根据注意力权重从 Value（值）中提取出的关键信息，后面跟全连接层等可以输出hidden state.**

---

<a id="origin-125"></a>
## 2. 一个 Attention Head 本质上在干什么？

可以把一个 Attention Head 简单理解成：

> 用一种特定的方式，判断“当前 token 应该从哪些 token 中读取信息”。

其计算过程是：

```text
当前 token
    ↓
生成 Query
    ↓
拿 Query 和所有 Key 比较
    ↓
得到 Attention Score
    ↓
Softmax
    ↓
决定从哪些 Value 中读取多少信息
```

公式：

```math
\operatorname{Attention}(Q,K,V)
=
\operatorname{softmax}
\left(
\frac{QK^T}{\sqrt{d_k}}
\right)V
```

也就是说，一个 Attention Head 同时包含两件事情：

第一件：

```text
去哪里找？
```

由：

```math
QK^T
```

决定。

第二件：

```text
找到之后拿什么信息回来？
```

由：

```math
V
```

决定。

---

<a id="origin-190"></a>
## 3. 那为什么一个 Attention Head 不够？

这是理解 Multi-Head Attention 最关键的问题。

考虑一句话：

```text
The animal didn't cross the street because it was too tired.
```

假设模型当前正在处理：

```text
it
```

对于 `it` 来说，它可能同时需要知道很多不同的信息。

例如：

<a id="origin-210"></a>
### 3.1 指代关系

模型可能需要知道：

```text
it 指的是谁？
```

可能重点关注：

```text
animal
```

---

<a id="origin-226"></a>
### 3.2 语法关系

模型可能需要关注：

```text
it → was → tired
```

---

<a id="origin-236"></a>
### 3.3 动作关系

模型可能还需要知道：

```text
谁没有 cross the street？
```

因此可能关注：

```text
cross
```

---

<a id="origin-252"></a>
### 3.4 局部上下文

某些情况下，模型可能只需要关注附近的 token：

```text
because it was
```

---

于是出现了一个问题。

如果只有一个 Attention Head，那么对于 `it`：

```math
Q_{\text{it}}
```

只能产生一套 Attention Score：

```math
Q_{\text{it}}K^T
```

然后得到一套 Attention 分布：

```math
\alpha_{\text{it}}
```

也就是：

```text
所有不同的信息关系
       ↓
都必须塞进
同一套 Attention 分布
```

这就会限制模型的表达能力。

---

<a id="origin-295"></a>
## 4. Multi-Head Attention 的核心思想

既然一个 token 可能同时需要从多个角度观察上下文，那么：

> 能不能让同一个 token 同时产生多个不同的 Query？

当然可以。

这就是：

<a id="origin-305"></a>
## 5. Multi-Head Attention

简称：

```text
MHA
```

假设：

```math
h=4
```

也就是有 4 个 Attention Head。

那么对于同一个 token `it`，我们不再只有：

```math
Q_{\text{it}}
```

而是有：

```math
Q_{\text{it}}^{(1)}
```

```math
Q_{\text{it}}^{(2)}
```

```math
Q_{\text{it}}^{(3)}
```

```math
Q_{\text{it}}^{(4)}
```

它们来自不同的投影参数：

```math
Q^{(1)}=XW_Q^{(1)}
```

```math
Q^{(2)}=XW_Q^{(2)}
```

```math
Q^{(3)}=XW_Q^{(3)}
```

```math
Q^{(4)}=XW_Q^{(4)}
```

因此：

```math
Q_{\text{it}}^{(1)}
=
x_{\text{it}}W_Q^{(1)}
```

```math
Q_{\text{it}}^{(2)}
=
x_{\text{it}}W_Q^{(2)}
```

等等。

---

<a id="origin-381"></a>
## 6. 不只是 Query 不一样，K 和 V 也不一样

标准的 MHA 并不是：

```text
多个 Q
共享一套 K/V
```

而是：

> 每个 Head 都有自己独立的 Q、K、V 投影。

例如四个 Head：

```text
Head 1:
Q¹   K¹   V¹

Head 2:
Q²   K²   V²

Head 3:
Q³   K³   V³

Head 4:
Q⁴   K⁴   V⁴
```

数学上：

```math
Q^{(i)}=XW_Q^{(i)}
```

```math
K^{(i)}=XW_K^{(i)}
```

```math
V^{(i)}=XW_V^{(i)}
```

第一个 Head：

```math
H_1
=
\operatorname{softmax}
\left(
\frac{
Q^{(1)}K^{(1)T}
}{
\sqrt{d_k}
}
\right)
V^{(1)}
```

第二个 Head：

```math
H_2
=
\operatorname{softmax}
\left(
\frac{
Q^{(2)}K^{(2)T}
}{
\sqrt{d_k}
}
\right)
V^{(2)}
```

依此类推。

最后：

```math
H
=
\operatorname{Concat}
(
H_1,H_2,H_3,H_4
)
```

然后再经过：

```math
O=HW_O
```

得到最终的 Multi-Head Attention 输出。

---

<a id="origin-479"></a>
## 7. MHA 的本质：为什么不同 Head 会学到不同特征？

<a id="origin-481"></a>
## 8. 先提出最关键的问题

很多资料介绍 Multi-Head Attention 时都会说：

> 不同 Attention Head 可以关注不同的信息。

例如：

```text
Head 1：可能关注语法关系
Head 2：可能关注指代关系
Head 3：可能关注局部上下文
Head 4：可能关注长距离依赖
```

但是这里其实跳过了最重要的一步：

> **为什么它们会不一样？**

模型训练数据里并没有这样的标签：

```text
Head 1，请你学习语法。

Head 2，请你学习指代。

Head 3，请你学习位置关系。
```

也没有一个 Loss 写成：

```text
如果 Head 1 学会主谓关系，奖励它。
```

真正发生的事情其实是：

```text
不同 Head
↓
拥有不同参数
↓
随机初始化时就已经不完全一样
↓
产生不同输出
↓
对最终预测产生不同影响
↓
反向传播得到不同梯度
↓
参数朝不同方向更新
↓
差异越来越明显
↓
最终形成不同的 Attention Pattern / 特征表示
```

所以首先一定要记住：

> **Head 的分工不是人工设计出来的，而是训练过程中自己“长出来”的。**

---

<a id="origin-544"></a>
## 9. 先从一个 token 的 hidden state 开始

假设当前 token 是：

```text
love
```

进入 Attention 层之前，它有一个 hidden state：

```math
x_{\text{love}}
```

例如模型维度：

```math
d_{\text{model}}=4096
```

那么：

```math
x_{\text{love}}\in\mathbb{R}^{4096}
```

注意：

这个向量并不能简单理解成：

```text
第 1 维 = 词性
第 2 维 = 情感
第 3 维 = 主语
第 4 维 = 动词
```

真实神经网络不是这么整齐的。

更准确地说：

> hidden state 的几千个维度共同编码了当前 token 的各种上下文信息。

里面可能混合包含：

```text
词义
词性
句法关系
实体信息
位置关系
上下文信息
指代信息
语义角色
……
```

这些信息是高度混合在一起的。

---

<a id="origin-605"></a>
## 10. Attention Head 做的第一件事，其实就是“重新看这个向量”

如果只有一个 Attention Head，我们会计算：

```math
Q=xW_Q
```

```math
K=xW_K
```

```math
V=xW_V
```

这里：

```math
W_Q
```

其实就是在做一个线性投影：

```text
原来的 hidden state
        ↓
经过 W_Q
        ↓
重新组织其中的信息
        ↓
得到 Query 表示
```

所以：

```math
Q=xW_Q
```

不是单纯地“把 x 复制一下”。

它实际上相当于：

> 从 hidden state 中提取、组合一组适合进行“查询”的特征。

---

<a id="origin-653"></a>
## 11. 一个简单例子：同一个 x 可以被投影成完全不同的东西

为了方便理解，假设 hidden state 只有 4 维：

```math
x=
[x_1,x_2,x_3,x_4]
```

假设这四维粗略地蕴含：

```text
x1：某类语法信息

x2：某类实体信息

x3：某类位置信息

x4：某类语义信息
```

这只是为了帮助理解，真实模型不会这么规整。

现在假设有两个不同的 Query 投影矩阵。

Head 1：

```math
W_Q^{(1)}
```

Head 2：

```math
W_Q^{(2)}
```

例如 Head 1 最终学成了：

```math
Q^{(1)}
=
xW_Q^{(1)}
```

更加依赖：

```text
x1、x3
```

而 Head 2：

```math
Q^{(2)}
=
xW_Q^{(2)}
```

更加依赖：

```text
x2、x4
```

那么即便输入：

```math
x
```

完全相同：

```text
同一个 love
同一个 hidden state
```

经过两个不同矩阵以后：

```math
Q^{(1)}\neq Q^{(2)}
```

于是两个 Head 看到的其实是：

```text
同一个 token 的不同投影视角。
```

---

<a id="origin-745"></a>
## 12. 用一个真正的数学例子看就非常直观了

假设：

```math
x=
\begin{bmatrix}
1 & 2 & 3 & 4
\end{bmatrix}
```

为了简单，我们让每个 Query Head 最后只有二维。

Head 1 的参数：

```math
W_Q^{(1)}
=
\begin{bmatrix}
1&0\\
0&0\\
0&1\\
0&0
\end{bmatrix}
```

那么：

```math
Q^{(1)}
=
xW_Q^{(1)}
```

得到：

```math
Q^{(1)}
=
[1,3]
```

**也就是说 Head 1 主要把：**

```text
第 1 维
第 3 维
```

**抽了出来，此时的$Q^{(1)}$就是一个只包含$x$的第1和第3维信息的查询向量。**

---

Head 2：

```math
W_Q^{(2)}
=
\begin{bmatrix}
0&0\\
1&0\\
0&0\\
0&1
\end{bmatrix}
```

那么：

```math
Q^{(2)}
=
xW_Q^{(2)}
```

得到：

```math
Q^{(2)}
=
[2,4]
```

也就是主要提取：

```text
第 2 维
第 4 维
```

于是：

```math
Q^{(1)}=[1,3]
```

而：

```math
Q^{(2)}=[2,4]
```

输入明明完全相同：

```math
x=[1,2,3,4]
```

但是：

```math
W_Q^{(1)}\neq W_Q^{(2)}
```

所以：

```math
Q^{(1)}\neq Q^{(2)}
```

---

<a id="origin-866"></a>
## 13. 所以“为什么 Query Head 可以不一样？”

答案其实非常直接：

**因为不同 Query Head 使用的参数不一样，因此它抽取的特征就不一样。**

对于同一个 token：

```math
x
```

Head 1：

```math
Q^{(1)}
=
xW_Q^{(1)}
```

Head 2：

```math
Q^{(2)}
=
xW_Q^{(2)}
```

Head 3：

```math
Q^{(3)}
=
xW_Q^{(3)}
```

因为：

```math
W_Q^{(1)}
\neq
W_Q^{(2)}
\neq
W_Q^{(3)}
```

所以自然：

```math
Q^{(1)}
\neq
Q^{(2)}
\neq
Q^{(3)}
```

<a id="origin-924"></a>
## 14. 实际代码中真的有很多个 W_Q 吗？

这里又有一个容易混淆的地方。

从数学上，我们经常写：

```math
W_Q^{(1)},W_Q^{(2)},...,W_Q^{(h)}
```

表示每个 Head 有自己的 Query 投影。

但是实际代码中通常不会真的写：

```python
self.q1 = Linear(...)
self.q2 = Linear(...)
self.q3 = Linear(...)
...
```

而是使用一个大的：

```math
W_Q
```

例如：

```math
W_Q
\in
\mathbb{R}^{4096\times4096}
```

先算：

```math
Q=XW_Q
```

得到：

```text
4096维 Q
```

然后 reshape：

```text
4096
↓
32 heads × 128 dimensions
```

于是：

```text
Q Head 1 → 前 128 维

Q Head 2 → 接下来 128 维

Q Head 3 → 再接下来 128 维

...
```

这在数学上等价于把大的：

```math
W_Q
```

按列切成：

```math
W_Q=
[
W_Q^{(1)}
\;
W_Q^{(2)}
\;
\cdots
\;
W_Q^{(32)}
]
```

所以本质仍然是：

```text
不同 Query Head
拥有不同的一组参数。
```

<a id="origin-1020"></a>
## 15. 单头 Attention 到多头 Attention：Query 的长度怎么变？

回忆：假设模型的 hidden size （Transformer 里，每个 token 用多少个数字来表示）是：

```math
d_{\text{model}}=4096
```

也就是说，一个 token 的 输入，即hidden state为：

```math
x\in\mathbb{R}^{4096}
```

---

<a id="origin-1036"></a>
## 16. 传统单头 Attention

单头 Attention 中，可以让：

```math
W_Q\in\mathbb{R}^{4096\times4096}
```

于是：

```math
Q=xW_Q
```

得到：

```math
Q\in\mathbb{R}^{4096}
```

也就是说：

> **单头 Attention 中，一个 token 只有一个 Query，这个 Query 的长度是 4096。**

可以画成：

```text
x
4096维
 ↓ W_Q
Q
4096维
```

即：

```text
单头 Attention：

Q
[----------------------------------------]
                  4096维
```

---

<a id="origin-1082"></a>
## 17. 变成 32 头 Multi-Head Attention

现在仍然假设：

```math
d_{\text{model}}=4096
```

并且设置：

```math
n_{\text{heads}}=32
```

输入仍然是：

```math
x\in\mathbb{R}^{4096}
```

先经过：

```math
Q=xW_Q
```

得到的总 Query 长度仍然是：

```math
4096
```

但是现在不再把这 4096 维看成一个 Query。

而是把它拆成：

```math
32
```

个 Query Head。

因为：

```math
4096\div32=128
```

所以每个 Query Head 的长度是：

```math
d_{\text{head}}=128
```

于是：

```text
Q
4096维

 ↓ reshape

32 × 128
```

也就是：

```text
多头 Attention：

Q
[Head1][Head2][Head3] ... [Head32]
 128    128    128           128
```

---

<a id="origin-1159"></a>
## 18. 最终发生了什么变化？

单头 Attention：

```text
1 个 Query

每个 Query：4096维
```

也就是：

```math
\boxed{
1\times4096
}
```

变成 32 头 MHA 后：

```text
32 个 Query Head

每个 Query Head：128维
```

也就是：

```math
\boxed{
32\times128
}
```

而：

```math
32\times128=4096
```

所以：

> **总维度并没有变化。**

只是从：

```text
1 个大的 4096 维 Query
```

变成：

```text
32 个小的 128 维 Query
```

---

<a id="origin-1217"></a>
## 19. 一张表看懂

| 结构           | Query 数量 | 每个 Query 长度 |  总长度 |
| ------------ | -------: | ----------: | ---: |
| 单头 Attention |        1 |        4096 | 4096 |
| 32 头 MHA     |       32 |         128 | 4096 |

所以最核心的变化就是：

```text
单头：

1 × 4096
```

变成：

```text
多头：

32 × 128
```

即：

```math
\boxed{
4096
=
32\times128
}
```

---

<a id="origin-1252"></a>
## 20. 一句话总结

> **Multi-Head Attention 并不是把 Query 的总长度扩大，而是把原来一个大的 Query 拆成多个较小的 Query Head。**

例如：

```text
单头：
1 个 4096 维 Query

↓

32 头 MHA：
32 个 128 维 Query Head
```

所以：

```math
\boxed{
\text{总维度不变，只是从“一个大 Query”变成“多个小 Query”。}
}
```

<a id="origin-1277"></a>
## 21. MHA 中为什么每个 Head 都有自己的 Q/K/V，以及 Q 为什么要切分

先明确一个最容易混淆的点：

> **标准 MHA 中，不是只有每个 Head 的 K/V 独立，而是每个 Head 都有自己独立的一套 Q、K、V。**

假设：

```math
d_{\text{model}}=4096
```

并且：

```math
n_{\text{head}}=32
```

那么每个 Head 的维度是：

```math
d_{\text{head}}
=
\frac{4096}{32}
=
128
```

所以：

```math
\boxed{
d_{\text{head}}=128
}
```

---

<a id="origin-1315"></a>
## 22. 每个 Head 实际上都有自己的一套 Q/K/V

标准 MHA 中，第 1 个 Head：

```math
Q^{(1)}\in\mathbb{R}^{128}
```

```math
K^{(1)}\in\mathbb{R}^{128}
```

```math
V^{(1)}\in\mathbb{R}^{128}
```

第 2 个 Head：

```math
Q^{(2)}\in\mathbb{R}^{128}
```

```math
K^{(2)}\in\mathbb{R}^{128}
```

```math
V^{(2)}\in\mathbb{R}^{128}
```

一直到第 32 个 Head：

```math
Q^{(32)},K^{(32)},V^{(32)}
```

它们也都是 128 维。

所以可以画成：

```text
Head 1:
Q¹：128维
K¹：128维
V¹：128维

Head 2:
Q²：128维
K²：128维
V²：128维

Head 3:
Q³：128维
K³：128维
V³：128维

...

Head 32:
Q³²：128维
K³²：128维
V³²：128维
```

<a id="origin-1381"></a>
## 23. 为什么 Q 也必须是 128 维？

因为一个 Head 内部要计算：

```math
Q^{(h)}K^{(h)T}
```

也就是 Query 和 Key 要做点积。

例如 Head 1：

```math
Q^{(1)}
\in
\mathbb{R}^{1\times128}
```

而：

```math
K^{(1)}
\in
\mathbb{R}^{1\times128}
```

那么：

```math
Q^{(1)}K^{(1)T}
```

维度就是：

```math
[1\times128]
\times
[128\times1]
```

得到：

```math
[1\times1]
```

也就是一个 Attention Score。

所以：

> **同一个 Head 内部的 Q 和 K 必须在同一个 head_dim 空间中。**

在这个例子里就是：

```math
128
```

维。

<a id="origin-1443"></a>
## 24. MHA 可以理解成很多个“小 Attention”

这是最容易理解的方式。

假设原来只有单头：

```text
一个大 Attention

Q：4096维
K：4096维
V：4096维
```

变成 32 头以后，可以理解成：

```text
32 个小 Attention

Head 1：
Q¹ = 128维
K¹ = 128维
V¹ = 128维

Head 2：
Q² = 128维
K² = 128维
V² = 128维

...

Head 32：
Q³² = 128维
K³² = 128维
V³² = 128维
```

每个 Head 独立计算：

```math
O^{(h)}
=
\operatorname{softmax}
\left(
\frac{
Q^{(h)}K^{(h)T}
}{
\sqrt{128}
}
\right)V^{(h)}
```

例如 Head 1：

```math
O^{(1)}
=
\operatorname{softmax}
\left(
\frac{
Q^{(1)}K^{(1)T}
}{
\sqrt{128}
}
\right)V^{(1)}
```

Head 2：

```math
O^{(2)}
=
\operatorname{softmax}
\left(
\frac{
Q^{(2)}K^{(2)T}
}{
\sqrt{128}
}
\right)V^{(2)}
```

<a id="origin-1527"></a>
## 25. 每个 Head 的输出最后再拼起来

每个 Head 的输出：

```math
O^{(h)}
\in
\mathbb{R}^{128}
```

一共有 32 个 Head：

```math
O^{(1)},
O^{(2)},
\dots,
O^{(32)}
```

最后：

```math
O
=
\operatorname{Concat}
(
O^{(1)},
O^{(2)},
\dots,
O^{(32)}
)
```

因为：

```math
32\times128=4096
```

所以最终：

```math
O\in\mathbb{R}^{4096}
```

于是整个 Attention 层的输入和输出维度保持一致：

```text
输入：

4096维

↓

32 个 Head

每个 Head：128维

↓

Concat

↓

4096维
```

**后面这个4096维度的带信息的向量会接比如全连接层输出logit。**

<a id="origin-1598"></a>
## 26. “每个 Head 有独立 K/V”到底是什么意思？

这里特别容易误解。

所谓：

> 每个 Head 有独立的 K/V

**不是说：**

```text
每个 Head 都有一整套 4096 维 K/V
```

而是说：

> 每个 Head 有自己独立的 K/V 投影参数。

例如：

```math
W_K^{(1)}
\neq
W_K^{(2)}
```

以及：

```math
W_V^{(1)}
\neq
W_V^{(2)}
```

但是每一个小矩阵的维度是：

```math
W_K^{(h)}
\in
\mathbb{R}^{4096\times128}
```

以及：

```math
W_V^{(h)}
\in
\mathbb{R}^{4096\times128}
```

所以：

```text
独立
```

指的是：

```text
参数不同
```

不是：

```text
每个 Head 都重新拥有完整的 4096 维空间。
```

## 27. Q 也是一样的

Query 也不是公共的。

每个 Head 同样有自己独立的：

```math
W_Q^{(h)}
```

例如：

```math
W_Q^{(1)}
\in
\mathbb{R}^{4096\times128}
```

```math
W_Q^{(2)}
\in
\mathbb{R}^{4096\times128}
```

并且：

```math
W_Q^{(1)}
\neq
W_Q^{(2)}
```

于是对于同一个 hidden state：

```math
x
\in
\mathbb{R}^{4096}
```

Head 1：

```math
Q^{(1)}
=
xW_Q^{(1)}
```

得到：

```math
Q^{(1)}
\in
\mathbb{R}^{128}
```

Head 2：

```math
Q^{(2)}
=
xW_Q^{(2)}
```

得到：

```math
Q^{(2)}
\in
\mathbb{R}^{128}
```

因为：

```math
W_Q^{(1)}
\neq
W_Q^{(2)}
```

所以通常：

```math
Q^{(1)}
\neq
Q^{(2)}
```

## 28. 所以标准 MHA 真正应该画成什么样？

假设某个 token 的 hidden state：

```math
x\in\mathbb{R}^{4096}
```

那么：

```text
                       Head 1
                 ┌─ W_Q¹ → Q¹ [128]
                 ├─ W_K¹ → K¹ [128]
                 └─ W_V¹ → V¹ [128]

                       ↓

                   Attention 1


                       Head 2
                 ┌─ W_Q² → Q² [128]
                 ├─ W_K² → K² [128]
x [4096] ────────┤─ W_V² → V² [128]

                       ↓

                   Attention 2


                       ...

                       Head 32
                 ┌─ W_Q³² → Q³² [128]
                 ├─ W_K³² → K³² [128]
                 └─ W_V³² → V³² [128]

                       ↓

                   Attention 32
```

也就是说：

> **每个 Head 都是一整套独立的小型 Attention。**

## 29. 从“为什么要多头”讲起：为什么参数量几乎不变，但 Multi-Head Attention 能表达更丰富的信息？

理解 Multi-Head Attention，可以从一个非常自然的问题开始：

> **既然一个 Attention Head 只能产生一套 Attention Weight，那我能不能多搞几个 Head，让模型同时从多个角度观察上下文？**

答案当然是可以。

但接下来马上会遇到一个问题：

> **如果每个 Head 都和原来的单头一样大，参数量岂不是直接爆炸？**

Multi-Head Attention 的整个设计，其实就是围绕这个问题展开的。

为了让整个过程更加具体，下面统一使用这句话作为例子：

```text
小明把一把红色雨伞递给小红，因为外面下雨了。
```

我们重点观察：

```text
小红
```

这个 token 在 Attention 中是怎样从前文获取信息的。

<a id="origin-1839"></a>
## 30. 从一个单头 Attention 开始

假设模型的 hidden size 是：

$$
d_{model}=4096
$$

对于句子：

```text
小明把一把红色雨伞递给小红，因为外面下雨了。
```

每一个 token 都有自己的：

$$
4096
$$

维 hidden state。

例如：

$$
x_{\text{小明}},
x_{\text{红色}},
x_{\text{雨伞}},
x_{\text{小红}},
x_{\text{下雨}}
\in
\mathbb{R}^{4096}
$$

如果现在只有一个 Attention Head，那么可以使用：

$$
W_Q,W_K,W_V
\in
\mathbb{R}^{4096\times4096}
$$

于是：

$$
Q=XW_Q
$$

$$
K=XW_K
$$

$$
V=XW_V
$$

所以对于 `小红`：

$$
q_{\text{小红}}
\in
\mathbb{R}^{4096}
$$

然后：

$$
q_{\text{小红}}
$$

会分别和前面所有 token 的 Key 进行匹配。

例如：

$$
q_{\text{小红}}k_{\text{小明}}^T
$$

$$
q_{\text{小红}}k_{\text{红色}}^T
$$

$$
q_{\text{小红}}k_{\text{雨伞}}^T
$$

$$
q_{\text{小红}}k_{\text{小红}}^T
$$

等等。

经过 Softmax，可能得到一套 Attention Weight。

例如为了方便理解：

```text
小明      30%
红色       5%
雨伞      40%
递给      10%
小红      10%
其他       5%
```

然后：

$$
o_{\text{小红}}
=
\sum_j
\alpha_jv_j
$$

最终：

$$
o_{\text{小红}}
\in
\mathbb{R}^{4096}
$$

## 31. 单头 Attention 真正的问题：只有一套 Attention Weight

刚才只有一套：

```text
小明      30%
红色       5%
雨伞      40%
递给      10%
小红      10%
其他       5%
```

这意味着：

> 整个 4096 维 Value，都必须按照这一套 token 权重进行信息聚合。

但是我们真正理解：

```text
小明把一把红色雨伞递给小红，因为外面下雨了。
```

时，其实可能同时需要回答很多完全不同的问题。

例如：

```text
问题 1：
“是谁把东西递给小红的？”

答案：
小明


问题 2：
“递给小红的是什么东西？”

答案：
雨伞


问题 3：
“雨伞是什么颜色？”

答案：
红色


问题 4：
“为什么要递雨伞？”

答案：
因为外面下雨了
```

这几个问题显然不应该使用完全相同的 Attention Weight。

例如：

```text
“是谁递东西？”
→ 应该主要关注 小明

“递的是什么？”
→ 应该主要关注 雨伞

“是什么颜色？”
→ 应该主要关注 红色

“为什么需要雨伞？”
→ 应该主要关注 下雨
```

但单头只有：

$$
\boxed{
1\text{ 套 Softmax 权重}
}
$$

所以一个非常自然的想法就是：

> **那我能不能多搞几个 Attention Head，让每个 Head 分别去找不同的信息？**

## 32. 最直接的想法：做 32 个完整的 4096 维 Head

假设我们想要：

$$
32
$$

个 Attention Head。

最直觉的做法就是：

```text
Head 1：4096维
Head 2：4096维
Head 3：4096维
...
Head 32：4096维
```

这样每个 Head 都可以拥有自己独立的：

$$
Q,K,V
$$

以及自己的：

$$
Attention
$$

例如：

```text
Head 1：
专门去找“是谁递东西？”

Head 2：
专门去找“递的是什么？”

Head 3：
专门去找“是什么颜色？”

Head 4：
专门去找“为什么发生？”

...
```

当然真实模型不会这么整齐地分工，但这个直觉非常适合帮助理解。

问题在于：

> 如果每个 Head 都还是完整的 4096 维，参数量和计算量会变得非常大。

<a id="origin-2109"></a>
## 33. 如果每个 Head 都是 4096 维，参数量会发生什么？

原来一个 Query 投影 **（线性变换，即把原来的表示映射到另一个特征空间，这里指的是把 hidden state 线性映射到 Query 特征空间。）**：

$$
W_Q
\in
\mathbb{R}^{4096\times4096}
$$

参数量：

$$
4096\times4096
$$

如果现在有 32 个完整的 4096 维 Query Head：

$$
W_Q^{(1)}
\in
\mathbb{R}^{4096\times4096}
$$

$$
W_Q^{(2)}
\in
\mathbb{R}^{4096\times4096}
$$

……

一直到：

$$
W_Q^{(32)}
\in
\mathbb{R}^{4096\times4096}
$$

那么总参数量就变成：

$$
32\times4096\times4096
$$

直接扩大：

$$
\boxed{
32\times
}
$$

K 和 V 同样如此。

所以这种设计虽然可以得到：

$$
32
$$

套独立 Attention，

但是代价太高。

因此真正的问题变成：

> **有没有办法得到 32 套独立 Attention，但是又不把参数量扩大 32 倍？**

答案就是 Multi-Head Attention 的经典设计。

---

<a id="origin-2183"></a>
## 34. 保持总维度 4096 不变，把它分给 32 个 Head

我们不让每个 Head 都占：

$$
4096
$$

维。

而是让总投影维度仍然保持：

$$
4096
$$

不变。

既然现在要分成：

$$
32
$$

个 Head，

那么每个 Head 分到：

$$
d_{head}
=
\frac{4096}{32}
=
128
$$

于是：

```text
Head 1：128维
Head 2：128维
Head 3：128维
...
Head 32：128维
```

总维度仍然：

$$
32\times128
=
4096
$$

所以：

$$
\boxed{
d_{head}
=
\frac{d_{model}}{N_{head}}
}
$$

可以从设计动机上理解为：

**想要 32 套 Attention，
但又不想付出 32 倍参数，
于是保持总投影维度 4096 不变，
把它分给 32 个 Head，
每个 Head 使用 128 维。**

---

<a id="origin-2257"></a>
## 35. 但是千万不要理解成“把原始 X 直接切成 32 段”

假设：

$$
x\in\mathbb{R}^{4096}
$$

一个很容易产生的错误理解是：

```text
X 的第 1~128维
        ↓
     Head 1

X 的第129~256维
        ↓
     Head 2

...

X 的最后128维
        ↓
     Head 32
```

如果真的是这样，那么：

> Head 1 永远只能看到 X 的前 128 维。

这确实会造成严重的信息割裂。

但 Transformer 不是这样做的。

真正发生的是：

**32 个 Head 都读取完整的 4096 维 X，
只是通过不同的投影矩阵，
各自生成不同的 128 维表示。
**

---

<a id="origin-2300"></a>
## 36. 真正的 Q：一个大投影可以看成 32 个小投影

整体：

$$
W_Q
\in
\mathbb{R}^{4096\times4096}
$$

可以从数学上看成：

$$
W_Q
=
[
W_Q^{(1)}
|
W_Q^{(2)}
|
\dots
|
W_Q^{(32)}
]
$$

其中：

$$
W_Q^{(h)}
\in
\mathbb{R}^{4096\times128}
$$

于是对于 `小红`：

$$
q_{\text{小红}}^{(1)}
=
x_{\text{小红}}W_Q^{(1)}
$$

$$
q_{\text{小红}}^{(2)}
=
x_{\text{小红}}W_Q^{(2)}
$$

……

$$
q_{\text{小红}}^{(32)}
=
x_{\text{小红}}W_Q^{(32)}
$$

每一个：

$$
q_{\text{小红}}^{(h)}
\in
\mathbb{R}^{128}
$$

但是关键是：

$$
\boxed{
\text{每个 Head 都以完整的 }x_{\text{小红}}\in\mathbb{R}^{4096}
\text{ 作为输入}
}
$$

可以画成：

```text
                         完整 x_小红
                         [4096维]
                            │
        ┌───────────────────┼───────────────────┐
        ↓                   ↓                   ↓
     W_Q^1               W_Q^2             ... W_Q^32
   4096×128             4096×128             4096×128
        ↓                   ↓                   ↓
    q_小红^1            q_小红^2            q_小红^32
      128维                128维                128维
```

所以：

**不是把 X 切成 32 份，
而是让 32 个不同的小投影器
同时从完整 X 中提取不同的 128 维 Query。**

v_{\text{雨伞}}^{(2)}
=
x_{\text{雨伞}}W_V^{(2)}
$$

等等。

## 45. V 可以理解成“找到我以后，我真正能给你什么”

例如：

```text
K_小明
```

主要负责帮助判断：

> `小明` 是不是这个 Query 正在寻找的 token？

但是一旦真正匹配到了：

```text
小明
```

真正取回的信息来自：

$$
V_{\text{小明}}
$$

可以粗略理解成包含：

```text
这是小明
他是一个人物
他刚刚执行了递雨伞这个动作
他和小红发生了直接交互
...
```

同理：

```text
K_雨伞
```

负责帮助判断：

> “雨伞是不是我要找的物品？”

而：

$$
V_{\text{雨伞}}
$$

真正提供的是：

```text
这是雨伞
它是被递出去的物品
它与红色这个属性相关
...
```

所以可以直接记：

$$
\boxed{
Q：
“我要找什么？”
}
$$

$$
\boxed{
K：
“我是不是你要找的？”
}
$$

$$
\boxed{
V：
“如果你选中了我，这是我真正提供给你的信息。”
}
$$

<a id="origin-2905"></a>
## 46. Q、K、V 都可以理解成一组“小投影器”

对于 Head 1：

```text
完整 X
4096维
   │
   ├── W_Q^(1) 4096×128 → Q^(1)
   │
   ├── W_K^(1) 4096×128 → K^(1)
   │
   └── W_V^(1) 4096×128 → V^(1)
```

对于 Head 2：

```text
完整 X
4096维
   │
   ├── W_Q^(2) 4096×128 → Q^(2)
   │
   ├── W_K^(2) 4096×128 → K^(2)
   │
   └── W_V^(2) 4096×128 → V^(2)
```

一直到 Head 32。

所以：

```text
                         完整 X
                        [4096维]
                            │
          ┌─────────────────┼─────────────────┐
          ↓                 ↓                 ↓
       Head 1            Head 2          ... Head 32
          │                 │                 │
     ┌────┼────┐       ┌────┼────┐       ┌────┼────┐
     ↓    ↓    ↓       ↓    ↓    ↓       ↓    ↓    ↓
    WQ   WK   WV      WQ   WK   WV      WQ   WK   WV
     ↓    ↓    ↓       ↓    ↓    ↓       ↓    ↓    ↓
    Q1   K1   V1      Q2   K2   V2      Q32  K32  V32
```

每个小投影：

$$
4096\rightarrow128
$$

---

<a id="origin-2960"></a>
## 47. 所以“4096×4096 变成 32 个 4096×128”这个理解是对的

从线性代数角度：

$$
W_Q
\in
\mathbb{R}^{4096\times4096}
$$

确实可以看成：

$$
32
$$

个：

$$
4096\times128
$$

的小投影并行工作。

K/V 同理。

所以完全可以建立这样的直觉：

$$
\boxed{
\text{一个大投影器}
\rightarrow
\text{32 个不同的小投影器}
}
$$

但更加准确的词应该是：

$$
\boxed{
\text{线性投影}
}
$$

而不是完整的“神经网络”。

因为：

$$
W_Q^{(h)}
$$

本质上只是 Linear Layer 的一部分，没有激活函数，也没有多层结构。

<a id="origin-3016"></a>
## 48. 每个小投影为什么有意义？

因为：

$$
W_Q^{(1)}
\neq
W_Q^{(2)}
$$

所以它们可以从同一个完整：

$$
4096
$$

维 X 中提取不同的东西。

例如：

```text
Head 1：

“小红现在想知道：
是谁把东西给我的？”
```

而：

```text
Head 2：

“小红现在想知道：
给我的是什么东西？”
```

再比如：

```text
Head 3：

“这个东西有什么属性？”
```

以及：

```text
Head 4：

“为什么发生这件事？”
```

所以：


**不是把一个问题切成 32 份，
而是让 32 个不同的小投影器
对同一份完整材料提出不同的问题。**

## 49. 那把 4096 压成 128，不还是有信息损失吗？

如果只看一个 Head：

$$
4096
\rightarrow
128
$$

确实属于降维。

所以：

$$
\boxed{
\text{单个 Head 不可能完整保留原始 4096 维中的所有细节。}
}
$$

可以说：

$$
\boxed{
\text{单个 Head 存在信息压缩。}
}
$$

但有两个非常重要的地方。

---

<a id="origin-3111"></a>
## 50. 第一：128 维不是直接从 X 中截出来的

它是：

$$
xW_Q^{(h)}
$$

或者：

$$
xW_K^{(h)}
$$

或者：

$$
xW_V^{(h)}
$$

所以：

$$
\boxed{
\text{这 128 维的每一个维度，都可以依赖完整的 4096 维 X。}
}
$$

例如 Head 1 虽然最终只有 128 维，

但是这 128 维可以从整个：

```text
小红当前知道的全部上下文信息
```

中提炼出：

```text
“谁把东西给我？”
```

相关的表示。

因此最准确的说法是：

$$
\boxed{
\text{信息来源是完整的，但表示是压缩的。}
}
$$

---

<a id="origin-3165"></a>
## 51. 第二：我们并不是只有一个 128 维 Head

我们有：

$$
32
$$

个 Head。

所以：

$$
32\times128
=
4096
$$

整体来看：

$$
4096
\rightarrow
32\times128
=
4096
$$

并没有把整个 Attention 的总表示维度压缩成：

$$
128
$$

更准确地说：

$$
\boxed{
\text{把一个大的 4096 维表示，
重新组织成 32 个不同的 128 维特征子空间。}
}
$$

<a id="origin-3210"></a>
## 52. 为什么这样比单头灵活？

如果只有一个 Head，

那么面对：

```text
小明把一把红色雨伞递给小红，因为外面下雨了。
```

可能只有一套Softmax后的比例：

```text
小明      87.7%
红色       2.4%
雨伞       6.6%
递给       4.9%
小红       3.3%
其他       2.0%
```

接下来真正取信息时计算：

$$
o_{\text{小红}}^{(1)}
=
0.807v_{\text{小明}}^{(1)}
+
0.066v_{\text{雨伞}}^{(1)}
+
0.049v_{\text{递给}}^{(1)}
+
0.033v_{\text{小红}}^{(1)}
+
0.024v_{\text{红色}}^{(1)}
+
0.020v_{\text{其他}}^{(1)}
$$

因此这个 Head 得到的输出中：

```text
绝大多数信息来自“小明”
```


然后所有：

$$
4096
$$

维信息都按照这一套权重提取。

这意味着：

```text
“是谁递东西？”
“递的是什么？”
“是什么颜色？”
“为什么发生？”
```

都只能共用同一套注意力分布。

这显然不够灵活。
