# 26 · YaRN：长上下文外推与频率缩放

<a id="origin-6277"></a>
## 1. RoPE 大矩阵、长位置外推与 YaRN 原理

前面已经知道，RoPE 的核心思想是：

> **根据 token 的位置旋转 Q 和 K，使 Attention 在计算 $Q\cdot K$ 时自然包含相对位置信息。**

但是这里还有三个很容易卡住的问题：

1. 为什么有些资料把 RoPE 写成一个巨大的 $d\times d$ 矩阵？
2. 这个大矩阵为什么又可以理解成很多个二维小旋转？
3. 如果训练时位置最大只有 2047，推理时为什么会突然出现 10000？YaRN 又是在解决什么？

下面从线性代数开始重新串起来。

---

<a id="origin-6293"></a>
## 2. 先回忆二维旋转

对于一个二维向量：

```math
x=
\begin{bmatrix}
x_1\\
x_2
\end{bmatrix}
```

旋转角度 $\theta$：

```math
R(\theta)
=
\begin{bmatrix}
\cos\theta&-\sin\theta\\
\sin\theta&\cos\theta
\end{bmatrix}
```

旋转以后：

```math
x'
=
R(\theta)x
```

也就是：

```math
\begin{bmatrix}
x'_1\\
x'_2
\end{bmatrix}
=
\begin{bmatrix}
\cos\theta&-\sin\theta\\
\sin\theta&\cos\theta
\end{bmatrix}
\begin{bmatrix}
x_1\\
x_2
\end{bmatrix}
```

得到：

```math
x'_1
=
x_1\cos\theta-x_2\sin\theta
```

```math
x'_2
=
x_1\sin\theta+x_2\cos\theta
```

所以：

```text
二维向量
↓
乘一个 2×2 旋转矩阵
↓
得到旋转后的二维向量
```

---

<a id="origin-6368"></a>
## 3. 但是 Q 可能是 96 维，怎么办？

假设为了教学简单一点：

```math
d=6
```

Q 是一个 6 维向量：

```math
q=
\begin{bmatrix}
q_0\\
q_1\\
q_2\\
q_3\\
q_4\\
q_5
\end{bmatrix}
```

RoPE 的思想是：

> **不要试图在一个人类无法想象的 6 维空间里整体旋转，而是把它拆成若干二维平面。**

例如：

```text
第 1 组：
(q0,q1)

第 2 组：
(q2,q3)

第 3 组：
(q4,q5)
```

分别进行二维旋转。

于是：

```text
(q0,q1)
↓
二维旋转 R0

(q2,q3)
↓
二维旋转 R1

(q4,q5)
↓
二维旋转 R2
```

---

<a id="origin-6427"></a>
## 4. 那为什么有些资料写成一个 $6\times6$ 大矩阵？

因为在线性代数里，这几个独立的二维旋转可以统一写成一个：

> **块对角矩阵（Block Diagonal Matrix）**

例如：

```math
R_m
=
\begin{bmatrix}
R_0&0&0\\
0&R_1&0\\
0&0&R_2
\end{bmatrix}
```

其中每个：

```math
R_i
```

本身都是一个：

```math
2\times2
```

矩阵。

展开以后就是：

```math
R_m=
\begin{bmatrix}
\cos\phi_0&-\sin\phi_0&0&0&0&0\\
\sin\phi_0&\cos\phi_0&0&0&0&0\\
0&0&\cos\phi_1&-\sin\phi_1&0&0\\
0&0&\sin\phi_1&\cos\phi_1&0&0\\
0&0&0&0&\cos\phi_2&-\sin\phi_2\\
0&0&0&0&\sin\phi_2&\cos\phi_2
\end{bmatrix}
```

这是一个：

```math
6\times6
```

大矩阵。

---

<a id="origin-6483"></a>
## 5. 线性代数中的分块矩阵乘法

> **对于块对角矩阵，与分块向量相乘时，各个对角块可以独立地和对应的小向量相乘。**

最简单的形式：

```math
\begin{bmatrix}
A&0\\
0&B
\end{bmatrix}
\begin{bmatrix}
x\\
y
\end{bmatrix}
=
\begin{bmatrix}
Ax\\
By
\end{bmatrix}
```

这就是关键。

---

<a id="origin-6509"></a>
## 6. 为什么成立？直接做一次矩阵乘法

来看：

```math
M=
\begin{bmatrix}
A&0\\
0&B
\end{bmatrix}
```

向量：

```math
v=
\begin{bmatrix}
x\\
y
\end{bmatrix}
```

做矩阵乘法：

```math
Mv
=
\begin{bmatrix}
A&0\\
0&B
\end{bmatrix}
\begin{bmatrix}
x\\
y
\end{bmatrix}
```

根据矩阵乘法规则：

第一块：

```math
Ax+0y
=
Ax
```

第二块：

```math
0x+By
=
By
```

所以：

```math
\boxed{
\begin{bmatrix}
A&0\\
0&B
\end{bmatrix}
\begin{bmatrix}
x\\
y
\end{bmatrix}
=
\begin{bmatrix}
Ax\\
By
\end{bmatrix}
}
```

这就是为什么：

```text
一个大块对角矩阵乘法
```

可以变成：

```text
几个互不干扰的小矩阵乘法
```

<a id="origin-6598"></a>
## 7. 放到 RoPE 里就非常清楚了

假设：

```math
q=
\begin{bmatrix}
q_0\\
q_1\\
q_2\\
q_3\\
q_4\\
q_5
\end{bmatrix}
```

把它写成三个二维小向量：

```math
q=
\begin{bmatrix}
q^{(0)}\\
q^{(1)}\\
q^{(2)}
\end{bmatrix}
```

其中：

```math
q^{(0)}
=
\begin{bmatrix}
q_0\\q_1
\end{bmatrix}
```

```math
q^{(1)}
=
\begin{bmatrix}
q_2\\q_3
\end{bmatrix}
```

```math
q^{(2)}
=
\begin{bmatrix}
q_4\\q_5
\end{bmatrix}
```

RoPE 大矩阵：

```math
R_m
=
\begin{bmatrix}
R_0&0&0\\
0&R_1&0\\
0&0&R_2
\end{bmatrix}
```

于是：

```math
R_mq
=
\begin{bmatrix}
R_0q^{(0)}\\
R_1q^{(1)}\\
R_2q^{(2)}
\end{bmatrix}
```

也就是：

```text
大矩阵版本：

        ┌ R0  0   0 ┐
R_m  =  │ 0   R1  0 │
        └ 0   0   R2┘

             ×

        ┌ q0,q1 ┐
        │ q2,q3 │
        └ q4,q5 ┘
```

完全等价于：

```text
(q0,q1) × R0

(q2,q3) × R1

(q4,q5) × R2
```

所以：

```math
\boxed{
\text{一个 }d\times d\text{ 的 RoPE 矩阵}
=
\text{很多个 }2\times2\text{ 旋转块组成的块对角矩阵}
}
```

## 8. 用一个真正的数字例子

假设：

```math
q=
\begin{bmatrix}
1\\
0\\
0\\
1\\
1\\
1
\end{bmatrix}
```

分成：

```text
第一组：
[1,0]

第二组：
[0,1]

第三组：
[1,1]
```

为了方便，假设三个二维平面分别旋转：

```text
第一组：90°
第二组：180°
第三组：0°
```

那么：

```math
R_0
=
\begin{bmatrix}
0&-1\\
1&0
\end{bmatrix}
```

```math
R_1
=
\begin{bmatrix}
-1&0\\
0&-1
\end{bmatrix}
```

```math
R_2
=
\begin{bmatrix}
1&0\\
0&1
\end{bmatrix}
```

---

<a id="origin-6781"></a>
### 8.1 第一组

```math
R_0
\begin{bmatrix}
1\\0
\end{bmatrix}
=
\begin{bmatrix}
0\\1
\end{bmatrix}
```

也就是：

```text
[1,0]
↓ 旋转90°
[0,1]
```

---

<a id="origin-6804"></a>
### 8.2 第二组

```math
R_1
\begin{bmatrix}
0\\1
\end{bmatrix}
=
\begin{bmatrix}
0\\-1
\end{bmatrix}
```

即：

```text
[0,1]
↓ 旋转180°
[0,-1]
```

---

<a id="origin-6827"></a>
### 8.3 第三组

```math
R_2
\begin{bmatrix}
1\\1
\end{bmatrix}
=
\begin{bmatrix}
1\\1
\end{bmatrix}
```

即没有旋转。

---

最终拼起来：

```math
q'
=
\begin{bmatrix}
0\\
1\\
0\\
-1\\
1\\
1
\end{bmatrix}
```

所以：

```text
一个 6×6 大矩阵乘法
```

实际上就是：

```text
3 次 2×2 小矩阵乘法
+
把结果重新拼起来
```

这就是大矩阵和二维旋转之间真正的关系。

<a id="origin-6877"></a>
## 9. 为什么大矩阵里有那么多 0？

因为不同二维平面之间：

> **不需要互相干扰。**

例如我们希望：

```text
(q0,q1)
```

只和：

```text
(q0,q1)
```

内部发生旋转。

不能突然让：

```text
q0
```

和：

```text
q4
```

混到一起。

所以块对角矩阵中：

```text
非对角位置全部是 0
```

这样就保证：

```text
第一对维度
只在第一对内部旋转

第二对维度
只在第二对内部旋转

第三对维度
只在第三对内部旋转
```

---

<a id="origin-6932"></a>
## 10. 真正的 RoPE 大矩阵

对于位置：

```math
m
```

第 $i$ 个二维平面的旋转角度：

```math
m\omega_i
```

因此：

```math
R_m
=
\begin{bmatrix}
R(m\omega_0)&&&\\
&R(m\omega_1)&&\\
&&\ddots&\\
&&&R(m\omega_{d/2-1})
\end{bmatrix}
```

其中：

```math
R(m\omega_i)
=
\begin{bmatrix}
\cos(m\omega_i)&-\sin(m\omega_i)\\
\sin(m\omega_i)&\cos(m\omega_i)
\end{bmatrix}
```

所以：

> **不同二维维度组使用不同频率 $\omega_i$，但是都遵守同一个二维旋转公式。**

<a id="origin-6978"></a>
## 11. 为什么普通 RoPE 长文本会出问题？

假设模型训练上下文长度是 2048：

```text
context length = 2048
```

那么一条训练样本最多：

```text
2048 个 token
```

它们的位置编号就是：

```text
token 1     → position 0
token 2     → position 1
token 3     → position 2
...
token 2048  → position 2047
```

所以：

```math
\boxed{
m_{\max}=2047
}
```

---

<a id="origin-7012"></a>
## 12. 但模型不是训练了万亿 token 吗？

对。

这特别容易误解。

假设模型训练了：

```text
1 万亿 token
```

并不意味着 position 会一直数：

```text
0
1
2
...
999999999999
```

不是这样的。

每一条新的训练序列都会重新从：

```text
position 0
```

开始。

例如：

```text
训练样本 A：

位置：
0 1 2 3 ... 2047


训练样本 B：

位置：
0 1 2 3 ... 2047


训练样本 C：

位置：
0 1 2 3 ... 2047
```

所以即使模型总共训练了：

```text
1000000000000 个 token
```

如果每条训练序列长度最大仍然是 2048，

模型看到的 position id 仍然只是：

```text
0 ～ 2047
```

**即模型只见过长度最大为2048的输入。**

---

<a id="origin-7083"></a>
## 13. 那推理时为什么会出现 position=10000？

因为推理时用户真的可能给模型一条：

```text
超过 10000 token 的连续上下文
```

例如用户一次粘贴了一篇：

```text
10001 token 的长文档
```

那么模型看到的 position 就是：

```text
第 1 个 token   → position 0
第 2 个 token   → position 1
...
第 2048 个      → position 2047
第 2049 个      → position 2048
...
第 10001 个     → position 10000
```

所以：

```math
\boxed{
m=10000
}
```

真的会出现。

---

<a id="origin-7121"></a>
## 14. 另一种情况：Prompt + 模型生成

例如用户输入：

```text
9000 token
```

然后模型开始生成。

那么：

```text
Prompt 最后一个 token
大约 position = 8999
```

模型生成：

```text
第 1 个新 token
position = 9000

第 2 个新 token
position = 9001

...
```

如果又生成了：

```text
1001 个 token
```

就会来到：

```text
position = 10000
```

所以：

> **position=10000 并不奇怪，它只是说明当前这一整条上下文已经有 10001 个 token。**

---

<a id="origin-7168"></a>
## 15. 问题来了：模型训练时从来没见过 position=10000

假设训练长度：

```math
L_{train}=2048
```

那么训练时：

```math
m\le2047
```

但是现在推理：

```math
m=10000
```

对于某一个 RoPE **频率（每往后一个 token，这一组二维向量要多旋转多少角度）**：

```math
\omega
```

训练时角度最大：

```math
2047\omega
```

推理突然变成：

```math
10000\omega
```

大约扩大了：

```math
\frac{10000}{2047}
\approx4.9
```

倍。

于是模型进入了：

> **训练时没有见过的 RoPE 旋转范围。**

YaRN 论文正是针对 RoPE 模型超出训练上下文长度时性能明显下降的问题提出长上下文扩展方法。

<a id="origin-7223"></a>
## 16. RoPE 中 $\omega$ 和 rad 分别是什么意思？

在 RoPE 中，我们经常看到：

```math
\phi=m\omega
```

这里：

```math
m
```

表示：

> token 的位置编号。

例如：

```text
第 1 个 token → position 0
第 2 个 token → position 1
第 3 个 token → position 2
...
```

而：

```math
\omega
```

可以暂时理解成：

> **这一组二维维度每往后移动一个 token，需要多旋转多少角度。**

---

<a id="origin-7262"></a>
## 17. $\omega$ 是什么意思？

例如：

```math
\omega=0.1
```

更完整地说可以理解成：

```math
\omega=0.1\ \text{rad/token}
```

意思是：

```text
position 每增加 1
↓
这一组二维向量
多旋转 0.1 rad
```

所以：

```text
position 0
→ 旋转 0 × 0.1 = 0 rad

position 1
→ 旋转 1 × 0.1 = 0.1 rad

position 2
→ 旋转 2 × 0.1 = 0.2 rad

position 3
→ 旋转 3 × 0.1 = 0.3 rad
```

因此：

```math
\boxed{
\phi=m\omega
}
```

其中：

```text
m：
位置

ω：
每走一个位置旋转多少

φ：
最终旋转角度
```

---

<a id="origin-7324"></a>
## 18. `rad` 是什么意思？

`rad` 是：

```text
radian
```

中文叫：

> **弧度**

它和：

```text
°
```

一样，都是表示角度的单位。

我们平常习惯：

```text
90°
180°
360°
```

但数学里更常使用弧度。

最重要的换算：

```math
\boxed{
\pi\ \text{rad}=180^\circ
}
```

所以：

```math
\boxed{
2\pi\ \text{rad}=360^\circ
}
```

---

<a id="origin-7372"></a>
## 19. 1 rad 等于多少度？

因为：

```math
\pi\ rad=180^\circ
```

所以：

```math
1\ rad
=
\frac{180^\circ}{\pi}
```

大约：

```math
\boxed{
1\ rad\approx57.3^\circ
}
```

因此：

```text
0.1 rad ≈ 5.73°
0.5 rad ≈ 28.65°
1 rad   ≈ 57.3°
π/2 rad = 90°
π rad   = 180°
2π rad  = 360°
```

## 20. 举一个具体的 RoPE 例子

假设：

```math
\omega=0.1\ rad/token
```

那么每个 token 向后移动一个位置：

```text
多旋转 0.1 rad
```

也就是：

```math
0.1\times57.3^\circ
\approx5.73^\circ
```

所以：

```text
position 0
→ 0 rad
→ 0°

position 1
→ 0.1 rad
→ 约 5.73°

position 2
→ 0.2 rad
→ 约 11.46°

position 3
→ 0.3 rad
→ 约 17.19°
```

<a id="origin-7452"></a>
## 21. 如果 position = 100 呢？

假设：

```math
m=100
```

并且：

```math
\omega=0.01
```

那么：

```math
\phi=m\omega
```

所以：

```math
\phi
=
100\times0.01
=
1\ rad
```

也就是：

```math
\boxed{
\phi\approx57.3^\circ
}
```

注意：

> `position = 100` 并不是旋转 100°。

而是：

```text
position
×
这一组维度自己的 ω
=
真正旋转角度
```

<a id="origin-7506"></a>
## 22. 为什么叫“频率”？

这里的：

```math
\omega
```

通常叫：

> **角频率（angular frequency）**

在 RoPE 中可以非常直观地理解成：

> **旋转速度。**

也就是：

```text
position 每增加 1
到底旋转多少角度
```

---

<a id="origin-7531"></a>
## 23. $\omega$ 大是什么意思？

假设：

```math
\omega=0.5
```

那么每走一个 token：

```math
0.5\ rad
```

换成角度：

```math
0.5\times57.3^\circ
\approx28.6^\circ
```

所以：

```text
position 0 → 0°
position 1 → 28.6°
position 2 → 57.3°
position 3 → 85.9°
...
```

旋转得非常快。

所以：

```math
\boxed{
\omega\ 大
\Rightarrow
旋转速度快
}
```

---

<a id="origin-7576"></a>
## 24. $\omega$ 小是什么意思？

例如：

```math
\omega=0.0005
```

那么每走一个 token，只旋转：

```math
0.0005\ rad
```

约：

```math
0.0005\times57.3^\circ
\approx0.0286^\circ
```

所以：

```text
position 增加很多
↓
角度才慢慢发生变化
```

因此：

```math
\boxed{
\omega\ 小
\Rightarrow
旋转速度慢
}
```

<a id="origin-7617"></a>
## 25. 为什么 RoPE 要很多不同的 $\omega$？

因为 RoPE 会把高维 Q/K 拆成很多二维组。

例如：

```text
第 1 组维度
→ ω₀

第 2 组维度
→ ω₁

第 3 组维度
→ ω₂

...
```

它们的旋转速度不同。

可以理解成：

```text
第 1 块钟
→ 转得快

第 2 块钟
→ 稍微慢

第 3 块钟
→ 更慢

...
```

这样模型就能同时拥有：

```text
对短距离位置变化敏感的维度

以及

对长距离位置变化敏感的维度
```

<a id="origin-7665"></a>
## 26. 高频和低频是什么意思？

<a id="origin-7667"></a>
### 26.1 高频

```math
\omega
```

比较大。

例如：

```math
\omega=0.5
```

每个 token：

```text
转 28.6°
```

所以位置稍微变化：

```text
角度就变化很多
```

因此对：

```text
短距离的位置变化
```

比较敏感。

---

<a id="origin-7703"></a>
### 26.2 低频

```math
\omega
```

比较小。

例如：






## 28. 如果超过 360° 怎么办？

完全没问题。

因为：

```math
360^\circ
=
2\pi\ rad
```

而 sin/cos 是周期函数：

```math
\sin(\theta+2\pi)
=
\sin\theta
```

```math
\cos(\theta+2\pi)
=
\cos\theta
```

所以：

```text
400°
```

和：

```text
40°
```

方向完全一样。

例如：

```math
400^\circ
\bmod360^\circ
=
40^\circ
```

因此 RoPE 中：

> **角度可以不断累积，数学上并不存在“超过 360° 就不能算”的问题。**

## 37. 高频维度怎么办？

```text

```

```math

```

```text

```

```text

```

<a id="origin-8313"></a>
## 38. 低频维度怎么办？

低频：

```text
转得非常慢
```

```math
\omega=0.0005
```

```text

```

结果推理到 10000：

```text

```

进入大量训练时没见过的区域。

```text

```

例如：

```math

\rightarrow

```

```text

↓

```

## 39. 那中间频率怎么办？

不能突然：

```text
这个维度不缩放
下一个维度突然 ÷5
```

这样变化太生硬。

所以 YaRN 在中间区域做：

> **平滑过渡。**

例如可以想象：

```text
高频                 中频                 低频

×1.0       ×0.9 ×0.7 ×0.5       ×0.2
  │                │                │
  ▼                ▼                ▼
基本保留         平滑过渡          强缩放
```

这就是 YaRN 非常核心的思想：

```math
\boxed{
\text{不同 RoPE 频率采用不同程度的位置插值}
}
```

而不是全部一刀切。YaRN 的方法正是针对不同 RoPE 频率采用分段/平滑的缩放策略来扩展上下文。

## 41. YaRN 可以理解成“多档变速器”

普通 RoPE：

```text

```

长文本来了以后，如果简单 Position Interpolation：

```text
所有钟
统一减速 5 倍
```

而 YaRN：

```text
高速钟
→ 基本保持

中速钟
→ 部分减速

低速钟
→ 明显减速
```

所以：

> **既尽量保留短距离位置能力，又给低频维度腾出更大的长距离表示范围。**

## 42. 为什么这种方法能扩展上下文？

原始训练：

```text
模型熟悉：

position 0 ～ 2047
```

但是现在希望：

```text
0 ～ 10000
甚至更长
```

YaRN 并不是要求模型：

```text
突然学会一个完全新的位置编码体系
```

而是在做：

```text
超长位置
↓
重新映射不同 RoPE 频率
↓
让大部分旋转模式
尽量落回模型熟悉的几何区域
```

所以可以理解成：

> **不是扩建一套全新的坐标系，而是重新调整原来那些“钟”的转速，让更长的距离仍能被原坐标体系表示。**

## 43. YaRN 还有一个更完整的思想：Attention 尺度校正

当 RoPE 频率重新调整以后：

```text
Q/K 的相对角度分布
```

也会发生变化。

这会进一步影响：

```math
QK^T
```

的分布，

从而可能改变 Softmax 的：

```text
尖锐程度
```

因此完整的 YaRN 还考虑：

> **Attention 的尺度 / temperature 校正。**

直观上，例如原来：

```text
scores：

[2, 1, 0]
```

Softmax 有一定区分度。

如果位置缩放以后变成：

```text
[1, 0.5, 0]
```

那么 Softmax 会变得更平。

所以需要适当校正 Attention score 的数值尺度，让扩展长度以后 Attention 的分布不要和训练阶段差太远。

YaRN 原论文除了频率的分段插值之外，也包含对 Attention scaling 的处理。

不过在理解 MiniMind 时，可以先关注：

```text
不同频率
不同程度缩放
```

这个核心。

## 44. RoPE 长上下文：高频是否见过 position=10000？压缩会不会导致信息失真？

这里有两个非常关键的问题：

1. 如果某个 RoPE 频率已经在训练阶段转过很多圈，那么推理到 `position=10000` 时，这个角度是不是其实训练时已经见过？
2. 如果为了扩展上下文而强行压缩位置，会不会导致原来的位置信息被压缩、分辨率下降？

答案分别是：

> **单个高频维度的某个“相位”确实可能在训练时已经反复见过；但 position=10000 对应的是所有频率共同组成的一整套相位组合，不能说整个位置已经见过。**

以及：

> **位置压缩确实会带来信息失真，最直接的表现就是位置分辨率降低；YaRN 的核心就是不要把所有频率一刀切地一起压缩。**

```text
position 2000
```

两个位置在这一维上区别比较明显。

---

<a id="origin-9157"></a>
## 56. 现在把位置压缩 10 倍

为了让超长上下文塞回原来的范围，

假设做：

```math
m'
=
\frac{m}{10}
```

那么：

```text
1000 → 100

2000 → 200
```

原本距离：

```math
1000
```

现在变成：

```math
100
```

所以相对角度：

```math
60^\circ
```

也会变成：

```math
6^\circ
```

即：

```text
原来：

position 1000
和
position 2000

相差 60°
```

压缩后：

```text
只差 6°
```

---

<a id="origin-9221"></a>
## 57. 这确实意味着位置信息被压缩了

原来：

```text
60°
```

两个向量方向差异比较明显。

现在：

```text
6°
```

两者方向变得非常接近。

因此模型更难区分：

```text
“这两个位置到底差多远？”
```

也就是：

```math
\boxed{
\text{Position Resolution 下降}
}
```

位置分辨率下降。

比如原来“小红喜欢小明”句子中**小红**和**小明**的距离角度差是60°，现在就变成了6°，推理中的信息就会相对没有之前训练时的那么精确，**因此这种压缩不适合高频压缩。**

---

<a id="origin-9259"></a>
## 58. 这其实是一个经典矛盾

可以概括成：

```math
\boxed{
\text{范围}
\quad vs\quad
\text{分辨率}
}
```

即：

```text
想表示更远的位置
↓
往往需要压缩坐标
↓
局部位置差异也会一起缩小
```

这和地图非常类似。

---

<a id="origin-9285"></a>
## 59. 地图类比

原来地图：

```text
1 cm = 1 km
```

两个地点相距：

```text
100 km
```

地图上距离：

```text
100 cm
```

非常明显。

现在为了把整个国家画到同一张纸上：

```text
1 cm = 10 km
```

那么同样：

```text
100 km
```

只剩：

```text
10 cm
```

所以：

```text
可表示范围变大
```

但：

```text
局部细节变少
```

位置压缩也是同样的道理。

---

<a id="origin-9341"></a>
## 60. 如果所有 RoPE 频率都统一压缩，会有什么问题？

假设统一：

```math
\omega'
=
\frac{\omega}{10}
```

那么所有角度差都会缩小 10 倍。

例如一个高频维度原来：

```text
相邻两个 token
角度差 = 30°
```

压缩以后：

```text
角度差 = 3°
```

原本：

```text
token100
和
token101
```

很好区分。

现在：

```text
两者方向几乎一样
```

所以：

> **短距离位置分辨能力也被牺牲了。**

---

<a id="origin-9388"></a>
## 61. 这就是为什么简单 Position Interpolation 有代价

最简单的长上下文扩展：

```text
所有位置统一压缩
```

优点：

```text
超长 position
可以重新映射到训练熟悉的范围
```

缺点：

```text
所有相对距离
也一起被压缩
↓
位置分辨率下降
```

所以存在：

```math
\boxed{
\text{Long Range}
\leftrightarrow
\text{Fine Resolution}
}
```

之间的 trade-off。

---

<a id="origin-9426"></a>
## 62. YaRN 为什么不全部一起压缩？

这正是 YaRN 的核心考虑。

RoPE 本来就有：

```text
高频维度
中频维度
低频维度
```

它们承担的位置尺度不同。

---

<a id="origin-9442"></a>
## 63. 高频维度主要干什么？

高频：

```math
\omega
```

大。

例如相邻两个 token：

```text
position 100
position 101
```

可能相差：

```text
30°
```

所以它对：

```text
局部位置变化
```

非常敏感。

可以粗略理解成：

```text
高频维度
↓
负责位置“显微镜”
↓
区分近距离 token
```

如果把它也强行压缩：

```text
30° → 3°
```

局部细节就容易被压糊。

所以：

> **高频应该尽量少动。**

---

<a id="origin-9497"></a>
## 64. 低频维度主要干什么？

低频：

```math
\omega
```

小。

相邻 token 的角度变化很小。

但是随着距离越来越远：

```text
角度才慢慢变化
```

所以更适合表达：

```text
长距离位置关系
```

可以粗略理解成：

```text
低频维度
↓
负责位置“广角镜头”
↓
看更远的位置范围
```

而长上下文外推时，

真正最容易进入未见区域的也是这些：

```text
训练阶段只转了一小段
```

的低频维度。

所以：

> **低频更适合做较强的缩放。**

---

<a id="origin-9547"></a>
## 65. YaRN 的思路

YaRN 不做：

```text
所有频率 ÷10
```

而大概做：

```text
高频
↓
基本保留
↓
保住局部位置分辨率


中频
↓
逐渐缩放
↓
平滑过渡


低频
↓
更多缩放
↓
扩大长距离范围
```

也就是：

```text
             缩放程度

高频          小
 ↓
中频          中
 ↓
低频          大
```

---

<a id="origin-9593"></a>
## 66. 所以 YaRN 本质上是在做一个折中

可以总结成：

```text
如果完全不压缩：

短距离精度保住了
但长距离跑到训练没见过的区域
```

如果全部统一压缩：

```text
长距离解决了
但短距离也被压糊
```

YaRN：

```text
高频少动
↓
保留局部精度

低频多动
↓
扩展长距离

中间平滑过渡
↓
两边折中
```

所以它是在解决：

```math
\boxed{
\text{长距离范围}
\quad+\quad
\text{局部位置分辨率}
}
```

之间的矛盾。


<a id="origin-9640"></a>
## 67. 用语言案例理解 RoPE 的高频、中频和低频

前面我们说：

```text
高频 RoPE
→ 位置稍微变化，角度就变化很多

低频 RoPE
→ 位置变化很多，角度才明显变化
```

如果只用“钟表”来解释，确实比较抽象。

更适合语言模型的理解方式是：

> **高频维度更适合表达局部、精细的位置差异；低频维度更适合表达跨度较大的位置关系。**

但需要先强调：

> **这不是人为规定“某几个维度专门负责主谓关系、某几个维度专门负责段落关系”。RoPE 只是提供不同的位置频率，模型训练以后自己学习如何利用这些不同尺度的位置特征。**

---

<a id="origin-9664"></a>
## 68. 先看一个非常局部的语言关系

例如：

```text
我 喜欢 吃 苹果
```

假设当前处理：

```text
吃
```

它可能需要区分：

```text
前 1 个 token：喜欢

前 2 个 token：我
```

这里：

```text
距离 1
```

和：

```text
距离 2
```

的区别就可能很重要。

例如：

```text
我 / 喜欢 / 吃
```

和：

```text
我 / 吃 / 喜欢
```

虽然 token 差不多，

但是局部顺序一变化：

```text
语言结构就完全不同
```

所以模型需要一种位置表示：

> **哪怕只移动 1～2 个 token，也能产生比较明显的变化。**

这就是高频位置维度擅长提供的能力。

---

<a id="origin-9728"></a>
## 69. 高频为什么适合局部关系？

假设某组 RoPE：

```math
\omega_H = 0.5\ \text{rad/token}
```

那么每移动一个 token：

```math
0.5\ rad
\approx28.6^\circ
```

所以：

```text
距离 1
→ 角度差约 28.6°

距离 2
→ 角度差约 57.3°

距离 3
→ 角度差约 85.9°
```

也就是说：

```text
只移动几个 token
↓
角度已经变化很多
```

所以它对于：

```text
距离 1
距离 2
距离 3
```

非常敏感。

---

<a id="origin-9776"></a>
## 70. 一个语言例子

例如：

```text
小明 非常 喜欢 小红
```

当前：

```text
喜欢
```

可能需要利用：

```text
前面 1 个 token：
非常

前面 2 个 token：
小明
```

如果换成：

```text
小明 喜欢 非常 小红
```

仅仅几个 token 的位置变化，

语言结构就明显不一样。

所以对于：

```text
词序
局部语法
短语结构
相邻 token 关系
```

模型需要很高的位置分辨率。

可以粗略理解成：

```math
\boxed{
高频 RoPE
\rightarrow
局部语言关系
}
```

---

<a id="origin-9833"></a>
## 71. 再看一个更长距离的语言关系

例如一篇文章：

```text
第 1 段：

浙江大学软件学院位于宁波。
学院主要开展软件工程和人工智能相关研究。

……

中间经过大量文字

……

第 20 段：

该学院近年来进一步加强了人工智能领域的研究。
```

这里：

```text
“该学院”
```

可能需要联系很前面的：

```text
“浙江大学软件学院”
```

两者可能相隔：

```text
几百
甚至几千 token
```

这时候模型真正需要的是：

> **知道它们处在一个较长距离的对应关系中。**

并不一定需要：

```text
距离到底是 1001 token
还是 1002 token
```

这种极其精细的区别。

---

<a id="origin-9888"></a>
## 72. 低频为什么适合这种长距离关系？

假设：

```math
\omega_L=0.0005\ \text{rad/token}
```

那么移动一个 token：

```math
0.0005\ rad
\approx0.0286^\circ
```

所以：

```text
距离 1
→ 0.0286°

距离 10
→ 0.286°

距离 100
→ 2.86°

距离 1000
→ 28.6°

距离 2000
→ 57.3°
```

可以看到：

```text
1 个 token
2 个 token
3 个 token
```

对这一维来说区别非常小。

但：

```text
1000 个 token
2000 个 token
```

才会出现明显的角度变化。

所以：

> **低频维度不会浪费大量表示能力去区分非常细的局部距离，而是能在较大范围内缓慢变化。**

---

<a id="origin-9947"></a>
## 73. 一个更具体的语言例子

假设文章开头写：

```text
张三于 2010 年加入浙江大学，
主要从事人工智能研究。
```

经过：

```text
1500 个 token
```

以后出现：

```text
他后来开始研究大语言模型。
```

这里：

```text
“他”
```

可能需要和前面：

```text
“张三”
```

建立关系。

模型需要知道：

```text
这是一个距离比较远的上下文信息
```

但是：

```text
张三距离“他”到底是 1498 token
还是 1501 token
```

往往没有：

```text
“喜欢”和它前面一个词到底是什么”
```

那么敏感。

所以可以粗略理解：

```text
高频：
更适合精细区分几十个 token 内的位置变化

低频：
更适合表示数百、数千 token 的长距离变化
```

<a id="origin-10015"></a>
## 74. 高频和低频分别像在回答什么问题？

<a id="origin-10017"></a>
### 74.1 高频位置特征

更像在回答：

```text
这个词是在我前面 1 个位置，
还是前面 2 个位置？

是紧挨着我，
还是中间隔了一个词？
```

例如：

```text
我 喜欢 苹果
```

和：

```text
我 苹果 喜欢
```

局部顺序非常重要。

---

<a id="origin-10045"></a>
### 74.2 低频位置特征

更像在回答：

```text
这个信息是在当前附近，

还是在前面很远的一段内容里？
```

例如：

```text
文章第一段介绍了一个人

↓

经过 1000 多 token

↓

后面再次使用“他”
```

需要建立长距离联系。

---

<a id="origin-10073"></a>
## 75. 为什么需要高频和低频一起存在？

因为语言同时存在：

```text
局部关系
+
长距离关系
```

例如一句话：

```text
张三告诉李四，他昨天购买的那本书非常有趣。
```

模型既要理解：

```text
“非常”修饰“有趣”
```

这种：

```text
非常局部的关系
```

又可能需要判断：

```text
“他”到底指张三还是李四
```

这种：

```text
跨越更长距离的关系
```

如果是一篇长文，

还可能需要联系：

```text
几百甚至几千 token 之前定义的人物、变量、概念
```

所以只用一种位置尺度是不够的。

---

<a id="origin-10125"></a>
## 76. 可以理解成“多尺度位置感知”

RoPE 的很多不同频率可以理解成同时提供：

```text
非常局部的位置尺度

局部的位置尺度

中距离的位置尺度

长距离的位置尺度
```

类似于：

```text
高频
↓
看细节

中频
↓
看句子 / 局部段落

低频
↓
看长距离结构
```

注意：

> 这只是帮助理解的位置尺度直觉，并不是说模型内部存在明确的“句法频率”“段落频率”标签。

<a id="origin-10159"></a>
## 77. 这也解释了为什么不能把所有频率都统一压缩

假设高频原来：

```text
相邻 token
角度差 = 30°
```

这对于：

```text
“非常 好”
```

和：

```text
“好 非常”
```

这种局部顺序区分很有帮助。

如果为了扩展上下文，

全部频率统一压缩 10 倍：

```text
30°
↓
3°
```

那么：

```text
相邻 token 的位置差异
```

也被严重压缩了。

---

<a id="origin-10202"></a>
## 78. 用语言案例理解这种信息损失

原本模型可能比较容易区分：

```text
A：

我 非常 喜欢 苹果
```

和：

```text
B：

我 喜欢 非常 苹果
```

因为：

```text
“非常”
相对于
“喜欢”
```

的位置关系变化非常明显。

如果所有高频位置特征都被大幅压缩：

```text
距离 1
距离 2
```

对应的角度差都变得很小，

那么模型利用这些位置维度区分：

```text
局部词序
```

就可能变困难。

---

<a id="origin-10249"></a>
## 79. 但是低频不压缩又有什么问题？

假设模型正在阅读一篇很长的技术文档。

前面某个位置写：

```text
position 100：

我们定义配置对象 user_config，
其中包含数据库地址、缓存策略和重试次数。
```

然后中间经过了大量内容，例如：

```text
数据库初始化
日志系统
线程池
任务调度
缓存模块
异常处理
……
```

到了很后面：

```text
position 10000：

在启动服务之前，
需要重新读取 user_config，
并根据其中的重试次数初始化任务调度器。
```

这里模型需要建立一个长距离关系：

```text
前面的 user_config 定义
            ↕
后面的 user_config 使用
```

也就是说：

> **模型需要知道：后面这个 `user_config`，和很早以前定义的那个 `user_config` 有关系。**


<a id="origin-10297"></a>
### 79.1 一句话理解

<a id="origin-10299"></a>
#### 79.1.1 训练的时候，模型见过这种情况：前面定义了 user_config，过了一两千个 token 后又用到了它，这种“隔得很远但还是有关联”的关系，在 RoPE 里可能对应大约 $60^\circ$ 的相对角度。后来推理时文本变得特别长，user_config 隔了快一万个 token 才再次出现，这时候相对角度可能一下变成 $280^\circ$。这个 $280^\circ$ 的位置模式模型训练时没怎么见过，所以不太知道该怎么处理。YaRN 做的事情，就是把这种 $280^\circ$ 的陌生关系压回到接近 $60^\circ$ 的熟悉范围，让模型可以继续按照以前学到的方式理解：哦，这还是“前面很久以前定义的那个 user_config，现在又被引用了”，所以我知道接下来要干啥了。

---

<a id="origin-10303"></a>
## 80. 这里最重要的不是精确差几个 token

前面的：

```text
user_config
```

在：

```text
position 100
```

后面的：

```text
user_config
```

在：

```text
position 10000
```

两者相差：

```math
10000-100=9900
```

个 token。

但对于理解这段文字来说，真正重要的通常不是：

```text
到底相隔 9899 个 token

还是 9900 个 token

还是 9901 个 token
```

而是：

> **这个信息出现在很久以前，现在又被重新引用了。**

所以这种关系更偏向：

```text
长距离位置关系
```

而不是：

```text
局部精细位置关系
```

---

<a id="origin-10365"></a>
## 81. 这就是低频位置特征更适合表达的东西

假设某个低频 RoPE 维度：

```math
\omega=0.0005\ \text{rad/token}
```

它每移动一个 token，只旋转：

```math
0.0005\text{ rad}
```

大约：

```math
0.0286^\circ
```

所以：

```text
差 1 个 token
→ 几乎没变化

差 10 个 token
→ 变化也很小

差 100 个 token
→ 开始有一些变化

差 1000 个 token
→ 才出现比较明显的变化
```

因此低频位置特征不会特别敏感于：

```text
前 1 个 token

前 2 个 token
```

而更适合提供一种：

> **“这个相关信息到底是在附近，还是在很远以前？”**

的位置尺度。

---

<a id="origin-10417"></a>
## 82. 如果训练时最长只有 2048 token

假设训练上下文长度：

```math
L_{train}=2048
```

那么训练时任意两个 token 的最大相对距离大约是：

```math
2047
```

对于：

```math
\omega=0.0005
```

最大相对旋转角：

```math
2047\times0.0005
\approx1.02\text{ rad}
```

约：

```math
58.6^\circ
```

所以训练过程中，这个低频维度看到的长距离关系大致是：

```text
两个相关词距离几十 token
↓
较小角度差

距离几百 token
↓
中等角度差

距离接近 2000 token
↓
最大大约 59°
```

也就是说：

> **训练过程中，这个低频维度只学过大约 $0^\circ\sim59^\circ$ 这一范围内的长距离位置模式。**

---

<a id="origin-10472"></a>
## 83. 用一个训练时可能见过的语言例子

例如训练文本：

```text
position 100：

我们定义配置对象 user_config。


……

position 1800：

程序启动时重新读取 user_config。
```

两者距离：

```math
1800-100=1700
```

对应角度差：

```math
1700\times0.0005
=
0.85\text{ rad}
```

约：

```math
48.7^\circ
```

这种模式模型在训练中是有机会见过的：

```text
前面定义一个对象

↓

经过很长一段文字

↓

后面重新引用这个对象
```

而低频相对角度可能是：

```text
40°
50°
接近 60°
```

这样的范围。

---

<a id="origin-10535"></a>
## 84. 但是推理时文本突然变得非常长

现在用户给模型一篇 10000 多 token 的代码文档。

前面：

```text
position 100：

user_config = {...}
```

后面：

```text
position 10000：

retry_count = user_config["retry_count"]
```

这两处相差：

```math
9900
```

个 token。

于是低频相对角度：

```math
9900\times0.0005
=
4.95\text{ rad}
```

约：

```math
283.6^\circ
```

于是情况变成：

```text
训练时模型熟悉的长距离关系：

前面的 user_config
        ↕
后面的 user_config

低频角度差大约：
0° ～ 59°
```

但现在推理：

```text
前面的 user_config
        ↕
9900 token 后的 user_config

低频角度差：
约 284°
```

也就是说：

> **语言关系本身其实还是“前面定义，后面引用”，但 RoPE 给出的低频位置模式已经跑到了模型训练时从没见过的区域。**

---

<a id="origin-10607"></a>
## 85. 问题不在于模型不认识 `user_config`

注意这里的问题不是：

```text
模型不认识 user_config
```

也不是：

```text
模型不知道两个字符串一样
```

真正的问题是：

> **Attention 在判断“当前位置应该如何利用 9900 token 前的信息”时，RoPE 提供了一种训练时从未经历过的相对位置几何关系（之前见的是两者相差48°时的关系，现在突然出现了相差284°，不知道怎么处理了）。**

也就是：

```text
内容关系：
模型可能认识

但是

位置关系：
超出了训练分布
```

所以长距离 Attention 可能变得不稳定。

<a id="origin-10641"></a>
## 86. 为什么要压缩低频？

假设我们把这个低频的旋转速度减慢 5 倍：

```math
\omega'
=
\frac{0.0005}{5}
=
0.0001
```

那么同样：

```math
\Delta m=9900
```

新的角度差：

```math
9900\times0.0001
=
0.99\text{ rad}
```

约：

```math
56.7^\circ
```

于是：

```text
原来：

position 100
↔
position 10000

距离 9900
↓
角度差约 284°
↓
训练没见过
```

压缩以后：

```text
position 100
↔
position 10000

距离仍然 9900
↓
角度差约 57°
↓
回到训练熟悉的范围
```

---

<a id="origin-10705"></a>
## 87. 从语言意义上怎么理解这个压缩？

可以把它理解成：

原本模型训练时学会了：

```text
“如果一个实体在前面大约 1000～2000 token 出现过，
现在又被引用，
这种长距离关系应该怎么处理。”
```

但现在推理：

```text
它出现在 9900 token 以前
```

模型没学过这么远。

于是 YaRN 做的事情相当于：

```text
真实距离：
9900 token

↓

在低频位置空间中压缩

↓

让它看起来更像：
模型以前训练过的
约 2000 token 级别长距离关系
```

于是模型可以复用原来学到的模式：

```text
“这是一个很早以前出现过，
现在重新被引用的信息。”
```

---

<a id="origin-10751"></a>
## 88. 但它不是把 9900 token 真变成 2000 token

这一点要特别注意。

文本本身：

```text
仍然有 9900 token 的实际距离
```

Attention 仍然可以访问：

```text
position 100
```

那个 token。

只是：

> **RoPE 中用于描述相对位置的旋转角度被重新缩放了。**

所以：

```text
内容没有删掉
token 没有合并
上下文没有截断
```

改变的只是：

```text
位置几何表示
```

---

<a id="origin-10789"></a>
## 89. 为什么这类关系特别适合低频？

因为对于这种长距离引用：

```text
position 100
↔
position 10000
```

模型通常不需要精确知道：

```text
它们到底差 9899
还是 9900
还是 9901
```

这些距离对于：

```text
“后面的 user_config 指的是前面的 user_config”
```

来说差别非常小。

真正重要的是：

```text
这是一个非常远距离的相关信息
```

所以低频这种：

```text
变化慢
```

的位置特征非常适合表示这种关系。

---

<a id="origin-10831"></a>
## 90. 对比高频语言关系

高频更适合：

```text
我 非常 喜欢 苹果
```

例如：

```text
“非常”
```

是在：

```text
“喜欢”前 1 个 token
```

还是：

```text
后 1 个 token
```

区别可能非常重要。

所以：

```text
距离 1
距离 2
```

需要精确区分。

---

而低频更适合：

```text
文章开头：

定义 user_config

↓

经过几千 token

↓

文章后面：

重新使用 user_config
```

这里更重要的是：

```text
近
还是
非常远
```

而不是：

```text
准确差一个 token
```

---

<a id="origin-10904"></a>
## 91. 这就是 YaRN 的直觉

YaRN 不想做：

```text
所有位置频率一起 ÷10
```

因为那会破坏：

```text
局部词序
短语结构
相邻 token 区分
```

它更希望：

```text
高频
↓
尽量保持
↓
继续分清：
前1个 token / 前2个 token / 前3个 token


低频
↓
更多压缩
↓
让：
几千 / 上万 token 的远距离关系
不要跑出模型熟悉的位置范围
```

<a id="origin-10940"></a>
## 92. YaRN 的核心公式：不同 RoPE 频率到底怎么缩放？

前面已经知道，普通 RoPE 中，第 $i$ 组二维维度有自己的旋转频率：

```math
\omega_i
```

位置 $m$ 对应的旋转角度：

```math
\phi_i(m)=m\omega_i
```

也就是说：

```text
position
×
这一组维度的旋转速度
=
最终旋转角度
```

<a id="origin-10966"></a>
## 93. YaRN 最核心的频率公式

可以写成：

```math
\boxed{
\omega_i'
=
(1-\gamma_i)\omega_i
+
\gamma_i\frac{\omega_i}{s}
}
```

把：

```math
\omega_i
```

提出来：

```math
\boxed{
\omega_i'
=
\omega_i
\left[
(1-\gamma_i)
+
\frac{\gamma_i}{s}
\right]
}
```

这就是理解 YaRN 最重要的公式。

---

<a id="origin-11005"></a>
## 94. 每一个符号是什么意思？

其中：

```math
\omega_i
```

是：

> 原始 RoPE 第 $i$ 组二维维度的频率。

---

```math
s
```

是：

> 上下文扩展倍数。

例如：

```text
2048 → 8192
```

那么：

```math
s=4
```

---

```math
\gamma_i
```

是：

> 当前这一组频率到底应该被压缩多少。

范围：

```math
0\le\gamma_i\le1
```

---

<a id="origin-11057"></a>
## 95. 如果 $\gamma_i=0$

代入：

```math
\omega_i'
=
\omega_i
\left[
1+\frac{0}{s}
\right]
```

得到：

```math
\boxed{
\omega_i'=\omega_i
}
```

也就是说：

```text
完全不压缩
```

通常可以理解成：

```text
高频部分
↓
尽量保持原来的旋转速度
↓
保住局部位置分辨率
```

---

<a id="origin-11096"></a>
## 96. 如果 $\gamma_i=1$

代入：

```math
\omega_i'
=
\omega_i
\left[
0+\frac1s
\right]
```

得到：

```math
\boxed{
\omega_i'
=
\frac{\omega_i}{s}
}
```

也就是：

```text
完全按照扩展倍数压缩
```

例如：

```math
s=5
```

那么：

```math
\omega_i'
=
\frac{\omega_i}{5}
```

旋转速度变成原来的：

```text
1/5
```

---

<a id="origin-11147"></a>
## 97. 如果 $\gamma_i=0.5$

那么：

```math
\omega_i'
=
\omega_i
\left[
0.5+\frac{0.5}{s}
\right]
```

假设：

```math
s=5
```

得到：

```math
\omega_i'
=
\omega_i
(0.5+0.1)
```

所以：

```math
\boxed{
\omega_i'=0.6\omega_i
}
```

也就是：

```text
不完全保持原频率
也不完全 ÷5

而是在中间平滑过渡
```

---

<a id="origin-11194"></a>
## 98. 用一个表格看最直观

假设：

```math
s=5
```

那么：

| $\gamma_i$ | 新频率 $\omega_i'$ | 含义    |
| -----------: | ----------------: | ----- |
|            0 |   $1.0\omega_i$ | 完全保持  |
|         0.25 |   $0.8\omega_i$ | 少量压缩  |
|          0.5 |   $0.6\omega_i$ | 中等压缩  |
|         0.75 |   $0.4\omega_i$ | 较强压缩  |
|            1 |   $0.2\omega_i$ | 完全 ÷5 |

所以 YaRN 不是：

```text
压
或者
不压
```

而是：

```text
不同频率
使用不同程度的压缩
```

<a id="origin-11229"></a>
## 99. $\gamma_i$ 是怎么来的？

YaRN 会先根据：

```text
这个频率在原始训练长度内
到底能转多少圈
```

来判断它属于：

```text
高频
中频
低频
```

假设原始训练长度：

```math
L
```

某个频率：

```math
\omega_i
```

那么它在整个训练窗口里大约能转多少圈：

```math
\boxed{
r_i
=
\frac{L\omega_i}{2\pi}
}
```

因为：

```math
L\omega_i
```

是走完整个训练窗口累计旋转的弧度，

而：

```math
2\pi
```

是一整圈。

所以：

```math
\frac{L\omega_i}{2\pi}
```

就是：

> **在训练窗口内一共转了多少圈。**

---

<a id="origin-11296"></a>
## 100. 举例

假设：

```math
L=2048
```

某个高频：

```math
\omega_H=0.5
```

那么：

```math
r_H
=
\frac{2048\times0.5}{2\pi}
```

约：

```math
r_H\approx163
```

也就是说：

```text
训练 2048 token 的过程中
这个维度已经转了约 163 圈
```

这种频率：

```text
大量相位都见过
而且对局部位置非常敏感
```

所以 YaRN 倾向于：

```math
\gamma_i\approx0
```

即：

```text
少压或者不压
```

---

<a id="origin-11352"></a>
## 101. 再看低频

假设：

```math
\omega_L=0.0005
```

那么：

```math
r_L
=
\frac{2048\times0.0005}{2\pi}
```

约：

```math
r_L\approx0.163
```

也就是说：

```text
整个训练窗口里
连一整圈都没转完
```

这种低频一旦来到超长上下文：

```text
position 10000
```

就非常容易进入训练阶段没见过的相位范围。

所以 YaRN 更倾向于：

```math
\gamma_i\approx1
```

即：

```math
\omega_i'
\approx
\frac{\omega_i}{s}
```

<a id="origin-11405"></a>
## 102. YaRN 用两个阈值决定怎么处理

YaRN 通常会引入：

```math
\beta_{fast}
```

和：

```math
\beta_{slow}
```

来判断某一组维度在原训练窗口里转了多少圈。

直观理解：

```text
转得非常多
↓
属于高频
↓
少压


转得非常少
↓
属于低频
↓
多压


处在中间
↓
平滑过渡
```

经典 YaRN 常见：

```text
beta_fast = 32
beta_slow = 1
```

含义可以粗略理解成：

```text
训练窗口里转了很多圈
→ 高频区域

训练窗口里连一圈左右都不到
→ 低频区域

中间
→ 逐渐过渡
```

<a id="origin-11465"></a>
## 103. $\gamma_i$ 的直观形式

可以把它理解成一个 Ramp：

```text
高频                     中频                     低频

γ=0                      0<γ<1                    γ=1

│                           │                       │
▼                           ▼                       ▼

不压                   平滑过渡                  完全压缩
```

数学上可以粗略写成：

```math
\gamma_i
=
\operatorname{clip}
\left(
\frac{i-i_{\text{low}}}
{i_{\text{high}}-i_{\text{low}}},
0,
1
\right)
```

其中：

```text
clip(...,0,1)
```

意思是：

```text
小于 0 → 设成 0

0～1 → 保持

大于 1 → 设成 1
```

所以：

```text
高频维度：
γ≈0

中频维度：
γ 从 0 慢慢变到 1

低频维度：
γ≈1
```

## 104. YaRN 中 $\gamma_i$、$i$、$i_{\text{low}}$、$i_{\text{high}}$ 分别是什么意思？

前面为了说明 YaRN 如何对不同 RoPE 频率做不同程度的压缩，我们用了一个简化的过渡公式：

```math
\gamma_i
=
\operatorname{clip}
\left(
\frac{i-i_{\text{low}}}
{i_{\text{high}}-i_{\text{low}}},
0,
1
\right)
```

这里最容易搞混的是：

```math
i
```

到底是什么。

<a id="origin-11550"></a>
## 105. $i$ 不是 token 的 position

首先要明确：

```math
i
```

不是：

```text
position 0
position 1
position 2
...
```

也不是：

```text
第几个 token
```

它表示的是：

> **当前正在处理第几组 RoPE 二维旋转维度，也就是第几个 RoPE 频率。**

---

<a id="origin-11579"></a>
## 106. 一个具体例子

假设一个 Attention Head 的维度是：

```math
d=8
```

那么 Q 可以写成：

```math
Q=
[q_0,q_1,q_2,q_3,q_4,q_5,q_6,q_7]
```

RoPE 会把这些维度拆成 4 组二维平面：

```text
第 0 组：
(q0,q1)

第 1 组：
(q2,q3)

第 2 组：
(q4,q5)

第 3 组：
(q6,q7)
```

每一组都有自己的旋转频率：

```text
第 0 组 → ω0
第 1 组 → ω1
第 2 组 → ω2
第 3 组 → ω3
```

因此：

```text
i = 0 → 第 0 组 RoPE 频率 ω0
i = 1 → 第 1 组 RoPE 频率 ω1
i = 2 → 第 2 组 RoPE 频率 ω2
i = 3 → 第 3 组 RoPE 频率 ω3
```

所以可以记：

```math
\boxed{
i=\text{RoPE 频率组的编号}
}
```

<a id="origin-11638"></a>
## 107. 那 $i_{\text{low}}$ 和 $i_{\text{high}}$ 是什么？

它们是两个：

> **频率分界位置。**

用来把所有 RoPE 频率划分成：

```text
基本不压缩
↓
平滑过渡
↓
充分压缩
```

三段。

例如：

```math
i_{\text{low}}=3
```

```math
i_{\text{high}}=7
```

**YaRN 并不是人工直接指定 `i_low=3、i_high=7` 这样的维度下标，而是先人为设定 `β_fast` 和 `β_slow` 两个阈值，再结合每组 RoPE 频率 $\omega_i$ 和原始训练长度 $L$，计算该频率在训练窗口内大约旋转了多少圈，从而自动确定哪些频率属于高频区、过渡区和低频区。**


那么可以理解成：

```text
i < 3
↓
基本不压

3 ～ 7
↓
逐渐增加压缩程度

i > 7
↓
充分压缩
```

<a id="origin-11687"></a>
## 108. `clip` 是什么？

`clip` 可以理解成：

> **截断 / 限幅：把一个数强行限制在指定范围内。**

例如：

```math
\operatorname{clip}(x,0,1)
```

意思是：

> 不管 $x$ 原来是多少，最后都把它限制在 $[0,1]$ 之间。

数学上：

```math
\operatorname{clip}(x,0,1)
=
\begin{cases}
0,&x<0\\
x,&0\le x\le1\\
1,&x>1
\end{cases}
```

例如：

```text
clip(-0.5, 0, 1) = 0

clip(0.3, 0, 1) = 0.3

clip(0.8, 0, 1) = 0.8

clip(1.6, 0, 1) = 1
```

也就是说：

```text
太小
↓
拉到下界

正常
↓
保持不变

太大
↓
压到上界
```

---

<a id="origin-11745"></a>
### 108.1 放到 YaRN 公式里

前面有：

```math
\gamma_i
=
\operatorname{clip}
\left(
\frac{i-i_{\text{low}}}
{i_{\text{high}}-i_{\text{low}}},
0,
1
\right)
```

先计算：

```math
\frac{i-i_{\text{low}}}
{i_{\text{high}}-i_{\text{low}}}
```

然后：

```text
结果 < 0
→ γ_i = 0

结果在 0～1
→ 保留原值

结果 > 1
→ γ_i = 1
```

所以最终保证：

```math
\boxed{
0\le\gamma_i\le1
}
```
---

<a id="origin-11790"></a>
## 109. 用具体数字看这个公式

假设：

```math
i_{\text{low}}=3
```

```math
i_{\text{high}}=7
```

那么：

```math
\gamma_i
=
\operatorname{clip}
\left(
\frac{i-3}{7-3},
0,
1
\right)
```

也就是：

```math
\gamma_i
=
\operatorname{clip}
\left(
\frac{i-3}{4},
0,
1
\right)
```

## 117. 完整 YaRN 还会做 Attention Scale 修正

YaRN 除了改变 RoPE 频率之外，

还会对 Attention 的尺度做一定校正。

常见的尺度因子形式可以写成：

```math
\boxed{
m(s)
=
1+0.1\ln s
}
```

当：

```math
s\le1
```

时通常取：

```math
m(s)=1
```

它的目的不是再处理“位置”，

而是：

> **频率变化以后，Q/K 点积和 Attention softmax 的统计分布也可能发生改变，因此适当修正 Attention 的尺度，让长上下文下的 Attention 分布不要和原训练阶段偏离太多。**

这一部分属于 YaRN 的进一步稳定化处理。YaRN 的核心仍然是前面的“按频率选择性插值”。
