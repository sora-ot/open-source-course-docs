# 02 · Tokenizer 训练与原理


<a id="origin-3"></a>
## 1. 为什么大语言模型需要 Tokenizer？

大语言模型不能直接理解“我喜欢自然语言处理”这样的字符串。

模型真正接收的是一串整数，例如：

```text
原始文本：
我喜欢自然语言处理

        ↓ Tokenizer

Tokens：
["我", "喜欢", "自然", "语言", "处理"]

        ↓ Token → ID

Token IDs：
[231, 518, 902, 736, 1145]

        ↓ Embedding

隐藏状态：
[seq_len, hidden_size]
```

因此，可以把 Tokenizer 理解成：

> **文本世界与神经网络数值世界之间的桥梁。**

整个 LLM 输入过程可以概括为：

```text
原始文本
   ↓
Tokenizer
   ↓
Token
   ↓
Token ID
   ↓
Embedding
   ↓
Transformer
```

MiniMind 的脚本使用的是 **ByteLevel BPE Tokenizer**，并将最终词表大小设置为：

```python
VOCAB_SIZE = 6400
```

同时预留 36 个特殊 Token。

---

<a id="origin-59"></a>
## 2. 为什么 MiniMind 不建议重新训练 Tokenizer？

MiniMind 已经提供了训练好的 tokenizer，一般不建议重新训练，本脚本主要用于学习 tokenizer 的工作原理。

原因是：

```text
模型参数
   ↕
Tokenizer
```

二者实际上是绑定的。

例如原来的 tokenizer：

```text
"人工智能"
↓
[521, 1732]
```

重新训练 tokenizer 后可能变成：

```text
"人工智能"
↓
[91, 352, 117]
```

虽然输入文本相同，但模型最终看到的 Token ID 已经完全不同。

因此：

> **Tokenizer 一旦改变，通常就需要重新训练模型。**

## 4. 第一步：准备 Tokenizer 训练语料

核心代码：

```python
def get_texts(data_path):
    with open(data_path, 'r', encoding='utf-8', errors='ignore') as f:
        for i, line in enumerate(f):
            if i >= 10000:
                break

            data = json.loads(line)

            contents = [
                item.get('content')
                for item in data.get('conversations', [])
                if item.get('content')
            ]

            if contents:
                yield "\n".join(contents)
```

这部分的作用并不是训练模型，而是：

> **从 SFT 数据集中抽取自然语言文本，作为 Tokenizer 学习词表的语料。**

假设原始 JSONL 数据为：

```json
{
  "conversations": [
    {
      "role": "user",
      "content": "什么是机器学习？"
    },
    {
      "role": "assistant",
      "content": "机器学习是人工智能的一个分支。"
    }
  ]
}
```

程序最终提取的是：

```text
什么是机器学习？
机器学习是人工智能的一个分支。
```

这里训练 Tokenizer 时主要关注的是 `content`，因为 Tokenizer 要学习的是：

> **文本应该如何切分。**

<a id="origin-207"></a>
## 5. 为什么使用 yield？

代码：

```python
yield "\n".join(contents)
```

使用的是 Python Generator。

它的特点是：

```text
需要文本1 → 读取文本1
需要文本2 → 读取文本2
需要文本3 → 读取文本3
```

而不是一次性把整个数据集读入内存。

因此：

```text
磁盘
 ↓
逐条读取
 ↓
Tokenizer Trainer
```

这种方式更适合大规模语料。

## 7. Byte Pair Encoding（BPE）

BPE 的核心思想：

> **不断把训练数据中最经常一起出现的 Token 合并成一个新的 Token。**

---

<a id="origin-259"></a>
## 8. BPE 是怎么工作的？

假设训练数据：

```text
low
lower
lowest
```

初始可以理解为：

```text
l o w
l o w e r
l o w e s t
```

发现：

```text
l + o
```

经常一起出现，于是合并：

```text
lo
```

得到：

```text
lo w
lo w e r
lo w e s t
```

再发现：

```text
lo + w
```

经常出现，于是继续合并：

```text
low
```

最终可能学习出：

```text
low
er
est
```

于是：

```text
lower  → low + er
lowest → low + est
```

---

<a id="origin-326"></a>
## 9. 为什么不直接“一个字一个 Token”？

例如：

```text
人工智能正在改变世界
```

若按单字切分：

```text
人
工
智
能
正
在
改
变
世
界
```

一共 10 个 Token。

如果训练数据中“人工智能”出现很多次，BPE 可以学到：

```text
人工智能
```

或者：

```text
人工
智能
```

于是可能只需要：

```text
人工智能
正在
改变
世界
```

4 个 Token。

因此 BPE 本质上是在做：

> **词表大小与序列长度之间的权衡。**

## 10. 为什么 MiniMind 使用 ByteLevel？

代码：

```python
tokenizer.pre_tokenizer = pre_tokenizers.ByteLevel(
    add_prefix_space=False
)
```

ByteLevel 的核心思想：

> **先把文本转换为 UTF-8 字节，再在字节序列上进行处理。**

因此：

```text
英文
中文
数字
emoji
特殊符号
```

都可以统一表示。

完整过程：

```text
文本
 ↓
UTF-8 字节
 ↓
ByteLevel
 ↓
BPE Merge
 ↓
Token
```

## 11. ByteLevel 与 BPE 的关系

ByteLevel 负责：

```text
文本的基础表示 / 预处理
```

BPE 负责：

```text
学习哪些连续片段应该合并
```

因此：

```text
原始文本
   ↓
UTF-8
   ↓
ByteLevel
   ↓
基础字节序列
   ↓
BPE 统计
   ↓
不断 Merge
   ↓
最终 Token
```

## 12. 特殊 Token 是什么？

代码定义了：

```text
<|endoftext|>
<|im_start|>
<|im_end|>

<|vision_start|>
<|vision_end|>

<|image_pad|>
<|video_pad|>

<tool_call>
</tool_call>

<tool_response>
</tool_response>

<think>
</think>
```

特殊 Token 不是普通语言，而是用于表示模型控制结构。

例如：

```text
<|im_start|>
```

表示一条消息开始。

```text
<|im_end|>
```

表示一条消息结束。

---

<a id="origin-500"></a>
## 13. 为什么特殊 Token 必须单独定义？

如果没有注册：

```text
<|im_start|>
```

Tokenizer 可能拆成：

```text
<
|
im
_
start
|
>
```

模型就无法把它当成统一的控制信号。

注册后：

```text
<|im_start|>
```

可以作为一个完整 Token。

因此：

> **特殊 Token 是文本中的控制信号。**

<a id="origin-603"></a>
## 16. Vocabulary Size 为什么不能无限增大？

Embedding 参数规模：

$$
N_{\text{embedding}} = V \times d
$$

其中：

- $V$：Vocabulary Size
- $d$：Hidden Size

例如：

```text
V = 6400
d = 512
```

则：

$$
6400 \times 512 = 3,276,800
$$

约 3.28M 参数。

如果：

```text
V = 100000
```

则：

$$
100000 \times 512 = 51.2M
$$

因此：

```text
小词表
→ 参数少
→ Token 序列长

大词表
→ Token 序列短
→ Embedding 参数多
```

<a id="origin-704"></a>
## 18. Decoder 是干什么的？

代码：

```python
tokenizer.decoder = decoders.ByteLevel()
```

编码：

```text
文本 → Token ID
```

称为 Encode。

解码：

```text
Token ID → 文本
```

称为 Decode。

例如：

```text
"我喜欢AI"
↓
[148, 283, 917]
```

再通过 Decoder：

```text
[148, 283, 917]
↓
"我喜欢AI"
```

## 20. tokenizer_config.json

重要配置：

```python

"eos_token": "<|im_end|>",

"model_max_length": 131072
```

| Token | 含义 |

| UNK | Unknown，未知内容 |
| `<\|im_start\|>` | 一条消息开始 |
| `<\|im_end\|>` | 一条消息结束 |

<a id="origin-1035"></a>
## 29. Tokenizer 压缩率

代码计算：

```python
compression_ratio = char_count / token_count
```

即：

$$
CompressionRatio =
\frac{\text{Characters}}
{\text{Tokens}}
$$

例如：

```text
Characters = 13
Tokens = 7
```

则：

$$
CompressionRatio =
\frac{13}{7}
\approx 1.86
$$

意思是：

> 平均 1 个 Token 表示约 1.86 个字符。

---

<a id="origin-1072"></a>
## 30. 为什么压缩率很重要？

Transformer 真正处理的是：

```text
Token 数
```

而不是字符数。

例如：

```text
Tokenizer A

1000 字
→
900 Tokens
```

Tokenizer B：

```text
1000 字
→
500 Tokens
```

Tokenizer B 会带来：

```text
更短序列
更低 Prefill 开销
更少 KV Cache 占用
更大的有效上下文
```

<a id="origin-1158"></a>
## 33. 为什么不能每生成一个 Token 就立即输出？

ByteLevel Tokenizer 处理的是 UTF-8 字节。

一个中文字符通常由多个 UTF-8 字节构成。

因此某个 Token 可能只包含：

```text
一个中文字符的一部分字节
```

如果立即解码，会出现：

```text
�
```

它就是：

```python
\ufffd
```

Unicode Replacement Character。

---

<a id="origin-1186"></a>
## 34. 为什么需要 token_cache？

假设字符“我”的 UTF-8 字节被分散到多个 Token：

```text
Token 1
→ E6

Token 2
→ 88

Token 3
→ 91
```

只有：

```text
E6 88 91
```

组合起来才能完整解码为：

```text
我
```

所以需要：

```text
收到 Token
   ↓
加入 token_cache
   ↓
尝试 Decode
   ↓
出现 � ?
  /     \
是       否
│        │
继续缓存  输出文本
         ↓
       清空缓存
```

<a id="origin-1233"></a>
## 35. Tokenizer 与模型训练的关系

完整输入链路：

```text
Raw Text
   ↓
Tokenizer
   ↓
Input IDs
   ↓
Embedding
   ↓
Transformer
   ↓
Logits
   ↓
预测 Next Token
```

例如：

```text
我 喜欢 自然 语言 处理
```

Tokenizer：

```text
[132, 825, 728, 391, 628]
```

训练时：

```text
输入：
[132, 825, 728, 391]

标签：
[825, 728, 391, 628]
```

语言模型学习：

$$
P(x_t \mid x_1,\ldots,x_{t-1})
$$

因此：

> **Tokenizer 决定了语言模型究竟在预测什么基本单位。**

<a id="origin-1287"></a>
## 36. Tokenizer 与 Embedding 的关系

假设：

```text
Vocabulary Size = 6400
Hidden Size = 512
```

Embedding Matrix：

$$
E \in \mathbb{R}^{6400 \times 512}
$$

一个 Token：

```text
Token ID = 153
```

模型执行：

```text
Embedding[153]
```

得到：

$$
x \in \mathbb{R}^{512}
$$

所以：

```text
"人工智能"
      ↓
Tokenizer
      ↓
Token ID = 153
      ↓
Embedding Table
      ↓
第153行
      ↓
512维向量
```

<a id="origin-1338"></a>
## 37. Tokenizer 与 KV Cache

Tokenizer 还会间接影响 KV Cache。

例如同一段文本：

```text
Tokenizer A
→ 1000 Tokens

Tokenizer B
→ 700 Tokens
```

Transformer 中每个历史 Token 都需要保存对应的 K、V。

因此：

```text
Token 数越多
      ↓
KV Cache Token 数越多
      ↓
KV Cache 占用越大
```

所以 Tokenizer 压缩率会间接影响：

```text
显存占用
Prefix 长度
Prefill 时间
KV Cache 大小
Serving 吞吐
```

## 38. 整份代码可以浓缩成四句话

<a id="origin-1378"></a>
### 38.1 第一句

Tokenizer 把：

```text
文本
```

转换成：

```text
Token ID
```

<a id="origin-1392"></a>
#### 38.1.1 第二句

MiniMind 使用：

```text
ByteLevel + BPE
```

ByteLevel 保证能表示各种 UTF-8 文本，BPE 通过高频合并减少 Token 数。

<a id="origin-1402"></a>
#### 38.1.2 第三句

除了普通 Token，还需要：

```text
BOS
EOS
PAD
Chat Token
Tool Token
Think Token
```

<a id="origin-1415"></a>
#### 38.1.3 第四句

训练完成后还必须验证：

```text
Chat Template
Encode / Decode
Compression Ratio
Streaming Decode
```

## 40. 本节重点问题

学完这一节后，至少应该能够回答：

1. Tokenizer 为什么是 LLM 必不可少的一部分？
2. Token 和 Token ID 有什么区别？
3. BPE 为什么要不断 Merge 高频 Token Pair？
4. ByteLevel 和 BPE 分别负责什么？
5. Vocabulary Size 为什么不能无限增大？
6. 为什么需要 `<|im_start|>` 和 `<|im_end|>`？
7. BOS、EOS、PAD 分别是什么意思？
8. Chat Template 有什么作用？
9. 为什么训练和推理必须使用相同的 Tokenizer？
10. 为什么 `Decode(Encode(x))` 应该尽量等于 $x$？
11. `Chars / Tokens` 为什么能衡量 Tokenizer 压缩效率？
12. 为什么一个中文字符可能不能由单个 ByteLevel Token 独立 Decode？
13. 为什么流式输出时需要 Token Buffer？
14. Tokenizer 为什么会间接影响 KV Cache 和推理效率？
