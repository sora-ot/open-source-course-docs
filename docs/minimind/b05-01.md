# 13 · SFT 与三种 Mask


> 核心问题：SFT 为什么只计算助手回答的 Loss？不计算用户问题的 Loss，模型还能看到用户问题吗？用户 Token 的 Q、K、V 还会参与训练吗？为什么改变 Loss 会改变梯度？

<a id="origin-5"></a>
## 1. SFT 在大模型训练流程中属于哪个阶段？

通常可以将训练划分为：

1. **预训练（Pre-training）**：通过海量文本学习下一个 Token 的预测，得到 **Base Model（基模）**。
2. **监督微调（SFT）**：使用指令及其答案进一步训练，让模型学习对话格式、指令跟随等能力。
3. **强化学习（RL，如 PPO、GRPO）**：根据奖励或优势等信号，进一步优化模型行为。

**严格按训练阶段划分，SFT 和 RL 都属于后训练（Post-training），不是预训练。**不过它们通常延续预训练得到的模型参数，并不是重新创建另一套 Transformer。

<a id="origin-15"></a>
## 2. SFT 为什么把用户问题部分的 Loss 屏蔽掉？

假设有一条训练样本（为方便理解，这里用词语代替真实的 Token）：

```text
用户：浙江大学在哪里？
助手：浙江大学在杭州。
```

模型的输入依然包含**整段对话**，但是用于计算 Loss 的目标（`labels`）大致是：

| 输入部分 | input_ids 是否保留 | labels | 是否作为预测目标计入 Loss |
|---|---|---|---|
| 用户问题 | 是 | -100 | 否 |
| 助手回答 | 是 | 对应的 Token ID | 是 |
| PAD 填充 | 通常保留占位 | -100 | 否 |

`-100` **不是把输入 Token 删掉，也不是把 Attention 设为 0，更不是把这个 Token 的 ID 改成 0**。它是 PyTorch 交叉熵函数的 `ignore_index` 标记：**忽略该位置作为预测目标的损失**。

**特别强调：这里说某个位置的 `Loss=0`，指的是该位置的损失被 Loss Mask 屏蔽、对总 Loss 的贡献为 0。这不代表后面的 Token 看不到前面的内容，也不代表后面 Token 的隐藏状态里没有前面内容的相关信息；它只是让该位置自身的预测损失不贡献梯度。前面的 Token 仍参与前向计算，后面助手回答的 Loss 仍可能通过 Attention 向前传播梯度，所以不能理解成“这个 Token 的隐藏状态和相关参数都没有梯度”。**

MiniMind 的 SFT 数据集核心逻辑可概括为：

```python
labels = [-100] * len(input_ids)  # 先忽略所有预测目标
# 找出 assistant 回复区间，把这一区间的 labels 恢复成对应 Token ID
```

在 Causal LM 中还有一个**错位对齐**，必须注意：

```python
x = logits[..., :-1, :]  # 位置 t 的输出
 y = labels[..., 1:]    # 监督位置 t+1 的目标 Token
loss = F.cross_entropy(
    x.reshape(-1, x.size(-1)),
    y.reshape(-1),
    ignore_index=-100
)
```

即：**前一个位置的输出预测后一个 Token**。预测第一个助手答案 Token 时，用的是紧挨着它之前的上下文位置输出，而不是把该答案 Token 本身作为输入后再预测自己。

<a id="origin-57"></a>
## 3. Loss Mask、Attention Mask、Causal Mask 是什么关系？

| 概念 | 控制什么 | 典型效果 |
|---|---|---|
| **Loss Mask（标签掩码）** | 哪些目标位置计算 Loss | 用户提问不算 Loss；助手回答算 Loss |
| **Attention Mask（注意力掩码）** | Query 可以关注哪些 Key 位置 | 屏蔽 PAD 或指定的注意力连接 |
| **Causal Mask（因果掩码）** | Attention Mask 的一种 | 当前位置只允许看到自己和过去，不允许看到未来 |

对于 `A B C D` 四个 Token，Causal Mask 的允许访问矩阵如下（行是 Query，列是 Key）：

```text
            Key: A  B  C  D
Query A          ✓  ×  ×  ×
      B          ✓  ✓  ×  ×
      C          ✓  ✓  ✓  ×
      D          ✓  ✓  ✓  ✓
```

实现思路：

```python
scores = Q @ K.transpose(-2, -1) / math.sqrt(d_k)
scores = scores.masked_fill(forbidden_positions, float('-inf'))
weights = torch.softmax(scores, dim=-1)
output = weights @ V
```

被设为 `-inf` 的注意力分数，经过 Softmax 后权重为 0（前提是该行仍至少有一个可关注的位置）。

**重要区别：**

- SFT 对用户问题应用 **Loss Mask**，不会阻止助手看到用户问题。
- 如果用 **Attention Mask** 专门禁止助手关注用户问题，那么对应的直接 Attention 路径才会断开。
- **Causal Mask 并不会屏蔽过去的用户问题**，因此助手仍可以利用用户问题的信息。
- 严格说，Attention Mask 屏蔽的是指定的注意力连接；在多层网络中，信息是否仍可能走其他路径，需要看整张计算图。

<a id="origin-93"></a>
## 4. 为什么用户 Token 不计算自己的 Loss，仍然能参与反向传播？

看如下信息流：

```text
用户：浙江大学在哪里？
        │
        │ 先计算它们的 Embedding、K、V 等
        ▼
助手预测：杭州
        │
        ▼
计算“杭州”的预测 Loss
        │
        ▼
Loss 对计算图反向传播
        │
        ├── 更新产生当前 Query 的 W_Q
        ├── 更新产生被关注 Key 的 W_K
        └── 更新产生被关注 Value 的 W_V
```

**一个 Token 不计算自己的预测 Loss，只表示它没有“直接作为监督目标”的梯度来源，不代表它不能作为后面预测的上下文，间接影响参数梯度。**

<a id="origin-117"></a>
## 5. 为什么 Loss 改了，梯度就改了？先把求导彻底算清楚

为了便于手算，先把实际的交叉熵简化为平方误差。设模型有一个共享可训练参数 `w`。

- **任务 1（用户部分）**：输出 `z_1=w`，目标为 `0`。
- **任务 2（助手部分）**：通过 Attention 等计算得到 `z_2=0.5w`，目标为 `1`。

两个位置的 Loss：

$$
L_1(w)=\frac12(w-0)^2=\frac12w^2
$$

$$
L_2(w)=\frac12(0.5w-1)^2
$$

<a id="origin-134"></a>
### 5.1 情况 A：SFT 忽略用户位置的 Loss

此时只有助手位置贡献 Loss：

$$
L_A(w)=L_2(w)=\frac12(0.5w-1)^2
$$

求梯度（链式法则）：

$$
\frac{\partial L_A}{\partial w}
=\frac12\cdot 2(0.5w-1)\cdot 0.5
=0.25w-0.5
$$

取当前参数 `w=1`：

$$
L_A(1)=0.125,\qquad \boxed{\frac{\partial L_A}{\partial w}=-0.25}
$$

**重点：用户位置自己的 Loss 虽然没算，但共享参数 `w` 仍然通过助手 Loss 收到了梯度 `-0.25`。**

<a id="origin-158"></a>
#### 5.1.1 情况 B：连用户位置的 Loss 也计算

这里为了突出梯度来源，采用**损失求和**而非求平均：

$$
L_B(w)=L_1(w)+L_2(w)
=\frac12w^2+\frac12(0.5w-1)^2
$$

逐项求导：

$$
\begin{aligned}
\frac{\partial L_B}{\partial w}
&=\frac{\partial L_1}{\partial w}+\frac{\partial L_2}{\partial w}\\
&=w+(0.25w-0.5)\\
&=1.25w-0.5
\end{aligned}
$$

当 `w=1`：

$$
L_B(1)=0.625,\qquad \boxed{\frac{\partial L_B}{\partial w}=0.75}
$$

<a id="origin-184"></a>
#### 5.1.2 对比：同一个参数为什么会朝相反方向更新？

学习率取 `η=0.1`，用 SGD 更新 `w_new=w-η∇L`：

| 情况 | Loss（w=1） | 梯度 | 更新后的 w |
|---|---:|---:|---:|
| 只计算助手 Loss | 0.125 | -0.25 | 1.025 |
| 用户和助手 Loss 都计算 | 0.625 | 0.75 | 0.925 |

**根本原因不是 Loss 数值从 0.125 变成 0.625，而是加入了新的函数项 `L_1(w)`，它对参数求导会额外贡献 `w`。**

反例：如果只是把 Loss 加一个与参数无关的常数 100：

$$
\frac{\partial [L_A(w)+100]}{\partial w}
=\frac{\partial L_A(w)}{\partial w}
$$

梯度完全不变！

真实 MiniMind 的交叉熵默认采用对**非忽略位置**求平均，所以改变掩码还可能改变归一化分母。上面特意用求和，是为了只观察“新增一个 Loss 项”带来的梯度变化，不把平均分母变化混进去。

<a id="origin-206"></a>
## 6. 回到 Transformer：屏蔽用户 Loss 后，W_Q、W_K、W_V 究竟谁会更新？

MiniMind 对一整段输入进行线性投影：

```python
xq = self.q_proj(x)  # W_Q
xk = self.k_proj(x)  # W_K
xv = self.v_proj(x)  # W_V
```

以一层 Attention 为例，当前助手位置 `t` 的输出：

$$
q_t=x_tW_Q,\quad k_j=x_jW_K,\quad v_j=x_jW_V
$$

$$
\alpha_{tj}=\operatorname{Softmax}_j\left(\frac{q_tk_j^T}{\sqrt{d_k}}\right),
\qquad o_t=\sum_{j\le t}\alpha_{tj}v_j
$$

只在后面答案位置计算 Loss，也依然可能更新：

- **`W_Q`**：助手当前位置的 `q_t` 决定关注哪些 Token，因此答案 Loss 可以更新它。
- **`W_K`**：用户 Token 的 `k_j` 决定被关注的权重，因此答案 Loss 可以更新它。
- **`W_V`**：用户 Token 的 `v_j` 直接贡献给 Attention 输出，因此答案 Loss 可以更新它。

**注意位置与参数的区别**：在单层 Attention 里，后面位置的 Loss 通常不会直接经过前面用户位置的 Query `q_j`；但是 `W_Q` 是所有位置共享的，因此仍会从助手当前位置的 `q_t` 获得梯度。多层 Transformer 还可能产生从后层回到前层用户位置 Query 的间接路径。

<a id="origin-235"></a>
## 7. 用真正的 QKV 注意力公式，给三个权重算出非零梯度

为了只研究 Attention 的梯度，把多头、RoPE、Norm、残差、输出投影、交叉熵等暂时略去；令 `d_k=1`。使用两维的 Token 输入：

$$
x_{user}=[1,0],\qquad x_{assistant}=[0,1]
$$

三个可训练投影权重（列向量表示）：

$$
W_Q=\begin{bmatrix}0\\\ln2\end{bmatrix},\quad
W_K=\begin{bmatrix}0\\1\end{bmatrix},\quad
W_V=\begin{bmatrix}3\\0\end{bmatrix}
$$

所以助手位置的 Query、两个位置的 K/V 是：

$$
q_a=\ln2\approx0.6931;\qquad
(k_u,k_a)=(0,1);\qquad (v_u,v_a)=(3,0)
$$

<a id="origin-258"></a>
### 7.1 第一步：前向 Attention

$$
\text{scores}=[q_ak_u,q_ak_a]=[0,\ln2]
$$

$$
(\alpha_u,\alpha_a)=\operatorname{Softmax}([0,\ln2])=(1/3,2/3)
$$

$$
z=\alpha_uv_u+\alpha_av_a=\frac13\times3+\frac23\times0=1
$$

假设**只对助手答案位置**计算一个简化平方误差，期望输出为 2：

$$
L=\frac12(z-2)^2=0.5,\qquad \frac{\partial L}{\partial z}=z-2=-1
$$

**没有计算用户位置自己的预测 Loss。**

<a id="origin-280"></a>
#### 7.1.1 第二步：V 的梯度

$$
\frac{\partial L}{\partial v_u}=
\frac{\partial L}{\partial z}\frac{\partial z}{\partial v_u}
=(-1)\times\frac13=\boxed{-1/3}
$$

$$
\frac{\partial L}{\partial v_a}=(-1)\times\frac23=\boxed{-2/3}
$$

因此：

$$
\boxed{\nabla_{W_V}L=[-1/3,-2/3]^T}
$$

<a id="origin-298"></a>
#### 7.1.2 第三步：K 的梯度

Softmax 对 score 的导数合并后有：

$$
\frac{\partial z}{\partial s_j}=\alpha_j(v_j-z)
$$

对于用户位置：

$$
\frac{\partial L}{\partial k_u}
=\underbrace{(z-2)}_{-1}
\underbrace{\alpha_u}_{1/3}
\underbrace{(v_u-z)}_{2}
\underbrace{q_a}_{\ln2}
=\boxed{-\frac23\ln2\approx-0.4621}
$$

同理：

$$
\frac{\partial L}{\partial k_a}=\boxed{+\frac23\ln2\approx+0.4621}
$$

因此：

$$
\boxed{\nabla_{W_K}L=[-0.4621,+0.4621]^T}
$$

<a id="origin-329"></a>
#### 7.1.3 第四步：Q 的梯度

由于 `s_j=q_a k_j`，有：

$$
\begin{aligned}
\frac{\partial L}{\partial q_a}
&=\frac{\partial L}{\partial s_u}k_u+
\frac{\partial L}{\partial s_a}k_a\\
&=(-2/3)\times0+(2/3)\times1\\
&=\boxed{2/3}
\end{aligned}
$$

因此：

$$
\boxed{\nabla_{W_Q}L=[0,2/3]^T}
$$

<a id="origin-349"></a>
#### 7.1.4 第五步：三个权重矩阵都可以更新

学习率取 `η=0.1`，使用 SGD：

| 权重 | 初始值 | 仅由助手 Loss 产生的梯度 | 一步更新后 |
|---|---|---|---|
| `W_Q` | `[0, 0.6931]` | `[0, +0.6667]` | `[0, 0.6265]` |
| `W_K` | `[0, 1]` | `[-0.4621, +0.4621]` | `[0.0462, 0.9538]` |
| `W_V` | `[3, 0]` | `[-0.3333, -0.6667]` | `[3.0333, 0.0667]` |

这就是最直接的数值证明：**即使用户 Token 不计算自身的预测 Loss，用户的 K/V 仍参与了助手预测，W_Q、W_K、W_V 三个共享投影权重仍可能全部发生变化。**

但要注意“**可能**”：在其他样本、其他具体数值下，一些梯度可能恰好为 0，或者因梯度抵消而变为 0；不能说三个矩阵的每个元素、每一步都必然变化。

## 8. 在 PyTorch 中亲自验证（可直接运行）

下面是独立的最简 Attention 实验，不需要下载 MiniMind 权重：

```python
import math
import torch

x = torch.eye(2)   # 两个 Token：[1,0] 和 [0,1]
W_Q = torch.tensor([[0.0], [math.log(2)]], requires_grad=True)
W_K = torch.tensor([[0.0], [1.0]], requires_grad=True)
W_V = torch.tensor([[3.0], [0.0]], requires_grad=True)

Q, K, V = x @ W_Q, x @ W_K, x @ W_V
scores = Q @ K.T  # d_k=1，无需缩放
causal_mask = torch.triu(torch.ones(2, 2, dtype=torch.bool), diagonal=1)
scores = scores.masked_fill(causal_mask, float('-inf'))
weights = torch.softmax(scores, dim=-1)
out = weights @ V

# 只使用助手位置（下标 1）的 Loss；用户位置的 Loss 完全不算
loss = 0.5 * (out[1, 0] - 2.0) ** 2
loss.backward()

print('Loss:', loss.item())
print('W_Q grad:', W_Q.grad.flatten().tolist())
print('W_K grad:', W_K.grad.flatten().tolist())
print('W_V grad:', W_V.grad.flatten().tolist())
```

预期结果（允许浮点误差）：

```text
Loss: 0.5
W_Q grad: [0.0, 0.6667]
W_K grad: [-0.4621, 0.4621]
W_V grad: [-0.3333, -0.6667]
```

真实 MiniMind 使用 CrossEntropy、更多层和更多 Attention Head，并可能使用 GQA、RoPE、Norm、残差与 AdamW；上面的实验不是完整 MiniMind，而是**隔离验证其 Attention 反向传播机制**。

## 9. 用公式总结 SFT 的“屏蔽”究竟去掉了什么

设 `m_t=1` 表示第 `t` 个**目标 Token**参与监督，`m_t=0` 表示不参与监督。为简洁起见，只写交叉熵损失：

$$
L(\theta)=\frac{1}{\sum_t m_t}\sum_t m_t\,\ell_t(\theta)
$$

于是：

$$
\boxed{
\nabla_{\theta}L
=\frac{1}{\sum_t m_t}\sum_t m_t\,\nabla_{\theta}\ell_t
}
$$

用户目标位置的 `m_t=0`，**删除的是这一位置作为监督目标时的损失项及其梯度贡献**。助手目标位置的 `m_t=1`，它的 Loss 仍通过完整的因果 Attention 计算图求导，能够涉及前面的用户 Token 和共享权重。

因此，不能把下面三件事混为一谈：

1. `labels[t]=-100`：忽略该位置作为**预测目标**的交叉熵。
2. `attention_mask` 屏蔽指定连接：禁止某个 Query **通过该连接**使用某个 Key/Value。
3. 冻结模型参数（例如 `requires_grad=False`）：使该参数本身**不接收用于更新的梯度**。

<a id="origin-429"></a>
## 10. 最终记住这六句话

1. **SFT 属于后训练；基模通常来自预训练。**
2. **SFT 的 `labels=-100` 是 Loss Mask，不是 Attention Mask。**
3. **Causal Mask 属于 Attention Mask，禁止看未来，但允许看过去的用户问题。**
4. **不计算某个 Token 自身的预测 Loss，不等于删除它的 Embedding/K/V，也不等于冻结 QKV。**
5. **Loss 变化是否让梯度变化，取决于新增或删去的函数项对参数的导数；不是简单由 Loss 数值大小决定。**
6. **只计算助手回答的 Loss，也可以通过 Attention 更新共享的 `W_Q、W_K、W_V`。**
