# 54 · Reward Model：偏好损失、梯度与评分尺度

<a id="origin-2707"></a>
## 1. 第二部分：Reward Model 到底是怎么训练出来的？

下面真正把它掰开来讲。

---

<a id="origin-2713"></a>
## 2. 第一阶段：Reward Model 的数据到底是什么？（重点）

假设数据：

```json
{
  "chosen": [
    {
      "role": "user",
      "content": "太阳从哪里升起？"
    },
    {
      "role": "assistant",
      "content": "太阳从东方升起。"
    }
  ],

  "rejected": [
    {
      "role": "user",
      "content": "太阳从哪里升起？"
    },
    {
      "role": "assistant",
      "content": "太阳从西方升起。"
    }
  ]
}
```

注意：

Reward Model 数据不是：

```text
Question → Correct Answer
```

而是：

```text
相同上下文

       ┌─ Answer A：更好
Prompt
       └─ Answer B：更差
```

---

<a id="origin-2763"></a>
## 3. 为什么必须是相同 Prompt？

因为我们的监督信号：

$$
r_c>r_r
$$

想表达：

> 对于**同一个问题**，回答 A 比回答 B 好。

如果：

```text
chosen：
1+1？ → 2

rejected：
法国首都？ → 伦敦
```

然后要求：

```text
chosen > rejected
```

根本不知道究竟比较的是什么。

因此代码检查：

```python
chosen[:-1] == rejected[:-1]
```

也就是：

```text
除了最后一个 assistant 回答
历史必须完全相同。
```

---

<a id="origin-2808"></a>
## 4. 为什么 `[:-1]`？（重点）

假设：

```text
chosen =

[
 user: Q1
 assistant: A1
 user: Q2
 assistant: 好答案
]
```

```text
rejected =

[
 user: Q1
 assistant: A1
 user: Q2
 assistant: 差答案
]
```

最后一条：

```text
最终 Answer
```

不同。

但是前面：

```text
Q1
A1
Q2
```

**必须一致。
**
所以：

```python
chosen[:-1]
rejected[:-1]
```

就是：

```text
去掉最后回答以后比较历史。
```

---

<a id="origin-2867"></a>
## 5. 第二阶段：把两条对话转换成 Token

假设：

```text
Prompt：
1+1?

chosen：
2

rejected：
5
```

为了方便教学，假设 Tokenize 后：

```text
chosen:

[1,10,20,2]
```

```text
rejected:

[1,10,21,2]
```

可以理解：

```text
1  = 开始/角色标记
10 = Prompt
20 = chosen answer
21 = rejected answer
2  = EOS
```

真实 MiniMind Tokenizer 当然不会这么简单。

---

<a id="origin-2910"></a>
## 6. 第三阶段：Batch 如何组织？

假设：

```text
B=2
```

也就是有两个偏好对：

```text
Pair 0：
c0
r0

Pair 1：
c1
r1
```

程序组织成：

```text
[
 c0,
 c1,
 r0,
 r1
]
```

所以真正 Transformer 输入数量：

$$
N=2B
$$

如果：

```text
batch_size=32
```

意味着：

```text
32 对
```

实际上前向：

```text
64 条序列。
```

---

<a id="origin-2967"></a>
## 7. 第四阶段：Reward Model **的模型结构**

这个 Reward Model 本质：

```text
MiniMind Backbone
+
Linear Reward Head
```

即：

```text
Token IDs

   ↓

Embedding

   ↓

Transformer Block 1

   ↓

Transformer Block 2

   ↓

...

   ↓

Transformer Block L

   ↓

Hidden States
[N,T,H]

   ↓

最后真实 Token
[N,H]

   ↓

Linear(H,1)

   ↓

Reward
[N]
```

---

<a id="origin-3024"></a>
## 8. 和普通语言模型差在哪里？

普通 Causal LM：

```text
Hidden State
    ↓
LM Head
    ↓
Vocabulary logits
```

如果：

```text
Vocab = 6400
```

每个位置：

```text
H → 6400
```

输出：

```text
下一个 Token 的概率。
```

Reward Model：

```text
Hidden State
    ↓
Reward Head
    ↓
1 个数字
```

：

```text
H → 1
```

不生成 Token。

---

<a id="origin-3074"></a>
## 9. 第五阶段：为什么首先加载 SFT 模型？

默认程序加载：

```text
full_sft_768.pth
```

这一点很重要。

想象一个完全随机 Transformer：

```text
"1+1等于2"

和

"1+1等于香蕉"
```

它连文字语义都不知道。

Reward Model 训练数据通常远小于语言模型预训练数据。

所以更加合理的是：

```text
已经会语言的 SFT Model

        ↓

拿掉 LM Head

        ↓

加 Reward Head

        ↓

训练 Preference
```

因此：

```text
SFT
已经学会“理解文本”

Reward Training
进一步学会“什么回答更好”
```

<a id="origin-3128"></a>
## 10. SFT 哪些参数被加载？

原来的 SFT State Dict 可能：

```text
model.embed_tokens.weight

model.layers.0....

model.layers.1....

...

lm_head.weight
```

程序：

```python
backbone = {
    k[len("model."):]: v
    for k,v in weights.items()
    if k.startswith("model.")
}
```

只选：

```text
model.*
```

也就是说：

```text
MiniMind Backbone
```

被拿出来。

而：

```text
lm_head.weight
```

不会加载。

然后：

```python
model.model.load_state_dict(backbone)
```

加载进 Reward Model 的 Backbone。

具体实现见文件。

<a id="origin-3188"></a>
## 11. 所以训练开始时是什么状态？

可以理解成：

```text
MiniMind Backbone：

已经经过 SFT
懂语言、懂问题、懂回答


Reward Head：

随机初始化
还不知道什么叫“好”
```

然后 Preference Dataset 开始教它：

```text
这种 Hidden State → 分数应该更高

那种 Hidden State → 分数应该更低
```

与此同时：

> Backbone 也会继续调整。

<a id="origin-3219"></a>
## 12. 第六阶段：Transformer 得到什么？

假设：

```text
N=4
T=6
H=768
```

输入：

```text
input_ids.shape

[4,6]
```

进入 MiniMind：

```python
hidden, _, aux_loss =
    self.model(...)
```

得到：

```text
hidden.shape

[4,6,768]
```

什么意思？

4 条句子。

每条 6 个 Token。

每个 Token：

```text
768 维 Hidden State。
```

---

<a id="origin-3266"></a>
## 13. 举一条序列

比如：

```text
用户
：
1+1
？
助手
：
2
<EOS>
```

每一个位置都有：

$$
h_1,h_2,\dots,h_T
$$

其中：

$$
h_T\in\mathbb R^{768}
$$

因为 Transformer 是 Decoder-only 因果注意力：

$$
h_T
$$

能够看到：

$$
x_1,x_2,\dots,x_T
$$

所以：

```text
h_T
```

不是只代表：

```text
EOS
```

它实际上已经融合：

```text
Prompt + Answer
```

的信息。

<a id="origin-3327"></a>
## 14. 第七阶段：Reward Head 怎么打分？

假设为了手算：

```text
H=4
```

最后 Hidden State：

$$
h=
[2,0,0,0]
$$

Reward Head：

$$
w=
[0.5,-0.5,0.25,0]
$$

那么：

$$
r=w h
$$

：

$$
r=
2\times0.5
+0\times(-0.5)
+0\times0.25
+0\times0
$$

得到：

$$
r=1
$$

于是这个完整回答：

```text
Reward = 1
```

---

<a id="origin-3379"></a>
## 15. 这是不是概率？

不是。

Reward 可以：

```text
10

2

0

-1

-100
```

没有要求：

$$
0\le r\le1
$$

所以：

```text
reward = 0.9
```

不能解释成：

```text
90% 是好答案。
```

这是一个：

```text
未校准标量。
```

<a id="origin-3423"></a>
## 16. 第八阶段：Chosen 和 Rejected 分数

假设一个 Batch：

```text
B=2
```

前向得到：

```text
scores =

[
 1.0,
 0.0,
-1.0,
 1.0
]
```

因为排列：

```text
[c0,c1,r0,r1]
```

所以：

```python
chosen, rejected = scores.chunk(2)
```

得到：

```text
chosen =
[1.0,0.0]
```

```text
rejected =
[-1.0,1.0]
```

因此：

第一对：

```text
chosen = 1
rejected = -1
```

第二对：

```text
chosen = 0
rejected = 1
```

<a id="origin-3486"></a>
## 17. 第九阶段：真正核心的 Reward Model 数学

我们并没有：

```text
chosen 的正确 Reward 标签
rejected 的正确 Reward 标签
```

只有：

```text
chosen 应该 > rejected
```

所以首先计算：

$$
\Delta=r_c-r_r
$$

---

<a id="origin-3509"></a>
### 17.1 第一对

$$
r_c=1
$$

$$
r_r=-1
$$

因此：

$$
\Delta=2
$$

---

<a id="origin-3527"></a>
### 17.2 第二对

$$
r_c=0
$$

$$
r_r=1
$$

因此：

$$
\Delta=-1
$$

---

<a id="origin-3545"></a>
## 18. 为什么用 Sigmoid？

定义：

$$
P(c\succ r)
=
\sigma(r_c-r_r)
$$

其中：

$$
\sigma(x)
=
\frac1{1+e^{-x}}
$$

它可以理解为：

> Reward Model 认为 chosen 胜过 rejected 的概率。

注意：

这里：

```text
Reward 本身不是概率
```

但是：

```text
Reward 差经过 Sigmoid
```

可以作为 Pairwise Preference Probability。

---

<a id="origin-3585"></a>
## 19. 第一对

$$
\Delta=2
$$

所以：

$$
\sigma(2)
=
\frac1{1+e^{-2}}
\approx0.8808
$$

意思：

```text
模型认为 chosen 比 rejected 好的概率约 88.08%
```

---

<a id="origin-3608"></a>
## 20. 第二对

$$
\Delta=-1
$$

：

$$
\sigma(-1)
\approx0.2689
$$

意思：

```text
模型只认为 chosen 有 26.89% 概率比 rejected 好。
```

说明当前模型：

```text
排反了。
```

---

<a id="origin-3635"></a>
## 21. 为什么 Loss 是负对数？

我们的标签永远是：

```text
chosen 胜出
```

也就是目标概率：

```text
1
```

因此采用 Negative Log Likelihood：

$$
L
=
-\log P(c\succ r)
$$

**$\succ$代表“优于”，** 代入：

$$
P(c\succ r)=
\sigma(r_c-r_r)
$$

得到：

$$
\boxed{
L=
-\log\sigma(r_c-r_r)
}
$$

这就是 Reward Model 最核心的公式。

代码正是：

```python
ranking_loss = -F.logsigmoid(
    chosen.float() - rejected.float()
).mean()
```

$$

于是：

$$
\Delta=0
$$

$$
\sigma(0)=0.5
$$

模型相当于：

```text
完全不知道哪一个好。
```

<a id="origin-3766"></a>
## 24. 情况 3：模型排反了

$$
r_c=0
$$

$$
r_r=2
$$

所以：

$$
\Delta=-2
$$

$$
\sigma(-2)=0.119
$$

Loss：

$$
-\log0.119
\approx2.127
$$

Loss 很大。

说明：

```text
不仅没区分出来，而且还反着排。
```

<a id="origin-3805"></a>
## 25. 这个 Loss 到底想做什么？

目标就是：

$$
r_c-r_r
$$

越来越大。

也就是：

```text
chosen 分高一点
rejected 分低一点
```

更准确地说：

```text
把二者的差拉大。
```

---

<a id="origin-3830"></a>
## 26. 从求导彻底看懂

定义：

$$
\Delta=r_c-r_r
$$

Loss：

$$
L=-\log\sigma(\Delta)
$$

它可以化成：

$$
L=\log(1+e^{-\Delta})
$$

对 $\Delta$ 求导：

$$
\frac{\partial L}{\partial\Delta}
=
\sigma(\Delta)-1
$$

---

<a id="origin-3860"></a>
## 27. 假设两个分数一样

$$
r_c=0
$$

$$
r_r=0
$$

所以：

$$
\Delta=0
$$

$$
\sigma(0)=0.5
$$

于是：

$$
\frac{\partial L}{\partial\Delta}
=
0.5-1
=
-0.5
$$

梯度下降：

$$
\Delta_{\text{new}}
=
\Delta
-
\eta(-0.5)
$$

：

$$
\Delta_{\text{new}}
=
\Delta
+
0.5\eta
$$

所以：

$$
\Delta
$$

会增大。

这正是我们想要的。

---

<a id="origin-3922"></a>
## 28. 分别对 chosen 和 rejected 求导

因为：

$$
\Delta=r_c-r_r
$$

所以：

$$
\frac{\partial\Delta}{\partial r_c}=1
$$

：

$$
\boxed{
\frac{\partial L}{\partial r_c}
=
\sigma(\Delta)-1
}
$$

而：

$$
\frac{\partial\Delta}{\partial r_r}=-1
$$

所以：

$$
\boxed{
\frac{\partial L}{\partial r_r}
=
1-\sigma(\Delta)
}
$$

---

<a id="origin-3964"></a>
## 29. 还是用两个分数相等的情况

$$
\Delta=0
$$

：

$$
\sigma(0)=0.5
$$

所以：

$$
\frac{\partial L}{\partial r_c}
=
-0.5
$$

$$
\frac{\partial L}{\partial r_r}
=
+0.5
$$

梯度下降：

Chosen：

$$
r_c'
=
r_c-\eta(-0.5)
$$

：

$$
r_c'=r_c+0.5\eta
$$

也就是：

```text
chosen 上升。
```

Rejected：

$$
r_r'
=
r_r-\eta(0.5)
$$

：

$$
r_r'=r_r-0.5\eta
$$

也就是：

```text
rejected 下降。
```

于是二者分开。

---

<a id="origin-4036"></a>
## 30. 这就是 Reward Model 训练的核心

可以把整个 Reward Training 理解成：

```text
人工：
这个好
这个差

     ↓

Reward Model：
给两个答案各自打分

     ↓

比较：
你现在有没有让好答案 > 差答案？

     ↓

如果没有：
调整模型

     ↓

让：
chosen ↑
rejected ↓

或者至少：
chosen - rejected ↑
```

---

<a id="origin-4072"></a>
## 31. Reward Head 是怎么被更新的？

Reward：

$$
r=w^Th
$$

Chosen：

$$
r_c=w^Th_c
$$

Rejected：

$$
r_r=w^Th_r
$$

因此：

$$
\Delta
=
w^T(h_c-h_r)
$$

设：

$$
g=
\frac{\partial L}{\partial\Delta}
$$

则：

$$
\boxed{
\frac{\partial L}{\partial w}
=
g(h_c-h_r)
}
$$

这句话非常重要。

Reward Head 实际学习：

> **哪些 Hidden-State 特征能够区分好回答与差回答。**

---

<a id="origin-4125"></a>
## 32. 一个最简单的数值例子

假设：

$$
h_c=
[2,1]
$$

$$
h_r=
[0,1]
$$

初始：

$$
w=
[0,0]
$$

因此：

$$
r_c=0
$$

：

$$
r_r=0
$$

：

$$
\Delta=0
$$

因此：

$$
g=-0.5
$$

而：

$$
h_c-h_r
=
[2,0]
$$

所以：

$$
\frac{\partial L}{\partial w}
=
-0.5[2,0]
$$

：

$$
[-1,0]
$$

如果：

$$
\eta=0.1
$$

梯度下降：

$$
w'
=
w-\eta\nabla w
$$

：

$$
w'
=
[0,0]-0.1[-1,0]
$$

：

$$
w'=[0.1,0]
$$

重新评分：

Chosen：

$$
r_c
=
0.1\times2
=
0.2
$$

Rejected：

$$
r_r
=
0.1\times0
=
0
$$

于是：

$$
r_c>r_r
$$

模型学会：

```text
Hidden State 第一维出现这种特征，
可能意味着这是更好的回答。
```

---

<a id="origin-4257"></a>
## 33. 那为什么 Backbone 也会更新？

因为：

$$
r=w^Th
$$

Reward Head 的输入：

$$
h
$$

不是固定特征。

它来自：

```text
Transformer。
```

所以：

$$
L
\rightarrow
r
\rightarrow
h
\rightarrow
Transformer
$$

梯度还会继续传播。

---

<a id="origin-4295"></a>
## 34. 对 Hidden State 的梯度

Chosen：

$$
r_c=w^Th_c
$$

因此：

$$
\frac{\partial r_c}{\partial h_c}
=
w
$$

于是：

$$
\frac{\partial L}{\partial h_c}
=
\frac{\partial L}{\partial r_c}w
$$

Rejected 同样：

$$
\frac{\partial L}{\partial h_r}
=
\frac{\partial L}{\partial r_r}w
$$

然后：

```text
Hidden State
↓
Transformer 最后一层
↓
上一层
↓
...
↓
Embedding
```

梯度一路往前传播。

---

<a id="origin-4345"></a>
## 35. 所以 Reward Model 不是：

```text
固定 SFT
+
训练一个简单 Linear
```

这个程序实际上是：

```text
SFT 参数作为初始化

         ↓

Reward Head 随机初始化

         ↓

整个模型一起训练
```

因此：

```text
Attention 参数会变
FFN 参数会变
Embedding 会变
Norm 会变
Reward Head 会变
```

---

<a id="origin-4379"></a>
## 36. 为什么这样训练后模型能够知道“答案好不好”？

因为大量数据不断提供：

```text
这种回答 > 那种回答
```

例如：

```text
正确回答 > 错误回答

完整回答 > 答非所问

安全回答 > 危险回答

遵循指令 > 不遵循指令

有事实依据 > 胡编乱造
```

如果训练数据里真的包含这些偏好，

模型就会逐渐调整：

```text
Hidden Representation
```

和：

```text
Reward Head
```

使得这些回答之间出现稳定的 Score 差异。

<a id="origin-5448"></a>
## 55. Reward Model 的输出为什么可以是无界标量（重点）？

<a id="origin-5450"></a>
## 56. 问题

Reward Model 最后输出的是一个标量：

$$
r = R_\theta(x,y)
$$

例如：

```text
回答 A：reward = 2.3
回答 B：reward = -0.7
```

这个分数通常没有经过 `sigmoid` 或 `tanh`，所以理论上：

$$
r \in (-\infty,+\infty)
$$

于是自然会产生一个问题：

> 如果 Reward 可以无限大或者无限小，会不会导致训练出问题？

答案是：

> **理论上确实存在把分数差不断拉大的趋势，但随着 chosen 和 rejected 已经被明显区分，梯度会迅速趋近于 0。真正需要注意的是：Pairwise Reward Model 只约束相对大小，并没有定义 Reward 的绝对标尺。**

---

<a id="origin-5481"></a>
## 57. Reward Model 真正优化的不是单个 Reward，而是分数差

Pairwise Reward Model 的损失通常为：

$$
L
=
-\log \sigma(r_c-r_r)
$$

其中：

- $r_c$：chosen 的 Reward
- $r_r$：rejected 的 Reward

定义：

$$
\Delta = r_c-r_r
$$

于是：

$$
L=-\log\sigma(\Delta)
$$

因此训练真正关心的是：

$$
\boxed{r_c-r_r}
$$

而不是：

$$
r_c
$$

或者：

$$
r_r
$$

各自到底应该是多少。

---

<a id="origin-5530"></a>
## 58. 为什么确实存在“把差距越拉越大”的趋势？

例如：

$$
r_c=2,\qquad r_r=0
$$

那么：

$$
\Delta=2
$$

于是：

$$
\sigma(2)\approx0.881
$$

Loss：

$$
L=-\log(0.881)\approx0.127
$$

如果进一步变成：

$$
r_c=10,\qquad r_r=-10
$$

那么：

$$
\Delta=20
$$

此时：

$$
\sigma(20)\approx1
$$

所以：

$$
L\approx0
$$

也就是说，从纯数学目标看：

```text
chosen 比 rejected 高一点
```

虽然已经正确，但是：

```text
chosen 比 rejected 高很多
```

Loss 会更低。

因此 Pairwise Loss 确实存在：

$$
\boxed{\text{不断增大 }r_c-r_r\text{ 的倾向}}
$$

---

<a id="origin-5602"></a>
## 59. 那为什么实际不会一直疯狂涨到无穷大？

关键要看梯度。

对于：

$$
L=-\log\sigma(\Delta)
$$

有：

$$
\frac{\partial L}{\partial \Delta}
=
\sigma(\Delta)-1
$$

也可以写成：

$$
\frac{\partial L}{\partial \Delta}
=
-\sigma(-\Delta)
$$

看几个数值：

| $\Delta=r_c-r_r$ | $\sigma(\Delta)$ | $\frac{\partial L}{\partial \Delta}$ |
|---:|---:|---:|
| 0 | 0.5000 | -0.5000 |
| 2 | 0.8808 | -0.1192 |
| 5 | 0.9933 | -0.0067 |
| 10 | 0.99995 | -0.000045 |
| 20 | 接近 1 | 接近 0 |

可以看到：

```text
分差小
↓
梯度大
↓
模型努力把 chosen 和 rejected 拉开
```

但是：

```text
分差已经很大
↓
梯度接近 0
↓
模型几乎不再继续推动这个样本
```

所以 Logistic / Bradley–Terry Loss 本身具有一种“软刹车”。

---

<a id="origin-5662"></a>
## 60. 例如：两个分数相等时

假设：

$$
r_c=0
$$

$$
r_r=0
$$

所以：

$$
\Delta=0
$$

此时：

$$
\sigma(0)=0.5
$$

因此：

$$
\frac{\partial L}{\partial \Delta}
=
0.5-1
=
-0.5
$$

梯度还很大。

模型会明显推动：

$$
r_c-r_r
$$

增大。

---

<a id="origin-5708"></a>
## 61. 但如果已经分得很开

例如：

$$
r_c=10
$$

$$
r_r=0
$$

则：

$$
\Delta=10
$$

：

$$
\frac{\partial L}{\partial \Delta}
\approx -0.000045
$$

几乎已经没有梯度。

可以理解成模型在说：

> 这个样本我已经非常确定 chosen 更好了，没有必要继续使劲拉开。

---

<a id="origin-5741"></a>
## 62. 更重要的问题：Reward 的绝对值其实没有意义

例如下面三组分数：

<a id="origin-5745"></a>
### 62.1 第一组

$$
r_c=2,\qquad r_r=0
$$

<a id="origin-5751"></a>
### 62.2 第二组

$$
r_c=102,\qquad r_r=100
$$

<a id="origin-5757"></a>
### 62.3 第三组

$$
r_c=-998,\qquad r_r=-1000
$$

三者都有：

$$
r_c-r_r=2
$$

因此：

$$
L=-\log\sigma(2)
$$

完全一样。

所以 Reward Model 根本没有学到：

```text
0 分应该代表什么
10 分应该代表什么
100 分应该代表什么
```

它只学到了：

$$
\boxed{\text{谁应该排在谁前面}}
$$

---

<a id="origin-5793"></a>
## 63. 因此 Reward 的“零点”是不确定的

例如：

```text
chosen = 2
rejected = 0
```

如果全部加 100：

```text
chosen = 102
rejected = 100
```

分差：

$$
102-100=2
$$

还是一样。

所以：

$$
\boxed{R(x,y)\rightarrow R(x,y)+C}
$$

不会改变 Pairwise Loss。

也就是说：

> **Reward 的绝对零点没有被 Pairwise Training 定义。**

---

<a id="origin-5831"></a>
## 64. Reward 的尺度也不是天然的“标准分”

例如：

```text
模型 A：

chosen = 2
rejected = 0
```

而另一个模型：

```text
模型 B：

chosen = 20
rejected = 0
```

不能说：

> 模型 B 认为这个回答比模型 A 好 10 倍。

因为不同 Reward Model 的分数尺度本来就可能完全不同。

所以 Reward 更适合解释成：

```text
模型内部的相对偏好分数
```

而不是：

```text
有固定单位的绝对质量分数
```

---

<a id="origin-5871"></a>
## 65. 为什么不直接在 Reward Head 后面加 sigmoid？

例如把：

$$
r=W^Th
$$

改成：

$$
r=\sigma(W^Th)
$$

这样 Reward 就被限制在：

$$
0<r<1
$$

看起来好像更加安全。

但是会出现问题。

因为 Reward Model 后面的 Pairwise Probability 又定义为：

$$
P(c\succ r)
=
\sigma(r_c-r_r)
$$

如果：

$$
0<r_c<1
$$

且：

$$
0<r_r<1
$$

那么最大的分差也只能接近：

$$
1-0=1
$$

于是最大的偏好概率只能接近：

$$
\sigma(1)
\approx0.731
$$

也就是说，即使模型极其确定：

```text
chosen 远远好于 rejected
```

最多也只能表达大约：

$$
73.1\%
$$

这就把模型表达能力限制得太死。

所以 Reward Head 通常直接输出：

$$
\boxed{(-\infty,+\infty)}
$$

范围内的实数。

---

<a id="origin-5952"></a>
## 66. Reward Head 后面为什么通常没有 sigmoid？

普通分类模型：

```text
logit
↓
sigmoid
↓
0~1 概率
```

但 Reward Model 不一样。

Reward 本身只是：

```text
一个 logit / score
```

真正变成“chosen 胜出的概率”的地方是：

$$
\boxed{
P(c\succ r)
=
\sigma(r_c-r_r)
}
$$

所以 sigmoid 用在：

```text
两个 Reward 的差
```

而不是：

```text
单个 Reward
```

上。

---

<a id="origin-5998"></a>
## 67. 从数学上看，它确实存在参数变大的可能

假设训练数据完全可以被模型正确分开。

只要：

$$
r_c>r_r
$$

那么把分差继续放大：

$$
r_c-r_r
\rightarrow+\infty
$$

就可以让：

$$
L\rightarrow0
$$

因此在理想化数学情况下，确实可能出现：

$$
\|W\|\rightarrow\infty
$$

的趋势。

这和 Logistic Regression 在完全线性可分数据上的现象很相似。

但是：

$$
r_c-r_r
$$

越大，梯度就越接近 0，所以这种增长会越来越慢。

---

<a id="origin-6041"></a>
## 68. 这份 `train_reward.py` 里还有两个机制帮助稳定训练

<a id="origin-6043"></a>
### 68.1 AdamW 的 Weight Decay

代码使用：

```python
optimizer = torch.optim.AdamW(
    model.parameters(),
    lr=args.learning_rate
)
```

AdamW 带有 Weight Decay。

可以理解成：

```text
参数变得太大
↓
会受到一定惩罚
```

因此能够在一定程度上抑制：

$$
\|W\|
$$

无限增大。

---

<a id="origin-6074"></a>
### 68.2 Gradient Clipping

代码：

```python
nn.utils.clip_grad_norm_(
    model.parameters(),
    1.0
)
```

表示：

```text
如果这一轮所有参数梯度的整体范数 > 1
↓
把梯度统一缩小
```

例如：

$$
\|\nabla\|=5
$$

可能整体缩放成：

$$
\|\nabla\|=1
$$

注意：

> Gradient Clipping 限制的是梯度大小，不是 Reward 本身。

所以它主要防止：

```text
某一次更新突然非常大
```

而不是直接限制：

```text
Reward ∈ [-10,10]
```

---

<a id="origin-6123"></a>
## 69. 真正需要特别注意的是：Reward 给 PPO 使用的时候

如果 Reward Model 只是用来：

```text
比较回答 A 和 B 哪个更好
```

那么：

```text
A = 2
B = 0
```

和：

```text
A = 102
B = 100
```

其实差别不大。

因为都是：

$$
A-B=2
$$

但是 PPO 会把 Reward 真正放进强化学习计算。

例如：

```text
Reward
↓
Return
↓
Advantage
↓
PPO Loss
↓
Policy Gradient
```

如果 Reward 的尺度突然特别大：

```text
正常：

Reward = 2
```

变成：

```text
Reward = 2000
```

那么：

```text
Return 变大
↓
Advantage 变大
↓
Policy Gradient 可能变大
↓
Policy 更新过猛
```

所以 PPO 阶段通常还需要特别处理 Reward 的尺度。

---

<a id="origin-6199"></a>
## 70. PPO 中常见的稳定手段

例如：

```text
Reward Normalization
```

把 Reward 调整到相对稳定的分布。

或者：

```text
Reward Scaling
```

人为乘一个缩放系数。

或者：

```text
Reward Clipping
```

限制极端奖励。

另外还有：

```text
KL Penalty
```

防止 Policy 为了追求 Reward：

```text
疯狂偏离原来的 Reference Model
```

以及：

```text
Advantage Normalization
```

控制 PPO 最终真正使用的 Advantage 的尺度。

---

<a id="origin-6247"></a>
## 71. 一个很好理解的类比：温度计

可以把 Reward Model 想象成一个：

```text
只学习相对冷热关系的温度计
```

训练数据只告诉它：

```text
A 比 B 热

C 比 A 热

D 比 C 冷
```

却从来没有告诉它：

```text
A = 30℃
B = 20℃
```

所以它可能学成：

```text
A = 2
B = 0
```

也可能：

```text
A = 102
B = 100
```

只要：

```text
A > B
```

并且分差合适，

Pairwise Loss 就满意。

因此：

$$
\boxed{\text{Reward Model 学的是顺序，而不是绝对刻度}}
$$

---

<a id="origin-6304"></a>
## 72. 最核心的一句话

Reward Model 的输出虽然是：

$$
\boxed{r\in(-\infty,+\infty)}
$$

但是 Pairwise Training 真正优化的是：

$$
\boxed{r_c-r_r}
$$

而不是单独优化：

$$
r_c\rightarrow+\infty
$$

或者：

$$
r_r\rightarrow-\infty
$$

同时，当：

$$
r_c-r_r
$$

已经足够大之后：

$$
\boxed{
\frac{\partial L}{\partial(r_c-r_r)}
\rightarrow0
}
$$

所以继续拉大分差的动力会迅速减弱。

---

<a id="origin-6349"></a>
## 73. 最终总结

Reward Model：

$$
R_\theta(x,y)
$$

输出一个无界标量：

$$
R_\theta(x,y)\in\mathbb R
$$

Pairwise Loss：

$$
\boxed{
L
=
-\log
\sigma(
r_c-r_r
)
}
$$

它只要求：

$$
\boxed{
r_c>r_r
}
$$

并希望二者有足够明显的分差。

但是：

```text
Reward 的绝对零点没有意义
Reward 的绝对尺度也没有统一标准
```

因此：

$$
\boxed{
\text{Reward Model 主要学习的是相对排序，而不是绝对打分}
}
$$

训练时由于 sigmoid 饱和：

$$
r_c-r_r\text{ 越大}
$$

则：

$$
\text{梯度越接近 0}
$$

因此不会一直以很强的梯度向无穷大推动。

而当 Reward 后续交给 PPO 使用时，还需要通过：

```text
Reward Normalization
Reward Scaling
KL Penalty
Advantage Normalization
```

等机制控制整个强化学习过程的数值尺度。

## 75. Reward Model 和 PPO 是什么关系？

经典 RLHF 可以：

```text
Preference Data
       ↓
Reward Model Training
       ↓
得到 Reward Model
       ↓
Policy 生成回答
       ↓
Reward Model 给回答打分
       ↓
PPO 根据 Reward
更新 Policy
```

所以 Reward Model 的作用可以简单理解为：

> **把“人类偏好”训练成一个可以自动运行的打分器。**

否则 PPO 每生成一次回答，都让真人过来打一次分，成本根本无法接受。

---

<a id="origin-6517"></a>
## 76. 为什么叫“人类偏好的代理模型”？

原本真实目标是：

```text
人觉得哪个好？
```

但真人不能每秒打几万次分。

所以训练一个：

$$
R_\theta(x,y)
$$

去近似：

```text
人类偏好。
```

之后强化学习就可以：

```text
不断调用 Reward Model。
```

---

<a id="origin-6547"></a>
## 77. 但 Reward Model 并不天然代表“真理”

这非常重要。

Reward Model 学到的是：

```text
训练数据中的偏好模式。
```

如果 Preference Dataset：

```text
存在偏差
存在错误
覆盖不足
```

Reward Model 也会继承这些问题。

所以 Reward Model 更准确的定义不是：

```text
真理模型
```

而是：

> **Preference Model。**

## 80. 最后用一个完整故事彻底串起来

假设今天我们刚刚有一个已经完成 SFT 的 MiniMind。

它已经能够理解：

```text
“1+1是多少？”
```

也能够生成：

```text
“2”
```

但是我们现在希望它进一步知道：

```text
哪些回答更受人偏好。
```

于是准备数据：

```text
Prompt：
1+1是多少？

Chosen：
2

Rejected：
5
```

---

首先把两段完整对话分别送进同一个 MiniMind：

```text
Prompt + Chosen
         ↓
      MiniMind
         ↓
      Hidden
         ↓
最后 Token Hidden
         ↓
Reward Head
         ↓
r_chosen
```

另一边：

```text
Prompt + Rejected
         ↓
      MiniMind
         ↓
      Hidden
         ↓
最后 Token Hidden
         ↓
Reward Head
         ↓
r_rejected
```

注意：

> 左右不是两个 Reward Model。

而是：

> **同一个 Reward Model 被调用两次。**

参数完全共享。

---

假设一开始模型：

```text
chosen = 0.1

rejected = 0.8
```

明显排反。

于是：

$$
\Delta
=
0.1-0.8
=
-0.7
$$

：

$$
P(c\succ r)
=
\sigma(-0.7)
\approx0.332
$$

Loss：

$$
L
=
-\log0.332
\approx1.103
$$

Loss 比较大。

---

反向传播以后：

```text
chosen 对应方向
得到“应该提高 chosen-rejected 差值”的梯度

rejected 对应方向
得到相反梯度
```

Reward Head 更新。

Transformer Backbone 也更新。

---

训练很多 Preference Pair 之后：

再次遇到类似输入，可能得到：

```text
chosen = 2.4

rejected = -0.3
```

那么：

$$
\Delta=2.7
$$

：

$$
P(c\succ r)
=
\sigma(2.7)
\approx0.937
$$

Loss：

$$
-\log0.937
\approx0.065
$$

模型已经很好地区分。

## 81. 整个 Reward Model 训练最重要的五个公式

<a id="origin-6909"></a>
### 81.1 公式一：完整输入

$$
s=(x,y)
$$

其中：

```text
x = Prompt / History
y = Response
```

---

<a id="origin-6924"></a>
### 81.2 公式二：Transformer

$$
H
=
f_\theta(s)
$$

：

$$
H\in
\mathbb R^{T\times d}
$$

---

<a id="origin-6941"></a>
### 81.3 公式三：Reward

取最后位置：

$$
h_{\text{last}}
$$

然后：

$$
\boxed{
r
=
w^T h_{\text{last}}
}
$$

---

<a id="origin-6961"></a>
### 81.4 公式四：Preference Probability

$$
\boxed{
P(y_c\succ y_r|x)
=
\sigma(
r_c-r_r
)
}
$$

---

<a id="origin-6975"></a>
### 81.5 公式五：Reward Model Loss

$$
\boxed{
L_{\text{RM}}
=
-
\frac1B
\sum_{i=1}^{B}
\log
\sigma
\left(
R_\theta(x_i,y_i^c)
-
R_\theta(x_i,y_i^r)
\right)
}
$$

这就是整个程序最核心的数学公式。

## 83. 最后一句话总结

这份代码做的事情其实可以压缩为：

> **先用已经会理解语言的 SFT MiniMind，把“Prompt + Response”压缩成最后一个 Token 的语义向量，再训练一个标量评分头，同时微调整个 Backbone；通过 `-log sigmoid(r_chosen-r_rejected)`，让人类偏好的回答分数逐渐高于不偏好的回答。**

所以 Reward Model 最本质的训练目标不是：

```text
学会“答案应该是多少分”
```

而是：

$$
\boxed{
\text{学会让好答案的分数相对更高}
}
$$

而这正是后续 RLHF / PPO 能够使用它作为自动奖励函数的基础。
