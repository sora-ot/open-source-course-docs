# 34 · 理论之外的 Tensor 操作


只看 Transformer 理论时，核心过程非常简洁：

```text
Embedding
↓
Q / K / V
↓
Attention
↓
FFN
↓
LM Head
```

但真正写 PyTorch 代码时，还会看到大量看起来和 Transformer 理论无关的操作。

这些操作大多数**不是新的模型理论**，而是为了：

```text
整理 Tensor 形状
对齐不同维度
处理 Batch 和多头
管理 GPU
保证内存布局
处理 Mask
保存 KV Cache
保证数值稳定
```

可以把常见的**难点**总结如下。

---

<a id="origin-36"></a>
## 1. `reshape()` / `view()`：重新组织 Tensor 形状

例如：

```python
x = x.view(B, T, num_heads, head_dim)
```

把：

```text
[B, T, 4096]
```

重新解释成：

```text
[B, T, 32, 128]
```

因为：

```text
4096 = 32 × 128
```

主要用途：

> 把理论中的“多个 Head”真正变成 Tensor 中的一个独立维度。

---

<a id="origin-68"></a>
## 2. `transpose()`：交换维度顺序

例如：

```python
q = q.transpose(1, 2)
```

把：

```text
[B, T, N_head, D]
```

变成：

```text
[B, N_head, T, D]
```

主要用途：

> 调整维度顺序，使后面的矩阵乘法能够按照 Attention 公式执行。

---

<a id="origin-94"></a>
## 3. `unsqueeze()`：增加一个长度为 1 的维度

例如：

```python
attention_mask = attention_mask.unsqueeze(1).unsqueeze(2)
```

把：

```text
[B, S]
```

变成：

```text
[B, 1, 1, S]
```

主要用途：

> 为广播做准备，让一个简单的 mask 能同时作用于所有 Head 和所有 Query。

---

<a id="origin-120"></a>
## 4. `expand()`：利用广播扩展 Tensor

例如 GQA 中：

```text
[B, T, Nkv, 1, D]
```

扩展成：

```text
[B, T, Nkv, n_rep, D]
```

主要用途：

> 让较少的 KV Head 可以被多个 Query Head 共享，而不需要从理论上重新计算新的 K/V。

---

<a id="origin-140"></a>
## 5. `cat()`：把多个 Tensor 拼起来

例如 KV Cache：

```python
k = torch.cat([past_k, new_k], dim=1)
```

把：

```text
历史 K
+
当前新 K
```

拼成：

```text
完整上下文 K
```

主要用途：

> 在推理时把历史缓存和当前 token 的新结果连接起来。

---

<a id="origin-168"></a>
## 6. `contiguous()`：整理实际内存布局

例如：

```python
x = x.transpose(...)
x = x.contiguous()
```

`transpose()` 后 Tensor 的逻辑维度虽然改变了，但底层内存可能不是连续排列的。

主要用途：

> 把 Tensor 真正整理成连续的内存布局，方便后续 `view()` 等操作。

它属于：

```text
内存工程问题
```

而不是 Transformer 理论。

---

<a id="origin-193"></a>
## 7. `.to(device)`：把数据或模型移动到 CPU / GPU

例如：

```python
x = x.to(device)
```

或者：

```python
model = model.to(device)
```

如果：

```python
device = "cuda"
```

就是把 Tensor 或模型参数移动到 GPU。

主要用途：

> 决定计算实际在哪个硬件设备上执行。

理论公式不会讨论：

```text
CPU
GPU
CUDA
```

但真实代码必须处理。

---

<a id="origin-231"></a>
## 8. `.float()` / `.type_as()`：控制计算精度

例如：

```python
scores.float()
```

可能先把低精度 Tensor 转成 FP32 计算 Softmax。

然后：

```python
.type_as(x)
```

再转回原来的数据类型。

主要用途：

> 在性能和数值稳定性之间取得平衡。

---

<a id="origin-255"></a>
## 9. `broadcast`：自动对齐长度为 1 的维度

例如：

```text
Attention Score:

[B, H, T, S]

Mask:

[B, 1, 1, S]
```

PyTorch 可以自动把 Mask 看成：

```text
[B, H, T, S]
```

主要用途：

> 避免手动复制大量相同数据。

很多 `unsqueeze()` 的目的，本质上就是为了触发正确的广播。

---

<a id="origin-283"></a>
## 10. `slice`：只取当前真正需要的数据

例如：

```python
freqs_cos[start_pos:start_pos + seq_length]
```

或者：

```python
input_ids[:, past_len:]
```

主要用途：

> 从提前准备好的大 Tensor 中，只取当前 forward 真正需要的一部分。

典型应用包括：

```text
RoPE 位置表
KV Cache 推理
训练标签对齐
```

---

<a id="origin-311"></a>
## 11. `register_buffer()`：保存“不训练但要跟着模型走”的 Tensor

例如 RoPE 的：

```text
cos
sin
```

这些 Tensor：

```text
不是模型参数
不需要梯度更新
```

但又需要：

```text
跟模型一起移动到 GPU
```

所以可以注册成 buffer。

主要用途：

> 管理不参与训练、但属于模型运行状态的 Tensor。

---

<a id="origin-341"></a>
## 12. `detach()` / `inference_mode()`：关闭不需要的梯度计算

训练时需要：

```text
计算梯度
保存计算图
```

推理时不需要。

例如：

```python
@torch.inference_mode()
```

主要用途：

> 推理阶段关闭梯度相关开销，降低显存使用并提高速度。

---

<a id="origin-364"></a>
## 13. `softmax(dim=-1)`：必须明确沿哪个维度归一化

理论只写：

```math
Softmax(QK^T)
```

但代码必须告诉 PyTorch：

```python
F.softmax(scores, dim=-1)
```

这里 `dim=-1` 表示：

> 对当前 Query 对应的所有 Key 分数进行归一化。

主要用途：

> 明确理论操作究竟作用在哪一个 Tensor 维度上。

---

<a id="origin-388"></a>
## 14. 最后总结

Transformer 理论可能只有：

```text
Q = XWQ
K = XWK
V = XWV

Attention
=
Softmax(QKᵀ / √d)V
```

但真正代码还需要大量：

```text
reshape / view
transpose
unsqueeze
expand
cat
contiguous
to(device)
dtype 转换
broadcast
slice
mask
ModuleList
register_buffer
Parameter
inference_mode
```

这些操作大部分不是在增加新的 Transformer 理论，而是在解决：

```text
Tensor 怎么摆
维度怎么对齐
多头怎么组织
Batch 怎么处理
GPU 怎么使用
内存怎么管理
Mask 怎么广播
缓存怎么保存
精度怎么控制
```

因此可以把两者的差距概括成一句话：

> **Transformer 理论告诉我们“应该算什么”，真实 PyTorch 代码还必须解决“这些 Tensor 到底应该以什么形状、什么精度、放在哪个设备上，才能真正把公式算出来”。**

进一步压缩就是：

> **理论关注公式，代码除了公式，还要处理 Tensor 形状、维度对齐、GPU、内存、Batch、Mask、Cache 和数值精度。**
