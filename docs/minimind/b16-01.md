# 40 · 推理：generate 流程与采样策略


先看核心代码的整体目标：

```python
@torch.inference_mode()
def generate(
    self,
    inputs=None,
    attention_mask=None,
    max_new_tokens=8192,
    temperature=0.85,
    top_p=0.85,
    top_k=50,
    eos_token_id=2,
    streamer=None,
    use_cache=True,
    num_return_sequences=1,
    do_sample=True,
    repetition_penalty=1.0,
    **kwargs
):
```

这段代码本质上在重复做一件事情：

```text
已有文本
   ↓
模型预测“下一个 token”的 logits
   ↓
对 logits 做温度调整
   ↓
重复惩罚
   ↓
Top-K
   ↓
Top-P
   ↓
采样 / argmax
   ↓
得到新 token
   ↓
拼回输入
   ↓
继续预测下一个 token
```

例如：

```text
输入：

I love

第 1 轮：
I love
   ↓
预测 AI

第 2 轮：
I love AI
   ↓
预测 very

第 3 轮：
I love AI very
   ↓
预测 much

最终：

I love AI very much
```

这就是所谓：

```text
Autoregressive Generation
自回归生成
```

## 1. `@torch.inference_mode()`：进入纯推理模式

代码：

```python
@torch.inference_mode()
```

意思是：

> 下面这个函数只是做推理，不需要计算梯度。

训练时：

```text
forward
↓
loss
↓
backward
↓
梯度
↓
更新参数
```

因此 PyTorch 必须保存很多中间结果：

```text
activation
计算图
梯度信息
```

但是生成文本的时候：

```text
I love
↓
AI
```

我们并不需要：

```python
loss.backward()
```

所以可以关闭梯度。

相当于：

```python
with torch.no_grad():
    ...
```

但 `inference_mode()` 更进一步针对纯推理做了优化。

主要好处：

```text
减少显存
减少额外计算
提高推理速度
```

## 2. `input_ids`：真正送给模型的不是文字，而是 token 编号

例如：

```text
"I love AI"
```

经过 tokenizer：

```python
input_ids = [1, 245, 893, 1024]
```

可能表示：

```text
1     → BOS
245   → I
893   → love
1024  → AI
```

因此：

```python
input_ids
```

实际上是：

```text
token ID 序列
```

而不是字符串。

## 3. `num_return_sequences`：一次生成几个答案

代码：

```python
input_ids = kwargs.pop("input_ids", inputs).repeat(
    num_return_sequences,
    1
)
```

假设原始输入：

```python
input_ids.shape = [1, 3]
```

内容：

```text
[BOS, I, love]
```

如果：

```python
num_return_sequences = 3
```

就会复制成：

```text
[BOS, I, love]
[BOS, I, love]
[BOS, I, love]
```

shape：

```text
[3, 3]
```

然后三条序列分别采样。

例如最终可能得到：

```text
I love AI.
I love programming.
I love this game.
```

<a id="origin-248"></a>
## 4. `attention_mask`：告诉模型哪些 token 是真的，哪些是 padding

例如一个 batch：

```text
句子 1：
I love AI

句子 2：
I love
```

为了组成矩阵，可能 padding：

```text
I love AI
I love PAD
```

对应：

```python
input_ids =
[
    [10, 20, 30],
    [10, 20,  0]
]
```

attention mask：

```python
attention_mask =
[
    [1, 1, 1],
    [1, 1, 0]
]
```

表示：

```text
1 → 有效 token
0 → padding，不应该参与 Attention
```

当新生成一个 token 时：

```python
attention_mask = torch.cat([
    attention_mask,
    attention_mask.new_ones(
        attention_mask.shape[0], 1
    )
], -1)
```

因为新生成的 token 当然是真实 token：

```text
原来：

1 1 1

生成一个 token 后：

1 1 1 1
```

## 5. `max_new_tokens`：最多新生成多少个 token

例如：

```python
max_new_tokens = 100
```

表示：

> 原输入之后，最多再生成 100 个 token。

注意它不是：

```text
最终总长度 = 100
```

而是：

```text
新增长度最多 = 100
```

例如输入已经有：

```text
500 token
```

那么最多得到：

```text
500 + 100 = 600 token
```

## 6. `past_key_values`：KV Cache

这是生成阶段最重要的优化之一。

假设第一轮：

```text
I love
```

模型计算：

```text
K_I
V_I

K_love
V_love
```

准备预测：

```text
AI
```

下一轮输入逻辑上变成：

```text
I love AI
```

如果完全重算：

```text
K_I
V_I

K_love
V_love

K_AI
V_AI
```

其中：

```text
I
love
```

的 K/V 明明上一轮已经算过了。

所以缓存：

```text
K_I
V_I
K_love
V_love
```

下一轮只计算：

```text
K_AI
V_AI
```

这就是：

```text
KV Cache
```

代码：

```python
past_key_values = outputs.past_key_values
```

代码：

```python
past_len = past_key_values[0][0].shape[1] if past_key_values else 0
```

假设缓存中已经有：

```text
I love AI
```

也就是：

```python
past_len = 3
```

此时：

```python
input_ids =
[I, love, AI, very]
```

那么：

```python
input_ids[:, past_len:]
```

就是：

```text
[very]
```

因此只把：

```text

```

送进去。

过去：

```text
I love AI
```

的信息由 KV Cache 提供。

<a id="origin-498"></a>
## 8. `outputs.logits[:, -1, :]` 为什么只取最后一个位置

模型输出：

```python
outputs.logits
```

shape 通常是：

```text
[B, L, V]
```

其中：

```text
B = batch size
L = sequence length
V = vocabulary size
```

例如：

```text
[B, 4, 32000]
```

说明四个位置都会产生一个词表预测。

例如输入：

```text
BOS I love AI
```

模型理论上同时输出：

```text
BOS → I
I → love
love → AI
AI → ?
```

但是生成阶段真正关心的只是：

```text
AI → 下一个 token 是什么
```

所以取：

```python
outputs.logits[:, -1, :]
```

得到：

```text
[B, V]
```

也就是：

> 最后一个位置对整个词表的预测分数。

## 9. logits 是什么

假设词表只有 5 个 token：

```text
AI
dog
cat
great
EOS
```

模型输出：

```python
logits = [
    4.0,
    1.0,
    0.5,
    3.0,
    -1.0
]
```

注意：

```text
logits 还不是概率
```

它只是模型给每个 token 的原始分数。

经过：

```python
softmax(logits)
```

才会得到概率。

<a id="origin-609"></a>
## 10. `temperature`：控制概率分布有多尖锐

代码：

```python
logits = outputs.logits[:, -1, :] / temperature
```

公式：

```math
P_i =
\frac{
e^{z_i/T}
}{
\sum_j e^{z_j/T}
}
```

其中：

```text
z_i = logits
T   = temperature
```

---

<a id="origin-637"></a>
### 10.1 Temperature = 1

假设：

```text
logits:

A = 4
B = 3
C = 2
```

直接 Softmax。

概率可能大约：

```text
A = 66.5%
B = 24.5%
C = 9.0%
```

<a id="origin-661"></a>
## 11. Temperature < 1：让模型更保守

假设：

```python
temperature = 0.5
```

那么：

```text
4 / 0.5 = 8
3 / 0.5 = 6
2 / 0.5 = 4
```

Softmax：

```text
A ≈ 86.7%
B ≈ 11.7%
C ≈ 1.6%
```

可以发现：

```text
原本：

66.5%
24.5%
9.0%

↓

降低 temperature：

86.7%
11.7%
1.6%
```

最高概率 token 变得更占优势。

因此：

```text
temperature 越低
↓
分布越尖
↓
模型越确定
↓
随机性越低
```

---

<a id="origin-719"></a>
## 12. Temperature > 1：让模型更随机

例如：

```python
temperature = 2
```

变成：

```text
4 / 2 = 2
3 / 2 = 1.5
2 / 2 = 1
```

概率会变平。

例如大约：

```text
A = 50.6%
B = 30.7%
C = 18.6%
```

于是原本低概率 token 更容易被抽中。

所以：

```text
temperature 越高
↓
概率越平均
↓
随机性越强
↓
生成越发散
```

## 13. Temperature 最简单的理解

可以把它理解成：

```text
Temperature

低：
“相信第一名”

高：
“第一名虽然最好，但后面的也给点机会”
```

例如模型预测：

```text
我今天去：

学校  60%
公司  25%
公园  10%
月球   5%
```

低温度：

```text
学校 ≫ 公司 ≫ 公园 ≫ 月球
```

高温度：

```text
学校
公司
公园
月球
```

之间差距缩小。

<a id="origin-805"></a>
## 14. `repetition_penalty`：重复惩罚

模型生成的时候经常出现：

```text
我喜欢人工智能，
人工智能非常有趣，
人工智能可以帮助我们，
人工智能……
```

甚至极端情况：

```text
很好很好很好很好很好很好……
```

因此可以惩罚已经出现过的 token。

代码：

```python
seen = torch.unique(input_ids[i])
```

得到：

```text
这条序列已经出现过哪些 token
```

然后：

```python
score = logits[i, seen]
```

找到这些 token 的 logits。

<a id="origin-844"></a>
### 14.1 用 5 列数值看清重复惩罚的全过程

先看 `torch.unique`。假设第 `i` 条序列已有的 token 编号为：

```python
input_ids[i] = tensor([3, 1, 3, 4, 1])
seen = torch.unique(input_ids[i])  # tensor([1, 3, 4])
```

`unique` 去掉重复编号，默认按编号排序。因此，已经出现过的 token 是 `1、3、4`。编号 `1` 和 `3` 虽然各出现两次，在本轮也只调整一次；这段代码不会按出现次数加重惩罚。

**这里的 `1、3、4` 是已经出现过的 token 的 ID（词表编号），在 `logits[i, seen]` 中也用作列索引，用来找到这些 token 对应的分数**。模型每次预测下一个 token 时，都会为整个词表中的候选 token 打分；**重复惩罚会调整 ID 为 `1、3、4` 的候选分数**。当惩罚系数大于 `1` 时，非零分数会降低，使这些重复候选相对未出现候选更难被选中；分数为零的候选保持不变。

接着看 `score` 和 `logits`。`logits` 的形状是 `[批次大小, 词表大小]`，`logits[i]` 表示第 `i` 条序列预测下一个 token 时，整个词表的分数。假设词表只有 5 个 token：

```text
token 编号：        0     1     2      3     4
调整前 logits[i]：[0.5,  2.0,  1.0,  -2.0,  0.0]
```

每一列对应一个 token 编号，列中的值是分数，不是概率。`seen` 用作列索引，取出已经出现过的 token 的分数：

```python
score = logits[i, seen]
      # logits[i, [1, 3, 4]]
      # tensor([2.0, -2.0, 0.0])
```

`score` 中三个值依次属于 token `1、3、4`。设 `repetition_penalty = 2.0`，执行：

```python
logits[i, seen] = torch.where(
    score > 0,
    score / repetition_penalty,
    score * repetition_penalty
)
```

逐列看原值 `->` 新值，就能看清哪些分数被调整：

```text
第 0 列（token 0，未出现）： 0.5 ->  0.5
    不参与重复惩罚，保持原值。

第 1 列（token 1，已出现）： 2.0 ->  1.0
    正数除以 2：2.0 / 2.0 = 1.0，分数变小。

第 2 列（token 2，未出现）： 1.0 ->  1.0
    不参与重复惩罚，保持原值。

第 3 列（token 3，已出现）：-2.0 -> -4.0
    负数乘以 2：-2.0 * 2.0 = -4.0，分数变小（变得更负）。

第 4 列（token 4，已出现）： 0.0 ->  0.0
    0 不满足 score > 0，走乘法分支；零乘以 2 仍然是零。
```

`torch.where` 得到 `[1.0, -4.0, 0.0]`，将它们分别写回 `logits` 的第 `1、3、4` 列，得到完整的前后对照：

```text
token 编号：        0     1     2      3     4
调整前 logits[i]：[0.5,  2.0,  1.0,  -2.0,  0.0]
调整后 logits[i]：[0.5,  1.0,  1.0,  -4.0,  0.0]
```

重复候选 token `1` 的分数从 `2.0` 降到 `1.0`，token `3` 从 `-2.0` 降到 `-4.0`。注意 **`-4.0 < -2.0`，虽然绝对值变大，但分数本身变小，所以也是惩罚**。未出现的 token `0、2` 保持原分数；重复候选 token `4` 因为分数为零，也保持不变。

为什么分数降低能惩罚重复？softmax 中，两个候选的概率比满足：

```text
p_j / p_k = exp(logit_j - logit_k)
```

降低重复候选的分数，同时保持未出现候选的分数不变，就会降低重复候选相对未出现候选的概率比。若把负数也用除法，`-2.0 / 2.0 = -1.0`，分数反而变大，相对未出现候选更有优势，因此负数要用乘法。

这里的惩罚效果以 `repetition_penalty > 1` 为前提；等于 `1` 不调整，介于 `0` 和 `1` 之间反而鼓励重复。零分数没有受到直接惩罚，而且 softmax 的归一化也受其他候选影响，因此不能保证每个重复 token 的绝对概率都下降。

<a id="origin-923"></a>
## 15. 为什么正数要除，负数要乘

代码：

```python
torch.where(
    score > 0,
    score / repetition_penalty,
    score * repetition_penalty
)
```

假设：

```python
repetition_penalty = 1.2
```

一个已经出现过的 token：

```text
logit = 6
```

变成：

```text
6 / 1.2 = 5
```

分数下降。

如果：

```text
logit = -2
```

不能做：

```text
-2 / 1.2 = -1.67
```

因为：

```text
-1.67 > -2
```

反而提高了概率。

因此负数应该：

```text
-2 × 1.2 = -2.4
```

这样也是降低分数。

所以：

```text
正 logits：
除以 penalty

负 logits：
乘以 penalty
```

共同目标都是：

```text
让出现过的 token 更难再次出现。
```

## 16. `top_k`：只保留概率最大的 K 个 token

假设词表：

```text
100000 个 token
```

如果直接采样：

```text
理论上 100000 个 token 都有机会被抽中
```

其中可能存在很多极低概率的怪词。

因此：

```python
top_k = 50
```

意思是：

> 只允许分数最高的 50 个 token 参与采样。

剩下：

```text
99950 个 token
```

全部：

```python
logit = -∞
```

## 18. Top-K 的问题

假设某一次预测非常确定：

```text
A 90%
B  5%
C  3%
D  1%
E  1%
```

Top-K=50 其实太宽了。

但另一种情况下：

```text
A 5%
B 5%

D 4.7%
...
```

模型很不确定。

这时候固定 Top-K=5 又可能太窄。

所以出现了：

```text
Top-P
```

<a id="origin-1139"></a>
## 19. `top_p`：根据累计概率动态决定保留多少 token

Top-P 也叫：

```text
Nucleus Sampling
核采样
```

例如：

```python
top_p = 0.85
```

意思不是：

```text
只保留概率 > 0.85 的 token
```

而是：

> 从概率最高的 token 开始累加，保留累计概率大约达到 85% 的这一组 token。

---

<a id="origin-1166"></a>
## 20. Top-P 数值例子

假设：

```text
A  40%
B  25%
C  15%
D  10%
E   6%
F   4%
```

累计概率：

```text
A       40%
A+B     65%
A+B+C   80%
A+B+C+D 90%
```

如果：

```python
top_p = 0.85
```

那么通常保留：

```text
A
B
C
D
```

因为：

```text
前三个 = 80%
```

还没达到：

```text
85%
```

加上 D 后：

```text
90%
```

于是 D 也保留。

剩余：

```text
E
F
```

删除。

<a id="origin-1234"></a>
## 21. 为什么代码要把 mask 右移一位

代码：

```python
mask = torch.cumsum(
    torch.softmax(sorted_logits, dim=-1),
    dim=-1
) > top_p
```

假设累计概率：

```text
A   0.40
B   0.65
C   0.80
D   0.90
E   0.96
```

`top_p=0.85`：

```text
mask:

A False
B False
C False
D True
E True
```

如果直接删：

```text
D
E
```

那么剩下：

```text
A+B+C = 0.80
```

反而没有达到 0.85。

所以代码：

```python
mask[..., 1:] = mask[..., :-1].clone()
mask[..., 0] = 0
```

把删除标志右移。

变成：

```text
A False
B False
C False
D False
E True
```

因此：

```text
D
```

作为第一个跨越阈值的 token 被保留下来。

最终候选集合：

```text
A+B+C+D = 90%
```

<a id="origin-1317"></a>
## 22. Top-K 和 Top-P 的区别

可以简单理解：

```text
Top-K：

“只允许前 K 名参加比赛。”
```

例如：

```text
固定前 50 名
```

而：

```text
Top-P：

“只保留累计概率达到 P 的那一小撮候选。”
```

例如：

```text
累计概率达到 85% 即停止。
```

所以：

```text
Top-K = 固定人数

Top-P = 动态人数
```

## 23. Top-K 和 Top-P 可以同时使用

对应代码如下：

```text
logits
↓
Top-K
↓
Top-P
↓
Softmax
↓
Sampling
```

例如原来：

```text
100000 个 token
```

先：

```python
top_k = 50
```

只剩：

```text
50 个
```

然后：

```python
top_p = 0.85
```

可能最后只留下：

```text
12 个
```

这 12 个再参与采样。

## 24. `do_sample=True`：采样还是贪心

代码：

```python
next_token = (
    torch.multinomial(
        torch.softmax(logits, dim=-1),
        num_samples=1
    )
    if do_sample
    else
    torch.argmax(logits, dim=-1, keepdim=True)
)
```

这是生成策略最核心的分支之一。

## 28. Temperature / Top-K / Top-P 的关系

这三个东西经常一起出现，但职责不同。

完整顺序：

```text
模型 logits
   ↓
Temperature
改变概率分布形状
   ↓
Top-K
按数量砍候选
   ↓
Top-P
按累计概率继续砍候选
   ↓
Softmax
   ↓
Multinomial
随机抽取
```

可以理解成：

```text
Temperature：
“候选之间差距多大？”

Top-K：
“最多让多少个候选参加？”

Top-P：
“到底保留多少概率质量？”

Multinomial：
“最终从留下的人里面抽谁？”
```

## 31. `finished` 的作用

```python
finished = torch.zeros(
    input_ids.shape[0],
```

例如 batch 有 3 条：

```text
False

False
```

表示：

假设第一条生成 EOS：


下一轮第二、第三条继续生成。

<a id="origin-1762"></a>
## 32. 为什么已经结束的序列还要填 EOS

代码：

```python
next_token = torch.where(
    finished.unsqueeze(-1),
    next_token.new_full(
        (next_token.shape[0], 1),
        eos_token_id
    ),
    next_token
)
```

原因是：

> 一个 batch 中所有序列必须保持相同长度。

例如：

```text
样本 1：
I love AI EOS

样本 2：
I love machine learning is ...

样本 3：
I love programming because ...
```

样本 1 已经结束。

但 batch 还要继续跑。

因此后续让它不断补：

```text
EOS EOS EOS
```

最终类似：

```text
样本1：
I love AI EOS EOS EOS

样本2：
I love machine learning EOS

样本3：
I love programming very much EOS
```

这样矩阵长度才能统一。

<a id="origin-1821"></a>
## 33. `finished |= ...` 是什么

代码：

```python
finished |= next_token.squeeze(-1).eq(eos_token_id)
```

假设之前：

```text
finished =
[True, False, False]
```

这一轮：

```text
next_token == EOS =
[False, True, False]
```

做 OR：

```text
True  OR False = True
False OR True  = True
False OR False = False
```

得到：

```text
[True, True, False]
```

所以：

> 一旦某条序列结束，就永远保持结束状态。

## 34. `finished.all()`：所有序列都结束就提前退出

代码：

```python
if finished.all():
    break
```

虽然：


但不代表一定生成 8192 个。

例如第 150 个 token 时：

就直接结束。

所以：

只是：

```text
最大上限
```

而不是必须生成的数量。

## 40. 为什么最后一个新 token 通常还没有进入 KV Cache

代码最后：

```python

    'generated_ids': input_ids,

```

这里有一个非常重要的细节。

假设：

```text

```

forward 得到：

```text

I
love
```

然后从 logits 采样得到：

```text
AI
```

接着：


## 47. 这段 generate 代码最核心的故事

整段代码可以浓缩成：

```text
第一步：
用 Transformer 计算下一个 token 的 logits

第二步：
用 Temperature 调整“模型有多自信”

第三步：
用 repetition penalty 避免疯狂重复

第四步：
用 Top-K 去掉排名很低的候选

第五步：
用 Top-P 去掉概率质量很小的尾部候选

第六步：
用 Multinomial 随机抽一个 token
或者 Argmax 直接选第一名

第七步：
把这个 token 拼回输入

第八步：
保存 KV Cache

第九步：
继续预测下一个 token
```

因此：

```python
generate()
```

本质不是一个新的神经网络。

它只是：

> **不断调用 `forward()`，然后决定如何从 logits 中选出下一个 token，再把这个 token 送回模型继续生成。**

真正负责：

```text
Q/K/V
Attention
RoPE
RMSNorm
FFN / MoE
```

这些神经网络计算的是：

```python
forward()
```

而 `generate()` 主要负责的是：

```text
循环生成
+
KV Cache 管理
+
采样策略
+
停止条件
+
流式输出
```

这也是理解：

```text
训练
forward
generate
```

三者区别的一个非常重要的分界点。

---
