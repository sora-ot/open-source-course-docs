# 60 · PPO 中的两类 KL 散度


> 本文只解释 `trainer/train_ppo.py` 中实际使用的两种 KL 计算：新旧 Actor 之间的 `approx_kl`，以及 Actor 与参考模型之间的 `kl_ref_penalty`。

<a id="origin-5"></a>
## 1. 三组 token 对数概率

代码先准备三组对数概率：

| 变量 | 含义 | 是否随训练更新 |
| --- | --- | --- |
| `old_resp_logp` | rollout 生成回答时，旧 Actor 给实际生成 token 的对数概率 | 否 |
| `mb_resp_logp` | 更新阶段，当前 Actor 重新计算的同一批 token 对数概率 | 是 |
| `ref_resp_logp` | 冻结参考模型给同一批 token 的对数概率 | 否 |

它们的形状都是 `[M, R]`：`M` 是 mini-batch 大小，`R` 是回答的最大 token 数。这里保存的是“实际生成 token”的对数概率，不是整个词表的概率分布。

当前 Actor 的对数概率由下面这段代码得到：

```python
mb_resp_logp = (
    F.log_softmax(res.logits[:, :-1], dim=-1)
    .gather(2, labels[inds].unsqueeze(-1))
    .squeeze(-1)
    .gather(1, logp_pos[inds])
)
```

计算过程是：

1. `log_softmax` 把 logits 转成词表上的对数概率；
2. 第一次 `gather` 取出实际 token 的对数概率；
3. 第二次 `gather` 只保留回答部分的位置。

<a id="origin-34"></a>
## 2. 新旧 Actor 的 `approx_kl`

<a id="origin-36"></a>
### 2.1 先计算对数概率比

```python
log_ratio = mb_resp_logp - old_resp_logp[inds]
```

对应公式：

$$
\text{log\_ratio}_t
=
\log \pi_{\text{new}}(a_t\mid s_t)
-
\log \pi_{\text{old}}(a_t\mid s_t)
=
\log\frac{\pi_{\text{new}}(a_t\mid s_t)}
{\pi_{\text{old}}(a_t\mid s_t)}
$$

若 `log_ratio` 接近 0，说明新旧 Actor 给该 token 的概率接近；绝对值越大，说明策略变化越大。

<a id="origin-57"></a>
### 2.2 用平方项近似 KL

代码为：

```python
approx_kl = (
    0.5 * (log_ratio ** 2) * resp_policy_mask[inds]
).sum() / resp_policy_mask[inds].sum().clamp(min=1)
```

也就是先对每个有效回答 token 计算：

$$
\widehat{D}_{\mathrm{KL},t}
=
\frac{1}{2}\left(\text{log\_ratio}_t\right)^2
$$

再对所有有效 token 求平均。这个式子是新旧策略比较接近时使用的二阶近似，因此变量名是 `approx_kl`，不是精确 KL。

例如：

```text
old_logp  = -1.2
new_logp  = -1.0
log_ratio = -1.0 - (-1.2) = 0.2
approx_kl = 0.5 * 0.2^2 = 0.02
```

它只用于判断当前 Actor 是否已经偏离 rollout 时的旧 Actor 太远：

```python
if approx_kl_val > args.early_stop_kl:
    stop_ppo = True
```

`approx_kl` 会先在多张卡之间取平均，然后与 `early_stop_kl` 比较。它不直接加入 `policy_loss`，也通过 `detach()` 切断了梯度。

<a id="origin-95"></a>
## 3. Actor 与参考模型的 `kl_ref_penalty`

代码先隐式构造：

$$
d_t
=
\log \pi_{\text{ref}}(a_t\mid s_t)
-
\log \pi_{\text{new}}(a_t\mid s_t)
$$

然后计算：

```python
kl_ref_penalty = (
    (
        torch.exp(ref_resp_logp[inds] - mb_resp_logp)
        - (ref_resp_logp[inds] - mb_resp_logp)
        - 1.0
    )
    * resp_policy_mask[inds]
).sum() / resp_policy_mask[inds].sum().clamp(min=1)
```

单个 token 的形式为：

$$
k_t=\exp(d_t)-d_t-1
$$

例如：

```text
ref_logp = -1.1
new_logp = -1.0
d        = -1.1 - (-1.0) = -0.1
k        = exp(-0.1) - (-0.1) - 1
         = 0.00484
```

因为对任意 $d$ 都有 $\exp(d)\ge 1+d$，所以每个 token 的 $k_t$ 都不会小于 0，mini-batch 较小时也不容易出现负的 KL 估计值。

它近似估计的方向是：

$$
D_{\mathrm{KL}}
\left(\pi_{\text{new}}\,\|\,\pi_{\text{ref}}\right)
$$

也就是衡量当前 Actor 偏离冻结参考模型的程度。当前代码使用旧 Actor 生成的 token 来估计它；PPO 会限制新旧 Actor 的差距，所以这里把这些 token 当作当前 Actor 的近似采样。

这个 KL 会真正加入策略损失：

```python
policy_loss = ppo_policy_loss + args.kl_coef * kl_ref_penalty
```

因此，`kl_ref_penalty` 越大，策略损失越大，优化器就越倾向于让 Actor 回到参考模型附近。

<a id="origin-155"></a>
## 4. `resp_policy_mask` 为什么必须参与计算

两个 KL 都乘了：

```python
resp_policy_mask[inds]
```

这个 mask 保留真实回答 token（包括首个 EOS），排除 PAD 和 EOS 之后的位置。最终都按有效 token 数量求平均：

```python
masked_value.sum() / mask.sum().clamp(min=1)
```

`clamp(min=1)` 防止极端情况下分母为 0。

<a id="origin-171"></a>
## 5. 两个 KL 的区别

| 名称 | 比较对象 | 计算形式 | 用途 |
| --- | --- | --- | --- |
| `approx_kl` | 当前 Actor 与 rollout 旧 Actor | $\frac12(\log\pi_{\text{new}}-\log\pi_{\text{old}})^2$ | 监控并触发提前停止 |
| `kl_ref_penalty` | 当前 Actor 与冻结参考模型 | $\exp(d)-d-1$，其中 $d=\log\pi_{\text{ref}}-\log\pi_{\text{new}}$ | 加入 `policy_loss`，约束策略偏移 |

阅读这段代码时，可以直接记住：

```text
old  KL：限制同一批 rollout 被重复更新得太远，只负责早停
ref  KL：限制 Actor 偏离冻结参考模型，直接参与反向传播
```
