# 25 · RoPE：旋转表示与相对位置

<a id="origin-1983"></a>
## 1. RoPE 原理：从位置编码到相对位置

RoPE 这一块最关键的不是先背公式，而是把下面这条逻辑真正想明白：

> **Attention 本身能判断“谁和谁内容相关”，但它天然不知道“谁在前、谁在后、距离多远”；RoPE 的做法不是把位置直接加到 hidden state 上，而是根据 token 的位置去旋转 Q、K，使得 $Q\cdot K$ 在计算相关性时自然同时包含“内容关系 + 相对位置关系”。**

---

<a id="origin-1991"></a>
## 2. 为什么 Attention 需要位置编码？

先回到最基本的问题。

假设有：

```text
我 爱 你
```

和：

```text
你 爱 我
```

Embedding 以后，每个 token 都有自己的向量。

Attention 做：

```math
QK^T
```

它本质上是在问：

> 当前 token 和其他 token 的内容匹配程度是多少？

但单纯的 Self-Attention 并没有天然的“第几个位置”的概念。

所以我们需要额外告诉模型：

```text
“我”在位置 0
“爱”在位置 1
“你”在位置 2
```

否则：

```text
我 爱 你
```

和：

```text
你 爱 我
```

仅靠“有哪些 token”是不够的。

---

<a id="origin-2045"></a>
## 3. 最直观的位置编码方法

一种非常直接的方法就是：

```math
x'=x+PE(position)
```

也就是：

```text
Token Embedding
      +
Position Embedding
      ↓
新的 hidden state
```

例如：

```text
“我”的语义向量
+
“位置0”的向量
```

得到：

```text
“位于位置0的我”
```

这种方法可以理解成：

> **直接把位置信息加进 token 表示。**

---

<a id="origin-2083"></a>
## 4. RoPE 的思路不一样

RoPE：

```text
Rotary Position Embedding
旋转位置编码
```

它不是简单做：

```math
x+PE
```

而是：

> **根据 token 所处的位置，把 Q 和 K 旋转一定角度。**

也就是：

```text
hidden state
    ↓
生成 Q、K
    ↓
根据 position
旋转 Q、K
    ↓
Q · K
    ↓
Attention Score
```

---

<a id="origin-2119"></a>
## 5. 什么叫“旋转一个向量”？

先别想高维。

只看二维。

假设：

```math
q=
\begin{bmatrix}
1\\
0
\end{bmatrix}
```

它在坐标系中指向右边：

```text
        y
        ↑
        |
        |
--------+------→ x
             q=(1,0)
```

现在把它逆时针旋转 $90^\circ$。

得到：

```math
q'=
\begin{bmatrix}
0\\
1
\end{bmatrix}
```

也就是：

```text
        y
        ↑
        q'
        |
--------+------→ x
```

---

<a id="origin-2170"></a>
## 6. 数学上怎么旋转？

二维旋转矩阵：

```math
R(\theta)
=
\begin{bmatrix}
\cos\theta&-\sin\theta\\
\sin\theta&\cos\theta
\end{bmatrix}
```

一个向量：

```math
x=
\begin{bmatrix}
x_1\\
x_2
\end{bmatrix}
```

旋转以后：

```math
x'
=
R(\theta)x
```

也就是：

```math
\begin{bmatrix}
x'_1\\
x'_2
\end{bmatrix}
=
\begin{bmatrix}
\cos\theta&-\sin\theta\\
\sin\theta&\cos\theta
\end{bmatrix}
\begin{bmatrix}
x_1\\
x_2
\end{bmatrix}
```

所以：

```math
x'_1=x_1\cos\theta-x_2\sin\theta
```

```math
x'_2=x_1\sin\theta+x_2\cos\theta
```

---

<a id="origin-2231"></a>
## 7. RoPE 怎么把“位置”变成旋转？

假设一个基础角度是：

```math
\theta
```

那么：

```text
position = 0
→ 旋转 0θ

position = 1
→ 旋转 1θ

position = 2
→ 旋转 2θ

position = 3
→ 旋转 3θ
```

于是同一个内容如果出现在不同位置：

```text
位置不同
↓
旋转角度不同
↓
Q/K 的方向不同
```

这样位置就进入了 Q、K。

---

<a id="origin-2269"></a>
## 8. 一个最简单的例子

为了方便，假设：

```math
\theta=30^\circ
```

并假设：

```math
q=
\begin{bmatrix}
1\\
0
\end{bmatrix}
```

<a id="origin-2287"></a>
### 8.1 token 在位置 1

旋转：

```math
1\times30^\circ
```

得到：

```math
q_1'
=
\begin{bmatrix}
\cos30^\circ\\
\sin30^\circ
\end{bmatrix}
```

约等于：

```math
q_1'
=
\begin{bmatrix}
0.866\\
0.5
\end{bmatrix}
```

---

<a id="origin-2319"></a>
### 8.2 同一个 token 在位置 2

旋转：

```math
2\times30^\circ=60^\circ
```

得到：

```math
q_2'
=
\begin{bmatrix}
0.5\\
0.866
\end{bmatrix}
```

所以：

```text
内容本身没变：

[1, 0]
```

但：

```text
位置 1
→ [0.866, 0.5]

位置 2
→ [0.5, 0.866]
```

也就是说：

> **位置被编码到了向量的方向里。**

---

<a id="origin-2362"></a>
## 9. 但这看起来只是绝对位置

如果只看到这里，好像只是：

```text
position 1 → 转 θ
position 2 → 转 2θ
position 3 → 转 3θ
```

似乎只是把绝对位置编码进去。

RoPE 真正精妙的地方在于：

> **当旋转后的 Q 和 K 再做点积时，绝对位置会自动转化成相对位置。**

---

<a id="origin-2380"></a>
## 10. 假设 Query 在位置 $m$

原始 Query：

```math
q
```

位置：

```math
m
```

旋转以后：

```math
q_m'
=
R(m\theta)q
```

Key 位于位置：

```math
n
```

旋转以后：

```math
k_n'
=
R(n\theta)k
```

Attention 需要计算：

```math
q_m'^Tk_n'
```

代入：

```math
(R(m\theta)q)^T
(R(n\theta)k)
```

---

<a id="origin-2431"></a>
## 11. 最关键的一步

旋转矩阵有一个性质（证明参考下方）：

```math
R(\alpha)^T
=
R(-\alpha)
```

因此：

```math
R(m\theta)^T
=
R(-m\theta)
```

由上可知：

$$
(q'_m)^T k'_n = (R(m\theta)q)^T(R(n\theta)k)
$$

根据：

$$
(AB)^T=B^TA^T
$$

得到：

$$
\boxed{
(R(m\theta)q)^T
=
q^TR(m\theta)^T
}
$$


于是：

```math
q_m'^Tk_n'
=
q^TR(-m\theta)R(n\theta)k
```

旋转矩阵还有另一个性质（证明同样参考下方）：

```math
R(a)R(b)=R(a+b)
```

所以：

```math
R(-m\theta)R(n\theta)
=
R((n-m)\theta)
```

最终：

```math
\boxed{
q_m'^Tk_n'
=
q^TR((n-m)\theta)k
}
```

注意：

原来的：

```math
m
```

和：

```math
n
```

最后只剩下：

```math
\boxed{n-m}
```

也就是：

> **两个 token 之间的相对位置。**

---

<a id="origin-2530"></a>
## 12. 为什么 $q^T R((n-m)\theta)k$ 看起来像只旋转了 K？

在 RoPE 的推导中，我们最终会得到：

$$
\boxed{
q^T R((n-m)\theta)k
}
$$

乍一看，好像只有 $k$ 被旋转了，而 $q$ 没有旋转。

但实际上并不是这样。真正的 RoPE 是：

$$
q'_m=R(m\theta)q
$$

$$
k'_n=R(n\theta)k
$$

也就是说：

```text
Q 在位置 m → 旋转 mθ
K 在位置 n → 旋转 nθ
```

所以 **Q 和 K 实际上都进行了旋转。**

之所以最后看起来只旋转了 K，是因为数学上把两个旋转之间的“相对关系”化简出来了。

---

<a id="origin-2565"></a>
### 12.1 为什么最后只剩一个旋转矩阵？

因为：

$$
R(-m\theta)R(n\theta)
$$

代表的是：

```text
先把 mθ 抵消掉
↓
再看 nθ
↓
最终只剩 (n-m)θ
```

所以原本：

```text
Q 旋转 mθ
K 旋转 nθ
```

在比较二者时，可以等价成：

```text
Q 不动
K 相对于 Q 旋转 (n-m)θ
```

因此：

$$
\boxed{
q^T R((n-m)\theta)k
}
$$

并不是说 RoPE 只给 K 做了旋转，而是说：

> **在计算 Q 和 K 的相对关系时，可以把 Q 当成参考系，于是只需要描述 K 相对于 Q 旋转了多少。**

---

<a id="origin-2611"></a>
## 13. 用一个具体角度例子理解

假设：

```text
Q 旋转了 30°
K 旋转了 80°
```

也就是：

$$
q'=R(30^\circ)q
$$

$$
k'=R(80^\circ)k
$$

我们真正关心的是 Q 和 K 之间相差多少角度：

$$
80^\circ-30^\circ=50^\circ
$$

如果把整个场景一起向回旋转 $30^\circ$：

```text
Q：30° - 30° = 0°
K：80° - 30° = 50°
```

于是原来的：

```text
Q 在 30°
K 在 80°
```

就等价于：

```text
Q 在 0°
K 在 50°
```

因此：

$$
(R(30^\circ)q)^T(R(80^\circ)k)
=
q^TR(50^\circ)k
$$

---

<a id="origin-2667"></a>
## 14. 所以 $q^TR((n-m)\theta)k$ 应该怎么读？

不要理解成：

> “只对 K 做了 RoPE。”

而应该理解成：

> **站在 Q 的参考系里，K 相对于 Q 旋转了 $(n-m)\theta$。**

也就是：

```text
实际执行：
Q → 旋转 mθ
K → 旋转 nθ

但是比较二者时：
只关心 nθ - mθ
```

所以：

$$
\boxed{
n\theta-m\theta=(n-m)\theta
}
$$

---

<a id="origin-2698"></a>
## 15. 其实也可以反过来，只看 Q 相对 K

有：

$$
q^TR((n-m)\theta)k
$$

利用：

$$
R(\alpha)^T=R(-\alpha)
$$

也可以写成：

$$
\boxed{
(R((m-n)\theta)q)^Tk
}
$$

这时候可以理解成：

```text
K 不动
Q 相对于 K 旋转 (m-n)θ
```

所以有两种完全等价的理解：

```text
方式一：以 Q 为参考
Q 不动
K 转 (n-m)θ

方式二：以 K 为参考
K 不动
Q 转 (m-n)θ
```

---

<a id="origin-2741"></a>
## 16. 这正是 RoPE 最核心的地方

原来：

```text
Q 的绝对位置：m
K 的绝对位置：n
```

经过 RoPE：

```text
Q 旋转：mθ
K 旋转：nθ
```

然后进行点积：

```text
mθ 和 nθ
↓
做相对比较
↓
nθ - mθ
↓
(n-m)θ
```

所以：

$$
\boxed{
m,n \longrightarrow n-m
}
$$

也就是说：

> **RoPE 虽然分别根据绝对位置旋转 Q 和 K，但在 Attention 点积中最终自然表现为相对位置。**

---

<a id="origin-2783"></a>
## 17. 从逆矩阵、正交矩阵到 RoPE 中的 $R(\alpha)^T=R(-\alpha)$

<a id="origin-2785"></a>
### 17.1 什么是逆矩阵？

先从普通数字开始。

例如：

```math
5\times\frac15=1
```

所以：

```math
\frac15
```

可以理解成：

> 5 的逆。

矩阵中也有类似概念。

假设有矩阵：

```math
A
```

如果存在另一个矩阵：

```math
A^{-1}
```

满足：

```math
AA^{-1}
=
A^{-1}A
=
I
```

那么：

```math
A^{-1}
```

就叫：

> **A 的逆矩阵。**

---

<a id="origin-2841"></a>
### 17.2 什么是矩阵转置？

假设矩阵：

```math
A=
\begin{bmatrix}
a&b\\
c&d
\end{bmatrix}
```

它的转置：

```math
A^T
```

就是：

> 把行和列交换。

所以：

```math
A^T
=
\begin{bmatrix}
a&c\\
b&d
\end{bmatrix}
```

可以简单记成：

```text
第一行 → 第一列
第二行 → 第二列
```

---

<a id="origin-2883"></a>
### 17.3 什么是正交矩阵？

如果一个矩阵：

```math
Q
```

满足：

```math
Q^TQ=I
```

那么它就叫：

> **正交矩阵（Orthogonal Matrix）**

因为：

```math
Q^TQ=I
```

而逆矩阵满足：

```math
Q^{-1}Q=I
```

所以：

```math
\boxed{
Q^{-1}=Q^T
}
```

这就是正交矩阵最重要的性质：

> **逆矩阵直接等于转置矩阵。**

---

<a id="origin-2927"></a>
### 17.4 为什么叫“正交”矩阵？

“正交”可以理解成：

```text
互相垂直
```

正交矩阵的列向量满足两个条件：

1. 每一列长度为 1；
2. 不同列之间互相垂直。

例如：

```math
Q=
\begin{bmatrix}
a&c\\
b&d
\end{bmatrix}
```

两列：

```math
\begin{bmatrix}
a\\b
\end{bmatrix}
```

和：

```math
\begin{bmatrix}
c\\d
\end{bmatrix}
```

都具有：

```text
长度 = 1
```

并且：

```text
点积 = 0
```

所以这两列：

```text
互相垂直
+
都是单位向量
```

这就是“正交”。

---

<a id="origin-2990"></a>
### 17.5 为什么旋转矩阵是正交矩阵？

二维旋转矩阵：

```math
R(\alpha)
=
\begin{bmatrix}
\cos\alpha&-\sin\alpha\\
\sin\alpha&\cos\alpha
\end{bmatrix}
```

看它的第一列：

```math
\begin{bmatrix}
\cos\alpha\\
\sin\alpha
\end{bmatrix}
```

长度：

```math
\sqrt{
\cos^2\alpha+\sin^2\alpha
}
```

因为：

```math
\cos^2\alpha+\sin^2\alpha=1
```

所以：

```math
\text{第一列长度}=1
```

---

第二列：

```math
\begin{bmatrix}
-\sin\alpha\\
\cos\alpha
\end{bmatrix}
```

长度：

```math
\sqrt{
\sin^2\alpha+\cos^2\alpha
}
=
1
```

---

两列做点积：

```math
\cos\alpha(-\sin\alpha)
+
\sin\alpha\cos\alpha
```

得到：

```math
-\cos\alpha\sin\alpha
+
\sin\alpha\cos\alpha
=
0
```

所以：

```text
第一列长度 = 1
第二列长度 = 1
两列点积 = 0
```

因此旋转矩阵是正交矩阵。

所以：

```math
\boxed{
R(\alpha)^{-1}
=
R(\alpha)^T
}
```

---

<a id="origin-3095"></a>
### 17.6 现在和负角度连起来

前面已经知道：

```math
R(\alpha)^{-1}
=
R(-\alpha)
```

同时因为旋转矩阵是正交矩阵：

```math
R(\alpha)^{-1}
=
R(\alpha)^T
```

两个式子右边都等于：

```math
R(\alpha)^{-1}
```

所以：

```math
\boxed{
R(\alpha)^T
=
R(-\alpha)
}
```

整个逻辑就是：

```text
旋转 α 的逆操作
=
旋转 -α
        ↓
R(α)⁻¹ = R(-α)


旋转矩阵是正交矩阵
        ↓
R(α)⁻¹ = R(α)ᵀ


所以：
R(α)ᵀ = R(-α)
```

---

<a id="origin-3150"></a>
### 17.7 也可以直接从公式验证

旋转矩阵：

```math
R(\alpha)
=
\begin{bmatrix}
\cos\alpha&-\sin\alpha\\
\sin\alpha&\cos\alpha
\end{bmatrix}
```

转置：

```math
R(\alpha)^T
=
\begin{bmatrix}
\cos\alpha&\sin\alpha\\
-\sin\alpha&\cos\alpha
\end{bmatrix}
```

再看：

```math
R(-\alpha)
=
\begin{bmatrix}
\cos(-\alpha)&-\sin(-\alpha)\\
\sin(-\alpha)&\cos(-\alpha)
\end{bmatrix}
```

利用：

```math
\cos(-\alpha)=\cos\alpha
```

以及：

```math
\sin(-\alpha)=-\sin\alpha
```

得到：

```math
R(-\alpha)
=
\begin{bmatrix}
\cos\alpha&\sin\alpha\\
-\sin\alpha&\cos\alpha
\end{bmatrix}
```

正好就是：

```math
R(\alpha)^T
```

所以：

```math
\boxed{
R(\alpha)^T
=
R(-\alpha)
}
```

---



<a id="origin-3228"></a>
## 18. 为什么 $R(a)R(b)=R(a+b)$？

二维旋转矩阵：

```math
R(a)
=
\begin{bmatrix}
\cos a&-\sin a\\
\sin a&\cos a
\end{bmatrix}
```

```math
R(b)
=
\begin{bmatrix}
\cos b&-\sin b\\
\sin b&\cos b
\end{bmatrix}
```

这里：

```text
R(b)
```

表示先旋转：

```math
b
```

然后再乘：

```text
R(a)
```

表示再旋转：

```math
a
```

所以：

```text
先转 b
↓
再转 a
↓
总共转 a+b
```

因此直观上：

```math
\boxed{
R(a)R(b)=R(a+b)
}
```

---

<a id="origin-3294"></a>
### 18.1 先用一个最简单的例子理解

假设一个向量：

```math
x=
\begin{bmatrix}
1\\
0
\end{bmatrix}
```

它原来指向右边。

先旋转：

```math
b=30^\circ
```

再旋转：

```math
a=60^\circ
```

那么总旋转角：

```math
30^\circ+60^\circ
=
90^\circ
```

所以：

```math
R(60^\circ)
R(30^\circ)
x
=
R(90^\circ)x
```

也就是说：

```text
原向量
↓
转30°
↓
再转60°
↓
最终和直接转90°完全一样
```

因此：

```math
\boxed{
R(60^\circ)R(30^\circ)
=
R(90^\circ)
}
```

---

<a id="origin-3362"></a>
### 18.2 为什么矩阵相乘可以理解成“连续做两个操作”？

假设：

```math
y=Bx
```

表示先对：

```math
x
```

做变换：

```math
B
```

然后：

```math
z=Ay
```

表示再做：

```math
A
```

代入：

```math
z
=
A(Bx)
```

根据矩阵乘法：

```math
z
=
(AB)x
```

所以：

> **矩阵乘法 $AB$，本身就表示“先执行 B，再执行 A”。**

因此：

```math
R(a)R(b)
```

表示：

```text
先旋转 b
↓
再旋转 a
```

总效果自然就是：

```math
a+b
```

---

<a id="origin-3436"></a>
### 18.3 直接从矩阵乘法证明

有：

```math
R(a)
=
\begin{bmatrix}
\cos a&-\sin a\\
\sin a&\cos a
\end{bmatrix}
```

以及：

```math
R(b)
=
\begin{bmatrix}
\cos b&-\sin b\\
\sin b&\cos b
\end{bmatrix}
```

相乘：

```math
R(a)R(b)
=
\begin{bmatrix}
\cos a&-\sin a\\
\sin a&\cos a
\end{bmatrix}
\begin{bmatrix}
\cos b&-\sin b\\
\sin b&\cos b
\end{bmatrix}
```

---

<a id="origin-3477"></a>
### 18.4 左上角

矩阵乘法左上角：

```math
\cos a\cos b
+
(-\sin a)\sin b
```

也就是：

```math
\cos a\cos b
-
\sin a\sin b
```

而三角函数和角公式：

```math
\cos(a+b)
=
\cos a\cos b
-
\sin a\sin b
```

所以左上角：

```math
\boxed{
\cos(a+b)
}
```

---

<a id="origin-3515"></a>
### 18.5 右上角

右上角：

```math
\cos a(-\sin b)
+
(-\sin a)\cos b
```

得到：

```math
-\cos a\sin b
-
\sin a\cos b
```

而：

```math
\sin(a+b)
=
\sin a\cos b
+
\cos a\sin b
```

所以：

```math
-\cos a\sin b
-
\sin a\cos b
=
-\sin(a+b)
```

因此右上角：

```math
\boxed{
-\sin(a+b)
}
```

---

<a id="origin-3563"></a>
### 18.6 左下角

左下角：

```math
\sin a\cos b
+
\cos a\sin b
```

根据和角公式：

```math
\sin(a+b)
=
\sin a\cos b
+
\cos a\sin b
```

所以：

```math
\boxed{
\sin(a+b)
}
```

---

<a id="origin-3593"></a>
### 18.7 右下角

右下角：

```math
\sin a(-\sin b)
+
\cos a\cos b
```

得到：

```math
-\sin a\sin b
+
\cos a\cos b
```

也就是：

```math
\cos a\cos b
-
\sin a\sin b
```

所以：

```math
\boxed{
\cos(a+b)
}
```

<a id="origin-3629"></a>
### 18.8 拼起来

因此：

```math
R(a)R(b)
=
\begin{bmatrix}
\cos(a+b)&-\sin(a+b)\\
\sin(a+b)&\cos(a+b)
\end{bmatrix}
```

而根据旋转矩阵定义：

```math
R(a+b)
=
\begin{bmatrix}
\cos(a+b)&-\sin(a+b)\\
\sin(a+b)&\cos(a+b)
\end{bmatrix}
```

所以：

```math
\boxed{

}
```

## 22. 为什么相对位置特别适合语言？

因为语言中的很多关系更依赖：

```text
距离
```

而不是：

```text
绝对位置编号
```

例如：

```text
我 非常 喜欢 苹果
```

真正有意义的是：

```text
“我”和“喜欢”相隔多远
```

而不是：

```text
“我”是不是整篇文章第 137 个 token
```

如果前面加几个词：

```text
昨天，我非常喜欢苹果。
```

整个短语整体后移。

但是：

```text
我 ↔ 喜欢
```

之间的相对关系基本没变。

所以：

```math
\boxed{
Relative\ Position
}
```

非常适合语言建模。

## 23. RoPE 最漂亮的一点

RoPE 没有直接显式计算：

```text
distance = position_K - position_Q
```

而是：

```text
position
↓
转换成旋转角度
↓
旋转 Q/K
↓
正常做 Q·K
↓
点积自动出现 n-m
```

因此可以记成：

> **RoPE 先把绝对位置编码成旋转角度，再利用旋转后的 Q、K 做点积，使 Attention Score 自然依赖相对位置。**

<a id="origin-3945"></a>
## 24. 为什么只旋转 Q 和 K？

Attention：

```math
Attention(Q,K,V)
=
softmax
\left(
\frac{QK^T}{\sqrt{d_k}}
\right)V
```

我们之前可以把 Q、K、V 理解成：

```text
Q：
我在找什么？

K：
我有什么特征，可以被谁找到？

V：
如果你决定关注我，
我真正提供什么内容？
```

决定：

```text
“应该关注谁？”
```

的是：

```math
QK^T
```

所以位置最需要影响的是：

```text
匹配关系
```

也就是：

```text
Q 和 K
```

而不是直接修改 V。

可以理解成：

> **位置主要影响“取谁、取多少”；V 负责“真正取回来什么内容”。**

## 25. Q/K 不是二维，而是高维怎么办？

实际模型中，一个 Attention Head 可能有很多维。

例如：

```text
head_dim = 96
```

RoPE 的办法是：

> **每两个维度分成一组。**

例如：

```math
q=
[q_0,q_1,q_2,q_3,q_4,q_5,\dots]
```

拆成：

```text
(q0, q1)
(q2, q3)
(q4, q5)
...
```

96 维：

```math
96/2=48
```

所以可以拆成：

```text
48 个二维平面
```

下一对：

做：

做：

```text
↓
```

<a id="origin-4104"></a>
## 27. 为什么每一对不用同一个旋转速度？

真实 RoPE 中，不是：

```text
所有维度：
position × 同一个 θ
```

而是：

```text
第 1 对维度 → 一个频率
第 2 对维度 → 另一个频率
第 3 对维度 → 再一个频率
...
```

可以直观理解成：

```text
有些维度旋转得快
→ 对短距离位置变化更敏感

有些维度旋转得慢
→ 可以表达更长距离的位置关系
```

这和经典正弦位置编码使用不同频率的 sin/cos 思想很接近。

<a id="origin-4136"></a>
## 28. 一个直观类比：很多块钟

可以把一个 Attention Head 想成很多块钟。

例如：

```text
第1块钟：转得非常快
第2块钟：稍微慢一点
第3块钟：更慢
...
第48块钟：转得很慢
```

position 每增加 1：

```text
所有钟都会向前转
```

但旋转速度不一样。

所以一个位置不是由：

```text
一个角度
```

表示，

而是由：

```text
很多不同频率的角度组合
```

表示。

## 29. cos 和 sin 是干什么的？

回到二维旋转公式：

```math
x'_1
=
x_1\cos\theta
-
x_2\sin\theta
```

```math
x'_2
=
x_1\sin\theta
+
x_2\cos\theta
```

所以只要知道：

```math
\cos(position\times\theta_i)
```

和：

```math
\sin(position\times\theta_i)
```

就可以完成旋转。

因此代码通常会提前计算：

```python
freqs_cos, freqs_sin = precompute_freqs_cis(...)
```

本质上就是：

> 提前把各个位置、各个频率所需要的 cos/sin 算出来。

## 31. RoPE 在 Attention 中的位置

```text
     ↓

     ↓

     ↓

     ↓
```

<a id="origin-4304"></a>
## 32. RoPE 和 $1/\sqrt{d_k}$ 不是一回事

这两个操作都在 Attention 附近，但解决的问题完全不同。

RoPE：

```text
解决：
token 在哪里？
两个 token 相隔多远？
```

而：

```math
\frac1{\sqrt{d_k}}
```

解决：

```text
Q·K 维度很多
↓
点积数值尺度随维度增大
↓
需要缩放
```

所以：

```math
\boxed{
RoPE=\text{位置信息}
}
```

```math
\boxed{
1/\sqrt{d_k}=\text{数值尺度控制}
}
```

<a id="origin-4348"></a>
## 33. RoPE 会不会改变向量长度？

不会。

旋转只改变方向，不改变长度。

例如：

```math
q=[1,0]
```

长度：

```math
\|q\|=1
```

旋转 $60^\circ$：

```math
q'=[0.5,0.866]
```

长度：

```math
\sqrt{0.5^2+0.866^2}
\approx1
```

所以：

```math
\boxed{
\|R(\theta)q\|=\|q\|
}
```

也就是说：

> **RoPE 主要通过改变 Q/K 的方向加入位置，而不是通过简单放大或缩小向量。**

```math
q=k=[1,0]
```

没有 RoPE 时：

```math
q\cdot k=1
```

无论两个 token：

```text
相隔 1 个位置
```

还是：

```text
相隔 100 个位置
```

如果内容向量相同：

```math
q\cdot k
```

都还是：

```math
1
```

Attention 看不出距离。

假设每个位置旋转：

```math
30^\circ
```

### 34.1 相差 1 个位置

角度差：

```math
30^\circ
```

点积：

```math
\cos30^\circ
\approx0.866
```

<a id="origin-4458"></a>
#### 34.1.1 相差 2 个位置

```math

=0.5
```

<a id="origin-4473"></a>


```text

距离 3 → score 0
```

> **RoPE 让 QK 的匹配不仅依赖内容，也能依赖相对位置。**

## 35. 不要误解成“越近一定越重要”

RoPE 并不是：

```text
距离近
→ Attention 一定大

距离远
→ Attention 一定小
```

真正的情况是：

```math
\boxed{
Attention\ Score
=
\text{内容关系和位置关系共同作用}
}
```

一个距离很远的 token，如果内容非常重要：

```text
模型仍然可以高度关注它
```

RoPE 只是让模型具有：

> **利用相对位置进行判断的能力。**

## 38. 为什么不直接给位置一个数字？

例如：

```text
位置 0 → 0
位置 1 → 1
位置 2 → 2
位置 3 → 3
```

这种绝对编号本身，并不会自然让 Attention 得到：

```text
位置 100
和
位置 101
```

之间：

```text
距离 = 1
```

的结构。

而 RoPE 利用：

```math
R(m\theta)^TR(n\theta)
=
R((n-m)\theta)
```

从数学上天然得到：

```math
n-m
```

这就是它非常漂亮的地方。

## 39. 整个 RoPE 故事线

可以把全过程串成：

```text
Self-Attention
只能根据内容计算 Q·K
↓
不知道 token 的顺序和距离
↓
需要加入 Position Information
↓
传统方法可以：
Embedding + Position Embedding
↓
RoPE 换一种思路：
不直接修改 token embedding
↓
生成 Q、K
↓
根据 token position
旋转 Q、K
↓
position m：
Q 旋转 mθ

position n：
K 旋转 nθ
↓
二者做点积
↓
R(mθ)ᵀR(nθ)
↓
R((n-m)θ)
↓
Attention Score
自然包含相对位置 n-m
```

所以：

```math
\boxed{
RoPE
=
\text{把位置编码成 Q/K 的旋转角度}
}
```

而它最精妙的地方是：

```math
\boxed{
\text{绝对位置经过 QK 点积以后，自然转化为相对位置}
}
```

## 40. 最后一句话

如果只记一句：

> **RoPE 的核心不是“给 token 加一个位置数字”，而是根据 token 的位置旋转 Q 和 K，使 Attention 在计算 $Q\cdot K$ 时，不仅知道“内容是否匹配”，还自然知道“两个 token 相隔多远”。**

进一步压缩：

```text
Attention：
谁和谁内容相关？

RoPE：
在这个匹配过程中，
再把“谁离谁多远”一起考虑进去。
```

<a id="origin-4736"></a>
## 41. RoPE 角度不是只有 360° 吗？位置重合怎么办？

这个问题非常关键。

因为旋转角度确实是周期的：

```math
360^\circ = 2\pi\ \text{rad}
```

并且：

```math
\sin(\theta+2\pi)=\sin\theta
```

```math
\cos(\theta+2\pi)=\cos\theta
```

所以如果只看**一个二维旋转平面**，确实会发生：

> 转一圈以后，方向重新回到原来的位置。

## 42. 单个频率确实会发生“重合”

假设某一组二维维度：

```math
\omega=90^\circ/token
```

那么：

```text
position 0
→ 0°

position 1
→ 90°

position 2
→ 180°

position 3
→ 270°

position 4
→ 360°
→ 等价于 0°
```

所以：

```math
position=0
```

和：

```math
position=4
```

在这一组二维维度上完全一样。

也就是说：

```text
单独一个旋转频率
确实存在周期重复
```

## 43. 为什么这不会让 RoPE 立刻失效？

```text

ω₁
ω₂
ω₃
...
```

每一组二维维度的旋转速度都不同。

例如为了方便，假设有三个频率：

```text

每个 token 转 90°

第二组：
每个 token 转 60°

第三组：
每个 token 转 10°
```

```text
第二组：0°
```

## 45. position 4 时

第一组：

```math
4\times90^\circ=360^\circ
```

等价于：

```text
0°
```

第二组：


第三组：

所以：

```text
(0°, 0°, 0°)


position 4：

(0°, 240°, 40°)
```

因此整体仍然完全不同。

---

<a id="origin-4928"></a>
## 46. 所以真正的位置不是“一个角度”

这是理解 RoPE 最重要的一点。

不要理解成：

```text
position 100
→ 一个角度
```

而应该理解成：

```text
position 100
→ 很多组不同频率的角度
```

例如：

```text
position 100：

第1组 → 角度 A
第2组 → 角度 B
第3组 → 角度 C
第4组 → 角度 D
...
```

最终位置由：

```math
\boxed{
(\phi_0,\phi_1,\phi_2,\ldots)
}
```

这一整组角度共同表示。

其中：

```math
\phi_i=m\omega_i
```

---


<a id="origin-4977"></a>
## 47. 另一个例子：单个频率确实可能把两个不同距离看成一样

假设某一组二维 RoPE 的旋转频率是：

$$
\omega=60^\circ/token
$$

也就是说：

> token 的相对距离每增加 1，这一组二维向量就多旋转 $60^\circ$。

在 Attention 中，我们真正关心的是 Query 和 Key 的相对位置：

$$
\Delta m=n-m
$$

这一组频率对应的相对旋转角度就是：

$$
\Delta\phi
=
\Delta m\cdot\omega
$$

---

<a id="origin-5005"></a>
## 48. 例子：距离 7 和距离 607

我们来看一个最终仍然有明显角度的情况。

---

<a id="origin-5011"></a>
### 48.1 距离 7

假设两个 token 相隔：

$$
\Delta m=7
$$

那么这一组 RoPE 频率产生的相对角度：

$$
\Delta\phi
=
7\times60^\circ
=
420^\circ
$$

因为：

$$
420^\circ
=
360^\circ+60^\circ
$$

旋转一整圈以后，还剩：

$$
60^\circ
$$

所以：

$$
420^\circ
\equiv
60^\circ
$$

因此：

$$
\boxed{
R(7\omega)=R(60^\circ)
}
$$

---

<a id="origin-5061"></a>
### 48.2 距离 607

现在两个 token 相隔：

$$
\Delta m=607
$$

那么：

$$
\Delta\phi
=
607\times60^\circ
=
36420^\circ
$$

其中：

$$
36420^\circ
=
101\times360^\circ+60^\circ
$$

也就是说，它已经完整转了 101 圈，然后又多转了：

$$
60^\circ
$$

因此：

$$
36420^\circ
\equiv
60^\circ
$$

于是：

$$
\boxed{
R(607\omega)=R(60^\circ)
}
$$

---

<a id="origin-5111"></a>
## 49. 所以距离 7 和距离 607，在这一组频率上完全一样

我们得到：

$$
\boxed{
R(7\omega)
=
R(607\omega)
}
$$

因为两者最终对应的角度都是：

$$
60^\circ
$$

也就是说：

```text
距离 7
→ 420°
→ 绕一圈以后剩 60°

距离 607
→ 36420°
→ 绕 101 圈以后剩 60°
```

所以对于这一组二维 RoPE 来说：

```text
距离 7
和
距离 607
```

产生了完全相同的相对旋转。

---

<a id="origin-5153"></a>
## 50. 这意味着模型学到的信息也一样吗？

如果我们 **只看这一组 RoPE 频率提供的位置关系信息**，那么：

$$
\boxed{
距离7
\quad\text{和}\quad
距离607
}
$$

**确实无法区分。**

因为：

$$
R(7\omega)=R(607\omega)
$$

所以这一组二维平面给 Attention 提供的相对位置变化完全一样。

可以粗略理解成：

```text
这一组 RoPE 维度：

距离 7
→ “相对角度是 60°”

距离 607
→ “相对角度也是 60°”
```

因此：

> **如果模型只有这一组频率，那么仅从这一组位置编码来看，距离 7 和距离 607 是无法区分的。**

不过要注意：

> 这里只是说“这一组 RoPE 频率提供的位置关系信号一样”，并不是说完整的 Attention 信息一定完全一样。

因为 Query 和 Key 本身还有语义内容，而且真实 RoPE 还有很多其他频率。

---

<a id="origin-5199"></a>
## 51. 为什么 RoPE 不会因此立刻失效？

因为 RoPE 并不是只使用一个：

$$
\omega
$$

而是使用很多不同频率：

$$
\omega_0,\omega_1,\omega_2,\omega_3,\ldots
$$

每一组二维维度的旋转速度都不同。

例如，为了方便理解，我们假设有三组频率：

```text
第一组：60° / token
第二组：10° / token
第三组：1° / token
```

---

<a id="origin-5225"></a>
## 52. 距离 7 时，三组频率分别是什么角度？

<a id="origin-5227"></a>
### 52.1 第一组：60° / token

$$
7\times60^\circ
=
420^\circ
$$

去掉一整圈：

$$
420^\circ\bmod360^\circ
=
60^\circ
$$

---

<a id="origin-5245"></a>
### 52.2 第二组：10° / token

$$
7\times10^\circ
=
70^\circ
$$

---

<a id="origin-5255"></a>
### 52.3 第三组：1° / token

$$
7\times1^\circ
=
7^\circ
$$

所以距离 7 的整体相位组合可以粗略写成：

$$
\boxed{
(60^\circ,\ 70^\circ,\ 7^\circ)
}
$$

---

<a id="origin-5273"></a>
## 53. 距离 607 时呢？

<a id="origin-5275"></a>
### 53.1 第一组：60° / token

$$
607\times60^\circ
=
36420^\circ
$$

去掉完整旋转：

$$
36420^\circ\bmod360^\circ
=
60^\circ
$$

所以第一组还是：

$$
60^\circ
$$

这一组确实和距离 7 撞车了。

---

<a id="origin-5301"></a>
### 53.2 第二组：10° / token

$$
607\times10^\circ
=
6070^\circ
$$

去掉完整的圈：

$$
6070^\circ\bmod360^\circ
=
310^\circ
$$

所以第二组：

$$
310^\circ
$$

---

<a id="origin-5325"></a>
### 53.3 第三组：1° / token

$$
607\times1^\circ
=
607^\circ
$$

去掉一整圈：

$$
607^\circ\bmod360^\circ
=
247^\circ
$$

所以第三组：

$$
247^\circ
$$

最终距离 607 的相位组合：

$$
\boxed{
(60^\circ,\ 310^\circ,\ 247^\circ)
}
$$

---

<a id="origin-5357"></a>
## 54. 现在比较距离 7 和距离 607

距离 7：

$$
\boxed{
(60^\circ,\ 70^\circ,\ 7^\circ)
}
$$

距离 607：

$$
\boxed{
(60^\circ,\ 310^\circ,\ 247^\circ)
}
$$

可以看到：

```text
第一组：
距离 7   → 60°
距离 607 → 60°
```

**这一组确实完全分不出来。**

但是：

```text
第二组：
距离 7   → 70°
距离 607 → 310°

第三组：
距离 7   → 7°
距离 607 → 247°
```

其他频率却明显不同。

所以整体上：

$$
\boxed{
距离7\neq距离607
}
$$

<a id="origin-5407"></a>
## 55. 即使某些维度重合，也不代表 Attention 完全一样

还有一个更重要的问题。

RoPE 只是作用在：

```text
Q
K
```

上。

Attention Score 仍然取决于：

```math
QK^T
```

而 Q、K 本身还来自：

```math
Q=XW_Q
```

```math
K=XW_K
```

其中：

```text
X
```

包含 token 的内容和上下文信息。

所以即使某几个 RoPE 维度的角度碰巧重合：

```text
位置部分某些维度一样
```

也不意味着：

```text
Q 完全一样
K 完全一样
Attention 完全一样
```

因为 token 内容本身可能完全不同。

---

<a id="origin-5462"></a>
## 56. RoPE真正依赖的是“多频率组合”

所以更准确的理解是：

```text
单个二维平面
↓
周期性很强
↓
会重复
```

但：

```text
几十个二维平面
+
几十个不同 ω
↓
组合成一个高维位置模式
```

因此：

```math
\boxed{
\text{单频率会重合}
\neq
\text{整个 RoPE 位置编码会立刻重合}
}
```

---

<a id="origin-5496"></a>
## 57. 那是不是永远不会重合？

不能这么说。

从纯数学角度看：

> 周期函数一定存在重复或近似重复的问题。

尤其当 position 非常非常长时，不同位置的多频率相位组合可能变得更难区分。

这也是长上下文 RoPE 会面临的问题之一。

所以：

```text
RoPE 并不是无限长度都完美
```

而是：

```text
在合理上下文范围内
多频率组合能够非常有效地表达位置
```

超出训练长度以后：

```text
位置越来越长
↓
相位组合进入陌生区域
↓
位置外推变难
```

于是才会出现：

```text
Position Interpolation
YaRN
NTK-aware scaling
```

这类长上下文扩展方法。

---

<a id="origin-5543"></a>
## 58. RoPE 中位置周期重复为什么会产生问题？

在 RoPE（Rotary Position Embedding，旋转位置编码）中，一个非常重要的问题是：

> 如果位置 $p$ 和位置 $p+12$ 对应相同的旋转状态，会发生什么？

核心答案是：

> **不同的相对距离可能被映射成相同的位置关系，从而产生“位置混叠（aliasing）”。**

更准确地说，并不是模型完全分不清两个 token，而是：

$$
\boxed{\text{RoPE 无法再帮助模型区分这两个不同的相对距离}}
$$

---

<a id="origin-5561"></a>
## 59. RoPE 真正编码的是相对位置

假设位置 $p$ 上有一个 Query：

$$
Q_p
$$

位置 $q$ 上有一个 Key：

$$
K_q
$$

经过 RoPE 旋转之后：

$$
Q'_p=R_pQ_p
$$

$$
K'_q=R_qK_q
$$

Attention Score 中需要计算：

$$
(Q'_p)^TK'_q
$$

代入：

$$
(R_pQ_p)^T(R_qK_q)
$$

得到：

$$
Q_p^TR_p^TR_qK_q
$$

旋转矩阵具有：

$$
R_p^TR_q=R_{q-p}
$$

因此：

$$
(Q'_p)^TK'_q
=
Q_p^TR_{q-p}K_q
$$

注意这里最终出现的是：

$$
\boxed{q-p}
$$

也就是两个 token 之间的**相对距离**。

因此 RoPE 最重要的性质不是告诉模型：

```text
这个 token 在绝对位置 100
```

而是告诉模型：

```text
Query 和 Key 相隔了多少位置
```

---

<a id="origin-5639"></a>
## 60. 如果位置编码每 12 个位置完全重复

为了方便理解，假设有一个极端情况：

$$
R_{p+12}=R_p
$$

那么就意味着旋转具有周期 12。

于是：

$$
R_1=R_{13}
$$

因为：

$$
13=1+12
$$

这意味着从 RoPE 的角度来看：

```text
距离 1
```

和：

```text
距离 13
```

对应的是完全相同的旋转关系。

---

<a id="origin-5677"></a>
## 61. 一个具体例子

假设当前 token 在位置：

$$
20
$$

现在它要关注前面一个 `"apple"`。

<a id="origin-5687"></a>
### 61.1 情况一：apple 很近

```text
位置19：apple
位置20：eat
```

相对距离：

$$
20-19=1
$$

所以对应：

$$
R_1
$$

---

<a id="origin-5708"></a>
### 61.2 情况二：apple 很远

```text
位置7 ：apple
...
位置20：eat
```

相对距离：

$$
20-7=13
$$

对应：

$$
R_{13}
$$

如果旋转周期为 12：

$$
R_{13}=R_1
$$

于是：

```text
距离 1
```

和：

```text
距离 13
```

从 RoPE 提供的位置关系来看：

$$
\boxed{\text{完全一样}}
$$

---

<a id="origin-5754"></a>
## 62. 这会造成什么问题？

原本模型应该可以区分：

```text
apple 就在我前面
```

和：

```text
apple 是很久以前出现的
```

也就是说：

```text
距离 1
```

和：

```text
距离 13
```

应该拥有不同的位置特征。

正常情况下可以理解为：

```text
距离 1  → 位置模式 A
距离 2  → 位置模式 B
距离 3  → 位置模式 C
...
距离13 → 位置模式 M
```

这样模型可以学习：

```text
距离很近的 token
通常具有较强局部联系
```

或者：

```text
某些很远的 token
具有长期依赖关系
```

---

但如果发生周期重复：

```text
距离 1  → 位置模式 A
距离13 → 位置模式 A
```

模型看到：

```text
位置模式 A
```

之后，仅凭 RoPE 无法判断：

```text
这是距离 1
```

还是：

```text
这是距离 13
```

因此发生：

$$
\boxed{\text{相对位置混叠}}
$$

---

<a id="origin-5841"></a>
## 63. 不是两个 token 完全一样

这里需要特别注意。

假设：

```text
位置7 ：apple
位置19：apple
位置20：eat
```

虽然位置 7 和位置 19 的 `"apple"` 是同一个单词，但它们经过前面 Transformer 层之后的 hidden state 不一定完全相同。

也就是说：

$$
K_7\neq K_{19}
$$

因为上下文不同。

所以模型并不是完全分不清：

```text
位置7
```

和：

```text
位置19
```

真正丢失的是：

$$
\boxed{\text{由 RoPE 提供的距离区别}}
$$

也就是说：

> 内容信息可能还能区分它们，但是位置编码本身已经无法说明“一个离我 1 个 token，一个离我 13 个 token”。

---

<a id="origin-5887"></a>
## 64. 为什么这对语言模型很重要？

考虑：

```text
not good
```

这里：

```text
not
```

和：

```text
good
```

非常接近。

模型应该很容易学习：

```text
not
↓
强烈影响
↓
good
```

---

但是另外一种情况：

```text
not
...
中间几千个 token
...
good
```

虽然同样出现：

```text
not
```

和：

```text
good
```

但它们之间的位置关系显然不同。

如果：

$$
R_1=R_{4097}
$$

那么 RoPE 对：

```text
距离 1
```

和：

```text
距离 4097
```

提供的位置特征完全一样。

那么位置编码就无法帮助模型判断：

> 这个 `not` 是紧挨着 `good` 的，还是 4097 个 token 以前出现的？

---

<a id="origin-5971"></a>
## 65. 所以不是“相对位置不明显”

更准确的描述不是：

> 相对位置变得不明显。

而应该是：

$$
\boxed{\text{不同的相对位置变得不可区分}}
$$

也就是：

```text
distance = 1
```

和：

```text
distance = 13
```

被映射到了相同的位置编码模式。

这就是：

$$
\boxed{\text{Position Aliasing}}
$$

即：

> **位置混叠。**

---

<a id="origin-6009"></a>
## 66. 为什么 RoPE 要使用很多不同频率？

如果只有一个旋转频率，那么它一定会周期性重复。

假设：

$$
\theta_p=p\omega
$$

旋转一圈：

$$
2\pi
$$

对应的位置周期为：

$$
T=\frac{2\pi}{\omega}
$$

于是：

$$
R_{p+T}=R_p
$$

所以单独一个频率一定存在周期重复。

---

因此 RoPE 不只使用一个频率，而是使用很多频率：

$$
\omega_1,\omega_2,\omega_3,\dots
$$

每一组二维维度对应不同的旋转速度。

可以理解成：

```text
第1组维度：非常快
第2组维度：比较快
第3组维度：比较慢
...
最后几组：非常慢
```

因此一个距离 $d$ 的位置特征实际上不是一个角度，而是：

$$
[
d\omega_1,
d\omega_2,
d\omega_3,
\dots
]
$$

---

<a id="origin-6072"></a>
## 67. 类似钟表

可以把它类比成钟表。

如果只有秒针：

```text
00 秒
```

和：

```text
60 秒
```

秒针的位置完全一样。

所以仅仅看秒针：

```text
无法知道过去了 0 秒
还是 60 秒
```

---

但如果同时有：

```text
秒针
+
分针
+
时针
```

那么即使：

```text
秒针回到了原来的位置
```

分针可能已经改变：

```text
秒针：一样
分针：不同
时针：不同
```

于是整体状态仍然可以区分不同时间。

---

RoPE 就类似于：

```text
高速旋转维度 ≈ 秒针
中速旋转维度 ≈ 分针
低速旋转维度 ≈ 时针
```

多个不同频率共同组成一个位置的：

$$
\boxed{\text{相位指纹}}
$$

---

<a id="origin-6143"></a>
## 68. 为什么不能让所有维度都高速旋转？

如果所有维度都在很短的长度内转很多圈，相当于：

```text
全部都是秒针
```

那么所有维度都会频繁发生周期重复。

于是长距离的位置区别能力就会下降。

因此 RoPE 有意同时保留：

```text
高频维度
```

和：

```text
低频维度
```

---

高频维度主要负责：

$$
\boxed{\text{短距离的精确区分}}
$$

例如：

```text
距离 1
距离 2
距离 3
```

变化非常明显。

---

低频维度主要负责：

$$
\boxed{\text{长距离的位置区分}}
$$

例如：

```text
距离 100
距离 1000
距离 10000
```

仍然可以保持不同的相位状态。

---

<a id="origin-6205"></a>
## 69. 最核心的结论

RoPE 中最重要的不是：

```text
某个位置转了多少圈
```

也不是：

```text
有没有覆盖完整的 360°
```

而是：

$$
\boxed{
\text{不同相对距离是否还能产生不同的多频率相位组合}
}
$$

如果：

$$
R_d=R_{d+T}
$$

那么：

```text
距离 d
```

和：

```text
距离 d+T
```

在 RoPE 的位置编码中就无法区分。

因此：

$$
\boxed{
\text{位置周期重复}
\Rightarrow
\text{相对距离混叠}
}
$$

进一步来说：

$$
\boxed{
\text{单个频率必然周期重复，但多个不同频率联合起来，可以大幅降低整体的位置混叠。}
}
$$

所以 RoPE 使用多频率，本质上就是利用：

```text
快指针
+
慢指针
```

共同编码位置，让模型既能精确识别短距离关系，又能区分长距离关系。

---
